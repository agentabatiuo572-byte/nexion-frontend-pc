# 专属客服工作台与维护闭环规格

需求来源：[OWNER-DECISIONS.md](OWNER-DECISIONS.md)，协调消歧见[HANDOFF.md](HANDOFF.md)。本规格定义功能；[CONTRACTS.md](CONTRACTS.md)定义数据、状态、API与计数；[ACCEPTANCE.md](ACCEPTANCE.md)给反例验收；[IMPLEMENTATION-PLAN.md](IMPLEMENTATION-PLAN.md)给阶段所有权。没有生产实现完成声明。原始决定不可修改；S1默认在C1显式列出，参数无来源保持未配置。

基本事实：现有绑定、会话接待和邀请关系各自保存，当前忙碌回退与普通转接不满足严格专属。不可变条件：一客至多一个顾问、消息隔离、邀请与财务关系不动。最小方案：复用现有客服/消息实体，收敛授权和绑定事务，补维护事实与活动事件。最小可证伪实验：A绑定G1但G1忙，A留言仍只交G1；主管转绑G2后G1所有旧路径均失权。

## 功能范围与入口

复用后台 `/service/overview`、`/service/sessions`、`/service/scripts` 与工单/知识库入口。普通客服登录默认进入本人工作台；主管在同域切换管理视图；超管配置规则。界面是否拆出新路由由 S2/S5 确定，但功能和权限不能因此缺失。客户端仅 `/pages/support/messages`、`/pages/support/chat` 及原有求助/工单相关入口必要对齐；AI、网站、营销、财务、语音视频不在范围。S2 提供实际生图、语义校正、可点关键流；本文件交互描述只约束行为，不含视觉规格。

#### [FEAT-M01] 本人工作台与客户列表

**① 用户故事 / 目的与对齐**

作为客服，我想要登录后看到本人客户和可执行待办，以便直接联系需要服务的客户。作为主管，我想要查看归属和待绑定缺口，以便安排交接。对应原始目标1、R03、六指标边界；不以会话数量冒充绑定人数。

**② 验收（GWT）与异常路径**

- Given G1/G2各有客户，When G1登录，Then 六指标和列表仅覆盖G1，点击指标得到同口径名单，分页不改变总量。
- 异常1：Given 活跃源缺失或规则未配置，When 打开工作台，Then 活跃/沉睡等受影响计数显示不可用及原因，未知客户仍能打开求助，不展示假零或假时间。
- 异常2：Given 旧页中的客户已转给G2，When G1点击客户或重试旧请求，Then 服务端拒绝并移除过期详情、草稿附件缓存，不能靠返回/收藏链接重看正文。
- 异常3：Given 网络中断或分页过程中数据改变，When 请求失败，Then 保留筛选、显示重试；响应带统计时间，禁止把旧列表与新指标宣称同一快照。

**③ 数据字典、参数与生成规则**

| 字段 | 类型/必填/默认 | 权威与规则 |
|---|---|---|
| overview | 六项 number或null / 是 / 不伪零 | CONTRACTS C4.3 服务端聚合 |
| records | CustomerSummary[] / 是 / [] | customerId唯一；含assignmentId/version、姓名/编号、顾问、活动标签、维护状态、下次维护时间、待回复 |
| evaluatedAt/rulesVersion/completeness | 时间/版本/完整性 / 是 | 同一聚合快照；列表空与数据不可用分开 |
| filters | enum+keyword+分页 / 是 | C5.2；只有主管可跨顾问筛选 |

只读接口 C5.2 overview/customers/detail；D/M/W 由 M05 管理。列表顺序使用待回复优先、到期时间升序、customerId稳定破同值的最小默认；服务端执行筛选，不把全客户拉到浏览器过滤。

**④ 状态机、操作与禁止动作**

查询 idle→loading→ready/empty/error；旧请求晚到不得覆盖新身份/新筛选。当前 ACTIVE/DORMANT/UNKNOWN 与窗口活跃分开（C4.3）。权限见 C5；禁止客服切他人 agentId、查看待绑定池全量资料。无写审计事件；访问敏感资料记既有访问日志，不新增无用途营销埋点。

**⑤ 交互原型多状态**

默认：六指标、客户/待办、会话入口，绑定人数与并发会话分列。空状态：说明尚无绑定或该筛选无人，保留切回全部。加载态：对应卡片/列表骨架，不允许用旧身份数据填充。报错：分区重试；长姓名/大数字不遮按钮，窄屏可逐行读客户与动作。无权限显示返回本人工作台；键盘焦点可达每一动作。

**⑥ 点击流矩阵**

| 触发 | 目标 | 反馈 / 退出 |
|---|---|---|
| 六指标任一 | 当前页匹配筛选列表 | 显示口径和数量；清除筛选回全部 |
| 搜索/筛选/分页 | 服务端查询 | 加载、取消过期请求、失败重试 |
| 客户行 | 客户详情 | 展示当前归属；关闭返回原筛选位置 |
| 联系/回复待办 | M03 对应客户会话 | 待回复优先定位未处理消息，首次联系预填客户但不自动发送 |
| 待维护/不再维护列表 | M04 | 显示原因及下一步 |
| 主管待绑定入口 | M02 管理视图 | 无权不显示，直接访问仍服务端拒绝 |

**⑦ 跨文档一致性 / 联动**

指标只由 C4.3 定义；入口复用 SOURCE-MAP 后台路由。客户端不显示后台维护算法/业绩。审查覆盖旧 M1 总览、M5 绑定入口和 shell badge；所有读旁路纳入 AC01、AC06。

#### [FEAT-M02] 分配、邀请继承与正式转绑

**① 用户故事 / 目的与对齐**

作为主管，我想要从待绑定池显式选择客户与顾问，以便建立唯一归属；作为被邀请注册的客户，我想要按已配置继承层数获得顾问，以便延续服务。对齐 R02/R03/R04，禁止借接待转接换顾问。

**② 验收（GWT）与异常路径**

- Given 测试规则L=2，A为人工root0，When B/C/D依次注册，Then B1/C2归同顾问，D入池；D人工分G2为root0，D未来邀请重新计层。2只作测试输入。
- 异常1：Given 两名主管同时分同一客户，When 两请求并发，Then 仅一个成功，另一个409；绑定唯一且失败请求不重置段、不制造历史记录，重新预览后才能确认。
- 异常2：Given 无邀请人/邀请人未绑定/超层/规则未配，When 注册，Then 注册成功且准确入池；邀请人后补绑不自动吸走既有池客户，禁止向祖先跳查。
- 异常3：Given G1离线/忙碌/并发满但资格有效，When 本人客户留言或新客户符合继承，Then 仍归G1；停用顾问不再接新继承，已有客户等待主管正式转绑。
- 异常4：Given 转绑预览后有客户归属变化或目标停用，When 批量提交，Then 全部失败并保留选择供刷新重审，不能一部分转完却显示整体成功。

**③ 数据字典、参数与生成规则**

| 字段 | 类型/必填/默认 | 生成与限制 |
|---|---|---|
| assignment / pool | C2对象 / 是 | 当前唯一；历史保留 |
| selectedCustomers | id+version+assignmentId数组 / 是 | 实际选中集；不得运行时扩大后代范围 |
| targetAgentAdminId | bigint / 是 | 服务端验证账号、客服资格；不由名字匹配 |
| reason | string / 是 / 无 | 8–200字，单独理由输入 |
| inheritanceMode/maxInheritanceDepth | enum+integer或null / 是 / UNCONFIGURED+null | 未配置/有限/不限明确区分；有限0合法，仅未来注册；不限也防环 |

接口 C5.1 分配/seat-assignment及 C5.2 pool/transfer；所有入口统一 C2.1 事务、幂等和版本。事件 `support.assignment.changed`、`support.binding.queued` 记录 customer/assignment/oldAgent/newAgent/ruleVersion/command/actor/reason；供审计与投影，不能修改邀请树。

**④ 状态机、权限与禁止动作**

UNBOUND→BOUND；BOUND(A)→BOUND(B)；BOUND停用顾问→保留绑定+交接待办。人工分配新root0，同顾问重试/no-op不重置。主管/超管可执行，普通客服不可分配/转绑/解除。每次变更确认实际清单、前后顾问及原因，追加审计。禁止旧 DELETE 解除绕过正式转绑；迁移冲突隔离按 M07。

**⑤ 交互原型多状态**

默认：待绑定池有原因、可搜索选择，转绑默认仅当前客户，后代显式展开选中。空状态：无待分配客户或无有效顾问分别解释，后者禁止确认。加载态：候选和影响预览独立骨架，未完成不可提交。报错：冲突逐项展示且保留选择；取消关闭不写入。长列表分页、全选仅明确当前页，显示实际选中总数，不做隐藏全库全选。

**⑥ 点击流矩阵**

| 触发 | 目标 | 反馈 / 退出 |
|---|---|---|
| 待绑定筛选/客户勾选 | 本页选择集 | 入池原因可读、分页选择可见 |
| 分配/转绑 | 确认弹窗 | 客户清单、原→新顾问、独立选择控件+理由 |
| 展开后代/逐个勾选 | 显式范围预览 | 未勾选保持原归属，返回不扩大选择 |
| 确认 | 原子API | 提交中禁重复；成功重读；未知结果同key回查 |
| 取消/返回 | 原管理视图 | 无副作用；提交未知先回查再放弃 |
| 顾问停用交接 | 绑定客户筛选→正式转绑 | 保留客户求助，不自动均衡 |

**⑦ 一致性 / 跨端**

R02/R04→C3；所有绑定入口（M1/M5/profile/seat）、注册和普通转接共用服务端不变量。客户端下一次读立即显示新顾问；老顾问流、历史和图片撤权。AC02–AC05、AC11验证。

#### [FEAT-M03] 严格专属私聊与求助

**① 用户故事 / 目的与对齐**

作为客户，我想要向自己的顾问留言并接续历史，以便顾问离线时也不丢求助。作为客服，我想要收到本人客户消息并回复，以便完成服务。R01/R03约束仅文字/图片，暂无语音视频。

**② 验收（GWT）与异常路径**

- Given A绑定G1，When A经advisor或support入口发信，Then 同一归属授权，G1可读回回复，A刷新仍见原作者及消息；已读不等于已回复。
- 异常1：Given A未绑定，When A提交文字/图片，Then 持久化留言并显示等待分配，不报伪发送失败、不分给随机空闲客服；主管能发现待绑定求助，正式分配后顾问接续。
- 异常2：Given G1编辑回复时A转绑G2，When G1发送或重连SSE，Then 拒绝且不落消息/执行；G2见必要历史，G1缓存清除，后台姓名字段不能伪装成G2。
- 异常3：Given 消息已提交但响应丢失，When 刷新后重试，Then 原key回查返回同消息；明确失败才可更换内容发新命令，不能新key重复轰炸。
- 异常4：Given 关闭的旧服务会话，When 客户再次求助，Then 建新段仍跟同一归属；工单内部换处理人不能赋予新处理人对客回复权。

**③ 数据字典、参数与生成规则**

| 字段 | 类型/必填/默认 | 规则 |
|---|---|---|
| conversationNo/version/status | 既有字段 / 是 | 保留现有会话状态和分页契约 |
| message | C2 HumanMessage / 是 | TEXT或IMAGE；senderAdminId服务端取 |
| bindingStatus/advisor | BOUND/UNBOUND/UNAVAILABLE+最小资料 / 是 | 客户端只读归属，不暴露层级与内部代码 |
| replyTargets | [{conversationNo,throughMessageId}] / 可选 | 显式处理同客户选中会话游标；存量关闭段在新段回复覆盖，不能吞并发新消息 |

现有会话/工单端点和SSE见 C5.1；普通服务发信 intent=SERVICE，维护入口才MAINTENANCE。会话并发是工作量，不是改变绑定的条件。事件 `support.message.committed` 供收件箱与维护事务使用；消息正文不进业务审计日志。

**④ 状态机、权限与禁止动作**

会话OPEN→RESOLVED/CLOSED前须无未处理客户消息，否则先回复；新求助续新段。存量关闭且未回复段由“接续回复”在新段发送并显式覆盖旧游标（C4.3），旧段不追加。旧TRANSFERRED只读兼容，人工线旧transfer拒绝。发送draft→sending→sent/unknown/failed；unknown同key回查，failed可编辑重发。当前顾问/本人客户发信，主管只审阅；列表/详情/历史/流/回查同一授权。禁止自动推送冒充人工执行、read清待回复。

**⑤ 交互原型多状态**

默认：会话列表、消息线程、当前顾问、可编辑输入。空状态：首次求助可直接输入，未绑定说明等待分配。加载态：历史骨架，输入不丢失。报错：消息旁重试/查询结果，断线可重连；失权关闭线程，保留合理提示不展示内部错误码。窄屏有返回列表，输入框不遮发送；键盘Enter/换行沿用现有规范。

**⑥ 点击流矩阵**

| 触发 | 目标 | 反馈 / 退出 |
|---|---|---|
| 客户/会话行 | 授权线程 | 读消息并标已读，不标已回复 |
| 发送文字/快捷话术 | 当前线程发送 | 需人工点击，成功读回，失败留稿 |
| 重试/查询结果 | 原命令 | 同key恢复；明确结果前禁重复新发 |
| 发图片/预览 | M06 | 上传与发送分离，可取消 |
| 关闭服务会话/再次求助 | 状态提交/新段 | 不解绑；明确原因、失败回退 |
| 存量关闭会话“接续回复” | 同客户新段编辑器 | 显示将处理的旧消息，成功才清指定游标，取消不清 |
| 转工单/工单详情 | 原M2工单 | 保留原功能，内部协作不授予对客权 |
| 主管正式转绑 | M02 | 当前归属与影响确认，普通客服仅提示联系主管 |
| 返回列表 | M01或消息列表 | 草稿按账号/客户隔离，失权清除 |

**⑦ 一致性 / 跨端**

后台M3与浮动接待dock、M2回复和客户端chat/messages须同步；知识库M4保留。Nova AI路径不混进人工归属/维护成功。AC03/AC06/AC09/AC12证明。

#### [FEAT-M04] 维护执行、成功与停止恢复

**① 用户故事 / 目的与对齐**

作为客服，我想要联系本人客户并分清已执行和成功，以便知道哪些客户仍待跟进；我想要有理由地停止与恢复主动维护，以便不反复联系已决定暂停的客户。严格对齐R05，不以客服回复冒充账户活动。

**② 验收（GWT）与异常路径**

- Given 本人到期客户，When 通过维护入口人工发送成功，Then 记录一次执行与OPEN周期；之后新的有效活动事件将其变为成功，执行和成功分别计数。
- 异常1：Given 原本活跃或unknown客户，When 发送维护，Then 不能立刻成功；必须有之后新有效事件。读取页面、客户回复、token刷新或重算阈值都不成功。
- 异常2：Given OPEN周期内重复联系或超时重试，When 新消息/同消息分别提交，Then 新消息只增执行、同消息不增；首次联系基线不重置，一个活动事件只结一个周期。
- 异常3：Given 已停止，When 客户重新活跃或主动求助，Then 更新真实活动/待回复但不制造维护成功，客服仍能服务回复；恢复后旧周期不复活，按现状计算到期。
- 异常4：Given G1维护后转绑G2，When 活动随后到达，Then G1原OPEN为TRANSFERRED，不能给G1补成功或给G2冒领；既有成功历史仍归G1，G2需自己新执行。

**③ 数据字典、参数与生成规则**

| 字段 | 类型/必填/默认 | 规则 |
|---|---|---|
| enabled/version/reason | boolean/bigint/string / 是 / true | C2客户级偏好，转绑保留；停止/恢复有理由 |
| execution/cycle | C2对象 / 执行后必有 | 同消息提交事务生成，不允许手动“完成”API |
| baselineActivitySeq/successEventId | seq/id / 周期必有前者、成功有后者 | C4.1真实新事件，数据缺失不补造 |
| nextDueAt/firstContact | 时间? / boolean | C4.2；M无来源则null不可用 |

接口 C5.2 maintenance及C5.1消息。参数只引用M05。事件 `support.maintenance.executed/succeeded/preference_changed` 各保存customer/assignment/agent/cycle/command或eventId，审计前后状态和理由，不发送额外自动营销消息。

**④ 状态机、权限与禁止动作**

OPEN→SUCCEEDED/STOPPED/TRANSFERRED，全为终态不可反改；恢复仅偏好stopped→enabled，下次实际联系另建OPEN。一个客户当前归属最多一个OPEN。禁止点击完成、修改备注、自动推送、规则重算、普通服务回复创建执行/成功。停止仅本人顾问且确认理由；主管只能转绑与审阅。并发停止/活动/发送按C2.1锁顺序线性化，最终结果可审计。

M仅控制待办提醒，提前人工维护或M未配置均可发信/新开周期；不得在界面新增无依据的到期发送限制。无OPEN的显式维护成功发送总是新周期，仍需之后新活动才能成功。

**⑤ 交互原型多状态**

默认：待维护清单、执行时间、等待活跃/成功结果分开；详情显示停止原因与恢复。空状态：没有到期待办，但仍可看全部客户。加载态：历史与状态占位，避免显示旧成功。报错：发送失败不显示执行；停止/恢复失败保持原状态，冲突刷新后重新确认；未配置解释依赖，不能用示例天数填位。停止弹窗直说仅停止主动跟进，仍接收求助。

**⑥ 点击流矩阵**

| 触发 | 目标 | 反馈 / 退出 |
|---|---|---|
| 联系维护 | M03编辑器MAINTENANCE意图 | 明示发送后记执行；取消不产生事实 |

#### [FEAT-M05] 规则配置与权限

**① 用户故事 / 目的与对齐**

作为超管，我想要配置沉睡、维护间隔、活动窗口和继承层数，以便按业务政策运行客服流程。作为主管，我想要看到生效范围，以便不误以为改层数会重排既有客户。来源原始目标2/4与配置边界。

**② 验收（GWT）与异常路径**

- Given 超管提交有效D/M/W/L及理由，When 保存成功，Then 读回新版本；D/M/W重算当前标签，L仅影响未来注册，不改任何历史归属或成功。

- 异常2：Given 负值、小数、同时有D/W且W>D或LIMITED缺L，When 提交，Then 拒绝并就地说明；D/M/W允许独立未配置，有限L=0合法，不限必须显式选择，不把null同时当未配和不限。
- 异常3：Given 两个超管读到同版本，When 先后保存，Then 第二次409，保留编辑内容与差异供重审；超时同key回查不增版本。

**③ 数据字典、参数与生成规则**

| 参数 | 类型/默认 | 生效范围 / 前端影响 |
|---|---|---|
| dormantDays D | 正整数/null，未配置 | 现有当前沉睡标签重算，客户端无额外展示 |
| maintenanceDays M | 正整数/null，未配置 | 现有到期重新计算，不重造执行 |
| activityWindowDays W | 正整数/null，W≤D | 活跃窗口重算，不当当前状态 |
| inheritanceMode / L | UNCONFIGURED（默认）/LIMITED/UNLIMITED；仅有限模式有非负L | 仅未来注册，有限0=不向下继承，不限仍只读直接邀请人并防环 |
| version/reason/updatedBy | 服务端生成/必填理由/认证主体 | 乐观锁、审计、结果回查 |

GET/PUT C5.2 rules；图片能力策略仅在配置可靠后启用，具体安全容量由S4交付环境证明。事件 `support.rules.changed` 只审计规则前后与版本，不产生客户成功行为。

**④ 状态机、权限与禁止动作**

规则各字段独立未配置→已配置；继承UNCONFIGURED↔LIMITED↔UNLIMITED。编辑draft→validating→saving→saved/conflict/error。禁止普通客服/主管写、禁止配置重算更新successEventId、禁止旧负载均衡改归属。原工单SLA/知识库权限保持。D/W未配置只影响各自指标，M已配置仍有待维护。

**⑤ 交互原型多状态**

默认：参数当前值和各自生效范围，数值控件。空状态：明确未配置及启用条件。加载态：不填默认数字，禁止保存。报错：字段级校验、冲突差异、网络重试；确认弹窗单独理由与影响摘要，取消保留编辑不写后端。

#### [FEAT-M06] 私有图片消息

**① 用户故事 / 目的与对齐**

作为客户或当前顾问，我想要发送与查看图片，以便解释求助内容；我想要上传失败可恢复，以便不丢掉已写说明。来源R01及私有访问边界；不做公开素材库。

**② 验收（GWT）与异常路径**

- Given 授权双方，When 上传合法图片、预览并发送，Then 图片成为持久消息，双方刷新可读；仅上传不算发送或执行。
- 异常1：Given 伪装MIME/超限/解码失败，When 上传，Then 拒绝且不生成可发附件；保留文字和重新选择入口，不能将HTML/SVG以图片打开。
- 异常2：Given 上传READY后转绑，When 旧顾问发送或拿旧URL读图，Then 拒绝；新顾问只能看已提交客服历史，不能读旧顾问未发草稿附件。
- 异常3：Given 已发图片响应超时或刷新，When 重试，Then 同一clientMessageId仅一条消息/执行，查询结果可恢复；未成功上传的临时本地预览不假装持久。
- 异常4：Given 存储失败/暂存过期，When 点击发送，Then 明确需重新上传，不产生空消息；客户端登出或换账号清本地blob及待发隔离状态。

**③ 数据字典、参数与生成规则**

| 字段 | 类型/必填/默认 | 规则 |
|---|---|---|
| attachmentId/metadata/state | C2附件 / 上传后必有 | 服务端校验并重编码，私有对象 |
| kind/attachmentId/content | IMAGE/id/可选文字 | 一条消息引用一张图片的最小首期模型 |
| uploadPolicy | MIME/大小/像素/TTL | 服务端已配置能力返回，无可靠值不启用按钮并解释 |
| clientUploadId/clientMessageId | string / 必填 | 分离上传和发送幂等，取消重选是新上传意图 |

接口 C5.2，后端私有流与后台二进制代理配套；S4不得用公共CMS上传代替私聊。事件只记附件id/大小/状态与消息关联，不记录图内容；安全清理仅未发暂存对象，已发历史不被TTL误删。

**④ 状态机、权限与禁止动作**

UPLOADING→READY→ATTACHED；UPLOADING/READY→REJECTED/EXPIRED；已ATTACHED不提供本期删除。READY只上传者本人可读写；ATTACHED按客户当前归属、主管审阅、本人客户授权。禁止通过猜id/换customerId/旧签名URL跨客访问；读取每次鉴权，转绑后在线权限立即撤销。发送和绑定/维护按C2.1原子化。
