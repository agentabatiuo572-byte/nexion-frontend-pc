# 客服中心统计与分级展示规格

本规格用于设计评审与后续实施拆分，未更改生产代码或 33041 配置。功能真源为 [CONTRACTS](CONTRACTS.md)，视觉与动效见 [DESIGN](../../design/support-analytics-20261006/DESIGN.md)，逐项反例见 [ACCEPTANCE](ACCEPTANCE.md)。相同规则只维护一次，本文列入口、状态及可验收交互。

#### [FEAT-CS01] 首充（含购机）及可信金额

① 用户故事

专属客服查看本人服务带来的首次付费转化；主管和总管理员能够核对充值、购机来源与历史归属。客户画像显示该客首次合格付款情况，不因换客服变成再次首充。

② 验收标准

首充候选、合格状态、去重、金额、退款及历史归属按 CONTRACTS §3–4。必须覆盖 FST-01–12、AGG-01–03、AGG-09：直接购机可首充；充值再购机只计一次；免费赠送/试用不计；付费转正式可计。

异常一：历史来源不完整时显示“历史待核实”，不判成未首充。异常二：请求失败或无权限不返回0，不泄露源单据。补到更早事实可审计重算，期间时区边界稳定。

③ 数据字典

复用 CONTRACTS §3 的付款事实、首充事实与查询元数据。首充来源、时间、金额/币种、发生时归属、来源业务ID不可缺；客户端只负责展示和跳转，不重新算财务事实。

④ 状态机

待核实 → 未首充 / 已首充（充值）/ 已首充（购机）；源错误和权限拒绝独立于业务状态。已确认首充不因换客服/退款而再进入未首充；错误事实修正走审计重算。加载期间不得先闪现旧账号数据。

⑤ 交互原型

默认显示首充人数与充值/购机来源拆分，说明“每客仅一次”；客户详情显示首事件卡及原单据入口。空数据明确“本期间暂无首充”；加载用占位线而非0；报错保留合法已知区域并提供重试，未知状态有解释。

⑥ 点击流

| 操作 | 到达与反馈 |
|---|---|
| 工作台点击首充人数/来源 | 打开携带日期、范围、来源的首充名单；专属客服的已转出客户仅保留汇总，明确不可下钻 |
| 名单点击当前有权客户 | 打开同客详情首充组；返回保持条件 |
| 点击首笔来源 | 有权打开原充值或订单；无权给原因，不显示越权业务明细 |

⑦ 一致性

M1客户入口、M3和360共享首充事实及金额字典；购机累计不叠入充值累计；多币独立；客服历史业绩与当前客户资产分别标明。客户列表不替换M2现有工单路由，既有充值/提现/余额口径不被改名覆盖。

#### [FEAT-CS02] 三种权限的工作台

① 用户故事

专属客服进入首页立即处理个人服务待办；主管先看本人负责组的经营总览、组对比与客服数据，从数据进入客户或业务事实，再处理发现的问题；总管理员看到全平台客户覆盖、客服账号及分组结构、经营数据。

② 验收标准

三种首页的主要区块和行动目标不同，不能仅替换标题；点击指标能到同范围清单。主管以全部负责组/单组选择范围，以总览/客服/客户/资金/设备/活跃独立选择视角；全部总览只含汇总及简短组对比，长列表随视角互斥，单组绑定客户可直接进入。主管只看本人当前负责组，全局池和其他主管组不可见。客服账号数、当前绑定客户数及充值按 CONTRACTS §4–5 区分当前快照/期间事件。覆盖 ACL-01–07、AGG-08–09 及 GROUPS 验收。

异常一：篡改客服筛选/URL/API时服务端拒绝越权；无负责组不回退全平台。异常二：切组后所有统计、图表、表格、待办与下钻同步，清无效客服筛选，旧详情关闭或重验，晚到响应不得覆盖新范围；登出、转绑时旧缓存和草稿不可读。未知或覆盖不全不给精确率，不以当前人数算期间转化率。

③ 数据字典

当前快照、期间业绩、任务数量、客服状态、归属覆盖、异常队列及数据时间见 CONTRACTS §4；范围由认证身份及原能力校验决定，前端只能请求权限内切片。范围、数据视角、客服筛选、期间、币种、排序和页码分别保存，定义见 GROUPS §7。

④ 状态机

身份解析 → 加载授权范围 → 正常展示 / 合法空态 / 服务失败 / 无权限。切换筛选重新查询；操作分配遵循预览→确认及理由→提交→成功回查/失败重试，处理中不可重复。管理员审阅与客服接待不是同一状态。

⑤ 交互原型

默认专属客服“我的工作台”以待回复/待联系/待维护为先，保留个人当前资产、期间首充和客户入口；主管“我的分组经营”以负责组经营数据为先，全部看总览及简短组对比，单组看独立总数据，按数据视角查看客服或客户/业务事实。客服全部视角只用一张列表按组分段，一个页面不同时放两个长列表；分配、调度、审阅保留为次要问题处理入口。总管理员“平台运营总览”显示平台覆盖、客服及分组数量、全平台充值/购机/首充、异常与规则摘要。

空态区分尚无客户/无待办/没有期间事件；加载各区独立；报错显示数据截至时间与重试，不能拿样例填充。无可靠服务日志的质量指标显示“待接入”，不编造评分或排名。

⑥ 点击流

| 角色与操作 | 到达与反馈 |
|---|---|
| 专属客服点待回复 | 本人待回复客户列表，等待最久优先 → 即时会话 |
| 主管切全部/单组、总览/客服/客户/资金/设备/活跃 | 范围与视角独立；全部看总体与组对比，单组看本组数据；按 GROUPS §7 同步查询并处理旧范围 |
| 主管点绑定客户/客服 | 绑定客户直接打开本组客户视角；点客服进一步筛其客户/业务事实，客服筛选可清回全组；返回保留组/视角/期间/币种和有效查询位置 |
| 主管点组待分配/停用待交接 | 仅负责组带过滤清单 → 明确选择客户/合法组内目标 → 正式分配流程 |
| 主管从异常点客服负载/会话 | 同组同客服问题清单或只读审阅；数据可读不增加代发权 |
| 总管理员点覆盖分组/客服状态 | 全平台对应集合；数量/过滤一致 |
| 总管理员点规则摘要 | 规则只读页 → 有对应权限才编辑并确认 |

⑦ 一致性

卡片、表格、曲线、下载和下钻范围一致；保留未分配/异常/历史未知独立分组。主管经营数据优先不改变专属客服的任务优先级，低充值客户的咨询仍可发现。规模与比例、当前资产与期间事件不混用；统计全可见不推出高敏动作自动可写。

#### [FEAT-CS03] 客户列表的邀请、充值与Tab排序

① 用户故事

客服能按服务任务、首充状态、邀请规模与金额快速找到客户；主管按客服筛选后用相同口径比较负载，避免靠当前页猜总量。

② 验收标准

列表增加直属邀请、邀请团队人数、个人累计充值、邀请团队累计充值、首充摘要与最近活跃；可配置显示列但默认保留核心客户身份与服务待办。每个Tab有明确默认排序，点表头可升降序。覆盖 AGG-04–07、SRT-01–06。

异常一：极值在第二页时全量排序仍回正确第一页；同值按稳定键翻页不重漏。异常二：循环邀请关系或部分未知财务不能显示完整0；跨客服只能看获准汇总。数据变更导致快照失效时提示刷新，不静默拼接新旧页。

③ 数据字典

字段定义、时间与币种、默认排序矩阵由 CONTRACTS §4、§6 单源维护。邀请团队为全后代不含本人，与客服当前名下客户不是一个集合。

④ 状态机

读取偏好 → 授权查询 → 正常列表/筛选空/无客户/失败。改变Tab、范围、日期、币种或排序均回第一页；看详情再返回恢复原条件。过期查询响应丢弃；缓存按登录身份隔离。

⑤ 交互原型

默认展示身份、服务原因、首充、邀请、金额和活跃，右侧固定查看/联系；排序表头带方向和简短口径。空态保留筛选条件及“清除筛选”；加载保留列宽；报错有重试。长表仅表格横向滚动，客户身份列和操作保持可达。

⑥ 点击流

| 操作 | 到达与反馈 |
|---|---|
| 选待回复Tab | 服务端按等待最久排序并刷新计数，其他条件明确保留 |
| 点邀请团队充值表头 | 在已选币种的授权全集排序，回第一页 |
| 点邀请人数 | 显示口径、可见明细及受限说明；不返回越权下级信息 |
| 点首充筛选/客户行 | 同口径过滤 → 同客详情；关闭回原列表 |

⑦ 一致性

客户行金额与M3右栏/完整资料一致；不能把各行邀请团队金额相加当作客服或平台总额。Tab互相重叠时计数不可相加；未知字段置末并保留未知标记。

#### [FEAT-CS04] 旧版即时会话台保留与增强

① 用户故事

客服在接待时同时看到完整客户背景，能从资金、设备、风险、标签直接打开合法动作；不用因新统计出现而到处找原来的资料。主管和总管理员可审阅相同上下文，不能冒名回复。

② 验收标准

按照 LEGACY-COVERAGE 的 LC01–LC27、NA01–NA05、MV01–MV06 逐项验收，包括截图里的全部有效字段/入口、三列布局、头像气泡、输入反馈、草稿、历史与维护。头像来源、发送/阅读状态、回复工具及静默策略按 CONTRACTS §9，覆盖 M3-01–21。新统计叠加，字段缺来源显示未知而非删除。旧KYC/临时转交/备用池仅按已确认退役清单移除。

异常一：详情资金部分读取失败，消息和其他已获权资料仍可用，失败区域单独重试。异常二：撤权/转绑发生在消息发送、附件或资料弹窗打开期间，立即停止越权读取和发送并给出可读解释。旧关闭/归档/未回复规则不能被视觉重构破坏。

③ 数据字典

客户身份、风险、资金四格、设备账户、标签备注、历史工单及快捷入口沿用 LC矩阵；新增首充/邀请/活跃/维护按 CONTRACTS。UID为业务编号，不拿内部ID代替；手机号脱敏；风险未知不猜等级。客服头像持久化资源ID，消息包含稳定发送ID、发送状态及独立阅读回执；当前段保留静默策略版本与最后有效对话活动，定义由 CONTRACTS §9 单源维护。

④ 状态机

未选择会话 → 拉取授权消息/客户资料 → 接待中/审阅只读/无权限；关闭后保留历史，后续求助进入同一客服的新段；归档独立不清待回复。草稿→提交中→已发送/结果未知先按同ID回查/确认失败按同ID重试；已发送不表示已送达，阅读未知/未读/已读独立且基于真实回执单调推进。无待客服回复时才进入静默计时→预告→结束当前段；待回复只跑SLA、不自动关闭。资料窗口打开关闭不丢会话、滚动和草稿。

⑤ 交互原型

默认三列：收件箱、消息与固定输入、独立滚动完整客户资料。右侧旧资料摘要与五个快捷入口直接展开，新增首充/邀请/活动维护跟在后续分组；完整档案打开宽面板按分组定位。窄屏右栏变可返回资料抽屉，内容同源。

空会话给主动联系或返回列表；加载局部占位，发送与阅读状态分别用真实文字；报错保持草稿并区分重试与回查。减少动态效果下停用脉冲和入场动画，键盘焦点仍清楚。客户复用已存照片，客服用持久化头像；头像缺失给姓名缩写，不冒充真实照片。工具弹层固定在输入区上方、话术/商品互斥，取消后原稿不变。超时入口展示真实当前版本；只读角色能看口径但不能修改。

⑥ 点击流

| 操作 | 到达与反馈 |
|---|---|
| 左侧选客户 | 中间客户、右侧资料、草稿一同切换；保留原会话草稿 |
| 快捷回复/客服话术 | 输入区上方搜索已发布有效内容 → 选择追加草稿 → 人工发送；关闭/Esc恢复输入焦点 |
| 推荐商品/图片 | 商品搜索或受控图片上传 → 预览 → 人工发送，同一发送通道；取消回草稿，发送前重验有效性与权限 |
| 消息结果未知/失败 | 未知按原ID回查；确认失败才按同ID重试；真实回执更新阅读状态，不盲发、不伪造未读 |
| 查看/修改超时策略 | 读取当前值与版本 → 有原配置权的总管编辑 → 旧新值、新段起效、理由确认 → 成功回读/未知回查；其他角色只读 |
| 资料栏五个快捷入口 | 打开当前客户历史/工单/密码/账户/备注的真实入口，权限不足有原因 |
| 查看完整客户档案 | 打开同客分组资料，资金/设备/邀请/活动有分页；关闭恢复焦点与位置 |
| 主管打开他人会话 | 显示审阅只读原因；需要改归属走正式分配流程，不代发 |

⑦ 一致性

同一资料组件服务M3右栏、窄屏抽屉和360详情，防止三处字段漂移。新统计不能挤掉输入框或旧动作；已有新版维护信息也不得回退。原模块高敏动作确认/理由/审计/失败出口照常，账户操作不在聊天里复制实现。3012旧版已观察到弹层与1/5默认值，仅作参考；本设计保留商品预览后人工发送、正式头像授权与客服绑定，33041产品能力仍待验证。

#### [FEAT-CS05] 无限继承默认与可控配置

① 用户故事

新注册的邀请链条不因为默认代数上限进入待分配池；总管理员仍能明确设置有限代数，并知道改规则影响哪些客户。

② 验收标准

执行 CONTRACTS §7 的新默认与迁移策略；LIMITED含合法0值不能被覆盖，UNCONFIGURED版本迁移需可审计且可重复执行。覆盖 CFG-01–06。已有绑定和历史池不自动重排。

异常一：配置缺字段/读取失败不能默认为无限继续运行。异常二：并发修改版本冲突必须展示差异，不能最后提交者静默覆盖；邀请异常或停用客服依旧按现行资格与无客服分配处理。

③ 数据字典

继承模式、有限深度、无客服分配模式、配置版本、起效时刻、操作者、理由与影响范围见 CONTRACTS §7。内部枚举仅在接口与技术契约出现，页面使用“无限制/限制代数”。

④ 状态机

读取 → 当前规则 → 编辑草稿 → 影响预览及确认 → 提交中 → 成功读回/失败留稿/版本冲突刷新。明确未配置的存量记录仅由版本迁移推进至无限；读错不进入迁移路径。

⑤ 交互原型

默认选“无限制”；选“限制代数”才出现非负整数步进器及根0说明；旁边说明无客服仍可能待分配。空配置说明待初始化/待核对；加载禁提交；报错可重试不展示伪默认。页内明确“仅影响后续注册，已有绑定和历史待分配客户不变”。

⑥ 点击流

| 操作 | 到达与反馈 |
|---|---|
| 总管理员打开服务规则 | 读取真实当前模式及版本；不会因设计默认无限覆盖已有有限值 |
| 修改模式或代数 | 预览旧值→新值及受影响范围，填写原规则要求的理由 |
| 确认提交 | 服务端权限/版本/参数检查；成功后读回，失败保留草稿 |
| 去处理历史待分配客户 | 独立打开待分配列表选择客户，再走原分配确认 |

⑦ 一致性

注册分配、后台规则、审计与文案同一状态；邀请统计全后代不受该深度截断。继承只沿现有合法直邀规则，不能把无限误做“不断向上寻找任何客服”。

#### [FEAT-CS06] 客服分组与多角度经营看板

① 用户故事

主管能够先比较本人负责组的客户、资金、设备和活跃数据，进入单组查看独立总数据和客服数据，直接查看组绑定客户或按客服继续筛选；发现问题后再分配、调度和审阅。总管理员能够管理全部组及负责人、未分组客服和平台待路由客户，核对平台与各组总数。

系统支持多名主管；总管理员通过原账号权限模块设置主管资格，在主管目录查看人数、负责组数及多维数据，按主管、组或客服切片下钻客户与业务记录，不强制先选客服才能进入组客户。

客服账号的创建与头像管理仍在原账号模块：男/女/未指定分别使用已审核对应池/混合池，新建或明确换头像才取样并保存资源ID；本人后续更换或原账号管理权限人员代改。不得按姓名/照片推断，也不得因主管资格增加账号创建权，详见 CONTRACTS §9.1。

② 验收标准

主管只看本人当前负责组，总管看全部组；一个客服同一时点仅属于一个组，分组不替代客户与客服的绑定。组管理、看板及异常严格按 [GROUPS](GROUPS.md) 验收。当前客户资产按现组；历史首充/充值/购机按事件发生时组，转组后不搬历史；组负责人移交后旧主管撤权，新主管接组历史。

异常一：直接请求外组ID、搜索关键词、导出、成员候选和全局待分配池，均不能泄露外组数据或计数。异常二：跨组调动与付款/发送/导出并发，提交校验版本与实时权限，不能双归属、旧主管继续读或旧导出继续下载。缺历史组关系显示未归组/历史未知，不用当前分组反推。

③ 数据字典

分组、负责人、客服成员关系及生效历史、组队列路由、统计查询范围和汇总字段由 GROUPS 单源定义。组总览包含客服启停/负载、客户覆盖、首充来源；资金含期间充值/购机/提现/退款及当前余额；设备含当前存量/来源/运行状态和期间新购；活跃含有效窗口、当前状态、未知覆盖及维护。每项明确集合、去重键、时间与币种。

④ 状态机

组草稿 → 创建生效 → 启用 → 满足人员和队列清理前置后停用/归档，历史不可硬删。成员待分组 → 加入组 → 同主管调组/总管跨主管调组 → 原子生效并审计。操作先预览原/目标成员及客户影响，填写理由，提交中禁重复，成功回查；失败留稿，版本冲突先重新预览。

⑤ 交互原型

默认主管看到“我的分组经营”：范围 Tab 为全部（本人负责组）/各组，数据视角为总览/客服/客户/资金/设备/活跃，两者独立。总览只有汇总与简短组对比；长列表随视角互斥，全部客服视角一张列表按组分段。单组提供独立总数据和直接绑定客户入口，客户视角有客服筛选及清除；当前资产与期间结果分区，异常待办及分组管理作为次要入口。总管可增加负责人切片、未分组与未路由入口。专属客服不开放组经营页，只可读自己所属组名称。

空态分别说明未负责任何组、组内无客服、无客户/期间事件；创建空组不会伪造数字。加载不闪0；报错各区独立重试；未知设备状态和活动覆盖单列，不塞进离线/不活跃。比较表分开绝对规模与比例，比例给分子/分母及覆盖；未知或覆盖不全不给精确率，不以当前人数计算期间转化率，不给无依据的经营评分。

⑥ 点击流

| 操作 | 到达与反馈 |
|---|---|
| 主管切全部/单组 | 服务端解析负责组 → 总览或单组独立数据；无效客服筛选清除，所有区块同步，旧详情关闭或重验，不显示外组名/数量 |
| 切总览/客服/客户/资金/设备/活跃视角 | 保留组/期间/币种 → 对应统计与互斥列表；同一有效查询切回恢复页码，条件失效回第一页 |
| 单组点绑定客户 | 直接进入本组客户视角，无需先选客服；客服筛选/清除可用，保留组和时间/币种口径 |
| 点客服后查看客户/业务事实、返回或清除客服筛选 | 打开同组客服切片；返回保持组/视角/期间/币种及有效查询位置，清除回全组，受限历史明确仅汇总 |
| 新建组/管理成员 | 仅获授权账号候选 → 预览归组、当前客户统计影响及历史不变 → 理由确认 |
| 总管设置主管/跨主管调组/移交负责人 | 复用账号权限设置；显示源/目标负责人、受影响成员和客户、旧访问撤销 → 原子提交并回查 |
| 有权创建客服/本人或有权人员更换头像 | 原账号入口 → 明确性别与头像预览/受控上传 → 保存资源ID并回读；取消/校验失败保留旧像，不随刷新改像 |
| 组待分配/离线设备/待维护 | 到同组同条件对象清单；仍需个人归属与原动作权才能对客操作 |
| 点击数量、金额、比例或图表数据点 | 保持原范围、时间、币种及当前/事件口径 → 相应明细；0为空列表，未知进入待核实清单，受限部分明确仅汇总 |

⑦ 一致性

组权限同步用于M1客户入口、M2既有工单、M3、360、附件、搜索、导出和旧收藏链接，不只隐藏菜单。组资金不加邀请团队金额；设备按唯一设备ID去重、客户按客户ID去重；充值和购机不相加为收入。组当前成员改变不改客户的服务归属和旧消息作者；负责人变动不重写事件时主管字段。平台可核对全部组+未分组/未路由+历史未知，主管只能核对本人授权集合。

#### [FEAT-CS07] 专属客服多维业绩排行

① 用户故事

专属客服在查看个人经营表现时，希望用公开且一致的榜单了解位置与差距，识别下一步服务重点；主管据客户基础进行辅导，而不是把名下存量或高金额等同服务质量。所有客服可看获准成绩，不能读同事客户隐私。服务身份统一规则见CONTRACTS §2.1，SUP-01–04覆盖旧入口与资格迁移。

② 验收标准

给定同客充值100后钱包购机80，当计算榜单，则首充一次、充值与购机分别计入各自榜。给定原单A100后转B再退40，当重算原月金额榜，则A有效额60、B不背负这笔扣减；给定外组同事行，当无原对象权点击，则仅公开汇总，不返回客户身份。RANK-01–12覆盖完整反例。

异常一：退款/历史覆盖不完整，不能按毛额或0生成完整金额名次。异常二：迟到响应、跨页变版、撤权不混入旧榜。真实0并列而非无数据，历史资格缺失不猜参榜人员；停止账号不抹历史成绩。

③ 数据字典

榜单键、月份/业务时区、币种、公开人员范围、定义/统计版本、参榜资格、原单成功/退款有效额、名次与覆盖单源维护于LEADERBOARD §2–5。首充唯一事实、事件时个人归属沿CONTRACTS，不新增首充状态；当前组标签不等于历史事件组。SUP/IDC补充只统一服务与托管事实，不影响金额模型。

④ 状态机

待计算→计算中→可用/暂定/失败。成功重算原子发布，失败不发布半榜；历史补数/退款会产生可追溯版本，已有名次不是永久终榜。撤权立即终止读取，切条件清失效分页，未知不转换成0。管理者不能直接写名次/业绩数。

⑤ 交互原型

业务交互说明见DESIGN §9；新排行榜尚未加入可点稿，后续先生图。默认本月首充榜；顶部条件、紧凑本人摘要、一张主列表，四榜互斥。规模榜固定当前时点，月份不可误导筛选。空态说明无人有资格并保留筛选，全部真实0仍正常列榜；加载保持布局，不闪旧身份数据；报错保留条件并可重试；暂定说明覆盖与未排名原因。窄屏不缩小业务字号。

⑥ 点击流

| 操作 | 到达与反馈 |
|---|---|
| 工作台→业绩排行 | 默认榜及本人同版本成绩，不改变原服务待办 |
| 切榜/月份/币种/获准人员范围 | 同条件全量排名后分页，回首并明确范围；无组可看全员 |
| 定位我/点击同事 | 定位本人页；同事仅公开摘要，有原对象权才另取明细 |
| 明细返回/版本变化刷新 | 恢复有效上下文；版本变化整榜重载，原未提交服务草稿保留 |

⑦ 一致性

排行榜公开投影是跨组汇总的窄例外；主管管理看板和客户/会话权限不放宽。原单有效额不改经营看板的退款事件口径，不阻止正常退款，不合成充值+购机总收入，不新设奖金/处罚。IDC设备无闲置，IDC-01–02覆盖相关同类页与旧有效能力保留。
