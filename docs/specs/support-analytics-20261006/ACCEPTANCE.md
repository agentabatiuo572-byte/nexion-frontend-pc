## 11. 最终对抗验收与不能签收的情况

独立审查至少覆盖事实来源、资金重复/遗漏、对象权限与转绑、全角色/全同类页面、人工操作和旧能力完整性。主线必须回源并复现实证确认 P0/P1，不能按审查人数裁决。

- 任一首充来源/真实成功充值历史/历史归属/购机退款/正式购机或资格历史映射仍靠猜测：相关能力不得记完整通过；未知可诚实呈现，但不能宣传为精确全量；成功充值不退款不免除这些证据门。
- 任一角色或入口可越权、转绑后仍可取正文/明细：阻断产品签收。
- 任一排序仅当前页、全历史金额受展示条数影响、邀请后代总和被重复合计：阻断统计签收。
- 任一有效旧字段/入口遗漏，或只验证新增加部分：阻断 M3 完整性签收。
- 只有生成图/原型/截图/静态绿灯，没有真实读取、授权、写入回查与刷新：只能报告已完成对应设计或静态检查，不能报告产品完成。

收尾按 done-review 六维分别记录：真落地、该有的在不在、交互完整、同形全扫、不变量覆盖、产品实景。设计阶段将产品写入/实景项标为待实施，不填通过；财务、首事件和配置相关写路径必须有隔离运行证据与可重复回查。

| NET-06 | 双向兑换、排队/完成/取消、持有与风险余额转换 | 原币成本、贡献和归属连续；价格变动、转移及内部转换不新增贡献，当前可用/预占/持有/风险余额与原件全部对上 |
| NET-07 | 独立与复合收益发放、释放、部分/零额追回 | 各实际写入只覆盖一次；零现金动作不造余额写入；已花收益不借后来充值补成未花，原来源缺失则未知 |
| NET-08 | 同秒多动作、相同金额的真实多笔、重放/并发提交、异常中断 | 按真实交易顺序和唯一凭证处理；不把合法同值流水误去重，不多计、不丢计、不留下半张榜 |
| NET-09 | 旧历史、缺归属、原件丢失/异常类型、未覆盖来源或读取失败 | 金额显示“-”、不参与完整排名；独立完整首充/客户规模仍可排；统计缺口不阻止已有合法现金动作，也不借扣其它订单预占 |
| NET-10 | 原客服停用/撤资格，旧客户已转出，本月出现原业绩冲减 | 历史原客服仍保留相应成绩，不能删负数或搬给现客服；旧对象明细继续按现权限拒绝 |
| NET-11 | 两币三榜、五宽、长名、待核实/暂定/负数与精确值展开 | 字号一致，日期/单位集中标题，金额保留符号和精度，提示不叠操作；设计稿对比和独立实际点击通过 |
| NET-12 | 同原来源的个人/组/主管/全平台及授权下钻 | 同时点同币种的期间贡献可对账；共享当前资产与期间原归属分开，逐笔明细与导出不扩大权限 |
