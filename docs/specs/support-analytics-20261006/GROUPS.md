# 客服分组、权限与经营看板契约

状态：详细设计，待实施。本文定义多主管、分组管理及组看板，不证明 33041 预览已实现。沿用 [CONTRACTS](CONTRACTS.md) 的首充、邀请、资金、默认无限继承与数据状态口径。主管只看本人负责的组，总管理员看全部组。

## 1. 目的与边界

主管按组安排客服、识别服务积压，并查看本组客户、资金、设备和活跃情况；总管理员管理组负责人、全局分配和跨主管调动。普通客服继续服务本人当前绑定客户。分组不是新的一套客户顾问绑定，也不增加奖金排名、绩效评分或 CRM 业务。

入口复用 M1 工作台的组概览/组详情、M2 客户列表、客服账号管理和待分配队列。组详情按客服、客户、资金、设备、活跃提供同范围看板和下钻；成员操作与统计权限由后端统一校验。即时会话、客户详情、搜索、工单、附件、导出均服从同一范围，不因入口不同放宽。

## 2. 最小模型与不变量

| 对象 | 最小契约 |
|---|---|
| 主管资格 | 复用现有管理员账号及角色/权限管理，可配置多名主管；记录资格启停及生效历史，不建第二套登录账号 |
| 客服组 | 稳定组 ID、名称、当前主管 ID、状态、版本、创建/更新时间；一层平级，不设父组、子组；每组只有一名负责人、不共享多个负责人，系统允许配置多名主管 |
| 组负责人历史 | 组 ID、主管 ID、生效起止、操作者、原因、操作 ID；同组同时仅一名负责人 |
| 成员历史 | 普通客服 ID、组 ID、生效起止、操作者、原因、操作 ID；同客服同时仅一组，或明确待分组 |
| 客户个人归属 | 复用现有顾问绑定及其历史；分组不复制或替代绑定，客户当前组由当前顾问的当前组派生 |
| 未绑定客户路由 | 客户 ID、目标组或全局未路由状态、生效历史、原因、版本；组路由不产生个人绑定 |
| 期间事实归属 | 源事件 ID、客户 ID、成功时间、发生时顾问/组/主管及各层归属状态、归属版本；未知不填当前值 |
| 读取范围 | 角色、获准组 ID 集合、权限版本、查询范围版本、数据截至时间；浏览器缓存不能成为授权依据 |

生效区间采用 `[生效时间, 失效时间)`，以服务端提交成功为生效点，不提供回填生效日期来搬动业绩。变更须原子写入当前状态、历史和审计；并发提交按版本拒绝过期写入。事件与调组同刻时使用可证明的事务顺序或版本；无法证明则相应层归属未知。

主管可以有多名，每名可负责零个或多个组；负责人身份不自动计入普通客服成员人数。成员须具有有效普通客服资格，账号启停与组成员关系是两件事：停用客服仍保留成员和已有绑定，计入待交接，不自动把客户变成未绑定。待分组客服仍可按现有个人权限服务本人客户，但不进入任一主管范围，也不参加组内新分配；总管理员负责补齐分组。无负责组的主管是合法状态，显示空范围，绝不回退为全客服。

主管兼任普通客服时，按实际资格分别判断管理和个人服务权限，不由组负责人身份推定兼任。具有明确客服资格且实际作为组成员的主管，计入该组客服成员人数，也计入主管人数；未兼任者不计客服人数。主管人数按账号 ID 去重，客服人数按实际客服成员 ID 去重；“全部人员”取两集合并集，不能直接相加。启用/停用、负责组数、有组/无组为各自维度，不能把停用且无组的同一主管计作两个人。兼任的个人服务权限不扩大主管组看板范围。

组负责人失效、角色不符、历史冲突或成员重复时，异常范围只交总管理员处理；主管不因异常获得额外访问权。历史组及历史客服记录持续存在，不因账号停用、调组、移交或归档删除。

## 3. 权限矩阵与队列隔离

| 能力 | 普通客服 | 主管 | 总管理员 |
|---|---|---|---|
| 主管目录与资格管理 | 无 | 不开放其他主管目录 | 可查看全部主管、按既有账号模块授予/停用/移除主管资格 |
| 个人客户服务 | 本人当前绑定客户 | 本人负责组的当前客户及组待分配客户 | 全部获准客服域客户 |
| 组看板、成员和组汇总 | 不开放组经营看板；保留个人工作台 | 仅本人当前负责组 | 全部组及待分组/未路由/异常分类 |
| 新建/改名组 | 无 | 新建时负责人固定本人；修改本人组 | 可指定合格主管，管理全部组 |
| 本主管各组间调客服 | 无 | 可；须校验来源和目标均本人负责 | 可 |
| 待分组账号分派、移出到待分组、跨主管调动 | 无 | 不可；不能取走其他主管或待分组账号 | 可 |
| 组内客户分配/转绑 | 依既有个人动作权限 | 只可在本人负责范围内，目标为对应组内合格客服 | 可跨组，仍走既有确认与审计 |
| 全局未路由池 | 无 | 不可见列表、数量、搜索命中或侧栏提示 | 可查看并路由到组，或显式绑定合法客服 |
| 组待分配队列 | 无 | 仅本人负责组 | 全部组 |
| 整组负责人移交 | 无 | 不可 | 可 |
| 停用/归档组 | 无 | 本人组，且满足退出条件 | 全部组，且满足退出条件 |
| 导出 | 现有个人导出能力与范围交集 | 现有导出能力与本人组范围交集 | 现有导出能力与全部获准范围交集 |

“总管理员看全部”限于已授予的客服域数据能力，不额外授予资金操作、支付凭证、密钥或其他业务域的能力。看板查看权不等于导出权、资金处置权或账号角色变更权。

未绑定池分成互斥两层：没有可信组路由的客户进入全局未路由池；有组路由但未绑定客服的客户进入该组待分配队列。个人绑定成功后退出队列；不得同时计作已绑定和待分配。主管不可用旧“未绑定池”接口、总数、筛选项、全局搜索或旧地址绕过隔离。组间队列转移仅总管理员可操作，原组立即失去当前明细权限。

自动继承默认无限仍按 CONTRACTS 执行，不由组数或邀请统计层数截断。继承到有效个人顾问时，客户当前组取该顾问当前组；未能绑定时，只有可信路由依据才能进入某组队列，否则全局未路由。保留既有显式 `SUPERVISOR` / `AUTO_RANDOM` 配置：`SUPERVISOR` 不再代表所有主管共同可见；`AUTO_RANDOM` 必须使用已确定组内合格候选，或总管理员配置且可审计的全局路由规则同时确定目标组和客服，缺路由不得默认开放全局候选。已有无限/有限配置、既有个人绑定和历史池数据不因本设计静默改写；不明旧池归总管理员核实。

## 4. 当前资产与历史业绩

### 4.1 两种时间口径

- **当前资产**：当前成员、当前绑定客户、当前组队列、当前余额、当前持有设备、当前在线状态。按查询快照的有效归属统计；日期筛选不把它们伪装成过去时点资产。
- **期间事件**：首充、充值、购机、提现、退款等，以相应成功事件时间落入 `[开始, 结束)`，按事件发生时顾问、组和主管归因。调组、转绑或移交后不搬动原事件。
- **当前客户的累计画像**：本人/本组当前客户的终身首充状态、历史充值、邀请画像，服务于当前客户理解；不能与“本组期间贡献”混为一列。

组当前客户集合由“本组客服当前绑定客户”和“本组未绑定队列客户”互斥组成，看板默认分列、合计按客户 ID 去重；队列客户没有个人顾问，不能摊入客服负载或个人业绩。其期间事件若能证明当时有效组路由，则记该组、顾问为当时未分配；没有可信组路由则不计入任何组。当前资金/设备可按这两个集合分别下钻，组总额只合并各客户自身事实，不能掺入邀请后代金额。

客服 A 从甲组移到乙组时，A 的客户个人顾问仍是 A，当前客户、余额和设备进入乙组当前资产；过去属于甲组的首充和充值继续留在甲组期间事实。对于当前已失去该对象明细权限的角色，甲组历史只能保留获准汇总，不能借旧业绩重新打开转出客户、会话、工单、附件或逐笔资金。主管同时负责甲乙组等仍有独立对象明细权的情形，按当前实际权限读取。乙组对现有客户可见既有客户详情权限允许的画像，但不因此得到甲组经营明细或将甲组历史记作乙组贡献。

整组从主管甲移交主管乙时，组 ID 和事件归属不变。主管乙获得该组全部获准历史汇总及当前客户明细；主管甲立即失去该组全部访问权，包括任职期间的组历史。事件上的“发生时主管”保留用于总管理员审计，不能作为旧主管继续访问的理由。主管查看多个本人组时按稳定组 ID 合并，不按历史主管字段截断。

### 4.2 已授权邀请画像的例外

当前客户的直属邀请数、全部后代数及已批准邀请树金额，继续按 CONTRACTS 展示获准聚合，后代不含本人。该画像可以跨顾问、跨组，但不开放超出当前角色获准范围的后代身份、逐客金额、会话、明细链接，也不得按范围外组拆分、对比或反查。主管负责范围内的后代及总管理员客服域权限内的后代，仍可按既有明细权限展开；邀请关系本身不扩大权限。

组经营资金只统计属于该组统计口径的客户**自身**事件，按源事件去重；绝不能把根客户的跨组邀请团队充值计入本组经营金额。不同根客户的邀请树可能重叠，禁止把各行邀请总额相加为组总额。此例外不开放外组看板、外组名单或全局未路由池数量。

### 4.3 未知事实

已知事件时顾问但缺组历史时，顾问归因可确认，组/主管归因仍未知；当时明确待分组、当时未绑定、历史不足三种情况分别保留。新建组或迁移时只从生效点建立可信历史，不用现成员反推过去。主管只看有证据属于本人组的事实；不能定位到组的历史只进总管理员的未知分类，不能平摊各组。

## 5. 看板指标

每项返回数值/金额、状态、口径、去重键、时间或窗口、币种、范围版本、截至时间与覆盖说明。状态至少区分可用、部分覆盖、未知、无权限、加载失败；无记录且覆盖完整才可返回 0。看板不编造排名、奖金、服务质量评分或充值加购机的“新增资金”。

| 角度 | 指标与去重 | 期间、分母与下钻约束 |
|---|---|---|
| 主管目录（仅总管理员） | 主管总人数、启停人数、有组/无组人数；每名主管负责组数、客服数、客户、资金、设备、活跃统计 | 主管按账号 ID；每主管当前管理统计合并当前负责组并按对应事实去重，沿用各项当前/期间口径；整组移交后新主管承接组历史看板，发生时主管仍为审计字段 |
| 客服规模 | 当前组成员数、启用数、停用/待交接数，按客服 ID；有客服资格且实际入组的兼任主管计入成员，未兼任者不计 | 当前快照；启用与停用按同一账号权威状态互斥，状态未知单列；跨角色总账号去重 |
| 服务负载 | 各客服当前绑定客户数、待回复客户数、待维护任务数；组待分配客户数 | 客户按客户 ID、任务按任务 ID；类别可重叠，不相加成“总工作量”；组队列不算个人负载 |
| 客户覆盖 | 当前绑定人数、组待分配人数、异常归属人数；已首充/未首充/历史待核实结构 | 组覆盖率 = 当前正常绑定人数 ÷（当前正常绑定人数 + 组待分配人数）；仅可信且完整分母可计算，异常另列，分母0显示不适用 |
| 平台覆盖 | 已绑定且有组、已绑定待分组、有组待分配、全局未路由、无法判定异常，客户 ID 互斥去重 | 仅总管理员；平台分母覆盖全部客服域客户。组看板不得据此泄漏平台规模或全局队列数量 |
| 首充 | 期间首次付费人数，来源充值/购机；各来源首事件金额 | 按客户终身唯一首事件，再按时间和币种筛选；当前已首充结构与期间首充人数分开；不除以当前客户数伪造期间转化率 |
| 充值 | 期间成功实际入账笔数、人数、金额 | 按合法充值源事件 ID；排除赠余额、人工加款、测试/重复及未成功记录；绝不混入购机 |
| 购机 | 期间实际付费购机订单数、人数、实付金额；必要时列已购买设备数量 | 付款事实按订单/稳定源事件去重，组合单不拆成多次付款；付费试用转正式计入，免费/赠送/全额抵扣单排除；设备台数另有设备 ID 口径 |
| 提现 | 期间成功提现笔数、人数、成功本金、手续费、实到金额，金额分列 | 以成功事实及时间为准；本金/手续费/实到取权威源字段及其币种，不相加冒充提现额；申请/审核/处理中另列状态量，不混为成功提现，按提现业务 ID 去重 |
| 退款 | 期间实际成功退款笔数、人数、金额，来源充值/购机等单列 | 按退款事件 ID，部分退款逐次去重；归退款发生时组，并保留原交易组作总管理员核查；不能从另一组原期业绩直接扣减 |
| 当前资金 | 当前客户余额及权威账本明确的可用/冻结等组成 | 当前客户 ID、账户 ID、币种去重；不能把充值累计当余额，也不能把流水加总当当前资产；组成是否可相加服从账户模型 |
| 设备存量 | 当前持有的正式购买、试用、赠送、来源未知台数，按设备 ID | 分类互斥；已转正式试用按正式购买事实分类，不能只看来源 TRIAL；处置/转出设备不计当前持有，历史购机台数另列 |
| 设备连接 | 在网、离线、未知及不适用台数 | 对具备可信连接能力的当前设备，用配置的心跳有效窗口判断；缺观测为未知，不具备连接能力为不适用，不冒充离线 |
| 客户活跃 | 有效窗口内活跃、窗口内未活跃、未知人数；绑定客户与队列客户分列 | 使用现有权威活动定义与可配置窗口；同客去重，客服操作不算客户活跃；活跃率仅在所选集合覆盖完整时按活跃人数/该集合当前客户人数计算，合计须明确包含队列，分母0为不适用 |
| 维护与即时状态 | 当前在线/离线/未知、待回复、维护到期/逾期、任务完成量 | 连接状态、窗口活跃、任务状态分别显示；任务完成以任务事件计，不能改写客户活动时间或当作客户活跃 |

首充与购机分类、钱包余额付款、零实付排除、试用转正式、置换正额差价、保留旧机另购设备及退款后首充保留均按 CONTRACTS。正式支付过的客户只计一次首充；充值后再用钱包购机不再计第二人。单独续存算力、续费或服务购买不因有付款就归作设备购买。

金额使用精确十进制及源币种精度，展示舍入不参与计算；不同币种分别汇总，不默认换汇相加。账本流入/流出、成功/处理中和退款方向明确，购机实付不冒称外部新增资金。跨币种人数先按客户去重；币种人数小计不承诺可加。普通客服/各组人数汇总只有在固定同一口径、组互斥且排除未知时才可对账，不能相加混合的当前与历史人数。

## 6. 动作、状态与异常

组状态为“启用 → 停用 → 归档”；停用可重新启用，归档保持业务只读和历史可查询，不硬删、不复用组 ID。总管理员仍可按同一移交契约调整归档组负责人，保证历史可被合法承接。负责人身份失效是异常，不自动转移到别的主管。

| 动作 | 必须检查与结果 |
|---|---|
| 授予主管资格 | 总管理员在已有管理员账号模块操作，校验账号有效、现有角色兼容性；可同时存在多名主管，授予后无组也合法，不自动接管现有组 |
| 停用/移除主管资格 | 总管理员先移交全部负责组（含停用/归档组）、客户队列及未结束管理动作；如兼任客服且同步失去该资格，另按既有规则交接其个人客户；有遗留则禁止提交，成功后原子撤销管理权限并审计，不硬删账号历史 |
| 新建/改名 | 必填名称、唯一有效主管；主管只能指定本人；组名称重名可提示区分，不用名称作权限键 |
| 加成员/调组 | 角色与账号存在、无成员重叠、来源/目标范围、目标组启用、前后版本；显示随客服迁移的当前客户数量与历史保留说明，确认并填写理由 |
| 个人转绑客户 | 按既有绑定契约确认、理由、审计；重新计算当前组，关闭旧队列状态，历史事件不变 |
| 路由未绑定客户 | 总管理员选择合法启用组；仅路由不绑定个人，原组或全局状态与新队列原子切换；分配个人另有明确操作结果 |
| 移交整组 | 总管理员选择合格新主管，展示组、成员、当前客户及队列影响；确认、理由、版本与幂等；当前与历史授权一次性切换 |
| 停用组 | 先处理全部组成员及组待分配客户，并处理依赖该组的未结束分配操作/路由配置；有遗留则禁止停用，展示有权限的具体处理入口 |
| 归档组 | 仅已停用且退出条件持续满足；历史仍归原组并依当前负责人授权查询，不改变首充和资金事实 |
| 重新启用 | 主管/总管理员在获准范围操作，校验负责人有效、路由配置与账号状态；不自动搬回曾调走的客服或客户 |

上述权限、成员、负责人、队列改变均保留操作者、理由、前后值、时间、操作 ID 和结果审计；重复操作只生效一次。失败必须整体不生效，不出现人员已动而客户范围未动、队列双计或旧权限仍可读的中间态。账号启停沿用现有角色管理能力，本设计不把改组权扩大成任意账号管理权。

权限提交成功后即生效：服务端逐次读取/写入、订阅、附件预览/下载、导出下载重新校验；客户端清理旧范围缓存、当前详情、会话、附件和未提交草稿。只清 UI 不算撤权。未提交发送/分配操作在服务端再次校验，旧主管不能靠已打开会话完成操作。下载入口不可绕过组授权，已生成但未下载的导出同样重验；已下载本地文件不被冒称可远程收回。

缺组信息、源服务失败、部分分页失效、筛选版本过期均返回明确状态与重试/重载出口，不显示伪零、默认全组或未经授权明细。无权访问与数据不存在对外不得暴露额外组或客户信息。

## 7. 查询、刷新与导出

所有卡片、图表、列表、搜索命中、筛选选项、下钻和导出先取同一获准范围，再筛选、排序、分页。客户行和金额按相同快照口径计算；跨页调组或转绑时固定快照，或返回范围变化并要求重新查询，不静默漏算/重算。

默认期间、预设、自定义日期、时区和时间边界复用 CONTRACTS。当前资产展示“截至时间”，期间事件展示起止与时区，活跃展示有效窗口；不能共用一个日期标签掩盖三种口径。各数据源更新频率不同时分别注明截至时间，部分失败只影响对应指标，并标明可用覆盖，不能让旧卡片与新列表伪装一致。

从组看板下钻须携带组、期间、币种、来源、状态及口径；客服或主管已失去转出客户的当前明细权限时，只给允许的汇总和不可下钻说明，不输出可反查身份。总管理员及仍具有该对象明细权限的角色可按既有权限核对源事实。总管理员可以切全部组或指定组；主管的选择器只出现本人组，不提供范围外组名称、数量或排行。没有获准组与加载失败分别显示。

导出复用同一指标和授权服务，不单建宽权限查询；请求、执行与下载阶段校验权限和版本。组归属变化导致范围不再合法时取消旧任务/拒绝下载并允许按当前范围重建。逐客/逐笔导出仅包含当前可见明细，历史汇总导出不得夹带已失去明细权限的转出客户标识；邀请画像导出仍不展开超出当前角色获准范围的后代。导出记录范围、时间、币种、截至时间和口径，保持审计。

### 7.1 数字到名单再到详情

所有真实统计数字都提供对应名单或事实列表，并允许进入获准对象详情；仅打开解释弹窗不算下钻。点击后保留角色/组范围、范围版本、时区、日期、币种、状态和指标口径。列表小计、去重口径与来源数字可核对；若包含只能看汇总的历史/跨组部分，明确区分“可见明细”和“受限汇总”，不得为凑齐行数泄露身份，也不得将受限部分伪装成已经全部展示。

| 数字 | 第一层真实下钻 | 对象详情与限制 |
|---|---|---|
| 主管/客服人数、启停/无组数量 | 按对应状态筛选的账号名单 | 总管理员到账号/资格及负责组；主管仅到本人组获准客服详情 |
| 组数、某主管负责组数 | 对应组列表 | 组详情，继续下钻人员、客户与各指标；主管目录本身仅总管理员可见 |
| 客户、首充人数、覆盖分类、队列数量 | 与口径对应的客户名单或首事件列表 | 到当前获准客户详情/首次付款事实；历史转出且当前已无对象明细权的部分只有受限汇总，未路由仅总管理员 |
| 充值/购机/提现/退款金额、笔数、人数 | 相应成功事件/订单/流水列表；人数视图按客户去重 | 到真实源事件及获准客户详情；显示金额、币种、成功时间和来源，提现分列本金/手续费/实到；不能只跳通用客户页；当前已无对象明细权的历史部分仅给汇总，总管理员仍按客服域明细权核对 |
| 当前余额及组成 | 对应客户账户余额列表 | 到获准账户及相关账本记录；不得用期间流水冒充余额组成 |
| 设备台数、来源、连接状态 | 对应设备 ID 列表 | 到设备详情及有权查看的状态证据；来源未知仍可列已知设备，连接不适用独立筛选 |
| 活跃/未活跃/未知、即时在线人数 | 同一客户集合与窗口的名单 | 到客户详情及获准活动证据；无证据显示未知，不伪造最后活动时间 |
| 待回复、维护到期/逾期、完成量 | 对应会话客户/任务列表 | 到获准会话或维护任务；任务与客户计数键分别说明 |
| 邀请画像聚合 | 当前有权的后代名单及受限聚合说明 | 超出当前角色获准范围的部分不展示身份、逐客金额或外组拆分；范围内按既有权限展开，此限制不能通过导出绕过 |
| 异常/未知数量 | 能定位的异常账号、客户、设备或事实列表 | 无法确定组的仅总管理员可见；确实缺明细证据的给出缺失分类及受影响数量，不编造对象 |
| 确认的0 | 保持相同筛选的空列表 | 清楚显示没有符合条件的记录；加载失败、无权限、历史不全不能以0提供空列表 |

总管理员可在客服域既有权限内查看完整源事实明细并对账；“完整”不意味着制造源系统不存在的记录。未知指标若连数量也无法确认，显示不可用而非假数字；可解释缺失原因及覆盖范围，但不声称已提供不存在的名单。组移交、客服调组或权限变化后，再点已有数字也按新权限校验，旧页面不能保持旧下钻能力。

## 8. 验收用例

以下为待实施验收要求，本设计文档不将其标记为运行通过。

| 编号 | 场景 | 必须结果 |
|---|---|---|
| G01 | 主管甲负责两组，主管乙负责一组 | 甲可看自己两组；列表、数量、筛选、直接 URL/API、附件和导出均无乙组泄漏 |
| G02 | 主管没有组或组加载失败 | 前者空范围，后者明确失败；均不回退全客服、不显示全局池数量 |
| G03 | 总管理员查看全部/指定组 | 全部覆盖含待分组/未路由/未知分类；指定组与该主管同口径对账，不越过其他业务域能力 |
| G04 | 普通客服存在组 | 仍只服务本人客户；不能据组 ID 查看同组其他客服、经营看板或组队列 |
| G05 | 主管创建、改名、组内调客服 | 仅本人组允许；伪造负责人或目标组拒绝；客服同时最多一组 |
| G06 | 主管取待分组账号、跨主管取人或移出到待分组 | 全部拒绝；总管理员可经确认、理由、审计处理 |
| G07 | 客服停用但仍有绑定客户 | 成员/绑定保留，标记待交接；停止新分配，不把客户变成无主或从当前资产漏掉 |
| G08 | 未绑定客户没有组路由 | 仅总管理员可见其列表和数量；任何主管旧池入口均不可读 |
| G09 | 客户已路由甲组但未绑定 | 仅甲主管与总管理员可见组队列；不计个人客户；绑定成功后队列退出、不双计 |
| G10 | 无限继承、有限超限、显式随机策略 | 保留既有明确设置与继承规则；未绑定按可信组路由隔离，缺路由不放宽全局候选；旧数据不静默重绑 |
| G11 | 客服从甲组调乙组且保有原客户 | 顾问不变；当前客户/余额/设备进入乙组；原首充/充值仍记甲组；甲不再打开客户明细 |
| G12 | 整组甲主管移交乙主管 | 组 ID 与事件历史不变，乙可看本组历史；甲缓存、会话、附件、旧 URL、待提交动作和未下载导出全部撤权 |
| G13 | 调组与支付同刻，或历史缺组 | 按可证明版本归因；缺证据归未知；不按现在成员补旧史，也不将未知分摊主管 |
| G14 | 充值100后钱包购机80，另有赠机、免费试用、付费转购 | 每客首充最多一次；充值与购机分别100/80；赠送/免费试用排除，真实付费转购可成为首次 |
| G15 | 组合单、零实付、正差价置换、保留旧机另购、单独续存算力 | 按 CONTRACTS 分类；组合付款不重复，零实付/单独续存排除，符合条件的实际购机计入 |
| G16 | 多次部分退款与原交易分属不同组/期间 | 退款按成功退款事件和当时组单列；源 ID 去重，不扣另一组原期数、不抹去真实首充 |
| G17 | 本组根客户跨组邀请且两棵树重叠 | 保留获准邀请聚合；不展开当前角色范围外身份、不按范围外组拆分；范围内按既有明细权展开；邀请金额不计组经营、不相加重复树 |
| G18 | 多币种、同客多订单/多设备、支付回调重放 | 金额精确分币种，首充全历史唯一；人数、订单、设备各自去重；重放不增加统计 |
| G19 | 来源TRIAL已付费转正式、赠机、设备缺心跳、连接不适用 | 存量按正式购买事实分类；未知/离线/不适用分开，缺记录不能推为离线 |
| G20 | 客服发消息、客户有效活动、维护完成、当前在线 | 只有有效客户行为影响窗口活跃；维护与即时状态独立；分母为0或覆盖不全不伪造比率 |
| G21 | 有成员/队列/未结束路由时停用归档，重复或并发提交 | 阻止退出并给处理入口；清理后可停用/归档，历史保留；重复一次生效、过期版本拒绝、失败原子回滚 |
| G22 | 看板刷新期间发生调组，旧导出等待下载，部分源失败 | 卡片/下钻/分页保持同范围快照或要求重载；旧导出重验；失败与0分开，更新时间和覆盖如实显示 |
| G23 | 总管理员授予多名主管，其中一名无组、一名兼任客服 | 可见真实主管目录及各组/客服/客户/资金/设备/活跃统计；无组为合法空态；主管人数按账号去重，全部人员按集合并集，不按角色相加 |
| G24 | 停用/移除仍负责启用或归档组的主管资格 | 未移交前拒绝；移交和必要个人客户交接后成功，管理会话/附件/导出立即撤权，资格与负责人历史保留 |
| G25 | 点击人员、组、客户、资金、设备、活跃、异常/未知和0数字 | 每类进入同条件真实名单/事实列表及有权详情；只弹解释不通过；总管理员可对源明细，主管的历史/跨组受限部分明确说明且不泄漏，伪造条件或沿旧链接越权拒绝 |

## 9. 实施前必须核定的事实

1. 正式后端的设备赠送/持有状态、连接能力和心跳权威源，以及活动覆盖起点；无法证明的来源保留未知，不用演示数据补齐。
2. 正式提现与退款成功事实的业务 ID、时间、币种、幂等关系；缺事实时对应指标不可用，不以创建时间或订单总额代替。
3. 既有账号、个人绑定、未绑定池与配置迁移方案：保留个人服务能力；只建有证据的当前分组/路由与生效历史，待分组、未路由和历史未知单列，总管理员处理异常。
4. 源接口、附件/会话授权、缓存和导出任务均完成组范围改造后才能开放主管入口；只改工作台筛选不足以满足本契约。
