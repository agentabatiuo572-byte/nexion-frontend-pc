# 专属客服业绩排行榜：业务设计方案

状态：主人已授权详细方案完成后恢复实施；产品验收仍为NOT-RUN。服务类型统一为专属客服，所有客服可看公开业绩排行，设备IDC持续托管、无闲置；提供每日排名升降与前三名荣誉标识。下文是本期实施契约，不涉及奖金或薪酬制度。基础事实沿用[CONTRACTS](CONTRACTS.md)，分组与当前明细权沿用[GROUPS](GROUPS.md)。视觉采用稿及允许差异见[还原基线](../../design/support-analytics-20261006/LEADERBOARD-BASELINE.md)。

## 1. 目的与范围

专属客服能看到自身在同一口径下的位置、差距和变化方向；主管能结合客户基础辅导团队，总管理员能核对真实业绩。规模与期间贡献分开，防止把分到大客户、转入老客户直接当作当月服务成果。排行榜提供正向比较，不改变待回复处理优先级，不自动算奖金、降级或处罚。

一期只做四个独立榜单，不用加权综合分，不引入另一套账本、积分、勋章和考核引擎。活跃人数、服务待办和客户来源作为背景；复购率、首响时长达标率、同期新客转化率等，要有完整事件和分母后另行设计，不能用消息数、已读数或首充人数除当前绑定数顶替。

## 2. 指标与排名口径

推荐默认“本月·首充人数榜”，让不同金额规模的转化也有展示机会。月份按后台业务时区的自然月`[月初,次月初)`；支持本月、上月和覆盖完整的历史月份，暂不开放任意分钟窗口或自定义指标拼接。

| 榜单 | 排名值 / 推荐用途 | 旁列与限制 |
|---|---|---|
| 首充人数榜（含购机） | 本期发生全球全历史唯一首次合格付款、当时归本客服的客户数，降序；呈现首次付费转化 | 充值来源人数/购机来源人数分列；每客一次，全币种去重，人数榜不按币种重算首次 |
| 充值贡献榜 | 本期成功充值原单截至榜单时间的有效金额，分币种降序 | 成功充值额、原单退款/撤销额、有效额；不含人工加款、礼赠、测试、邀请后代跨客服金额或余额购机支出 |
| 购机贡献榜 | 本期合格设备购买原单截至榜单时间的有效实付，分币种降序 | 付款事实合并去重，组合单不按设备重复计款；赠机/免费试用/零实付不算，真实付费转购算；不与充值相加为收入 |
| 客户规模榜 | 当前有效绑定客户去重人数，降序；衡量服务资产与负载 | 固定“截至现在”，切换此榜隐藏月份/币种；标明非本月新增业绩。名下全历史累计充值只作资产背景，不设默认业绩冠军 |

### 2.1 金额采用原单有效额

每笔原单有效额 = 合格成功金额 − 与该原单唯一关联、截至榜单时间已成功的退款/撤销金额；客服归属和月份取原单成功时，不取退款时现客服。提现、内部转账、手续费和购机消费不是充值退款，不能扣错。不同币种不换汇相加，金额按原始精度比较，显示舍入不参与排名。

例如10月A名下成功充值100，11月客户已转B后退款40：10月A的充值榜由100更新为60，B的充值榜不扣40。经营看板“11月退款40”仍按其既定退款事件时间/归属展示；这是两个不同指标，列名必须明确，不能静默改原看板算法。充值100后钱包购机80，分别进入100充值、80购机，不形成180新增资金。

退款来源必须能逐原单对账；多次部分退款按源ID去重，退款超过原额、币种不匹配或无法关联时标待核实，不截成0掩盖错误。缺完整退款覆盖的金额榜不以毛额冒充有效额，可显示已知成功额和“暂不可排名”。退款不抹去真实首充历史，也不能在下次支付重新算首充；已证明的错误/测试/重复事实经审计修正后可重算。

### 2.2 归属、并列与候选

- 首充/充值/购机依事件发生时专属客服，转绑、调组、月底集中交接均不搬历史；组名只显示“当前组”，不据当前组汇总成历史组冠军。无绑定或归属未知事件不分摊给个人。
- 月榜候选为当月曾有有效专属客服资格的真实账号，包含后来停用/离岗者；本月新入岗直接进入，纯主管或纯总管理员不参榜，兼任者按同一账号一次。历史候选依资格历史，不能按今天的启用名单重建旧榜。历史资格覆盖不足单列待核实。
- 当前客户规模榜候选为当前具客服资格者，加仍有合法绑定待交接的停用/撤资格账号；注明状态。已停用账号不得登录查榜，其历史成绩仍保留。禁止通过停用账号抹掉竞争者名次。
- 所选范围内按精确值降序，相同值使用`1、2、2、4`竞争排名；账号稳定键只固定同行次序，不破并列。完整可信0正常并列；缺数、错误或覆盖不足不以0入榜，名次显示“暂不可比”。
- 任一候选资料不足影响总体比较时，整榜标“暂定：部分数据待核实”；已知子集名次不称完整榜名次，未排名数量与原因可查看但不泄露客户。纯净完整榜与暂定榜分开标识。

## 3. 可见性与公平背景

### 每日名次比较与荣誉

默认采用“较昨日末”：当前榜单与上一业务日结束前最后一份完整发布快照比较；显示真实基线时间，不假称一定采到23:59:59，不以今天补数重写旧快照。名次变化为昨日竞争名次减当前竞争名次，正数显示“↑ 上升N位”，负数“↓ 下降N位”，0为“— 持平”。这表示排名变化，不等于今日新增业绩或服务质量变化。

必须同榜、同币种、同月份（规模榜无月份）、同定义、同获准范围且覆盖可比。本月首日无同月基线；缺快照/旧数据不全/定义变化显示“暂无可比基线”，不补0。只有确证基线后新增参榜资格才叫“新入榜”，补齐历史、调组不是新入榜。组内人员或负责组集合改变时显示“成员变化，暂不可比”；全员榜不因单纯调组失去比较资格。历史月份不显示每日升降，以真实更新时间说明退款/补数可能改榜。

按精确竞争名次1/2/3赋予本榜金/银/铜王冠头像框；并列同名次同标识，不能只取前三行。荣誉仅在所选榜单范围内有效，不变成永久客服等级、权限或薪酬资格。范围/币种/榜单切换时重新确定荣誉；暂定或不可排名者不授予确定名次的荣誉。

新增窄范围公开权限：有效登录且有客服域读取权的专属客服、主管和总管理员可看全员榜。公开响应只含客服展示名/头像、当前组展示名或待分组、参榜资格/启停标记、名次、上述获准聚合成绩、口径/覆盖/截至时间；不用真实姓名替换既有展示名，也不输出手机号等账号资料。

| 操作 | 专属客服 | 主管 | 总管理员 |
|---|---|---|---|
| 看全员排名、同事公开成绩摘要 | 可以 | 可以 | 可以 |
| 查看客户/交易/会话明细 | 仅本人现有合法对象权 | 仅当前负责组的合法对象权 | 原客服域全量及字段权限 |
| 导出 | 一期不开放排行榜批量导出；原本人业务导出仍按既有权 | 原负责组业务导出不扩大 | 原业务导出；榜单原单核对需原相应权限 |
| 改口径、排除/补造业绩 | 不可以 | 不可以 | 不能直接编辑名次/数值；仅经原数据修正与审计链纠正事实 |

排行榜的公开身份、组名和聚合数是原“主管只看负责组”的明确例外；其他页面不因此获得外组数据。原组管理选择器仍只列负责组，榜单只支持全员、本人所在组或负责组范围；不开放任意外组经营切片、逐客维度或全文业务搜索。按组筛选只筛当前参榜人员并重算范围内名次，页面明确“按当前成员筛选”；不是该组事件时业绩总表。无个人组且无负责组时只提供全员榜。

公开榜与明细API由服务端分离授权/字段白名单，榜单行不得暗带客户ID、订单号、附件地址或隐藏明细。点同事展示公开汇总，有当前对象权限时才额外加载授权明细；历史已转出客户依然只能保留获准汇总。任何旧URL、导出或socket不得借榜单扩大权限。

客户资源差异放在本人摘要及主管原授权辅导视图：当前绑定数、当期首次分配/人工转入/转出、入岗日期及在岗天数。只有真实历史才能展示，创建账号时间不能冒充入岗时间；同客期间反复转入按明示去重规则计背景，不形成额外业绩。对同事的公开榜不另公开完整人事信息。当前客户多不代表服务质量高，不设置“低充值优先级低”的隐含规则。

## 4. 页面与操作

入口、布局和视觉规则在[DESIGN §9](../../design/support-analytics-20261006/DESIGN.md#9-业绩榜交互与荣誉设计)。客服中心主导航在即时会话之后、分组看板之前提供“业绩榜”，个人工作台提供短入口。静态稿只演示交互，既有样例缺退款覆盖时保持金额不可排名，不用生成图的数字补齐事实。

- 一个页面一张长榜单，Tab切换四榜；上方本人摘要随同一查询变化，不在首页再堆四张榜单。本人显示名次/参榜规模、所选成绩和与上一档不同成绩的差距，已第一则不显示差距；暂定榜不输出误导性差距。
- 范围筛选后的名次明确“本范围”，可附本人全员名次；两个值都来自同一榜单版本，不能混成一个。切榜/月份/币种/范围回首，返回保留有效查询与位置；“定位我”跳到本人所在页。
- 默认态显示可信榜；空态区分无人有资格与全部真实0（后者不是空榜）；加载不闪旧币种/身份结果；失败保留条件重试；部分覆盖保留已知数且不伪装完整名次。
- 本人不在候选集合或不可比时，就地说明资格/覆盖原因；不展示倒数羞辱文案、虚假进步箭头、奖金暗示或自动催充。待回复和服务待办仍在原入口可见。
- 查找客服只定位/过滤已计算完整榜，保留原名次，不能把搜索结果重新排成第一。点击每日升降可查看当前/基线名次、时间和不可比原因，使用文字与图形共同表达；变化数字不靠颜色单独传意。

## 5. 数据、刷新与可控参数

只读接口最小查询为榜单键、月份（规模榜无）、币种（金额榜有）、获准人员范围与页码。响应含榜单定义版本、统计版本、统计时间/业务时区、资格与覆盖、总人数/已排名数/未排名数、本人摘要和公开行；每日比较附基线版本/真实截止时间/人员集合版本/旧竞争名次/可比状态及原因，由完整榜生成。金额decimal字符串、人数整数、未知null+原因，非法任意过滤参数拒绝。API路径在I3/I5R形成真实合同后固定，不先虚构。

状态链：待计算→计算中→可用/暂定/失败；过期可用版本保留真实截至时间，但不能冒称最新。重新计算成功后原子发布新版本，分页/本人卡/公开摘要同版；版本变化提示刷新整榜，不能拼接。失败重试不发布半张新榜。读取撤权即时拒绝，不等榜单刷新。

| 参数 | 推荐默认 / 允许值 | 维护与生效 |
|---|---|---|
| 默认榜 | 首充人数；可选已接齐数据的四榜 | 总管理员经原配置能力维护，不改变指标算法 |
| 默认月份 | 本月；历史仅可选已覆盖月份 | 沿业务时区，不自造时区配置 |
| 金额币种 | 沿后台当前合法选择；无偏好用既有默认币种 | 只列真实支持且说明覆盖的币种，不能拿USDT填NEX |
| 刷新间隔 | 推荐5分钟，可配置1–60整数分钟 | 先负载验证，界面始终展示真实截至时间；刷新按钮获取最新完成版，不承诺强制即时算完 |

本月为动态榜；历史月份也允许退款、迟到事实或审计修正重算，保留修正版本、时间与原因，不承诺永不变化的终榜。每日升降须保存前述日末基线，没有可比快照时明示原因，不展示伪箭头。无新增客户侧埋点；消费既有资格、绑定、付款、退款事实，配置/数据更正/重算失败沿原管理审计记录，不建新风控评分。

## 6. 防刷与实施约束

首充唯一和原单去重防拆单/重复回调；按事件归属防月底转绑搬业绩；有效额防原单退款后仍保留金额冠军。不能为了排行榜阻止合法退款，不能单凭名次或金额自动判作弊；源事实核实沿现审核流程，修正留审计，不让主管任意剔除竞争者。

设备持续IDC托管，不设计闲置率/唤醒数榜；活跃指客户真实活动，不用设备运行小时冒充客户活跃。邀请树金额有重叠与跨归属，不进入客服个人业绩相加。新增绑定更多受分配资源影响，客户规模只作独立榜和背景，暂不承诺“拉新贡献”。

先落实I1资格/权限和I2事实；I3提供单独公开投影与原授权明细；I5R接排行榜，在客户基础修正后集成。原事实不可全量回溯时先显示覆盖边界，必要的金额榜保持未开放，不以不完整净额宣布完整排名。完整出口见[IMPLEMENTATION](IMPLEMENTATION.md)。
