# 客服增强功能规格

目的：在现有严格专属1v1、维护和归属撤权模型上，补回全部有效旧能力，增加统一无顾问分配、人工圈选群发、真实服务资料与顾问头像。

权威输入：[ASSESSMENT](ASSESSMENT.md) D01–D06/P01–P03（均已确认）及[原始决定](../support-redesign-20260929/OWNER-DECISIONS.md)。字段/权限/接口唯一源为[CONTRACTS](CONTRACTS.md)，完整验收为[ACCEPTANCE](ACCEPTANCE.md)。设计会话负责生图与可点关键流；本文件只写功能契约，不能用设计样例数值代替真实数据。

基本事实：注册、当前归属、顾问资格、消息提交、财务成功事实均由服务端判定；页面不能授予权限。最小方案复用现有 assignment、消息事务、维护引擎、资料来源、对象存储和审计，仅补缺失字段/查询和批次头+逐客持久项。最小可验证实验由后续阶段在隔离库分别证明并发只能一绑定、发送重试只一消息、转绑即撤权、超过30笔仍正确累计。

范围包括 M1/我的客户/M3会话/客服资料360/分配设置、账号创建编辑的头像，以及正式uniapp的必要顾问/消息显示；保留工单/知识库/AI原有效流程。KYC继续退役，临时转接变正式转绑；不新增语音视频、营销排程、微服务、客服全局资金权限、网站或生产部署。

#### [FEAT-CS01] 无顾问统一分配

① 用户故事

作为超管，我想要用一个选项决定真正无顾问客户的分配方式，以便所有入池原因遵循统一规则。作为主管，我想要预览历史池名单再确认随机分配，以便历史关系不被后台静默改变。

② 验收与异常路径

- Given 有可信有效直接邀请绑定且未超层 When 新客户注册 Then 先继承，忽略自动/主管选项。
- Given 自动模式且真正无归属 When 自然注册、邀请人未绑或超层客户进入 Then 等概率随机合格顾问，root=本人/depth=0；允许抽中原顾问，不改已有下级。
- 异常：Given 历史池已有客户 When 超管启用自动 Then 该名单不变；主管另行预览明确名单、排除项和人数，确认后才逐客处理，名单过期/版本变化要求重新预览。
- 异常：Given 顾问已绑定但离线/忙碌/停用 When 客户求助 Then 保留原归属、可留言；停用提供主管正式交接，不能随机重分。
- 异常：Given 新自动记录无候选 When 分配尝试 Then 正常注册/求助可继续，保存无候选与可追踪重试；主管模式暂停未提交自动任务，历史池不混入重试。
- 异常：Given 并发主管分配/自动任务/顾问停用/同key重试 When 提交 Then 重验当前归属和资格，只一个结果提交；超时先查结果，重复不再抽签；关系矛盾继续待核对。

③ 数据字典

字段和生成见 CONTRACTS C2：unboundAssignmentMode、规则版本、RANDOM来源、段root/depth、pool autoEligible、尝试记录、预览及逐客结果。D/M/W和继承mode/L独立，不新增分原因开关或猜默认值。

④ 状态机与禁止动作

可信新无归属→继承或主管池或随机；自动无候选→等待/暂停→重试→已绑定。存量池→明确预览→确认→逐客结果。禁止已有绑定自动重排、暗批历史、越过未绑定邀请人上溯、候选失效仍绑定、改层数改旧归属；流程见 CONTRACTS C2。

⑤ 交互原型状态

默认：分配设置显示当前单选值、影响范围；池显示来源/状态、邀请关系最小信息。空状态：无待分配客户或无候选说明及下一步。加载态：规则和名单读取中禁止确认。报错/极限：权限、规则冲突、名单过期和候选失效保留选择，允许重新读取；不把失败显示为已处理。

⑥ 点击流矩阵

| 触发 | 目标/响应 | 前置/反馈 |
|---|---|---|
| 模式单选→保存 | 影响/理由确认→规则保存 | 超管；CAS/key；成功读回，冲突保留输入 |
| 历史池筛选/分页/圈选 | 当前池 | 真实授权名单，页面全选和全部筛选明确区分 |
| 批量随机 | 冻结名单预览→理由确认→逐客结果 | 主管；过期重新预览；可退出不提交 |
| 无候选记录查看/重试 | 尝试详情/实际结果 | 自动资格不扩大到历史；先查未知结果 |
| 已停用顾问交接 | 现有正式转绑确认 | 主管显式范围，不拉走下级 |

⑦ 一致性

CONTRACTS C1/C2/C6 为唯一规则；验收 A01–A12。旧“超限一律主管”仅此处被 D01 覆盖，正式转绑和继承段不变量继续有效。设计原型需覆盖设置→历史预览→部分结果，不复制未确认数值。

#### [FEAT-CS02] 会话、资料与旧能力完整保留

① 用户故事

作为当前顾问，我想要在会话内看到本人客户全部服务所需资料并使用原有效工具，以便解决问题时不跳到无权页面或丢掉原功能。作为主管，我想要审阅真实资料，以便安排正式交接而不冒名回复。

② 验收与异常路径

- Given 本人客户 When 进入会话/服务360 Then 展示全部旧有效字段与新版归属/活动/维护字段，资金全历史按币种，近期流水独立分页；模板、SKU、标签备注、归档、工单和历史入口真可操作。
- 异常：Given 来源未采集、无权限、接口失败或真实0 When 展示 Then 分别未知/无权限/失败重试/0，风险无可信评级不猜低中高，设备失败不猜零；注册/最近登录/有效活动不混用。
- 异常：Given 客户转绑 When 旧顾问继续请求/开旧详情/附件/工单副本/WS/命令结果 Then 服务端立即撤权，页面清旧数据；主管仅审阅，所有敏感操作仍走原模块权。
- 异常：Given 已写草稿 When 插入模板或切客户 Then 模板按光标插入、不静默覆盖，草稿按会话/客户隔离；超时恢复沿用原key，刷新不重复消息。
- 异常：Given 下架SKU/已失效旧链接/无实时信号/未回复会话 When 操作 Then SKU拒发并说明，旧文字可读但不伪导航；在线/输入/回执标未知；结束服务不能逃避待回复，归档不清待办。

③ 数据字典

CONTRACTS C3定义identity/finance/devices/risk/annotations/service的来源与分组status；C5定义SKU/LINK和旧消息兼容。模板、SKU、回执、会话/工单分页和归档复用原模型，保留source/接待身份；具体字段清单逐项在ACCEPTANCE R01–R35，不以“能打开页面”代替。

④ 状态机与禁止动作

会话open→resolved/closed按原状态机；closed后新求助建立新段接续，不在旧段任意追加。客户新消息尚未处理时禁止关闭、归档（含批量）或转工单，必须先合法回复处理对应游标；REST/WS和旧入口同样执行。archive/unarchive是独立维度，不解绑、不删除。旧转接入口只引导主管正式转绑，不恢复代班。维护enabled/停止/恢复、OPEN/SUCCEEDED/STOPPED/TRANSFERRED继承旧C4；已读不等于已回复，显式replyTargets才更新相应游标，群发不清游标。

⑤ 交互原型状态

默认：列表/消息/资料三个互相关联的真实对象，资料入口可切服务360。空状态：无会话/消息/模板/SKU/设备/记录均有说明。加载态：各分组独立读取，计数/权限未就绪不展示伪0。报错/极限：独立失败重试、无权限说明、长昵称/数字/多币种/长历史不溢出；窄屏可在列表/聊天/资料间返回，键盘可达，减少动画时无强制消息动效。

⑥ 点击流矩阵

| 触发 | 目标/响应 | 前置/反馈 |
|---|---|---|
| 会话筛选/搜索/分页/点击 | 当前客户会话/历史游标加载 | 本人/主管scope，未读/进行中/已结束/归档计数一致 |
| 客户头像/资料/360 | 本客户服务详情/360 | 对象鉴权，返回恢复原会话，不授全局权限 |
| 文字/图片/SKU/链接发送 | 当前专属发送链 | 当前有效顾问；加载/失败/未知结果恢复；图先上传后发 |
| 普通模板/顾问话术搜索、分组、点选 | 草稿光标插入 | 真实已发布内容，两类独立入口；取消不覆盖 |
| 系统标签/自定义标签增删/备注增删 | 本客户标注 | 系统只读；原编辑权限；理由/作者/时间与持久化回读 |
| 资金/设备更多/分页/重试 | 本组详情页或列表 | 与累计分离，币种明确，子失败独立处理 |
| 历史会话/工单数量/转工单/工单详情 | 本客户对应记录 | 未回复禁止转工单；R08私聊副本限制；返回可续聊 |
| 重置密码/账户操作 | 原授权模块具体客户 | 无动作权限显示原因；执行原确认/理由/审计 |
| 归档/撤销/批量归档 | 当前会话名单更新 | 未回复禁止归档；显式范围、版本/key、历史保留；失败回查 |
| 结束服务/超时配置/正式转绑 | 原状态操作或有权配置/主管入口 | 未回复阻止结束；主管审阅不能代发 |
| 单客主动联系/回复/维护停止恢复 | 本人客户专属新段/偏好 | 原规则；停止仍可回复求助；正式转绑撤权 |

⑦ 一致性

CONTRACTS C1/C3/C5/C6，验收R01–R35/F01–F05/X01–X06。360、资料、消息和工单私聊副本使用同一当前对象授权。消息气泡配色/分组/新消息动画由设计产物约束；文档不指定视觉token，KYC不复活。

#### [FEAT-CS03] 人工圈选群发

① 用户故事

作为当前顾问，我想要圈选本人客户发送普通联系或联系维护，以便一次准备内容而每客仍有独立私聊和责任记录。

② 验收与异常路径

- Given 本人可维护客户 When 冻结名单、预览内容/用途/排除项并确认 Then 产生持久批次和逐客独立消息，客户不能看到其它接收者；SERVICE不计执行，MAINTENANCE成功落库才计执行，后续有效活动才计成功。
- 异常：Given 已不再维护/无权限/筛选字段未知 When 两类主动群发选人 Then 都排除停止者和非本人；未知单列、不当0；仍可回复其主动求助。
- 异常：Given 跨页选择后名单新增/转绑/顾问停用/客户停止维护 When 批次执行 Then 只处理固定名单，每客提交再验；新增不追加、失权跳过，新顾问不续原发起人任务。
- 异常：Given 部分失败、超时未知、进程中断、关闭或刷新浏览器 When 查看或重试 Then 原结果持久，先按稳定消息id查落库，只重试未成功项；同消息无重复维护执行；已发送不整体回滚。
- 异常：Given 上传一次群发图片/中途取消/SKU下架 When 提交 Then 每客独立可撤权附件；取消只取消未发送项，已发仍可读；下架不发伪商城消息，保留逐客解释。
- 异常：Given 客户已有未回复问题 When 群发发送成功 Then 不自动清待回复、不把上传/送达/已读当消息落库或维护成功。

③ 数据字典

CONTRACTS C5唯一规定SelectionPreview/Filters/BulkJob/BulkRecipient/BulkAttachment/message payload；逐客clientMessageId永久唯一，counts覆盖固定名单，失败/跳过原因独立。batch/actor/时间由服务端生成，不复用全局通知发信绕过归属。

④ 状态机与禁止动作

DRAFT→QUEUED→RUNNING→COMPLETED/CANCELLED，逐客PENDING→SENT/FAILED/SKIPPED/CANCELLED；响应丢失先查真实消息，再决定恢复。禁止改原已确认内容/收件人、自动追加、成功项重发、跨顾问继续、停止者主动联系、伪全成功。服务端恢复执行无需浏览器存活。

⑤ 交互原型状态

默认：我的客户/M3主动联系→圈选→内容与用途→名单确认→结果。空状态：无合格客户，给出排除原因/返回选人。加载态：人数和冻结名单未读取完不能提交；执行中展示逐客进度。报错/极限：部分失败/未知待回查/冲突/过期/失权明确区分，保留草稿，重试限定未成功项，支持跨页和窄屏键盘操作。

⑥ 点击流矩阵

| 触发 | 目标/响应 | 前置/反馈 |
|---|---|---|
| 我的客户/M3主动联系→批量联系 | 圈选页 | 当前有效顾问；单客入口仍保留 |
| 筛选/单选/本页全选/跨页/全部筛选/排除 | 服务端预览 | 实际人数，未知单列，冻结确认集合 |
| 用途单选/模板/文字/图片/SKU/链接 | 内容草稿 | SERVICE/MAINTENANCE必选，模板插入，上传可取消 |
| 下一步/返回/关闭 | 确认或选人/草稿 | 返回保留输入，提交前退出不产生批次 |
| 确认发送 | 持久批次结果 | 名单/内容/用途/当前顾问/理由/排除原因明确 |
| 刷新/结果分页/查看单客 | 原批次权威结果 | 逐次对象鉴权，SENT只承诺落库 |
| 取消剩余/重试失败 | 原批次 | key/version，成功项不重发，未知先查结果 |

⑦ 一致性

CONTRACTS C1/C5/C6，验收B01–B13。两入口同一冻结名单/发送链；私有图片逐客授权；维护计数和R05/现行C4完全一致。设计会话提供选人/确认/部分结果可点原型，不能以全局通知campaign充当私聊群发。

#### [FEAT-CS04] 顾问账号头像与正式客户端兼容

① 用户故事

作为超管，我想要创建顾问/客服时设置头像并能在创建后替换，以便后台和客户看到一致且可信的顾问身份。作为客户，我想要识别当前顾问和历史消息作者，以便转绑后不会混淆是谁发的消息。

② 验收与异常路径

- Given 超管上传有效头像 When 创建/编辑确认成功 Then 一份账号权威资源和版本刷新后仍在，账号/坐席/会话标题/消息作者/正式客户端一致，历史作者仍原账号。
- 异常：Given 上传/存储/版本冲突/读取失败 When 替换 Then 保留原头像，草稿可重试；取消不保存、不改原账号，不把失败变成创建成功。
- 异常：Given 既有无头像账号或旧服务端无字段 When 展示 Then 姓名占位且原坐席继续工作；本轮不额外强制所有账号补图或不补图停用。
- 异常：Given 非超管/错误资产/其它客户消息作者 When 写/读 Then 拒绝越权，不能为上传头像赋device权限；新头像不扩大私聊附件授权。
- 异常：Given 已转绑/旧消息不可信作者/新增SKU或LINK字段错误 When 客户看历史 Then 不改作者，未知占位；合法旧文字仍可读，新坏payload明确失败，不能静默丢消息/伪有效链接。

③ 数据字典

CONTRACTS C4/C6：avatarAssetId/avatarVersion唯一存于admin账号；currentAdvisorAvatar/senderAvatar仅投影；client assignmentState/availability保持原枚举。客户头像只读取现有资料；不新增客服代改权限。

④ 状态机与禁止动作

未选图→上传中→READY预览→账号提交ATTACHED；失败/取消不改旧值。替换需原账号expectedVersion和幂等，旧历史作者不重写。禁止两套账号/坐席头像权威、任意URL或单客attachmentID充当头像、未配置策略猜上限、非超管写头像。

⑤ 交互原型状态

默认：创建/编辑有上传、预览、替换和取消，客户端当前顾问及可信历史作者展示头像。空状态：无图姓名占位。加载态：上传/账号保存分开，未完成时不能把暂存当已保存。报错/极限：文件校验、存储错误、权限与版本冲突可理解且可返回，长昵称/窄屏不遮操作，头像读取失败回占位。

⑥ 点击流矩阵

| 触发 | 目标/响应 | 前置/反馈 |
|---|---|---|
| 创建/账号编辑→选图 | 文件选择/上传/预览 | 超管、真实策略，上传不是创建 |
| 替换/取消/返回 | 新暂存或旧头像 | 取消清暂存引用不改账号 |
| 保存账号/确认替换 | 原账号提交→刷新读回 | key/version/reason，失败保留原头像 |
| 客户打开顾问/会话/历史 | 正式uniapp现有入口 | 本人授权，头像与作者一致 |
| SKU/合法链接点击/失败重试 | 当前有效商城或支持入口 | 白名单+当前状态，失效有说明，输入/原消息保留 |

⑦ 一致性

CONTRACTS C1/C4/C5/C6，验收V01–V06/X01–X06。后台头像资源与正式客户端一套权威；支持当前实际语言与H5/APP分别验收，H5不代替APP实机。页面配色/动效在独立设计交付，不把旧原型当正式客户端实现。
