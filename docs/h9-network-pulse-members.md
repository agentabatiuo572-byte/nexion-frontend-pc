# H9 网络脉搏注册用户跳动（2026-10-28）

交接 03 UI-05。App 按「起跳值 + 每跳增加人数之和」显示网络脉搏注册用户，并在缺少这组参数时隐藏整块；本补充把参数交给 H9 维护。每跳增加人数在「最少—最多」之间，由服务端与 App 用同一确定性规则计算（起点为种子的 32 位哈希偏移，长期平均为两者中点），所有设备、刷新后数字一致且不回退。现行设置（2026-10-28 用户指定）：每 60 秒增加 3–10 人，平均每跳 6.5 人，约每天 9,360 人。

| 字段 | 合法域 | 说明 |
|---|---|---|
| `H.publicStats.registeredUsersBase` | [0, 100000000]，整数 | 起跳值，沿用原注册用户基数 |
| `H.publicStats.registeredUsersTickIntervalSec` | [1, 86400]，整数 | 跳动间隔（秒） |
| `H.publicStats.registeredUsersTickStepMin` | [0, 100000000]，整数 | 每次最少增加人数 |
| `H.publicStats.registeredUsersTickStepMax` | [0, 100000000]，整数 | 每次最多增加人数，不小于最少值；两者相等即固定增量 |

- 跳动间隔、每次最少和最多增加人数三项一起保存，只填一部分或最多小于最少都不能保存；未设置前公开接口不下发这组参数，App 不显示该块，后端 `networkPulse.registeredUsers` 继续按月增长率推算。
- 修改起跳值、跳动间隔或增加范围，服务端把起点重置为保存时刻，数字从起跳值重新开始；其他字段保存不移动起点。已设置的跳动参数不能清空，只能改为新值。
- 公开接口只多下发起跳值、起点、跳动间隔、每次最少和最多增加人数五项，其余运营参数仍只在管理接口。该数字是展示用推算值，不是注册统计，不改变真实账户和设备预估排名。
- 后端：nexion-backend `GrowthPublicStatsService`（PR #21）。旧版后台不传这两项时保留已保存值。
- 默认值与部署：「恢复默认」填入 60 秒、3–10 人；后端迁移 `20261028_h9_member_tick_default.sql` 在尚未设置时写入同一组值并把起点重置为部署时刻，已由运营设置的值不会被覆盖。只存过单一增量的旧数据按「最少 = 最多」读取。
