# 业绩榜绑定客户数

主人要求客服列表补充对应绑定客户数量。本契约补充 `LEADERBOARD-ROW-BASELINE.md`；涉及列定义时以本契约为准，原图装饰及其余口径不变。

## 列与统计口径

唯一主列表按“排名、姓名、业绩额、首充人数、绑定客户数、操作”排列。组名位于姓名下，简略升降紧跟姓名。原独立升降列的位置用于绑定客户数；不新增第二个长列表。

- **绑定客户数**：统计截至展示快照时，当前有效绑定到该客服的去重客户人数。包括已绑定但尚未首充的客户；不把邀请链下级人数、历史绑定人数、本期新增绑定或首充人数当成当前有效绑定数。
- **首充人数**与**业绩额**：保持所选期间的既定口径；列头或统计说明明确“本期”和“当前”的区别。未知显示“待核实”，真实零显示 `0`。
- 所有榜单均显示这三列。客户规模榜按同一“绑定客户数”列排序并突出该列，不再复制一列客户数；首充及金额作为本月参考。切币种仅改变参考金额，不改变绑定客户数、名次或升降。
- 分页、筛选、定位本人、并列名次均使用同一服务端快照；不从当前页人数反推绑定数或总计。头像、姓名、组名与客户数必须始终对应同一客服记录。

## 查看与下钻

全体客服可见公开排行榜中的聚合绑定客户数。查看客户明细仍按既定权限：专属客服仅本人，主管仅负责组，总管理员全部。具备权限时数值可进入对应客服的当前有效绑定客户明细；无权限时使用普通数值，不显示无法执行的明细入口。公开聚合不会扩张客户资料读取权限，后端必须独立校验。

## 验收

重新核验四类榜单、本人栏、分页及窄屏：三列独立存在，数值不会串行、遮挡或被原图烘焙文字覆盖。重点包含 `0`、未知、长数字、绑定数大于首充人数、本人在页外，以及有权/无权下钻。客户规模榜只突出绑定数主指标；币种变化和历史月份切换不得改变当前有效绑定口径。公开数值与私有明细权限分别验收，不用视觉fixture证明真实API权限。

新增列属于已授权的设计差异；冻结新输入后重新截图、运行和独立审查。旧五列表格的通过证据不用于本版本。
