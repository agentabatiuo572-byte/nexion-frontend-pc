# 客服中心详细交互设计

设计对象是 33041 客服改版业务线。功能真源：[CONTRACTS](../../specs/support-analytics-20261006/CONTRACTS.md)；旧内容逐项对照：[LEGACY-COVERAGE](../../specs/support-analytics-20261006/LEGACY-COVERAGE.md)。本文件只维护布局与交互，不重复财务/权限规则。

## 2. 共同框架与信息优先级

沿用 `app/globals.css` 的 `html[data-theme="dark"]`，不另建蓝调主题：页面 `--v5-bg #0A0A0A`，内容面 `--v5-surface #121214`，次级面 `#17171B`，三级面 `#202027`，分隔线为白色7%/13%透明度。顶栏、侧栏、聊天背景、表头、输入、弹窗、空态及骨架均使用这套黑灰令牌；禁止大面积蓝底或蓝色环境渐变。青蓝 `--admin-domain-m #38BDF8` 只用于局部选中、链接及顾问消息；主操作用 `--v5-brand #9EDC1D`。风险、成功、警告使用现有语义色并始终有文字。数据面板用平面分区，不层层嵌套。

沿用后台字体与字重不超过600；正文14px、操作与说明12.5px、元信息至少10.5px，标题18–20px或26–30px。数字等宽对齐。桌面点击目标至少32px，关键动作40px；触屏断点至少44px；键盘焦点可见。表格金额右对齐并统一标币种，未知不用0占位。每个统计区都能解释“谁的、何时的、什么币、是否完整”。

页头固定范围、期间、币种与统计时刻；只有有权角色显示客服切片选择。当前资产与期间业绩分区，避免日期筛选看起来控制所有卡片。示例角色开关与状态开关只属于设计查看器，生产页面按登录身份决定角色，不放自助提权开关。

## 3. 三角色首页

| 页面 | 第一屏 | 主区 | 次区与下一步 |
|---|---|---|---|
| 我的工作台 | 当前绑定、近配置窗口活跃；期间首充（含购机）与期间充值 | 今日服务待办：待回复→首次待联系→到期待维护，按紧急性；每项直接回复/联系 | 首充来源拆分；当前名下客户简表；累计购机在详情独立展示 |
| 我的分组管理 | 负责组数量、组待分配、待回复、逾期待维护、停用待交接 | 组概览及组内客服负载表：账号状态、当前绑定/活跃、待回复/维护、期间首充/充值；仅可选本人组及组内顾问 | 管理异常队列、已有服务趋势与首充来源。全局未路由池不可见，点分配进入合法组目标 |
| 平台运营总览 | 客服账号总数/启停；全平台客户/归属覆盖；期间充值/购机/已确认首充 | 绑定/待分配/异常互斥覆盖图；客服经营与服务明细，带“当前/期间”分组表头 | 停用待交接、历史待核实、规则摘要；从总数到名单，不能用客服行的邀请团队金额合计平台 |

三个首页均不把充值排序当作服务优先级，也不新增带奖金暗示的排行榜。主管侧重处理，超管侧重全局；主管和超管打开他人会话都有“审阅，只读”提示。兼任客服时仅本人绑定客户的接待区可发送。

## 4. 客户列表

上方是服务Tab，下方是关键词、首充状态、币种及角色有权的顾问筛选。首充筛选可与待回复组合，不能拿“未首充”覆盖服务待办。每个Tab有默认排序；表头给明确升降序，显示当前优先依据。手工排序只改变排序，不清除服务标签。

默认列：头像+昵称+UID+等级、服务原因/归属、首充状态与来源、直属邀请、邀请团队人数、个人累计充值、邀请团队累计充值、最近活跃、操作。较长列表可选择列显示，核心身份/服务原因/操作不能全部隐藏。邀请团队金额注明不含本人，各行不可相加。窄屏金额区横向滚动，客户列与操作仍可定位。

下钻不是统一弹空白框：首充定位首笔记录；邀请定位授权关系；金额定位资金明细；待回复直接打开相关会话；历史已转出客户仅给汇总，不能再次打开个人资料。

## 5. 即时会话：旧骨架保留，新信息向下扩展

### 三列及响应式

桌面宽屏参考 300–360px / 自适应至少480px / 320–380px，列间细线，无多余大页头。左列、消息区、右资料分别滚动；中间工具和输入贴底，不随长资料向下跑。1440/1920应保持三列；约1200以下右栏变“客户资料”抽屉；更窄时收件箱与会话逐层返回，所有内容保留。

左侧沿旧版收件箱：标题/数量、超时策略、主动联系，搜索，合法状态Tab，头像+昵称+等级+摘要+时间+未读徽标+接待身份，底部分页。选中行保持青蓝底和左细条。退役的临时转入/备勤池开关不恢复。

中间顶部：当前客户、UID、顾问及会话状态；标记已解决、转工单、资料入口及必要会话菜单。中间顾客深色/客服蓝色气泡，真实作者头像、时间、回执、系统事件分层。底部普通模板/顾问话术、商品、图片与输入；Enter换行，Ctrl/Cmd+Enter发送，输入法组合期间不发送。发送中、结果未知、失败分别给文字和相应回查/重试；上传不等于发送。

### 右资料顺序（旧摘要默认展开）

| 顺序 | 展示内容 | 点击后的目标 |
|---|---|---|
| 1 身份 | 头像、昵称、UID、等级、当前顾问、完整档案按钮 | 同客360，不丢会话和草稿 |
| 2 风险研判 | 等级、客服可读说明、评估时间；未知不假造 | 有权的风险摘要，案件细节另按权限 |
| 3 资金概览 | 原2×2累计充值/累计提现本金/当前余额/关联工单；明确币种 | 资金详情含退款、手续费、实际到账、处理中、分页流水；工单精确定位 |
| 4 账户与设备 | 设备数量/型号/在网、算力、闲置、地区、掩码手机、账龄、最近登录/活跃各自命名 | 设备明细、账户详情；旧持仓及近30天提现在相应明细保留，缺源标待核实 |
| 5 标签与快捷操作 | 系统/自定义标签；最新备注；历史会话、关联工单、重置密码、账户操作、添加备注五个图标文字入口 | 有权到原动作；无权有禁用原因。入口允许右栏滚动到达，不能藏入默认折叠“更多” |
| 6 首充与购机 | 首充达成状态、来源、时间、金额/币种；累计购机金额独立 | 首事件及购机订单明细 |
| 7 邀请表现 | 直属、邀请团队人数、团队充值（不含本人），统计时间 | 可读集合及跨归属受限说明 |
| 8 活动与维护 | 当前有效活动状态、最后有效活动、维护开停、下次维护、最近联系、执行/周期及最近服务 | 复用已有真实分页记录，不能以“已读/在线”替代有效活动 |

长流水、设备列表和历史放到完整档案，摘要和入口仍留在右栏。相同资料内容组件供右栏/窄屏抽屉/档案使用，减少再次遗漏。字段不可用有就地提示，不能用删除字段掩盖后端缺口。

### 动效与无障碍

| 触发 | 反馈 | 约束 |
|---|---|---|
| 会话选中/按钮hover | 100–140ms颜色与边框过渡 | 键盘焦点同样明显，不仅hover才显示操作 |
| 新消息 | 约180–240ms淡入及4px轻移 | 历史加载/换会话不重播整屏；不自动把正在看历史的客服拉到底，显示新消息按钮 |
| 发送 | 按压与提交文字反馈，成功以真实回执更新 | 不用烟花、金币或动画伪装成功 |
| 资料/模板/商品面板 | 约180–240ms开合 | Esc可退、焦点返回触发点、Tab不跑到遮罩后 |
| 输入/在线提示 | 只在真实信号有效期间显示轻节奏提示 | 无信号不伪造；切换/断线即停 |
| 减少动态效果 | 停止位移/脉冲/循环动画 | 状态仍有文字可读，功能不依赖动画结束 |

## 6. 规则页与四态

服务规则默认方案为“无限制”，切换“限制代数”才显示非负整数步进器，0解释为下一代不自动继承。说明无限仍要求直接邀请人的合法顾问关系，无有效顾问依旧按原分配策略处理。保存前显示旧→新、仅影响新注册、旧绑定/旧池不变、理由；写权限按原能力验证，不提供普通客服可点保存按钮。

默认、空、加载、报错是每页必须设计的四态；资料还要有未知、无权限及部分可用。空表提供清除筛选或原合法下一步；加载不闪0；错误保留筛选/草稿并重试；部分失败不摧毁整页。模拟控件仅用于评审这些状态，不证明真实后端已通过。

## 7. 分组管理与多角度看板

功能契约见 [GROUPS](../../specs/support-analytics-20261006/GROUPS.md)。本页是新增需求的设计入口；组负责人不是一个允许越权的前端筛选。

顶部“全部负责组/单组”、期间、币种、数据时间固定；总管理员额外可选主管及未分组队列。主管下拉只返回本人负责组，不在下拉里显示无权组名称。组选择后M1/M2/会话审阅同范围联动，普通客服仅能看自己的组名和个人数据。

总管理员增加“主管管理”入口，人数按真实账号去重，明确启用/停用和有组/无组。主管目录行包含姓名与账号、资格状态、负责组数、客服数、当前服务客户、期间首充/充值/购机、设备数、活跃及积压；行中数字均可下钻。设置主管复用原账号权限表单；组负责人选择只列有效主管。允许多名主管各管多组，不能把主管固定为一个全局账号。

主管停用或撤销资格前展示负责组/待处理队列及移交目标；未处理不能留下无负责人运行组。成员移组、负责人移交和撤权的提示分开，避免把“修改分组名称”误做人员权限动作。

| 分页 | 主要内容 | 可执行的下一步 |
|---|---|---|
| 总览 | 当前客服/绑定客户/设备/已确认活跃，与期间首充/充值分区；组间比较表，显示服务负载和未知数量 | 点组进入单组；异常待办到组待分配、待回复、逾期维护、停用交接 |
| 资金 | 期间充值人数/笔数/金额、首充来源、购机订单/金额、成功提现本金/费用/实到、退款；当前余额另区 | 按当前或事件口径下钻；不能把余额叫收入，充值购机不合计为新增资金 |
| 设备 | 当前持有客户/设备数，实购/试用/赠送/未知来源；在网/离线/未知状态；期间付费新增独立 | 查离线/未知设备、到对应客户设备档案；缺遥测不假造利用率 |
| 活跃 | 窗口已确认活跃/已确认不活跃/未知、当前状态、最近有效活动分布、待联系/维护/未回复 | 点群体进入精确过滤清单；数据覆盖不全显示已知数和未知，不画伪精确百分比 |
| 成员 | 客服头像/姓名、启停/接待状态、入组时间、当前负载、期间业绩；当前与期间分列 | 增减成员、同主管调组、总管跨主管调动；不因调组修改客户顾问 |

“管理分组”抽屉列组名称、负责人、客服/客户/组待分配数量、状态。新建/改名表单只填必要字段；成员选择用可搜索多选名单，不输入ID串。主管负责人固定本人，总管可选有效主管。未分组账号只有被明确授权或总管才出现。

调组确认展示：从何组/何主管到何组/何主管、成员清单、当前绑定客户数与待办影响、旧主管访问将撤销、历史业绩不迁移、理由。组负责人移交单独动作，不藏在改名表单。停用/归档若仍有成员或待分配队列，明确阻止并给“去处理”的下一步；不一键抛失客户。

比较默认按待处理负载和组名稳定排序，支持按各列排序；不按充值生成综合排名，不把小组规模不同当成绩优劣。人均负载/活跃比例只有分母明确且覆盖完整时才显示；周期变化、未知来源、跨组统计不一致有就地说明。

下钻统一为“统计→对应明细→原对象详情”，顶部保留面包屑及组/时间/币种/口径。资金到充值或购机/提现/退款事实，设备到设备清单，活跃到客户清单，主管/组/客服数到对应名册；图中日期点自动带该日。数字旁的小信息按钮只解释口径，不代替数字自身下钻。无数据展示空列表；未知展示待核实原因和有权对象；已转出客户的受限个人明细不因点击历史业绩重新开放。

新增组看板采用同套暗色平面分区，金额/设备/活跃使用一致表格和图例。窄屏Tab横向滚动、比较表局部横向滚动；标题和当前组始终可见。所有组页状态和管理表单继承默认/空/加载/失败、键盘/焦点/减少动态规范。

## 8. 最小实施边界

复用现有组件、API、确认流程与资料入口，按角色和组范围组合页面；先统一分组历史/权限及统计事实/排序，再接页面。分组只做一层平级服务组，不扩成多级组织架构；不新增CRM框架、聊天协议、排名奖励或另一套账本。生成图负责视觉方向，可点击稿负责布局和关键流程，真实产品仍需按 ACCEPTANCE 和 GROUPS 的接口与浏览器用例逐项通过。
