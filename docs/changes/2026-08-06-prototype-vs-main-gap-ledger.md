# 原型线 × 实现线 全量功能面差距台账(2026-08-06)

> **两线定位**(主人 2026-08-06 澄清):`rhythm-configurable` = **交互原型演示**(全量 mock,产品设计源);
> `main` = **依原型实现的真代码**(接真后端)。故「合并」的主体不是 git merge 代码,而是
> **差距盘点 + 分层处置**:原型演示过而实现面没有的,要么补实现、要么确认有意收掉。
>
> 方法:13 域并行深比 agent(逐 tab 读原型全部交互面 → 对照 main 实现现状)+ 1 个旧线独有提交资产分类 agent。
> 判定口径:mock→真后端的**形态变化不算差距**(如本地 store 换 REST、demo 身份切换换真登录态);
> 只记「原型演示过、运营在 main 上确实做不到或看不到」的功能面。
>
> **进度状态**:✅ **13 域 + 旧线资产分类全部完成**(2026-08-06)。共 **99 条差距**,含 2 条踩项目铁律的硬缺陷。

## 🔴🔴 动手前必读:这份台账记的是「差异」,不是「该补什么」

2026-08-07 教训 —— 按 L1 层动手的那两批里,**4 条被证伪**,其中 **2 条造成回归**:

| 条目 | 台账怎么写的 | 实际 |
|---|---|---|
| E-1 置换促销 7 参 | 「删除时没留任何声明」 | 是 P1 缺陷 `PCFULL-035` 的**修复**,同提交焊了禁止它出现的断言。补回去 = 把修好的缺陷装回去 |
| C-6 互动卡 | 「前端 14 个渲染点里独缺它」 | 2026-08-03 已**有意合并**进「参与与通知」区 |
| H-1 H6 入口 | 「main 上直接 404」 | 一直是 302 到 /growth/daily,自 2026-07-02 起 |
| M-3 深链参数 | 「目标页面完全不读参数」 | 两个目标页早就在读 |

**根因**:比对 agent 看的是「原型有 / main 没有」,**没看 main 为什么没有**。而 main 的缺席分三种,
只有第一种该补:① 真没做到 ② **有意收掉**(签字规格退役 / 域合并 / 职责移交)③ **台账事实就是错的**。

🔴 **动手前对每一条做三件事**(缺一条就别写码):
1. `git log -S "<被删的标识串>" -- <文件>` —— 查它是怎么没的。**是被删的就去读那个提交**,
   删除往往带着理由(缺陷编号 / 验收报告 / 契约测试)。
2. `grep -rn "<标识串>" tests/ scripts/ docs/` —— 有没有断言/文档**明令它不该存在**。
   ⚠️ 孤儿测试(不在 verify、不在任何 script)照样是**声明**,只是没人跑。
3. 数据通道回源:字段在不在 client 的**显式类型**里?contract/normalizer 会不会过滤掉?
   `JsonRecord` 这类索引签名会让 tsc 对错误字段名**完全沉默**。

判据一句话:**「原型有而 main 没有」是问题的开始,不是结论。**

### 4b 的红队评估(为什么不能纯前端做)

后端 `reconcileD1VietQr` 只有三个动作,入账动作 `match-credit` **按回单锁定牌价入账**;
迟到回单的锁价已过期,直接给它开入账口 = **允许用过期汇率入账**,等于开一个「等汇率有利时把旧回单翻出来补」的套利口。
后端也没有下发「当前牌价」字段,前端无法自行重算。
**正确做法**:后端补「按当前牌价重算入账」的动作(或返回当前牌价供前端显式对照确认),再开 UI 入口。

## ✅ 反向错分复核结论(2026-08-07 · 已回源逐条核实)
