## 🔴 后端阻断判定(回源核实,非推测)

`lib/admin/g4-client.ts` 现有端点:概览读取、通用参数写 `PATCH /nex/genesis/params/{key}`、
市场状态开关、阶梯档位 CRUD、分红批次重跑。**没有任何挂单 / 成交流水 / 盘面统计写入端点**。

- **M-1 挂单 CRUD**:需要真实的二级市场挂单实体(用户要能承接 → 涉及扣款、持有、入账),
  这是**资金链路**,不可能在前端造。必须后端提供 `POST/PATCH/DELETE /nex/genesis/listings`。
- **M-2 虚拟成交对用户可见**:main 现有实现刻意做成 ADMIN_ONLY 隔离演练,其「不进市场统计、
  不对用户端展示」是**后端约束**(响应即如此),前端无法把它变成用户可见。需要后端另开
  「可见成交流」写入面,并明确它与真实成交在账本层的隔离规则。
- **M-3 盘面统计可配**:后端已下发四项真值(`floor/vol24h/listed/owners`),但**没有写入面**;
  通用参数写虽在,但 `/params/{key}` 后端有键白名单(F 域先例:未知 key 直接失败),
  新键需后端登记。
- **M-4/M-5**:同为新配置键,需后端登记。

### 红队记录(为什么不做前端本地实现)

D7 用过「本地假数据层」方案(后端缺席时前端自持配置)。**这里不能照搬**:
D7 配的是提现参数,假值只影响后台自己的展示;而造市的产物是**给用户看的盘面与可承接的挂单**——
前端本地假数据会让运营以为已经挂单/已在造市,而用户端一无所知(或反之),
且「用户可真实承接」这条链天然穿透到资金侧,前端造不出也不该造。

### 后端接口需求

| 端点 | 用途 | 关键约束 |
|---|---|---|
| `GET /nex/genesis/listings` | 运营挂单列表 | 区分 `source: ops \| user`;分页 |
| `POST /nex/genesis/listings` | 新建运营挂单 | token 从高位段分配(避撞用户持仓);幂等键;返回分配到的 token |
| `PATCH /nex/genesis/listings/{token}` | 改价 | 乐观锁(version);只影响该卖单 |
| `DELETE /nex/genesis/listings/{token}` | 下架 | 🔴 已承接的不受影响(承接即扣款入账),下架只停后续承接 |
| `POST /nex/genesis/activity/synthetic` | 注入可见成交 | 🔴 必须在账本层与真实成交隔离:不入账本、不动持仓、不改已售数;但**计入对用户展示的盘面** |
| `DELETE /nex/genesis/activity/synthetic/{id}` | 移除注单 | 仅影响展示 |
| `PATCH /nex/genesis/params/{key}` | 新键登记 | `genesis.fomo.{enabled,intervalMinMs,intervalMaxMs,priceBandPct,dailyCap}` · `genesis.stats.{floor,vol24h,listed,owners,change7d}` · `genesis.showcaseEnabled` · `genesis.presalePerks`(JSON) |

### 参数值域(前端将按此校验,后端须同口径)

- 频率区间:下限 < 上限,均 > 0(毫秒)
- 价格带:0 < band < 1(地板价 ×(1±band))
- 日上限:正整数(防刷)
- 盘面统计五项:非负数;**改动须留审计**(它们是对用户展示的数字)
