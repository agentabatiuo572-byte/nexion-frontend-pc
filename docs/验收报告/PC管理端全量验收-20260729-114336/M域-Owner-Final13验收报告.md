## 4. 未关闭缺陷

### M-FINAL13-001（P1）M3 转接弹窗无法加载权威客服候选

**复现前提**

1. 使用两个独立 SUPPORT 用户完成真实 MFA 登录。
2. `/api/admin/content/support-agents` 权威读取返回两个同名、启用、可转接的席位，且各自具有稳定 ID。
3. 从可见侧栏进入 M3，主动发起真实会话。

**复现步骤与现象**

1. 点击页面可见的“主动发起会话”，会话创建成功。
2. 自转接 API 返回 422，符合业务约束。
3. 点击可见“转接”入口。
4. 持续等待 12 秒，弹窗始终没有任何候选按钮，无法按稳定席位 ID 选择另一个 SUPPORT 席位。
5. 在 `pw-m3-transfer-r2`、`pw-m3-transfer-r3` 两次完整重跑中结果一致。

**影响**

客服可以创建会话，但无法完成跨席位转接主生命周期；这不是文案或低频边界问题，而是 M3 核心操作链路中断，故定级 P1，并触发硬性不通过。

**归因判断**

当前证据表明：Final13 已恢复发起会话所需的身份/authEpoch，但认证或导航后的 `transferCandidates` 渐进权威读取没有驱动转接弹窗形成可选状态。静态合同中的同名席位/稳定 ID 约束为通过，但真实运行失败两次；最终归因仍需结合该请求的 trace、前端状态迁移和后端响应继续定位，不能用静态合同覆盖运行时失败。

- R3 失败截图 SHA-256：`92046CF51275E2BA225E958A7E2AB501544262D1941362D6FBFDDC13B48C5301`
