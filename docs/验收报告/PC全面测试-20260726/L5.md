## 1. 锁定范围与权威边界

L5 不生产 L1–L4、D4 或 I5 的业务真值，只负责在创建时固化服务器权威快照、执行数据出境治理并提供限时下载。

| 出口 | 权威来源 | 必须成立的不变量 |
|---|---|---|
| KPI / 漏斗 / 财务 / 运营聚合 CSV | L1 / L2 / L3 / L4 当前服务器结果 | 创建时快照；后续数据变化不改写旧报告；下载内容与快照哈希一致 |
| 敏感明细 | L4 团队树等受保护事实 | 独立权限、原因、审批、脱敏、短期令牌和审计同时成立 |
| 七类账单明细 | D4 权威账本 | 理由有界、全字段脱敏、公式安全、A2 与 A4 可追溯 |
| 四类监管模板 | I5 当前披露真值 + J4 治理口径 | 生成时校验披露版本；不输出明文 PII；risk 角色生成后可按类型权限下载 |

锁定了匿名、未知报表、空快照、过期令牌、令牌泄漏、双会话、刷新/重登、重复点击、同键重放、公式注入、MinIO 缺对象、流中断和 A4 发布失败等分支。

## 3. 修复后技术调用链

```text
L1 / L2 / L3 / L4 / I5 / D4 权威事实
  -> OpsBiService / OpsRegulatoryReportService / OpsTreasuryService
  -> 公式安全 CSV + SHA-256
  -> MinIO bi-reports/*.csv
  -> nx_bi_report_artifact 元数据
  -> nx_bi_report_download_grant（report + token hash + actor + TTL）
  -> StreamingResponseBody
  -> 创建/批准时事务内 A2 + A4 admin.report_exported
  -> 完整流结束后下载完成 A2
  -> J4 / BI / 监管追溯
```

技术复核结论：

- 新报告把 CSV 权威文件写入 MinIO，MySQL 保存对象键、大小、哈希和内容类型；事务未提交时会回收外部对象。
- 下载端从对象流直接写入 HTTP 响应，不再把整个文件复制成数据库文本和 JVM `byte[]`；旧数据库快照仅保留只读兼容。
- MinIO 元数据存在但对象缺失时失败关闭，不返回空文件或重新生成“近似报告”。
- 下载授权按每次签发独立持久化；校验同时匹配 report、token hash、签发管理员和 TTL，一个新令牌不会覆盖另一个仍有效会话。
- 控制器允许 `bi_l5_regulatory_generate` 到达令牌与下载端点，服务层仍按报表类型二次校验，避免粗粒度放权。
- 通用聚合、监管和 D4 三条 CSV 生产链均移除 CR/LF，并在去除前导空白后拦截 `= + - @` 公式前缀。
- 普通聚合创建、敏感快照批准、I5 监管报告和 D4 账单导出均发布已注册的 A4 `admin.report_exported`；schema/outbox 失败时随业务事务回滚。

## 6. 墨菲定律对抗复审

- HTTP 200 缺字段、未知类型、未知状态或空 `reportId`：PC 严格协议必须整块失败关闭。
- 同一 Idempotency-Key、同一载荷重复点击：返回同一报告；同键异载荷必须冲突，不能覆盖旧快照。
- 报告创建后原始数据变化：旧 CSV 内容和哈希不得改变。
- CSV 首字段为 `" =cmd"`、制表符后 `+SUM`、负号、`@`、CR/LF：下载后均只能作为文本。
- 两个管理员或同一管理员双会话分别签发令牌：各自令牌独立有效；交叉使用、篡改、过期或注销后的令牌全部拒绝。
- 只有 L5 聚合权限、只有敏感导出权限、只有监管生成权限的账号：只允许对应报告类型，不能因到达同一下载端点而扩大权限。
- MinIO 写成功而数据库事务回滚：对象被清理；数据库提交但对象消失：下载明确失败，不返回空成功。
- 客户端中断下载：不得提前记录完整下载成功；完整流结束后才写成功审计。
- A4 schema 不存在、字段越界或 outbox 入库失败：报告事务回滚，不出现只有 A2 没有 A4 的半成功。
- 刷新、退出、重登：PC 不持久化 CSV 或权限；重新登录后按当前账号从服务器读取报告和授权。

## 7. 统一部署后的锁定终验

1. 串行执行后端测试与构建，应用 `20260727_l5_export_artifact_storage.sql`，确认 migration 289 无版本冲突，再部署 8110 和 3002。
2. 创建四类聚合与四类监管报告，核对 `nx_bi_report_artifact`、MinIO `bi-reports/*.csv`、文件大小和 SHA-256 一致，MySQL 不再保存新 CSV 正文。
3. 生成大于 JVM 常规响应缓冲阈值的报告，观察流式下载内存；中途断开后检查没有虚假的下载完成审计。
4. 删除测试对象但保留元数据，确认下载失败关闭；制造事务回滚，确认 MinIO 孤儿对象被清理。
5. 注入含前导空格/制表符的 `=+-@` 和 CR/LF 载荷，分别从聚合、监管、D4 下载并用表格软件核对为纯文本。
6. 使用 risk 监管角色、聚合角色、敏感导出角色和无权账号，逐类型验证令牌申请与下载；双会话并行签发，验证互不覆盖、actor 绑定、TTL 和泄漏拒绝。
7. 核对普通聚合、敏感批准、监管生成和 D4 导出均产生 A2 记录与 A4 `admin.report_exported` outbox/消费回执；注入 schema/outbox 失败验证全事务回滚。
8. 清理全部验收报告、授权、对象和事件夹具，由非 L5 修复者从可见入口完整重跑初审与同范围复审，才可改为最终通过。
