## 技术 / 墨菲审查

### 已确认缺陷

1. **PCFULL-122（P0）签到奖励资产真值分叉。** 页面和产品日志宣称 NEX，真实服务仍写 POINTS ledger，里程碑和 A4 契约也保留 POINTS。
2. **PCFULL-123（P0）App remote 仍是本地假链。** localStorage、客户端日期、随机数和本地钱包/账单决定签到、里程碑、Saver、Power-Up 与榜单；未知结果可能双发。
3. **PCFULL-124（P1）PC 标识与并发控制不可靠。** 里程碑/Power-Up 用显示序号推导数据库 ID；写入没有 expected value；Power-Up 两字段分两次提交可能半成功。
4. **PCFULL-125（P1）服务端状态机缺口。** 越南业务日、断签、Saver 消耗恢复、Power-Up 激活与徽章事实没有形成服务端原子生命周期。

### 对抗性检查结论

- 权限：App 状态及命令要求有效登录用户；PC 写路径继续受 H5 专属 RBAC、J1 与强审计保护。
- 单一真源：remote 只接受 `/api/points/*` canonical 投影；网络或协议失败清空权威状态，不回退 localStorage/静态数据。
- 资产一致性：签到资产固定为 NEX；旧 POINTS 响应、POINTS 里程碑和畸形 reward asset 均失败关闭。
- 业务时区：日期、连续天数、断签判断和重置倒计时只认服务端 `Asia/Ho_Chi_Minh` 投影，浏览器时区不能推进状态。
- 账号隔离：切换账号立即清空 canonical/pending；旧账号晚到响应由 generation 守卫丢弃。
- 幂等/未知结果：签到、里程碑、Saver、Power-Up 各自保留稳定命令键；结果未知时先回读权威状态，未落终态才使用同一键重试。
- 并发：规则、里程碑和 Power-Up 使用真实数据库 ID 与 SQL compare-and-set；同值或陈旧页面返回 409 `H5_CONFIG_STALE`。
- 原子更新：Power-Up 的触发天数与备注合并为一个端点、一个 DTO、一次 CAS；不存在第一字段成功、第二字段失败的半配置。
- Saver：仅在服务端判定已断签、库存大于 0 时锁行消费；恢复值为 `min(longestStreak, 30)`，并发双击只能成功一次。
- Power-Up：资格、幂等、激活与徽章授予均在服务端锁定执行；不能由 App 本地领取或伪造。
- 资金/事件：签到经钱包 CAS 写 NEX 和 D4 ledger；强审计或 A4 outbox 任一步失败都不得留下半入账；事件字段统一为 NEX 语义。
- 榜单隐私：只返回服务端脱敏用户标识与连签事实，不允许 App 用静态排名冒充真实榜单。

## 修复清单

### PC

- H5 里程碑和 Power-Up 全链改用稳定数据库 ID，删除 `id - 1` / `+ 1` 推导。
- 签到规则、里程碑奖励和 Power-Up 调整携带页面可见旧值，陈旧页与同值失败关闭。
- Power-Up 天数与备注改为一次原子配置命令；失败后回读权威值。
- 增加 H5 跨仓 owner 合同，覆盖 CAS、稳定 ID、原子更新和 App remote 禁止本地派奖。

### 后端与迁移

- 签到使用越南业务时区，状态接口返回服务端日期、下一重置时刻、Saver、里程碑、Power-Up 和脱敏榜单。
- 签到从 POINTS ledger 收口为 NEX 钱包 CAS 与 D4 ledger；响应和事件改用 `baseNex/rewardNex/streakBonusNex`。
- 新增 Saver 使用、Power-Up 激活端点；锁定资格和库存，写强审计、徽章事实及 A4 outbox。
- H5 管理写使用数据库稳定 ID、事务及 SQL CAS；Power-Up 双字段一次更新。
- 新增幂等迁移 `20260727_h5_daily_nex_canonical_closure.sql`：基础奖励 1→2、Day-3/7 POINTS→NEX、A4 daily.checkin 字段升级，并注册 `daily.streak_restored`、`daily.power_up_activated`。

### App

- 新增严格 Daily API，拒绝错误资产、错误日期、重复/非法状态和畸形响应。
- remote store 以服务端状态为唯一真源，支持并发刷新合并、账号 generation 隔离和未知结果回读。
- 签到、里程碑、Saver、Power-Up 只发真实命令；remote 分支不再本地推进连签、调用 RNG、修改钱包/账单或写 localStorage 奖励状态。
- 页面奖励、领取态、倒计时、榜单和 Power-Up 全部使用 canonical 投影，并提供失败重试。

## 统一部署后锁定复验

必须从可见入口使用干净、可回滚夹具完整重跑，不得只测已修改控件：

1. 执行 H5 增量迁移，串行运行 H5 后端聚焦测试和统一 Maven，再部署同一源码的 8110、3002 与 App H5。
2. 从 PC 可见侧栏进入 H5，核对 `baseline=2 NEX`、Day-3/7 为 NEX、真实数据库 ID 与页面一致；刷新、退出重登后仍一致。
3. 两个运营员基于同一旧页面并发修改规则、里程碑和 Power-Up；每项只能一个成功，另一个得到 stale，同值不得制造版本/审计。
4. Power-Up 天数与备注注入第二字段非法值、审计失败和网络未知结果，确认整体不变且同幂等键回放不重复。
5. App 用干净真实账号执行 state→签到；核对只增加一次 NEX 钱包、一次 D4 ledger、一次 A2 和一次 A4，POINTS ledger 不得新增。
6. 覆盖同键重放、异键重放、并发双击、响应超时后先回读、钱包 CAS 冲突、强审计失败和 outbox 失败；均不得双入账或留下半状态。
7. 构造 Day-3/7、USDT、NEX、SPIN、BADGE 里程碑，核对资产、领取资格、幂等与 B1 最终裁决；未知 POINTS 类型必须失败关闭。
8. 跨越越南午夜并切换浏览器时区，确认只有服务端业务日重置；客户端改时钟不能补签、提前签到或延长倒计时。
9. 构造 48 小时断签及 Saver 库存 1，两个请求并发使用；只消费一个并恢复 `min(longest,30)`，刷新重登保持一致并有 A2/A4。
10. 在门槛前后并发激活 Power-Up，核对未达门槛失败、达标仅一次成功、徽章不重复、App 与 PC 刷新后状态一致。
11. 切换两个账号并注入旧账号晚到响应，确认连签、Saver、里程碑、Power-Up、榜单和 pending key 不跨账号泄漏。
12. 核对 `daily.checkin`、`daily.streak_restored`、`daily.power_up_activated` 的 A4 schema/required properties 与真实 outbox payload 完全一致；清理用户状态、钱包/ledger、audit/outbox 与临时配置并附前后 SQL 计数。
