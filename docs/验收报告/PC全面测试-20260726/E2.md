## 第一性原理闭环

E2 的业务真相不是“后台能展示 12 个任务”，而是运营配置必须成为新派单、收益提示和风险约束的同一份权威事实：

`nx_admin_device_task + nx_config_item → E2 管理端 → B1 兑付红线 → A2/A4 → App /earn → 新派单与收益展示`

按奥卡姆剃刀，修复没有在 App 再维护一份任务价格，而是增加两个最小公开只读端点，让 remote 模式直接读取 E2 权威数据；按贝叶斯更新，代码检索到 App 直接导入 `@/mock/tasks` 和本地手机档位后，把“PC 改了但用户端不变”从风险假设提升为已证实缺陷。异常时失败关闭：远端协议无效或接口失败时不展示旧 mock 收益，并提供明确重试入口。

## 修复设计

### App 读取 E2 权威配置

- 后端新增 `GET /api/config/task-pricing` 与 `GET /api/config/phone-tiers`，只暴露 E2 现行只读投影，不开放写能力。
- App 严格校验 taskClass 恰好为六类且不重复、QUEUE_SATURATION 位于 `[0,1]`、奖励区间和显存非负、teaser 设备类型合法。
- 手机档位必须恰好为 T1–T5，USDT/NEX 日产随档位单调不降；任一字段漂移都拒绝整份响应。
- remote 模式在启动与回到前台时刷新；成功后替换手机收益和 locked teaser，失败时清空权威快照、显示不可用与重试，不回退 mock。
- 显式非 remote 本地演示仍可使用种子数据，不与生产远端事实混用。

### B1 红线闭环

- 下列方向被定义为放大资金流出：提高 `minReward`、提高 `maxReward`、提高 `QUEUE_SATURATION`、降低 `minVRAM` 扩大可接设备范围、从停派恢复为派发。
- 服务端在事务内按 before/after 判定实际方向；若覆盖率低于红线，返回 `COVERAGE_BELOW_REDLINE`，不能依赖前端提醒。
- 降低奖励、降低饱和度、提高 minVRAM、停止派发等收紧方向仍可执行，避免风险状态下连止损动作也被锁死。
- 定向测试使用 `99/100` 覆盖率验证奖励上调、显存门槛放宽和饱和度上调均被拒绝，同时验证收紧方向可用。

### 幂等、A2 与 A4

- E2 直接配置写要求 `Idempotency-Key`，相同键/相同载荷只能返回同一结果，不同载荷冲突关闭。
- 有活动 A2 提案锁住同一任务时，直接写返回 `OBJECT_LOCKED_BY_A2`；新增/编辑任务仍通过操作确认进入 A2 maker-checker 语义。
- 成功配置写发布 `admin.task_pricing_changed` outbox，并记录 before、after、taskClass、field、operator、reason、effectiveAt 和幂等键审计事实。
- 统一部署后的最终复审必须核对 A4 schema ACTIVE、outbox PUBLISHED、consumer SUCCESS，而不能只凭代码判定通过。

## 域内外调用链审查

| 交界 | 工程结论 | 统一部署后必验 |
|---|---|---|
| E1 → E2 | E1 SKU `aiUnlocks` 引用 E2 任务；E2 任务停派/删除存在引用保护语义 | 对已被 SKU 引用的任务执行停派、编辑、删除，不能产生悬空引用 |
| E2 → E3 | E3 生命周期容量衰减影响设备实际日产，不得改写 E2 新派单价格 | 同一设备跨阶段后收益投影变化，但历史已派任务价格保持 |
| E2 → E5 | E5 暂停派单/故障隔离应压过 E2 的全局启用状态 | DC/设备暂停后不可继续接新任务，恢复后按 E2 当前配置派发 |
| E2 → E6 | E6 算力与 VRAM 是资格事实，E2 minVRAM 是任务门槛 | 8/24/96/192/640 GB 边界命中正确，无前端自造算力 |
| E2 → B1/D | 所有放大流出方向已增加服务端红线门禁 | 人为制造低于红线场景，写接口必须 422；收紧方向必须可用 |
| E2 → A2/A4 | 幂等、活动提案对象锁、审计和 outbox 代码闭环存在 | 双操作者 maker-checker、同键重放、schema/outbox/consumer 实测 |
| E2 → App | 六类配置和手机五档收益已改为远端严格读取 | PC 改动生效后 App 前台刷新同步；503/畸形 200 不显示旧 mock |
