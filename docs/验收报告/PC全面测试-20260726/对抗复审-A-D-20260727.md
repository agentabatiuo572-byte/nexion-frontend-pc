## 6. 缺陷、修复与复验

### ADFINAL-001：C2 被误点“强制登出”

- 类型：验收脚本缺陷。
- 现象：通用 surface 用 `/退出登录|登出/` 命中 C2 页面中禁用的“强制登出”，等待 20 秒失败。
- 修复：系统退出按钮改为精确匹配 `^(退出登录|登出)$`。
- 复验：C2 1/1 通过；随后完整锁定范围重跑通过。

### ADFINAL-002：B3 在正确失败关闭状态下被误判

- 类型：验收脚本缺陷。
- 现象：当前 A4 数据不足，页面正确显示“当前漏斗不可安全计算”，旧用例仍强制寻找 Day0/Day7 指标。
- 修复：用例等待“可计算指标”或“失败关闭警告”二选一；失败关闭分支必须禁用保存/导出并且不得渲染伪漏斗。
- 复验：B3 可见入口和匿名 401 共 2/2 通过。

### ADFINAL-003：B4 跨域链接定位不唯一

- 类型：验收脚本缺陷。
- 现象：`/B1/` 同时命中侧栏入口与归因卡，Playwright strict mode 拒绝继续。
- 修复：按归因区及精确 `href` 验证 B1/B2。
- 复验：B4 可见链和未知路由共 2/2 通过。

### ADFINAL-004：C1 非规范手机号掩码与短号明文风险

- 类型：真实产品/隐私合同缺陷。
- 现象：当前数据包含 `H8N****8599` 一类非规范掩码；后端旧 Mapper 对长度小于 7 的手机号会直接返回原值，存在短号明文返回的潜在风险。
- 第一性原理：C1 不需要知道源数据为什么异常；任何不能证明符合公开掩码合同的值都不应向运营端传播。
- 根修复：
  - 后端 `UserOpsMapper.java`：只有 `^[0-9]{7,15}$` 才生成 `前三位****后四位`，其余返回 `NULL`；脱敏搜索也只匹配规范数字手机号。
  - PC Users BFF：递归校验 JSON 中所有 `phoneMasked`，不符合 `^[0-9]{3}\*{4}[0-9]{4}$` 的值置为 `null`；成功响应 JSON 无法解析时返回 502 `USERS_RESPONSE_INVALID`。
  - C1 合同增加 BFF 失败关闭断言；live 用例明确禁止 6-15 位原始数字手机号。
- 当前数据库只读核对：16 个有效用户中，9 个规范数字手机号、7 个非规范历史值、**0 个 1-6 位短数字手机号**。因此当前运行数据没有触发短号明文泄露；7 个历史非规范值应在后续数据治理中清理。
- 复验：
  - C1/B3/B4 定向 5/5 通过。
  - C1 新合同随全量合同 156/156 通过。
  - A1-D6 终局 surface 25/25 通过。

### ADFINAL-005：登录恢复与退出跳转竞态导致 B2/B4 假失败

- 类型：验收脚本缺陷。
- 现象：B2 登录按钮在服务端会话恢复时被卸载；B4 在退出跳转尚未完成时重新进入，旧 shell 短暂可见后被登录页替换。
- 修复：登录按钮卸载时仅在 shell 已恢复后视为成功；登录完成同时等待用户名输入框隐藏；退出操作必须等待用户名输入框重新可见后才允许继续。
- 复验：B2/B4 聚焦 2/2 通过；随后 A1-D6 25/25 完整重跑通过。
