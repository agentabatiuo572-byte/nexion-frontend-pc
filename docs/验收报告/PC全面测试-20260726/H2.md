## 技术 / 墨菲审查

### 已确认缺陷

1. **PCFULL-110（P0）App H2 仍是本地模拟。** 默认 remote 模式没有调用 `/api/trial/*`，资格、时间、收益、扣款和设备均可由客户端时间/RNG/localStorage 伪造。
2. **PCFULL-111（P1）Model A 收益抵扣上限不可写且摘要字段错误。** 后端漏白名单，PC 顶部误读 `discountCapUSD`。
3. **PCFULL-112（P1）状态与收益不是事实投影。** 已过期 ACTIVE 仍显示 active；终态显示理论满额而非 settled 值；grace/extension 边界和收益冻结不闭合。
4. **PCFULL-113（P1）失败恢复与终态不闭合。** GET 失败无重试；FAILED 仍暴露强制动作；余额不足未用 CAS 落失败和冷却。
5. **PCFULL-114（P0）管理员强制处置绕过权威生命周期。** 强制取消/扣款裸改 H2 表，绕过 B1、D4 多资产账本、设备创建、冷却和 A4。

### 对抗性检查结论

- 权限：匿名 GET/PATCH 均拒绝。
- 幂等：缺键拒绝；同键同 payload 精确重放；同键异 payload 冲突关闭。
- CAS / 并发：用户生命周期继续使用 claim version；管理员入口保留 A2 对象锁，并委托同一生命周期 CAS。
- 未知结果：前端命令保留 scope 内稳定幂等键，失败不清键；只有收到权威成功结果才清理。
- 失败关闭：App 协议漂移、无会话、网络错误时清空 H2 权威投影并禁止本地回退；PC GET 失败不展示写按钮。
- 刷新 / 重登：App 账号重绑、前台恢复均刷新 `/api/trial/state`；PC 修复后仍需部署态重跑。
- B1：转正奖励前继续检查覆盖率；覆盖率不可靠或低于红线时整笔回滚。
- D4 / E / A4：成功转正复用同一事务完成 USDT 扣款、USDT/NEX 奖励、三类账本、真实设备和 outbox；管理员不再另造简化资金事实。
- K2：开始试用继续检查循环养号信号；取消/扣款失败写 cooldown。
- 时间：ACTIVE 到期读时派生 GRACE；收益最多累计 `durationDays`，grace/extended 不再继续增发。
