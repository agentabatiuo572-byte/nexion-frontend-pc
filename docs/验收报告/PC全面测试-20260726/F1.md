## 5. 第一性原理与调用链复核

### 5.1 晋升

一个事件只产生一个相邻等级变化。原因不是“页面看起来更合理”，而是每一阶都可能绑定独立权益、奖励、审计和下游计算；跨阶会破坏不可跳过的不变量。

链路：

```text
订单/推荐/团队业绩事件
→ VRankPerformanceRepository 统一快照
→ VRankPromotionEngine 相邻一阶判定
→ nx_team_member 当前等级
→ nx_user_level_log 快照/事件/审计号
→ 奖励派发
→ F2/F4 权益与票权
→ F5/A4 可追踪
```

### 5.2 人工调整

PC 只创建 A2 提案，不直接写业务表。A2 replay 时服务端再次执行：

- 权限检查。
- 对象锁检查。
- Idempotency-Key 检查。
- 当前等级与方向检查。
- 业务写入、流水、审计。

直接请求业务端点即使参数完全合法，也不能绕过 maker/checker。

### 5.3 派发处置

- 重发：仅 `REVERSED → REISSUED`，放大资金流出，进入 A2/B1/D4。
- 冲正：仅 `GRANTED/REISSUED/PENDING_GRANT → REVERSED`。
- `FAILED/REVERSED/UNKNOWN` 等状态均失败关闭。
- 资金类写 D4；权益类保持派发流水和审计，不伪造资金账。

### 5.4 App 真值

remote 模式的当前等级和进度只允许来自：

- `GET /api/config/v-ranks`
- `GET /api/team/rank`

协议不是精确 V0～V12、字段非法、接口失败或用户 subject 不成立时，App 等级页明确不可用，不回退本地 seed。

## 6. 墨菲审查

已按“最容易出错的地方一定会出错”审查：

- BFF 严格路由遗漏：已补并用契约锁定。
- 多阶同时达标：已锁为一次一阶。
- 同一事件重复消费：沿用触发事件/派发幂等防重。
- 两名管理员同时处置：A2 对象锁 + 服务端状态重检。
- A2 被直接 API 绕过：服务方法内部强制 replay。
- 重发已发放记录：状态机拒绝。
- 二次冲正：状态机拒绝。
- 未知派发状态：失败关闭，不显示操作。
- App 协议缺阶/重复阶/非法数值：严格解析失败。
- App remote 接口异常：不使用 localStorage 假结论。
- 刷新/重登：终验脚本已包含，待新部署执行。
