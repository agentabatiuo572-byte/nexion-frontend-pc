## 技术与墨菲审查

### 已验证的失败与并发场景

- 未登录、App/管理员令牌混用、只读写入、低权限发布：401/403 失败关闭。
- 并发相同幂等键、同键异载荷、陈旧 version：只产生单一持久事实或稳定 409。
- report 重放、report 同键异载荷、非法 platform：相同事实可恢复，冲突/畸形无副作用。
- 上游 503、成功码畸形响应、响应体损坏、刷新与重登：不显示旧数据、不伪造成功、稳定 key 可复用。
- 远程命令目标被停用、来源/DNS 条件漂移、三元组不完整：pending 再次验证并返回 `JANUS_REMOTE_TARGET_UNAVAILABLE`。
- App 应用失败和失败 ACK 丢失：不声明目标状态，保留相同失败 ACK 下次重试，原始应用错误不被 ACK 网络错误覆盖。
- 非远程状态：清除旧远程绑定；远程状态：必须四字段齐全且 URL 为无凭据、无 query/hash 的 HTTPS。
- 多账号：report/ACK 按 userId 隔离，退出重登不会把上一账号事实发给下一账号。

### 第一性原理闭环

K6 的最小可信事实是“服务端策略决定的设备状态”和“批准目录中的精确不可变目标”。PC 只管理，App 只上报原始信号并执行服务端命令；幂等键解决结果未知，CAS 解决并发陈旧页，再读取解决刷新/重登一致性。任何无法确认的状态、目标、权限或上游结果都失败关闭，不增加第二套客户端状态机。

只有以下场景在新候选包通过，才允许总报告把 K6 标成“最终部署验收通过”：

6. 清理目标、策略、账号和命令夹具，再从侧栏完整重跑，而非只点修复控件。
