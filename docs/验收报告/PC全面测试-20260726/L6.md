## 1. 第一性原理与锁定边界

L6 的最小真值不是“页面上能显示一张热力图”，而是：当前 App 真实产生隐私最小化行为事实，后端可幂等、可拒绝脏事实，PC 只显示完整聚合，并且这些客户端事实永远不能变成资金、KPI 或风控权威事实。

| 边界 | 不变量 |
|---|---|
| App producer | `app.page_viewed` / `app.element_clicked` 只含匿名会话、去查询参数路由、目录层级、坐标/区域、停留、设备和 locale；不采集可见文本、手机号、钱包、金额或原始用户 ID |
| A4 事件性质 | 两个行为事件均为 `is_server_authoritative=0`；只供 L6 行为分析，不进入 L1/L2 主漏斗、L3 资金或 K 风险权威裁决 |
| 幂等与时间 | 32 位 clientEventId 唯一；show/hide 同 id 只回填 dwell，不重复 PV/outbox；缺失、超过 24h、乱序和 300ms 点击冲突失败关闭 |
| 页面目录 | 目录来自当前 `NX1.0/src/pages.json` 构建版；系统入口明确排除，新增/删除页不静默漂移 |
| PC 协议 | 目录、PV/UV、点击、停留、跳出、趋势、坐标、时区和质量全有或全无；脏 200 不补零、不保留旧快照、不开放导出 |
| 导出治理 | 只有非空、已校验、当前无错误且具 `bi_l6_export` 才能导出；同一事务写 A2 和 A4 `admin.report_exported` |

奥卡姆剃刀落实为一条 AppChassis 全局生产链、一张服务端目录、一套 clientEventId 幂等语义；贝叶斯证据分为旧运行态、源码合同和待部署实物三层，互不冒充；墨菲审查覆盖重复、乱序、脏 200、空集、越权、刷新重登、目录漂移和治理写失败。

## 3. 修复后的完整调用链

```text
当前 NX1.0 页面 AppChassis
  ├─ show -> app.page_viewed(clientEventId, dwell=0)
  ├─ hide -> 同 clientEventId 回填 dwell
  └─ tap  -> app.element_clicked(clientEventId, x/y, zone, safe elementId)
        ↓ Bearer /api/app/analytics/events
BehaviorAnalyticsService
  ├─ 当前 build page catalog 校验
  ├─ clientEventId 唯一 + FOR UPDATE
  ├─ clientTs / 顺序 / 300ms / 坐标 / locale / device 失败关闭
  ├─ 匿名 session/actor hash
  ├─ nx_behavior_event_fact
  └─ A4 client analytics outbox（non-authoritative）
        ↓
/api/admin/bi/behavior
/api/admin/bi/behavior/click-heat
/api/admin/bi/behavior/page-catalog
        ↓ bi_l6_read
PC 严格整包校验
  ├─ PV/UV/点击/停留/跳出
  ├─ 页面/L1/L2/L3、设备、locale、24h/7d/30d
  ├─ 单页坐标热力、页面曝光 PV 与 CTR
  └─ UTC+08:00 / clientEventId 去重 / 迟到下一查询
        ↓ 非空 + bi_l6_export
CSV -> A2 required audit + A4 admin.report_exported -> L5/J4/监管追溯
```

域外边界复核：

- L1、L2 主事件集合不包含 `app.page_viewed` / `app.element_clicked`。
- L3 资金 Mapper 与 K 风险事实读取要求 `is_server_authoritative = 1`。
- L6 迁移把两个行为事件固定为客户端、非权威、behavior family。
- 因此点击、曝光或停留数据只能解释 UI 行为，不能提高收入、转化、兑付或风险分。

## 7. 墨菲定律对抗复审

- 同一 show/hide 重复提交、双击或网络重试：同 clientEventId 最多一个 PV/outbox，只有更大 dwell 可回填。
- 同 clientEventId 改 route、session 或 eventName：必须冲突，不能覆盖原事实。
- 客户端时间缺失、超过 ±24h、晚于已接收事实反向到达：拒绝，不替换为服务器当前时间。
- click 的 x/y 为 NaN、越界、zone 与坐标不符，或 elementId 含文本/空格：拒绝。
- 未知页或已退役页：拒绝；系统入口明确 excluded，不算行为活跃。
- 24h/7d/30d、L1/L2/L3、设备、locale、排序非法：拒绝，不回退近似值。
- HTTP 200 缺字段、负数、UV>PV、跳出率/坐标/权重 >1、目录重复、质量元数据矛盾：PC 整页失败关闭。
- 读请求 5xx 后：清空当前结果、显示重试，不能拿旧筛选数字冒充新筛选；导出禁用。
- 有 read 无 export、risk 角色、匿名和会话过期：只读或 401/403；刷新后的当前权限重新计算。
- 空集合：不生成只有表头的“成功文件”。
- A2 或 A4 schema/outbox 写失败：导出事务失败，不返回文件。
- 行为事件被恶意构造为资金/风控信号：non-authoritative 属性和消费者 allowlist/权威过滤双重阻断。

## 8. 统一部署后的锁定终验

1. 串行运行后端 `BehaviorAnalyticsServiceTest` 与相关 migration contract，应用 `20260727_l6_behavior_acceptance_hardening.sql`；确认 90 个当前 pages.json route 全部存在、5 个退役 route 为 deleted、clientEventId 唯一索引生效。
2. 部署 8110、3002 和当前 H5/App 包；用新建普通用户从可见 App 页面进入商城、设备详情、钱包、客服，点击主 CTA/内容/底部导航并正常离开。
3. 核对 show 立即产生 PV、hide 只回填同一事实 dwell；同 id 重放不重复 PV/outbox，同 id 异载荷冲突，并发重复只成功一次。
4. 注入缺失/过期/乱序 clientTs、未知页、坏坐标/zone、非法 device/locale；均失败关闭且不留下 fact/outbox 半记录。
5. 从 PC 可见侧栏进入 L6，逐一验收 24h/7d/30d、全部/L1/L2/L3、APP/H5/MP、zh-CN/en-US/vi-VN、四排序、单页坐标、曝光/CTR、空态和真实趋势。
6. 注入 HTTP 200 脏响应与 503；确认整页不显示伪零/旧筛选，导出禁用，点击“重新加载”后恢复；刷新、退出、重登后按当前权限重新读取。
7. 分别用 growth、risk、auditor、无权账号验证 read/export：risk 只能读，growth/auditor 按权限导出，匿名 401；空结果所有角色均不可导出。
8. 非空导出后核对 CSV 当前筛选、无 PII、A2 审计与 A4 `admin.report_exported` outbox/消费回执；注入 A2/A4 失败验证不返回文件。
9. 对照 L1/L2/L3/K4 前后数值，注入大量行为事件后资金、KPI、漏斗主事实和风险分必须不变。
10. 清理用户、行为 fact、outbox 与导出夹具；由非 L6 修复者从可见入口完整重跑初审和同范围复审，才可标记最终通过。
