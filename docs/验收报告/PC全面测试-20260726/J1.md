## 第一性原理闭环

J1 的最小事实不是 PC 上的开关颜色，而是“同一权威 gate 状态必须在每一个真实用户写入口、后台执行入口和跨域批处理入口重新裁决，关停时零业务副作用，恢复时先过资金红线”。据此建立闭环：

1. 五闸只认 `nx_emergency_control_setting` 的 canonical key；兼容旧 key 只做读回退。
2. PC 只能发起命令，不能替后端判定权限、B1、当前状态或并发胜者。
3. 用户入口必须在任何钱包、订单、claim、账本、事件副作用前读取 J1。
4. 同一人工命令使用稳定幂等键；响应未知时保留弹窗、理由和原 key。
5. 不同幂等键的两个运营员仍必须通过 expected value/CAS 竞争，最多一个成功。
6. 成功、失败和冲突都要有可追责证据；失败不得留下半写业务状态。

奥卡姆剃刀的修复选择是让 D2/H2 的现有真实服务直接读取同一 J1 状态，没有在 App 或 PC 再造第二套开关。贝叶斯更新中，发现 D2 审批检查不能证明 App 提交检查、H2 管理处置检查不能证明 App start 检查后，“矩阵显示已关停但用户仍可发起”的风险由假设升级为两个 P0。墨菲审查按断网、重复点击、响应丢失、双运营员、旧页面、格式漂移、刷新、重登、批处理晚到和依赖不可用必然发生来设计失败关闭。

## 缺陷与修复

| 编号 | 级别 | 初始证据 | 修复闭环 |
|---|---|---|---|
| PCFULL-173 | P0 | `AppWithdrawalService.submitOnce` 从 KYC 开始执行，没有 J1 检查；J1 withdraw 只在 D2 管理审批被消费 | 在用户事务最前读取 current/legacy withdraw gate；关停返回 409 且不触发 KYC、K3/K4/K5、余额、订单、D4、A4；policy 投影 `withdrawalEnabled/gateSource`，App 严格解析并禁用提交 |

| PCFULL-175 | P1 | J1 SLA/auto rule 请求只带新值，服务端 blind upsert；不同 key 可覆盖 | PC 携 `expectedValue`，确认窗禁止同值；服务端要求基线并原子 CAS，缺失、陈旧、并发输家、同值均失败关闭并记录 rejected audit，成功才记 changed audit |

## 权限、A2、B1、幂等与并发

- 权限按方向拆分：`emergency_j1_gate_kill`、`gate_resume`、`batch_kill`、`write`；读失败或无权限时不渲染写入口，后端仍二次鉴权。
- 当前 PRD v4 的 J1 高敏操作是“业务确认窗 + 理由 + 认证操作者立即执行 + 强审计”，不是先进入 A2 双人审批中间态。验收没有虚构 maker-checker；A2 的审计/回放/对象边界继续检查，J1 每次执行仍由一个被授权的真实操作者承担责任。
- withdraw、staking、genesis、exchange 恢复均由服务端 B1 红线裁决；trial 不直接放大资金流出，不要求 B1。
- 单闸和批量命令使用稳定幂等键；同 key 同 payload 返回原结果，同 key 异 payload 冲突。
- SLA/auto rule 新增 expected value + 数据库 CAS，解决“不同 key、同旧页面”的陈旧覆盖；同值不产生成功审计。
- 批量应急关停携 `triggerBasis`、`regulatoryContext`，包含 staking/genesis 时强制 `dispositionPlan`；目标集合为空不允许确认，服务端原子处理，不能部分显示成功。
- GET/协议漂移/网络失败均清空权威数据并隐藏写入口；写响应未知时不乐观改 UI、不清理由和 key。

1. 统一构建并部署同一源码的 8110、3002、App H5；执行 J1/D2/H2 聚焦测试和统一 Maven。
2. 从登录和侧栏入口重跑本报告全部 4 条 Playwright，不得只点修改过的控件。
3. 用可回滚夹具逐一关停五闸，分别从真实 App 用户入口验证：
   - withdraw：返回 409，钱包、提现单、D4、K3/K4/K5、A4 均零新增；
   - staking：新开仓失败，存量赎回按产品规则继续；

   - trial：新开始失败，存量取消/结算仍可完成。
4. 对每一闸恢复前制造 B1 低红线/不可靠快照；前四闸必须阻断，trial 按非资金闸恢复。再使用健康快照恢复并核对 App 状态传播。

8. 刷新、退出重登、切换账号后重新读取 canonical matrix；无前一账号权限或临时 UI 状态泄漏。
9. 清理所有 gate、参数、审计、outbox、订单/claim 测试夹具，并附前后计数与恢复后的五闸快照。
