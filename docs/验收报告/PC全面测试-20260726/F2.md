## 缺陷与修复

### PCFULL-056：PC 费率/Partner Status 口径与 L1 不变量失真

- 严重度：P0。
- 修复：
  - F2 页面不再复用 `rateTiers()` 的 V-Rank/peer 数据。
  - Partner 改为 Standard/Verified/Premium/Diamond，明确是非资金倍率权益档；兼容读取旧 JSON，提交只写当前 schema。
  - 删除假“Rate Tier”、可调层级深度、peer/最小提现/nexCap/backfill 等当前 F2 非闭环控件。
  - L1 页面显示“固定 10%”且不提供 USDT 调整；后端直接调用也返回 `422 F2_L1_DIRECT_RATE_FIXED_AT_10_PERCENT`。
  - 新增迁移把历史 active UNILEVEL L1 纠正到 `0.100000`。
  - 删除 Direct+L1 叠加文案，改为七层名义费率合计和 A2/B1 边界。

### PCFULL-057：运营配置写成功但结算不消费

- 严重度：P0。
- 根因：
  - PC 写入 `team.ui.F.*`，引擎读取 `F.*` 或 `F.commission.*`。
  - 暂停值由 PC 写 `on/off`，引擎只识别 `true`。
  - promo 倍率此前完全没有进入结算公式。
- 修复：
  - pause、depth gate、Influence clamp、promo 统一读取 `team.ui.F.*`。
  - pause 识别 `on/true/1`；非法 depth gate 不再把 `V2+` 误解析成 L2，而是失败关闭到 L4。
  - `finalUsdt = base × Influence(L2-L7) × promo`；NEX 继续基于同一个最终 USDT 结果派发。
  - 新增单层暂停和 `Influence clamp × promo` 真实金额测试。

### PCFULL-058：App remote 仍用本地 mock 真值

- 严重度：P0。
- 修复：
  - 后端新增公开只读 `/api/config/commission/rates`，只投影 F2 结算同源的 `nx_commission_rule + nx_config_item`。
  - App 新增严格协议：恰好 L1–L7、L1=10%、总和≤25%、Partner 阈值递增、clamp/cooling/promo 合法。
  - remote store 初始与请求失败均保持空费率、空事件；禁止本地新增佣金、解锁或提现。
  - unilevel、tree、team roster 改为消费响应式 canonical store；Partner 第三档显示 Premium。
