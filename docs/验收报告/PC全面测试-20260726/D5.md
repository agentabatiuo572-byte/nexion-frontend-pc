## 修复闭环

### App command、配对事实与 canonical tracking

- 提交请求固定使用 `{ amount, chain, address }`，测试精确断言 request body。
- remote 模式从后端 KYC 权威边界读取 `pairedAddress/network`；未配对、未知网络、策略未加载或协议畸形时失败关闭，不回退本地 mock。
- 新增 `/api/withdrawals/policy` 严格解析；预览统一使用 D5 网络费率/上下限、H1 惩罚率/冷却期、NEX 抵扣率和后端允许网络。
- 提交成功后把服务端 `withdrawalNo/status/riskRoute/holdUntil` 投影为 canonical `latestWithdrawal` 并持久化，再进入跟踪页；未知状态拒绝解析。

### H1 单源与 D5 确认语义

- `OpsFinanceService.withdrawalParams()` 和 D5 限额读面统一调用 `GrowthRhythmFacade.snapshot()`。
- facade 不可靠、月份/阶段/惩罚率/冷却期不合法时返回不可用，不读取 legacy flat mirror 假装成功。
- PC 确认窗改为“提交成功后生效并写入审计”；只有真实 PUT 成功后才提示已生效。
- 浏览器已验证打开确认窗后取消不会产生修改；刷新、退出、重新登录后 D5 页面可恢复，过程中无 page error 和 5xx。

### D2 不可变费用证据

- `nx_withdrawal_order` 新增并写入：
  - `d2_network_fee_rate`
  - `d2_network_fee_min`
  - `d2_network_fee_max`
  - `d2_network_fee`
- 列表、详情、PC 严格解析同时接通；缺字段、负数、最大值小于最小值、实际网络费超边界、总费用不守恒时 fail-closed。
- 历史单只回填 0，不使用今天的 D5 参数伪造历史快照。

### D4 central ledger 与费用组件

- 已从 `AppWithdrawalMapper` 移除提现私有 `insertLedger`，全部提现账本经 `TreasuryLedgerPostingFacade`。
- USDT 采用三个可审计组件：
  - `WITHDRAW_NET_PRINCIPAL`
  - `WITHDRAW_NETWORK_FEE`
  - `WITHDRAW_PENALTY_FEE`
- 仅金额大于 0 的组件落账，且强制满足：

```text
net principal + actual network fee + actual penalty fee = withdrawal amount
```

- NEX 抵扣固定顺序为：**先冲减 H1 惩罚费，再冲减网络费**。这样尽可能保留真实链上成本的可见性；抵扣自身以 `WITHDRAW_FEE_OFFSET` 的 NEX OUT 记录。
- D4 按用户+资产串行计算每行 `balance_after`。测试验证 78 + 2 + 20 的三行 USDT OUT 从 100 连续到 22、20、0，总 OUT=100。
- 每个组件首次插入在同一事务发布一条 `wallet.ledger_posted`；精确重放直接返回既有指纹，不重算余额、不重复账本、不重复 outbox。

### A2/A4

- D5 拒绝审计使用独立 idempotency scope 和稳定请求摘要；同 key、同失败结果仅记录一次，不同 payload 冲突关闭。
- `withdraw.submitted` migration 已升级到 revision **276**，注册 **28** 个 active 属性，包含：
  - 网络费三元组与 gross network fee；
  - `penalty_fee_waived/network_fee_waived`；
  - `actual_penalty_fee/actual_network_fee`；
  - 总费用、NEX、到账、冷却和 K3/K4/K5 证据。
- migration 已幂等执行到本地 `nexion`。只读核对结果：`current_revision=276`、active properties `28`；四个 D2 网络费列均为 NOT NULL。
