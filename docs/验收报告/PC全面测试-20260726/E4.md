## 修复闭环

### PCFULL-038：状态不可由人工点击凭空生成

后端把“相邻状态”升级为“相邻状态 + 业务事实”：

1. placed→paid 必须已有 D1 或 D4 结算事实，否则返回 `ORDER_PAYMENT_CONFIRMATION_REQUIRED`。
2. paid→provisioning 必须支付状态已结算、D1/D4 资金方向与状态有效，并已有设备实例、设备 ID 和数据中心，否则返回 `ORDER_PROVISIONING_EVIDENCE_REQUIRED`。
3. provisioning→activated 必须关联设备已有 E5 激活时间，否则返回 `ORDER_DEVICE_ACTIVATION_REQUIRED`。
4. 既有 CAS、终态不可逆和非删除约束保留；前端依据同一事实隐藏非法按钮并显示缺失证据，不靠乐观 UI 代替后端裁决。

### PCFULL-039：App 只展示服务器订单真值

- remote 普通购买改为 `POST /api/orders`，使用稳定 `Idempotency-Key`，订单号只接受服务器生成值。
- 新单必须返回 `PENDING/PENDING_PAYMENT`；未结算前 App 不再本地扣钱包、不写本地账单、不生成设备、不自动推进 paid/activated。
- `GET /api/orders` 严格解析十种 canonical 状态，逐一保留 payment_failed、expired、provisioning_failed、refunded、chargeback、cancelled。
- server-authoritative 订单禁止客户端 `tickOrders`、手工推进、取消或激活；刷新、前后台切换和重登均重新读取权威快照，失败时清空并失败关闭。
- E3 置换完成后刷新 E4 canonical 订单和 E3 设备，不保留本地假订单。

### PCFULL-040：可发现与可追溯

- 列表增加订单号、用户、SKU、设备关键词输入，并把查询传给真实 E4 API。
- 年龄改为分钟、小时、天的人类可读口径。
- 详情提供 A2 审计、A4 事件与 D4 账本入口，调查链不再停在 E4 页面。
