## 技术 / 墨菲审查

### 已确认缺陷

1. **PCFULL-126（P0）App 领券和核销是假链。** remote 模式仍读静态券和 localStorage，向真实订单发送服务端不存在的本地 voucherId。
2. **PCFULL-127（P1）已领券追溯语义错误。** 暂停/删除定义会让已领券从用户查询消失且无法核销；到期券也直接被过滤，违背“已领不回收”和过期可见。
3. **PCFULL-128（P1）库存与并发治理缺失。** 没有发行上限、统一库存裁决、版本号或管理 CAS；多来源并发可超发，运营员可陈旧覆盖。
4. **PCFULL-129（P1）管理生命周期不完整。** PC 看不到来源批次、领取/可用/核销/撤销事实，没有撤销未核销动作；数据库异常还会被伪装成空列表。

### 对抗性检查结论

- 单一真源：App remote 只接受 `/api/vouchers` 和 `nx_growth_voucher_grant`；协议/网络失败清空 canonical 状态，不回退静态券或 localStorage。
- 权限：PC 读写仍使用 `growth_h7_read/growth_h7_write`；App 只读取/操作登录用户自己的 grant；订单核销同时校验用户归属。
- A2/J1：H7 编辑、上下架、删除和撤销在执行前检查 A2 对象锁；管理命令继续经过统一 command boundary、RBAC、理由和强审计。
- CAS：券定义新增 `version`；编辑、上下架、删除、撤销均携页面可见版本，SQL `WHERE version=expectedVersion`，陈旧请求返回 `409 H7_VOUCHER_STALE`。
- 发券并发：H4、F1、用户 claim 等来源统一调用 `VoucherGrantFacade`；事务先锁券定义行，再比较总发行量，只有一个请求能占用最后库存。
- 幂等：精确 grant key 重放在有效性/库存检查前返回原 grant；同 key 不同业务内容返回冲突；未知 App claim 保留同一命令键并先回读对账。
- 库存口径：`issuanceLimit=0` 表示不限量，正整数为累计总发行上限；USED、AVAILABLE、EXPIRED 投影和 REVOKED 历史均不凭清 storage 重置。
- 定义与持券分离：暂停/删除仅关闭新领取，已领 AVAILABLE 仍可按原定义、有效期和 SKU 核销；已到期按服务端时间投影 EXPIRED，不可再核销。
- 订单原子性：E4 下单锁定本人 AVAILABLE grant，服务端重算门槛、SKU 和折扣并在订单事务内标记 USED；App 创建后必须同时回读订单与券 USED，结果未知使用原订单幂等键重试。
- 撤销：PC “撤销未核销”只把 AVAILABLE 改为 REVOKED，USED 历史保持；动作使用版本 CAS、理由和强审计。
- 读失败：移除 H7 数据库异常吞噬；迁移缺失、数据库故障或响应畸形都返回错误，PC 只给重试并隐藏写入口。
- 刷新/账号隔离：App 合并并发读；账号切换递增 generation、清空 pending/canonical，旧账号晚到响应不能覆盖新账号。
- 跨域：H4/F1 只负责提出发券请求，H7 统一拥有 grant/库存；E4 只通过 H7 grant 核销；D4 只记录订单权威金额，不产生可提现券余额；A4 记录领取/发券事件。

## 修复清单

### PC

- 配置表单新增发行上限，结构化校验为 0～10,000,000 的整数。
- 列表新增来源批次、累计领取、当前可用、累计核销和累计撤销；顶部展示领取/核销总量。
- 新增“撤销未核销”业务动作，明确已核销历史不变。
- 编辑、上下架、删除和撤销全部携 `expectedVersion`；服务端返回 stale 时失败关闭。
- H7 响应执行严格字段检查；版本/计数/数组/状态缺失时不渲染半可信页面。
- 修正 500 故障注入用例：错误态写按钮必须不存在，不再用陈旧断言误报产品失败。

### 后端与迁移

- `nx_growth_voucher` 新增 `issuance_limit`、`version`，提供幂等迁移 `20260727_h7_voucher_inventory_cas.sql`。
- H7 管理读模型返回来源批次和 issued/available/redeemed/revoked 计数；数据库异常不再伪装为空数据。
- 所有管理变更使用版本 CAS、A2 对象锁、事务和强审计。
- `VoucherGrantFacade` 在券定义行锁内统一裁决发行上限；精确重放优先返回原结果。
- 用户券投影把定义投放态与 grant 生命周期拆开；已领暂停/删除券保留，过期按服务端时间投影。
- 订单核销不再要求定义 active/未删除，但仍要求本人 AVAILABLE、有效期内、SKU 匹配并持行锁。
- 新增撤销 AVAILABLE grant 端点，已核销事实不可逆。

### App

- 新增严格 `voucher-api.ts`，校验枚举、数值、时窗、数组、重复 ID、claimable/grantStatus 组合和命令响应。
- remote voucher store 使用服务端 canonical 状态，支持账号 generation、并发读合并、stable idempotency key 和未知结果回读。
- 领取弹层和 banner 使用服务端券目录、可领状态及领取入口；remote 不再写本地券账本。
- 券包的 AVAILABLE/EXPIRED 由服务端投影；USED/REVOKED 不冒充可用券。
- 结算只使用真实 AVAILABLE grant；订单响应 voucherId 必须与提交一致，随后回读订单和券 USED 状态。
- App 启动、前台恢复和下拉刷新均刷新 H7 canonical 状态；mock 逻辑只保留显式 mock 模式。
