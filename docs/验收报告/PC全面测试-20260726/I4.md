## 2. 第一性原理与域内外调用链

I4 的最小闭环不是“PC 上能看到六张卡”，而是：

```text
PC 草稿/发布/回滚/下架/恢复
  → A2 maker-checker（高敏发布）
  → 后端认证身份、权限、理由、持久幂等、快照 CAS、行锁、状态机
  → MySQL 当前 section + version
  → 匿名 current API
  → App 按服务端发布字段和值渲染
  → content.trust_section_viewed / 治理 outbox / A4 / BI
  → 刷新、重登、并发和未知结果重试仍回到同一事实
```

按奥卡姆剃刀保留一个当前发布版事实，不在 App 维护第二套财务、团队、合规和市场元数据。按贝叶斯风险优先审查“旧页面陈旧覆盖”“后端已提交但响应丢失”“归档后无版本可恢复”“浏览器可点但原生端无动作”四类高概率故障。

| 检查面 | 结论 | 证据/判断 |
|---|---|---|
| 六固定版块 | 源码通过 | API 严格接受 financials、leadership、nexNarrative、complianceBadges、auditsReserves、listings；未知/重复版块和重复字段失败关闭 |
| App 单一事实源 | 修复通过 | 只读匿名 current；无本地业务回退；description/structure/label 使用服务端发布值；多语言值按 `.zh/.vi/.en` 选择 |
| App 载体 | 修复通过、待真机 | 内部链接 allowlist；外链只允许无凭据 HTTPS；H5 新窗口、原生 `plus.runtime.openURL`，失败显式提示 |
| App 曝光 | 修复通过 | 可见版块逐项发 `content.trust_section_viewed`；埋点用 `Promise.allSettled`，不阻塞首屏内容 |
| 多运营员 | 修复通过、待运行态 | 当前 section `version+status` 和 draft revision CAS；section/version `FOR UPDATE`；陈旧请求在写内容、审计和 outbox 前失败 |

## 4. 修复内容

PC：

- 草稿增改携当前 section version/status，删除携 draft revision。
- 发布、回滚、下架的 A2 命令固化当前 version/status。
- archived 状态把当前历史发布版纳入选择并明确显示“恢复上线”。
- A2 提案按动作快照和理由生成指纹，未知结果保留确认窗与同一 command key。

后端：

- 六类 I4 写纳入独立 `AdminIdempotencyService` scope。
- section/version 读取增加 `FOR UPDATE`，所有变更执行快照 CAS。
- 草稿删除强制 revision；发布同时校验草稿 revision 与当前 section 快照。
- archived+当前版本允许恢复，published+当前版本仍按非法转换拒绝。
- 草稿、发布、回滚、下架的持久化与治理事件归属统一取 `authenticatedOperator()`。
- 新增缺快照、陈旧快照、草稿删除 revision、归档恢复、A2 replay 参数和 operator spoofing 回归用例。

App：

- 新增严格 Trust API；只读服务端当前发布版，协议异常、网络失败和真空态分离。
- 删除硬编码财务、团队、审计、交易所事实及本地 CMS 元数据覆盖。
- 按服务器字段 key 的 `.zh/.vi/.en` 后缀选择值；description/structure/label 保持服务端发布值。
- 曝光事件非阻塞上报；链接只允许受控内部路由和无凭据 HTTPS。
- H5 使用安全新窗口；Android/iOS 使用 `plus.runtime.openURL`；打开失败显式提示。
