## 第一性原理闭环

G3 的最小业务事实不是“表格能保存”，而是“一个服务端权威价格状态机按受控排程发布价格，任何写入都不能越过资金红线、并发版本、审计和事件边界”。

1. weekly curve 是未来排程参数，当前价是已发布事实；编辑参数不能隐式重放当前帧。
2. 只有排程推进或明确的应急 override 可以发布价格；抬价方向必须先过 B1。
3. 幂等解决同一命令重放，CAS 解决两个不同命令争写，二者不能互相替代。
4. pin/loop/oracle 是有限状态，不接受任意字符串；UI 与服务端的 0 值边界必须一致。
5. G2、G7 和 App 只读同一 G3 现价，不接受客户端随机价或客户端报价。
6. A2 对象锁、A2/A4 不可变证据和强制 A2 审计必须与业务写同事务失败关闭。

奥卡姆剃刀的修复是保留现有曲线、价格索引、动态 scheduler 和公共 App market API，只拆掉错误的“保存曲线即 applyFrame”耦合并补 expected state，而没有再造第二套版本表或客户端行情协议。贝叶斯更新中，真实写探针从三个独立方向均返回错误成功后，缺陷从静态风险升级为已证实 P0/P1。墨菲审查进一步假设低覆盖率、两个运营员同时提交、陈旧页面、非法枚举、零值边界、网络重试、刷新和重登都会发生。

## 权限、幂等、CAS 与跨域审查

- 权限：目标价、pump、一般曲线、现价 override、暂停分别使用精确 G3 authority；服务层再次校验，匿名管理 API 被拒。
- A2：曲线、control、override 在服务端检查 A2 对象锁；A2 replay 才能绕过普通交互基线。
- CAS：PC 每次提交携当前权威值/曲线；后端在 `nx_config_item` 行锁内比较，两个不同 idempotency key 也只能一条成功。
- 幂等：`G2G3AdminCommandService` 按操作 scope、key、payload hash 执行一次；同键异 payload 冲突关闭。
- B1：曲线提高峰值、现价抬价、推进抬价、暂停后恢复均由服务端最终裁决；PC 只做同源镜像。
- G2/G7：下游从服务端 currentPrice 读取，不接受客户端价格。
- App：公共 `/api/config/market/nex` 明确 `serverCanonical=true`，严格协议失败时 remote store 清空，不退回 mock。
- A4：live schema registry 中 `admin.nex_price_curve_changed`、`market.curve_advanced`、`admin.nex_price_overridden`、`admin.nex_oracle_source_changed`、`admin.market_paused/resumed`、`admin.market_schedule_changed` 均为 ACTIVE、server-authoritative，并登记 G2/G7/B1/A2/A4 消费边界。
- A2 审计：live 已存在 11 条 `G3_%` 探针/历史审计；修复后所有 G3 高风险成功审计使用 fail-closed 写入。
