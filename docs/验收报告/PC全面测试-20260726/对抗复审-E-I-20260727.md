## 4. 缺陷、根修复与闭环复验

### EIFINAL-001：App 匿名登录时账户重绑触发请求风暴

- 类型：**真实产品/跨域调用链缺陷**。
- 影响域：F1 V-Rank、F2 佣金配置；D1 VietQR 是触发同类未登录认证刷新的支撑链。
- 现象：
  - 未登录打开 5174 时，V-Rank store 在实例化和 `bindAccount("default")` 中调用“公开阶梯 + 已认证当前等级”组合请求。
  - VietQR store 在默认账户重绑时调用已认证意向单列表。
  - 全局 401 处理再次清理并重绑全部 store，佣金公共配置因此被重复刷新；实测 2.5 秒内 `/api/config/commission/rates` 604 次，浏览器随后出现 `ERR_INSUFFICIENT_RESOURCES`。
- 第一性原理：匿名登录页没有用户身份，任何“当前用户等级/意向单/佣金账户态”都没有合法查询对象；最小正确行为是保留未知/加载态并且不发认证业务请求。
- 根修复：
  - `NX1.0/src/store/v-rank.ts`：无 access token 时不启动 canonical rank 链；认证后才加载；重复 bind 复用 in-flight 请求。
  - `NX1.0/src/store/deposits.ts`：无 access token 时不请求 VietQR 意向单，清空账户事实并保持失败关闭。
  - `NX1.0/src/store/commission.ts`：无 access token 时不加载账户佣金数据；认证后才读取，重复 bind 不再强制绕过 in-flight。
  - 增补/扩展 V-Rank、Deposits、Commission 远程模式测试，锁定“匿名 0 认证业务请求”和“认证后单次加载”。
- 修后证据：
  - 聚焦测试 14/14 通过。
  - App 全量 233/233 通过，类型检查通过。
  - 当前 5174 无构建、无重启，通过 HMR 激活后重新开全新 Chromium：上述 5 个公共配置各 1 次；V-Rank/佣金/VietQR 账户请求 0；失败请求 0；pageerror 0。

### EIFINAL-002：E2 重登 helper 与 Shell 恢复竞争

- 类型：验收载具缺陷，非产品缺陷。
- 现象：退出后未等待登录表单稳定；填写过程中 Shell 若被既有会话恢复，会留下空字段校验假红。
- 修复：退出后明确等待 username；填写每个字段前后允许 Shell 已恢复；侧栏组仅在未展开时点击。
- 复验：E2 3/3；终局 E-I 31/31。

### EIFINAL-003：E3 侧栏展开和重登时序不稳定

- 类型：验收载具缺陷，非产品缺陷。
- 修复：退出后等待登录表单；侧栏只在 `aria-expanded != true` 时展开，避免把已展开分组误收起。
- 复验：E3 3/3；终局 E-I 31/31。

### EIFINAL-004：I5 首屏用同步 `isVisible` 探测登录表单

- 类型：验收载具缺陷，非产品缺陷。
- 现象：DOM 尚未出现时同步探测返回 false，用例跳过登录后错误等待运营总览。
- 修复：对 Shell/username 做有界竞争等待，并采用 Shell 恢复感知的逐字段填写；退出后等待登录表单稳定。
- 复验：I5 2/2；终局 E-I 31/31。
