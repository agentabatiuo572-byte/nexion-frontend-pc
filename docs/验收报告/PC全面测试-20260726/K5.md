## 三、技术与墨菲审查

### 3.1 阈值与状态机

| 验收项 | 结论 |
|---|---|
| `largeWithdrawReviewUsdt` | 只接受 $100–$50,000；默认展示 ≥ $1,000 |
| `cumulativeKycThresholdUsdt` | 只接受 $50–$1,000；默认 $100 lifetime |
| `reviewSlaDays` | 只接受 1–15；新工单使用工作日计算 |
| `reviewTriggerScore` | 只接受 70–100；消费 K4 有效风险分 |
| 工单状态 | `in-review → passed/rejected` 使用 ticket version CAS |
| 重复触发 | 同用户开放工单锁读 + 唯一键 + 版本合并 |
| 过期 | `due_at` 形成 SLA 告警；修改 SLA 会重算开放工单截止时间 |
| 撤回/提现 | K5 不直接放款；通过只把 D2 回到人工审核、G2 回处理队列，资金放行仍由 D2/G2 自己裁决 |

### 3.2 跨域调用链

| 调用链 | 审查结论 |
|---|---|
| D5/H1/K3/K4/C4 → D2 → K5 | 提现提交先取真实网络/费用与 K3/K4/C4 事实；合法大额事实才触发 K5，命中后 D2 为 `FROZEN` |
| G2 → K5 | G2 持有兑换阈值；累计达线创建/合并 K5 工单。PCFULL-205 后，裁决只允许从 `KYC_REQUIRED` CAS 到 `QUEUED/CANCELLED` |
| K4 → K5 | 当前风险分跨过 K5 阈值时持久化 crossing，重复事实不会无限开单 |
| K5 → C4 | C4 是实名状态唯一真值；裁决写 C4 使用 profile version CAS，并记录 ticketId/evidenceRef |
| K5 → D2 | 通过只回 `REVIEWING`，并要求精确 `K5_REVIEW:<ticketId>` hold；驳回维持冻结/驳回路径 |
| K5 → G2 | 通过/驳回均使用前态 CAS；CAS 失败令外层事务回滚，不允许“工单成功、来源失败” |
| K5 → C2/K3 | 驳回不会自动冻结账户或修改 K3；需要账户级限制时必须走 C2 独立动作 |
| K5 → A2/A4/I3 | 高敏裁决有 required audit；C4/G2 触发链产出注册事件，订阅只接受权威 `in-app` 渠道闭集 |
| K5 → MinIO | K5 消费材料引用，不持有对象真值；MinIO 健康 200，浏览器响应未泄露凭证 |

### 3.3 失败关闭

真实浏览器注入并验证：

1. overview 503：隐藏旧队列和全部裁决按钮，仅显示“K5 数据加载失败 / 仅重试 K5”。
2. 网络连接失败：与 503 同样失败关闭，不继续显示陈旧可写状态。
3. HTTP 200 但 payload 畸形：严格响应合同拒绝，不把缺字段补成默认值。
4. 重试恢复：移除故障后只重试 K5，权威队列恢复。
5. 只读角色：无手动触发、保存订阅和裁决控件；服务端直调仍 403。
6. 用户不可用：404，工单状态和 version 不变。
7. PCFULL-207：空 userNo、非正金额、空来源单号或空理由在读阈值前抛稳定错误，不再返回“无需复审”。

## 四、缺陷修复说明

### 4.1 PCFULL-205：G2 并发终态保护

修复前，`MarketExchangeKycReviewFacadeAdapter` 使用无前态条件的 `updateExchangeStatus`。修复后：

- 通过：仅 `KYC_REQUIRED → QUEUED`。
- 驳回：仅 `KYC_REQUIRED → CANCELLED`。
- 已完成、已取消、缺失或被并发推进的订单返回 false。
- K5 外层检测 source update 失败后抛错，事务回滚工单和 C4 写入。
- 新增单测同时锁定“不得回退到无条件 update”与 Mapper SQL 的 current status guard。

### 4.2 PCFULL-206：验收载具跟随 A1/K5 最新契约

修复后脚本：

- 登录使用 A1 响应中的 `temporaryPassword`。
- 首次登录改成满足 16 位复杂度的新密码并完成 TOTP。
- K5 驳回使用闭集中的 `KYC_MATERIAL_INVALID`。
- 清理前读取账号最新 version，禁用成功后用返回的新 version 移除角色。
- 全套专项从 1/4 阻断恢复到 **4/4 PASS**。

### 4.3 PCFULL-207：畸形上游事实失败关闭

修复后，大额提现和大额兑换触发入口先独立校验：

- userNo 非空。
- amountUsdt 为正数。
- withdrawalNo/exchangeNo 非空。
- reason 非空。

只有合法事实才进入阈值比较；合法但未达线才能返回 `notRequired`。建单、合并、来源记录和审计统一使用 trim 后标识，避免同一业务号因首尾空格分裂。
