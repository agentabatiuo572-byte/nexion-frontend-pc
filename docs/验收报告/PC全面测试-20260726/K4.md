## 三、缺陷与修复闭环

### 3.1 PCFULL-200：跨字段不变量

后端写接口已经强制：

```text
70 <= autoEscalateScore <= 100
autoEscalateScore >= bandHighMin
```

旧 PC 只检查第一行，导致浏览器仍可把“高风险从 90 开始、85 自动升级”带入确认流程。更严重的是，客户端收到这种历史脏模型时仍展示并开放写入口，后端 `findCurrentScoreUser` 也只检查升级线 0–100，可能继续把矛盾模型传播给 C1/D2。

修复：

- PC `modelValid` 同时检查 `autoEscalateScore >= bandHighMin`。
- 输入矛盾时显示明确原因并禁用“保存模型草稿”。
- `normalizeK4Model` 拒绝矛盾服务端响应，不回退默认值，不保留旧写入口。
- 后端当前分读取要求升级线至少 70 且不得低于高风险下限，否则返回不可用。
- 合同测试锁定 UI、客户端解析和后端下游失败关闭。

### 3.2 PCFULL-201：空集合不是调用失败

旧脚本在 D2 没有提现单时仍查找某一行 K4/K3 文本。修复后分两支：

- 有记录：逐行核对 K4 分或明确不可用标记，并核对 K3 路由。
- 无记录：核对服务端口径标题和“暂无提现记录”空态。

两支都要求页面成功加载，不能把空集合当成功能缺失，也不能用空集合掩盖 5xx。

### 3.3 PCFULL-202：B5/J1 单一真值

live 精确返回：

```text
503 B5_KILL_SWITCH_SOURCE_UNAVAILABLE
```

只读数据库核对确认 5 个功能闸中仅缺 `killswitch.staking` 持久行。J1 权威 `KillSwitchState` 明确规定“缺行=enabled”，J1 页面和各业务生效域均按该规则；B5 新读模型却把缺行当成整个来源不可用。

修复：

- B5 缺行复用 `KillSwitchState.enabled`，返回 `enabled=true` 和 `defaulted=true`。
- 显式非法值仍返回 503 `B5_KILL_SWITCH_SOURCE_INVALID`。
- 未直写数据库，未临时切换闸，未改变 J1 当前业务状态。
- 新增“缺 staking 行”和“显式 unknown”两类单测，分别证明 canonical 默认和非法值失败关闭。

- 写成功后的回读由同一动作 Promise 完成；网络结果未知时必须复用原命令键并先回读，不生成第二条业务命令。

## 六、数据缺失、漂移与墨菲定律

- 活动模型被 DBA 写成升级线低于高风险下限：PC 读失败；C1/D2 当前分也返回不可用。
- 两个运营员同时从同一旧页面保存：后提交者由 row version 409 拒绝。
- 保存响应丢失：原键重放得到原结果；改载荷复用原键 409。
- 发布过程中页面刷新：重读活动版本和 `recomputePending`，不在浏览器继续本地计数。
- 评分事实比活动模型旧：当前分读取要求模型版本一致，不能把旧分标成当前分。
- 人工覆盖与模型重算并发：用户 row version/CAS 决定唯一成功者，输家回读权威状态。
- 批量超过服务端上限：422，不能拆成浏览器无界并发绕过。
- D2 没有数据：显示真实空态；D2 读取失败则是错误态，两者严格区分。
- B5 某闸缺行：使用 J1 已定义 canonical 默认并显式标 `defaulted`；显式非法文本仍失败关闭。
- B5 SSE 或 overview 5xx：终验必须记为失败，不能只以 B 域另一聚合接口成功替代。
- 重新登录或换账号：丢弃旧页面内存，从服务端重新加载权限和模型。
- App 内部另有七维聚簇配置：不得把它当 K4 六维模型或向用户暴露内部风控分。
