## 技术 / 墨菲审查

### 已确认缺陷

1. **PCFULL-115（P0）App remote 仍本地完成和本地派奖。** 页面访问、分享、绑卡可写 localStorage 并直接增加本地钱包，服务端完成事实、PC 奖励和真实账本均可被绕过。
2. **PCFULL-116（P1）PC 写契约与并发闭环断裂。** 首日奖励按“显示序号+1”猜数据库 id；周任务、月度奖励和促销卡使用后端不识别的键；无 CAS、无 durable 互斥、强审计与业务写不在同一事务。
3. **PCFULL-117（P1）读写真源和恢复路径不一致。** 首日窗口/三段奖励/周冠军从无关任务行拼接；暂停促销被读接口过滤而无法恢复；GET 失败没有重试。

### 对抗性检查结论

- 权限：H3 用户状态接口要求已认证且有效用户；PC 写继续受 RBAC/J1/A2 守卫。
- 稳定主键：任务按 `mission_code`、月度挑战按 `challenge_code` 更新，不再依赖数据库自增顺序。
- CAS / 并发：PC 携 `expectedValue`；后端在 `H3_CONFIG` durable 行锁和事务内比较，陈旧页返回 `QUEST_CONFIG_STALE`，同值返回 `QUEST_CONFIG_NO_CHANGE`。
- 未知结果：App 领取结果未知时立即回读权威状态；未确认终态的重试复用同一幂等键，避免换键重放。
- 账号隔离：账号重绑清空任务、促销、错误与命令状态；旧账号晚到 GET/claim 响应不得覆盖新账号。
- 失败关闭：App state 协议畸形、重复 quest code、未知枚举或网络失败时清空 canonical 投影，不回退静态任务；PC GET 失败不展示写区并提供重试。
- B1：任务奖励上调、促销基础奖励/倍率上调、促销从 paused→active 都由后端做覆盖率红线最终裁决；收紧方向不被前端错误阻断。
- A2 / 事务：业务值与 `recordRequired` 在同一事务，强审计失败整笔回滚。
- A4 / 完成事实：App remote `markComplete` 固定 no-op；只有订单、学习、设备、佣金和邀请的服务端 canonical producer 可推进任务。
- D4 / 领取：App 不再本地加款；领取仍由服务端锁任务、计算 H1 倍率、CAS 钱包、写唯一 ledger 和 outbox。
- 首页促销：PC 和 App 可读取 paused 配置，但 App 仅在 active 时展示；服务端未提供稳定商品 code 时只进入商城列表，不用本地推导商品详情冒充配置结果。

## 修复清单

### PC

- `h3-quest-events.tsx`：任务与月度奖励改用稳定业务 code；所有 H3 配置提交 current expected value；数值编辑禁止同值并按增减方向标识资金放大。
- 首页转化卡补全基础奖励、倍率、倒计时、目标展示与上下架真实命令；paused 仍可读、可恢复。
- 错误卡增加“重试加载”；首日窗口、三段奖励和周冠军摘要改读同一服务端配置。
- `h-client.ts` 增加 expected value；错误消息补齐 stale、no-change、缺配置和业务对象不存在。
- 新增 `tests/h3-owner-closure-contract.test.mjs` 与 `tests/e2e/h3-owner-acceptance-20260727.spec.ts`。

### 后端

- `GrowthConfigUpdateRequest` 增加 `expectedValue`，保留四参数构造兼容既有调用。
- `OpsGrowthService.updateQuestConfig` 增加事务、durable H3 mutex、CAS、同值拒绝和 B1 方向门；支持 mission/monthly/promo stable-key 合同。
- `GrowthQuestEventMapper` 按业务 code 锁定和 CAS 更新任务/月度奖励；promo 读取包含 paused；单字段写入在同一事务完成。
- 新增 `GET /api/quests/state`，只返回登录用户的真实任务定义、用户进度、paused/active promo 与 H1 multiplier。
- `schema.sql` 与增量迁移补 `H3_CONFIG` mutex 和一条 paused 促销安全种子。
- Java 回归源码覆盖任务 stable-code/CAS/stale、暂停促销恢复、App canonical state；Maven 交统一串行阶段执行。

### App

- 新增严格 `quest-api.ts`：拒绝重复 code、未知 layer/status、空/越界 promo 和错误领取响应。
- `quest.ts` remote 模式禁用本地完成、reset 和派奖；账号隔离读取 canonical state，合并并发刷新，丢弃旧账号晚到响应。
- 领取失败先对账；未知且未终态时保留同一幂等键，已对账为 CLAIMED 时更新页面而不弹虚假失败。
- 首页首日任务、任务中心周任务、首页转化卡均读取服务端；remote 模式不再展示本地 weekly defs 或客户端推导促销。

## 统一部署后锁定复验

必须从侧栏可见入口使用干净或可回滚夹具完整重跑，不得只点修复按钮：

1. 执行 H3 增量迁移，构建并部署同一源码的 8110、3002 与 App H5；运行后端 H3 聚焦测试和统一全量 Maven。
2. 重跑通用 surface 与 `h3-owner-acceptance-20260727.spec.ts`，确认入口、刷新、退出重登、H1 往返、无 5xx/脚本错误。
3. 对 mission、monthly、三个 `growth.quest.*` 摘要和 promo 每个写按钮执行“修改→刷新→退出重登→另一账号读取→恢复原值”，核对 DB、A2 audit 和页面一致。
4. 两个运营员从同一旧值并发提交：只允许一个成功，另一个必须 stale；同值拒绝；审计注入失败整笔回滚。
5. B1 覆盖率低于红线时验证奖励上调、倍率上调和 promo 上架失败；奖励下调、promo 下架保持可用。
6. 使用五类 canonical producer 各完成一条任务，核对 A4 delivery、completion fact、`nx_user_mission` 与 App 状态一致；访问页面或调用 remote `markComplete` 不得完成任务。
7. 对可领取任务执行 claim、同键重放、异键重试、并发双击和超时后对账；核对只产生一次钱包增量、一次 D4 ledger、一次成功审计/事件。
8. 注入 state 协议错误、重复 code、网络错误、H1 不可用、钱包 CAS 冲突和 A4 写失败，确认 App/服务端失败关闭且无半领取。
9. 切换用户、刷新和退出重登，确认任务、promo、claiming 状态和晚到响应无跨账号泄漏。
10. 清理测试 mission/user_mission/promo、钱包/ledger、audit/outbox 与生产者夹具，并附前后 SQL 计数。
