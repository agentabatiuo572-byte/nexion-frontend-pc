## 缺陷与修复闭环

### PCFULL-137：PC 文案/实验没有进入真实 App 用户链（P0）

修复：

- 后端新增按 UI 位置交付接口；只接受活动位置且必须唯一匹配一个发布文案。零匹配返回 404，多匹配返回 `409 CONTENT_COPY_POSITION_AMBIGUOUS`，不猜测“最新一条”。
- 唯一命中后仍复用原服务端稳定分桶、assignment 粘性、首曝幂等和三语版本选择，不把实验逻辑下放客户端。
- App 新增严格 `content-copy-api` 和 Pinia store；remote 模式首页 `home.conversion-banner` 在可见组件挂载时读取服务端变体，并按 zh/en/vi 当前语言渲染；协议异常清掉受管副本，退回内置兜底，不保留跨账号旧实验内容。
- App 订单权威快照只对 `paid/provisioning/activated` 服务端订单提交 orderNo；assignment 加载后主动复读一次订单快照，消除首页文案与启动期订单并发加载造成的漏归因；后端再次校验用户归属及 paid/completed 事实，并用唯一转换记录幂等写入 A4。

### PCFULL-138：文案换版缺少并发 CAS（P1）

修复：

- 草稿和发布请求增加 `expectedRevision`；回滚/下架同时增加当前 `expectedVersion + expectedRevision`。
- 后端在事务内锁定 `nx_content_copy` 后先比较快照；缺失、revision 不一致或当前版本不一致统一 `409 COPY_REVISION_CONFLICT`。
- 冲突发生在版本、i18n、审计写入前；运营员必须刷新后重新确认，不允许静默覆盖。

### PCFULL-139：框架参数并发覆盖与理由边界（P1）

修复：

- PC 携页面所见 `expectedValue`。
- 后端事务内对 framework 行 `FOR UPDATE`，先比较旧值；不一致返回 `409 COPY_FRAMEWORK_VALUE_CONFLICT`。
- 理由统一为 8–200 字；同值提交仍拒绝，成功后才更新与审计。

## 技术与墨菲复审

| 检查项 | 修复后结论 | 证据 |
|---|---|---|
| 位置无发布文案 | 失败关闭 | 404，不生成 assignment |
| 同一位置多个发布文案 | 失败关闭 | 409 ambiguous，不按时间猜值 |
| 三语缺失/半个实验 assignment | App 协议失败关闭 | strict parser 测试 |
| 切换账号/退出 | 清空受管副本与 assignment | `clearLocalAccountSession → useContentCopy().clear()` |
| 重复订单回读 | 幂等 | App 去重 orderNo，后端 conversion 唯一写 |
| 客户端伪造转化 | 不计入 | 后端核验 order.user_id 与支付/完成状态 |
| 草稿/发布陈旧 revision | 409 | 后端锁行后 CAS |
| 回滚/下架陈旧版本或 revision | 409 | 双快照 CAS |
| 框架参数陈旧值 | 409 | framework 行锁 + expectedValue |
| Idempotency-Key | 保持原语义 | 同键重放仍由服务端幂等层返回原结果 |
| 权限 | 保持原 RBAC | I1 文案与实验分别由 `content_i1_write`、`content_i1_experiment_manage` 控制 |
| 旧运行态证据 | 未冒充 | 新接口/App/CAS 均列入统一部署后补验 |

## 统一部署后的必跑探针

1. 以真实普通用户打开 App/H5 首页，确认 `home.conversion-banner` 的 `data-copy-key/version/experiment-id` 与 I1 当前发布文案/实验一致；切换中/英/越语言后正文分别来自同一服务端版本。
2. I1 创建两变体实验并启动；同一用户刷新、退出重登、换设备仍保持同一 assignment，曝光只首记一次；另一用户稳定进入其服务端分桶。
3. 为已分组用户生成真实订单并由服务端推进到 paid/activated；App 回读后 conversion 只增加一次，伪造他人 orderNo、未支付 orderNo、重复提交均不污染统计；核对 A4 `content.variant_exposed/converted`。
4. 两个运营员同时打开 I1：A 先发布/回滚/下架/改框架，B 用旧页面提交必须分别收到 `COPY_REVISION_CONFLICT` 或 `COPY_FRAMEWORK_VALUE_CONFLICT`，刷新后重新确认才可成功；核对失败路径无 i18n/审计/版本副作用。
