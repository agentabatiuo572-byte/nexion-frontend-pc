## 修复闭环

### A4 schema 与 outbox

- 新增 `scripts/migrations/20260727_d4_wallet_ledger_event_schema.sql`。
- 注册 `wallet.ledger_posted` 为 ACTIVE、服务端权威、100% 采样，revision 110。
- 注册 8 个 canonical snake_case 字段：`user_id`、`biz_type`、`asset`、`direction`、`amount`、`balance_after`、`biz_no`、`status`。
- 迁移已幂等执行到本地 `nexion` 数据库；只读核对显示 schema ACTIVE、8 个字段全部 `required_field=1` 且 `is_deleted=0`。全局 schema revision 原为 274，`GREATEST` 规则未造成降级。
- 新增迁移契约测试和 `EventOutboxService` 的 canonical payload 测试。

### 历史 Running Balance

- 后端新增 `reconciliationScope`：
  - `CURRENT_WALLET`：时间区间覆盖当前末端，核对最新已结算账本与当前钱包；
  - `HISTORICAL_RANGE`：历史截止区间只检查区间内连续性，不读取当前钱包做假核对。
- 历史范围的 `reconciliation` 明确返回 `null`，并返回 `reconciliationNote`；`sources` 只声明 `nx_wallet_ledger`。
- PC 客户端严格校验 scope：当前范围必须有 USDT/NEX 差额，历史范围必须为 `null`，不符合即 fail-closed。
- PC 页面在历史范围显示“历史截止区间……不使用当前钱包核对”，并隐藏钱包差额卡。
- PENDING 等未结算流水继续显式标为 `UNSETTLED`，不参与连续性与钱包核对。

### A2 对象映射

- 新增纯函数 `resolveA2AuditObject()`。
- `detail.obj/detail.resource` 仍具有最高优先级；否则把 `resourceType` 与 `resourceId` 合并为可筛选文本，例如 `D4_BILLS · all`。
- 因此服务端对象筛选命中 `resourceType` 后，PC 二次过滤不会再把真实 D4 审计隐藏，同时仍可按 `resourceId` 搜索。

### 幂等与调用链

- 账本写入先按数据库唯一键加锁并检查既有 fingerprint；精确重放不重算后续余额。
- 冲突插入捕获 `DuplicateKeyException` 后回读并校验 fingerprint，冲突方不发布 outbox。
- 只有真实插入 1 行时发布 `wallet.ledger_posted`，D4 consumer 才确认投递完成。
- 用户/状态/时间参数已由实际 BFF 对应的 `OpsBillsController` 透传至服务层。
