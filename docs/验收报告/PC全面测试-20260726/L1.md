## 3. 技术调用链验收

```text
App 注册/推荐关系/换机结账
  -> A4 权威事件注册表与 outbox
  -> B3 L1 读模型
  -> PC overview / drilldown / trend / export

checkout.completed
  -> F2 L1-L7 网络佣金 + D4 台账
  -> commission.paid
  -> L1 #7 / L4 / F5
```

复核结论：

- 注册统一发布 `auth.register_completed`，存在 sponsor 时同事务发布 `referral.bound`。
- 已支付换机同事务发布 `checkout.completed` 和 `device.purchase_completed`。
- F2 每笔网络佣金与台账同事务发布 `commission.paid`；事件 actor 是佣金接收人，并附 source/layer/order 归因。
- L1 读侧按分母事件锚定，只接受同 actor、发生在锚点之后的分子事件；Day7 用“成熟日落在观察窗”选 cohort。
- 事件按 `event_id` 去重；空 actor、坏时间、非法 latency/quantity 失败关闭，不静默丢弃并继续出数。
- 当前、上期和六点趋势使用同一算法；趋势缺数时不再挤掉空点造成标签错位。
- 自定义时间窗由服务端严格校验，按中国业务时区计算；非法范围不回退到 7d。
- PC 严格校验恰好 #1–#8、顺序、可用态、数值范围、定义、分子/分母和趋势对齐。
- 下钻和趋势响应会真实覆盖明细与曲线；异常响应不覆盖上次可信数据。
- 刷新失败保留上次已校验快照，显示陈旧告警且不提前切换时间窗。

## 6. 墨菲定律对抗复审

- 少一个 KPI、顺序错、非法值、可用态和值矛盾：整页失败关闭。
- 重复投递：`event_id` 去重，不放大 Genesis 或转化率。
- 分子先于分母：不计入转化。
- Day7 注册发生在窗口前：只要成熟日落入窗口即可进入分母。
- 过滤维度在后续事件改变：仍以分母锚点维度决定归属。
- 下钻 200 但内容畸形：保留概览，不用假成功覆盖。
- 刷新 503：保留上次可信快照、显示陈旧、不切换筛选。
- 无分母：返回不可计算，不展示 0%。
- 重复点击/重登：只读查询无副作用；模块表面刷新/重登已通过。
- 权限与 401/403：统一认证门禁和 BFF 错误出口存在；新部署后仍需用受限账号补做 L1 专项拒绝证据。
