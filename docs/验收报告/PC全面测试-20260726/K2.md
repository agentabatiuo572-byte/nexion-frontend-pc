## 三、缺陷修复闭环

### 3.1 PCFULL-190：处置码单源

后端只保存四个 canonical code，H8/K4/F4 继续按闭集消费；PC 使用显式映射显示中文。未知处置值不猜成任意业务动作，只显示中性“已处置”。

迁移 `20260727_k2_runtime_detection_closure.sql` 幂等归一化历史中文值。动作审计仍保留前后快照、理由、操作者、版本和幂等键，展示翻译不改持久事实。

### 3.2 PCFULL-191：运行态检测所有权

新增 `K2DetectionScheduler`：

- 默认初始延迟 10 秒、固定延迟 60 秒。
- 在服务端事务中调用唯一 `refreshK2AuthoritativeProjection()`。
- E3、H2、H8 和 F4 使用同一刷新入口。
- overview 可调用同一幂等方法以缩短运营可见延迟，但不再是唯一触发器。
- 调度失败记录错误且不伪造空结果；下一轮可恢复。

### 3.3 PCFULL-192：H8/F4 真实生产者

新人礼：

- 只读取 `nx_referral_reward_settlement.status=SETTLED` 的真实结算。
- 用 K1 `nodes_json` 的 canonical userNo 归入实体簇。
- 同簇结算数达到服务端参数才生成 `K2-GIFT-C{clusterHash}`。
- 未处置派生行在事实消失时退役；已处置历史不被检测器覆盖。

排行榜：

- 新表 `nx_risk_k2_leaderboard_snapshot` 按周、五分钟桶、用户唯一。
- 快照保存累计有效返佣和真实直推数。
- 两个最近桶的正增量形成样本；已被 K2 标记的账号先排除，再计算中位数基线。
- 服务端按 `>5x` 或配置的运算符/倍率判定；没有两个时间桶时保持空态，不从单点累计值猜速度。
- K2 只产 `risk.leaderboard_velocity_flagged`，F4 取消资格仍由 F4 权限和状态机执行。

### 3.4 PCFULL-193：H2 实体级循环

检测顺序改为：

1. 读取 A4 registry 已登记、`analytics_event=1`、`schema_registered=1`、`is_server_authoritative=1` 的 `trial.started`。
2. 校验 payload 中 `user_id` 为正整数且用户存在。
3. 用无损 canonical userNo 解析当前 K1 簇。
4. 按 `cluster_id` 聚合；无簇用户才使用 `USER:{id}`。
5. 达阈值后生成稳定簇行 `K2-H2-C{SHA256(clusterId)[0..40]}`。
6. 信号投影覆盖簇内每个真实用户，不只覆盖代表用户。

信号号以 `rowId + userId` 为稳定键，不把不断增长的循环次数放进唯一键，避免调度器每次刷新累积重复活动信号。

### 3.5 PCFULL-194：高位 ID 无损编码

K1/K2/K4 风险链及其 H8/F4/D2 消费路径统一改为：

```sql
CONCAT('U', LPAD(id, GREATEST(8, CHAR_LENGTH(CAST(id AS CHAR))), '0'))
```

该表达式只在不足八位时补零，超过八位时保留全部数字。修复范围包括：

- K1 节点生产和簇成员解析。
- K2 E3/H2/H8/F4 行、subject 和信号解析。
- K4 分数用户初始化、读取、重算、KYC 关联。
- H8 奖励风险簇消费。
- F4 排行榜用户投影。
- D2 提现队列与 App 提现的 K4 userNo 关联。
- K4 初始化和 D2 路由迁移。

全仓扫描合同会输出所有仍使用固定八位截断表达式的文件和行号。当前风险链命中为 0，但其他域仍有 50 处，因此 PCFULL-194 尚不能关闭。

## 六、权限、幂等、CAS、失败关闭与恢复

- 读权限和四类写权限分别由 PC 显示边界、Controller 和 Service 双层约束。
- 标记套利、拦截新人礼和标记刷榜是直接预防动作；K1 簇冻结仍走 A2 maker/checker。
- 行动作和参数写必须带理由、当前 version 和 Idempotency-Key。
- 同键同载荷返回原结果；同键异载荷 409；陈旧 version 409。
- 读接口 500/503 时清空 K2 旧投影并隐藏写入口。
- 写结果未知时保留表单和同一命令键，不换键盲重试。
- 刷新或重新登录只能从服务端恢复处置、参数和版本，不能使用浏览器本地状态推进。
- 调度器重复运行不重复活动信号；软删除信号在同一权威事实重新出现时可安全重激活。

## 七、墨菲定律审查

- 管理员连续数天不打开 K2：调度器仍产事实和信号。
- H2 在三个账号间轮换两次：按 K1 实体聚合，不按单账号漏检。
- K1 节点是 11 位 ID：不截断、不碰撞、不串到其他用户。
- K1 簇同时处于历史 released 和当前 detected：选择当前活动簇；统一终验必须覆盖成员迁移。
- H8 重放同一 settlement：唯一约束和 K2 聚合都不重复计数。
- 排行榜只有一个快照桶：不计算伪速度。
- 样本含已标记巨额账号：先排除再算中位数，避免攻击者抬高基线。
- 全体增量为 0：保持空态，不除零或把 0 基线当异常。
- 调度在行处置同时发生：已处置行不被退休/重建覆盖，version/CAS 仍保护人工动作。
- 权威行短暂消失后恢复：旧调度信号退休，同稳定键重激活且不重复。
- outbox 发送失败：业务事实和 outbox 同一事务，不能只留下信号无事件。
- F4 看到 flagged：只展示风险命中，不擅自写 disqualified。
- H8 看到 gift_blocked/cluster_frozen：先阻断资金副作用，再返回可解释原因。
- overview 返回畸形 200：PC 合同必须失败关闭，不能补默认行开放写入口。
- 全仓其他域继续产生截断 userNo：PCFULL-194 全仓合同保持红灯，禁止只宣布 K 域局部通过。
