## 2. 第一性原理与域内外调用链

I3 的最小闭环不是“PC 能显示 Campaign”，而是：

```text
PC 草稿/受众/排期/CAP
  → 后端权限、理由、幂等、CAS、状态机
  → MySQL Campaign/CAP/用户通知事实
  → retention 与逐用户送达
  → App 分页读取、已读、CTA
  → A2 审批/审计 + A4 delivered/read/action
  → 刷新、重登、未知结果重试仍回到同一事实
```

按奥卡姆剃刀保留一个服务端通知账本、一个 CAP 事实和一个 canonical CTA route；按贝叶斯风险优先审查“静态页面通过但用户端丢通知”“同键幂等但不同键陈旧覆盖”“网络超时后重复动作”三类高概率故障。墨菲审查结论如下。

| 检查面 | 结论 | 证据/判断 |
|---|---|---|
| Campaign 状态机 | 源码通过 | draft 才能编辑/删除/调度；scheduled 才能取消/发送；claim、revision CAS、防重 bizNo 已存在 |
| 草稿输入 | 修复通过 | create/edit 均限制名称/标题 160、正文 4000；JSON 正文、三语占位符、受众、预算、CTA 均失败关闭 |
| CAP/retention | 修复通过 | expectedCap + SQL 原子 CAS；critical locked；成功后同事务 retention；low 标签可正确抽取 30 |
| 多运营员 | 修复通过、待运行态 | Campaign revision 原有 CAS；CAP 新增 CAS；不同幂等键也不能陈旧覆盖 |

## 4. 修复内容

PC：

- CAP 表单从装饰标签提取首个数量，不再把 TTL 数字拼入容量。
- A2 `i3_cap_adjust` 命令固化 `expectedCap`，直连接口也要求 expectedCap。
- 通用数字确认窗拒绝指数记法，避免 PC 可提交、后端批准回放才失败。
- CAP A2 提案在弹窗内 await 完成，并按命令指纹保留稳定 key；未知结果不关闭弹窗、不生成第二张票。
- 增加 I3 专用首次用户/错误恢复 Playwright 和跨三仓合同测试。

后端：

- `NotificationCapUpdateRequest` 增加 expectedCap。
- `NotificationCapRuleMapper` 用 `tier + expected cap + unlocked + active` 单条 SQL compare-and-set。
- stale 或竞态统一返回 `409 NOTIFICATION_CAP_STALE_VERSION`，retention 只在 CAS 成功后同事务执行。
- A2 回放透传 expectedCap。
- 草稿编辑补齐名称、三语标题、三语正文长度边界。
- 已读事实锁定后更新 0 行立即抛错回滚，禁止把未发生的写入返回为成功。
- CTA `INSERT IGNORE` 未写入时二次读取幂等回执；只有用户、通知、动作和 canonical route 全部一致才视作重放，缺失或冲突均失败关闭。
- CTA 在锁定可清理的通知事实前先核对长期幂等回执；通知已被 retention/clear-read 删除后仍可用同 key 恢复原 canonical route。
- 新增 stale CAP、超长草稿、A2 expectedCap 与控制器合同测试。
- 新增已读行数不一致、CTA 竞态同回执、竞态冲突与回执缺失测试。

App：

- 通知 store 保存 `nextCursor`，支持加载更多并保留前页；拒绝跨页重复 ID 和不前进 cursor。
- 通知页、全局抽屉明确显示 loading/error/retry/empty，失败不再伪装空通知。
- mark-read 失败保持未读事实且停止展开/跳转。
- CTA 动作回执核对 notificationId/action，只导航服务端 canonical route。
- CTA 未知结果复用稳定 key；成功后才清理。
- 三语补齐加载、失败、重试和加载更多文案。

## 6. 依赖模块验收

- I2：Nova 的通道 gate/template/cooldown 决定上游是否生成通知；I3 负责通用账本、保留与 Campaign，不允许绕过 I2 gate 伪造 Nova。
- I5/J4：风险披露重确认和应急通知走 critical；critical CAP 永不开放调整，执行权限继续提升到合规/超管。
- A2：CAP 是高敏参数提案；expectedCap 在提案时固化，批准回放时必须再次 CAS。
- A4/L1/B3：delivered/read/action 是真实漏斗事实；CTA 回执错配、重复和失败都不能计数。
- H1：Campaign 受众使用权威当前阶段；阶段不可用或受众为零时失败关闭。
- App：通知页和抽屉只是服务器账本的显示窗口，不保留 remote 本地事实或客户端导航真值。
