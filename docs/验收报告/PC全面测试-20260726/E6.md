## 第一性原理闭环

E6 的目标不是“后台能保存几个数字”，而是让同一份服务端配置安全、确定地影响用户端算力入口和后续收益计算，同时保持资金红线、设备真实状态和历史结算不可被绕过。

最小可信链路为：

```text
PC 可见入口
→ 结构化输入、权限、理由与 A2 maker-checker
→ 完整候选快照校验
→ B1 放大方向红线门禁
→ 幂等 + A2 目标锁 + 配置行锁
→ nx_config_item:E.compute.*
→ A2 before/after 版本事实 + A4 outbox
→ /api/config/platform
→ App 启动/前台 60 秒刷新
→ 入口、显卡映射、在线系数与收益展示
→ 刷新/重登/异常恢复后仍以服务端为准
```

按奥卡姆剃刀，不在 App 再维护一套“生产默认值”，而是让 remote 模式只读一个公共服务端投影。按贝叶斯更新，运行态接口返回 `入口=true、0.6、4h`，而代码证据显示 App 仍使用 `入口=false、0.6、2h` 后，“可能漂移”被提升为已证实 P0。按墨菲定律，假设运营会输入单字段合法但整体矛盾的数据、重复点击、并发审批、网络结果未知，并假设 B1 正处于不可用或低于红线状态；因此保护必须放在事务内完整候选快照和服务端红线门禁，不能依赖前端提示。

## 修复设计

### App 只读服务端权威配置

- 新增 `platform-config-api.ts`，只允许读取 `/api/config/platform`。
- 精确校验 `computeShareEnabled`、两项在线系数、三项收益估算、G1–G6、固定 `keyword1..6`、下载配置及公共/完整投影镜像一致性。
- remote 模式初始状态失败关闭：入口隐藏、显卡配置清空、`syncFailed=true`。
- App 启动和回到前台时刷新；健康结果 60 秒内复用，同一时刻只发一个请求。
- 失败后清除可信状态、隐藏入口并阻止依赖配置的本地收益循环；下一次可见刷新成功后恢复。
- mock 模式仍保留显式本地演示能力，不与 remote 生产事实混用。

### 服务端完整候选快照

- `ComputeConfigRegistry` 新增稳定顺序的全部参数键和唯一默认值查询。
- 单参数和批量写在同一事务内按稳定顺序读取并锁定完整配置，避免并发交叉写产生中间态。
- 缺失或单字段非法存量值使用与只读投影一致的注册表默认值；候选值仍必须通过严格校验。
- G1–G6 TOPS 必须严格递增。
- 所有非空显卡识别词在六档中必须大小写无关唯一。
- 批量写完整校验后才落表；任一失败时全部不写。

### B1 放大方向失败关闭

以下方向被定义为放大未来资金流出：

- `computeShareEnabled: off → on`
- `h5BaseFactor` 增加
- `continuityFullHours` 减少
- `topsBaseline` 减少
- `dailyUsdtPerBaseline` 增加
- `nexPerUsdt` 增加
- 任一显卡档位 TOPS 增加

服务端在锁定旧值后判断实际方向。若 B1 覆盖快照缺失、不可靠、字段为空或低于红线，统一返回 `COVERAGE_BELOW_REDLINE` 并零写入。关闭入口、降低 H5/收益、增加满额时长等止损和回滚方向仍可执行。

### 版本、回滚与生效边界

- 每次批准记录参数键、before、after、理由、可信操作人、幂等键和时间。
- A2 操作单与 A4 事件构成不可变版本链；旧记录不能覆盖或删除。
- 回滚操作不是直接改历史行：从 A2 找到目标版本的 before 值，回到 E6 重新提交理由和审批；回滚本身生成新版本。
- 同一幂等键重复提交不产生第二个版本。
- A2 批准写入后立即成为服务端当前版本，不等待 H1 阶段/月度切换。
- App/H5 最迟在下一次 60 秒刷新后读取新值；历史已结算记录不回算。

| 维度 | 工程结论 | 统一部署后必验 |
|---|---|---|
| 读取 | 管理聚合接口受 E6 读权限；公共端点只暴露用户端所需投影 | 匿名管理读 401；公共端点不泄露管理操作与审计信息 |
| 普通写 | `device_e6_write` | 只读角色按钮不可见且直调 403 |

| CAS/并发 | A2 目标锁 + 固定顺序配置行锁 + 事务候选快照 | 两个并发提案/写入不能丢更新、倒序或产生半批次 |

| 刷新重登 | PC 重读服务端；App 60 秒刷新 | 成功持久、失败不回退旧 mock、重登不串账号缓存 |
| A4 | 规范事件已登记 ACTIVE | 核对 schema、属性、outbox PUBLISHED、consumer SUCCESS |

## 域内外调用链

| 交界 | 不变量 | 最终运行态断言 |
|---|---|---|
| E1 → E6 | E1 目录定义真实 SKU/设备能力，E6 不能伪造不存在的设备 | 改显卡映射不新增 SKU、不改 E1 上架/阶段门 |
| E2 → E6 | E2 minVRAM/任务门槛与 E6 算力映射共同决定资格 | 临界 VRAM/TOPS 命中唯一档位；E6 不能绕过 E2 停派 |
| E3 → E6 | E3 生命周期/容量衰减优先于 E6 展示系数 | 报废、回收或衰减设备不能被 E6 调参恢复历史算力 |
| E5 → E6 | E5 设备/DC 真实运行状态是可用性事实 | E5 暂停后 E6 开入口也不能继续派单或伪造在线 |
| H1 → E6 | H1 控制阶段/月度节奏，E6 是全局当前配置 | E6 写入不等待阶段切换，也不能修改 H1 当前阶段 |
| E6 → B1/D | 放大收益会增加未来负债/兑付压力 | 低红线或不可靠覆盖快照时服务端拒绝 |
| E6 → A2/A4 | 每个有效版本可追溯、可安全回滚 | before/after/理由/操作者/幂等键完整，事件可消费 |
| E6 → App | 用户端从公共投影读取同一权威值 | PC 改动后 App 前台刷新同步；503/畸形 200 失败关闭 |

## 统一部署后锁定用例

### E6-R01 入口与会话

1. 新浏览器上下文从登录页以可见表单登录。
2. 从侧栏进入 E6。
3. 核对开关、系数、收益参数、六档显卡和下载配置来自真实接口。
4. 刷新、退出、重登并再次进入。
5. 不得出现 JavaScript 未处理异常、5xx 或旧缓存伪成功。

### E6-R02 权限与 maker-checker

1. 只读角色可查看，所有写按钮不可见，直调写接口 403。
2. 仅有 `device_e6_flag_toggle` 的角色只能提入口开关。
3. maker 发起系数变更，maker 自批失败。
4. checker 批准后写入生效。
5. 绕过 A2 直接调用单写和批量写均返回 `A2_CONFIRMATION_REQUIRED`。

### E6-R03 结构化校验

1. 分别提交空标签、零/负数、H5 大于 1、非 HTTPS、超长文案。
2. 提交 G3 TOPS 小于等于 G2。
3. 提交跨档大小写不同的重复关键词。
4. 每次均返回精确错误，数据库、审计和 outbox 零副作用。
5. 批量请求一项非法时全部不写。

### E6-R04 B1 红线

1. 构造可靠且 `99/100` 的 B1 快照。
2. 依次尝试开入口、提高 H5、缩短满额、提高基准日产/NEX/TOPS、降低 TOPS 基准。
3. 全部返回 `COVERAGE_BELOW_REDLINE`。
4. 降低 H5、延长满额、关闭入口等收紧方向成功。
5. B1 不可用、超时、缺字段时同样失败关闭。

### E6-R05 幂等、并发与结果未知

1. 同一 Idempotency-Key/同 payload 连续双击，只有一次版本、一次审计和一次 outbox。
2. 同键不同 payload 冲突关闭。
3. 两个操作者并发修改同一参数，不能丢更新。
4. 单写和批量写并发时，最终快照仍满足 TOPS 递增和关键词唯一。
5. 响应返回前断连时显示结果未知，保留原键，先 GET 权威值再决定重放。

### E6-R06 版本与回滚

1. 通过 E6 页面完成一次合法变更。
2. 从“查看 E6 版本记录”进入 A2，找到 before/after、理由、操作者、幂等键和时间。
3. 复制 before 值回到 E6，重新提交回滚理由并由 checker 执行。
4. 旧版本保持不可变，回滚生成新版本。
5. 刷新/重登后值仍是回滚结果。

### E6-R07 App 传播与失败关闭

1. remote App 登录真实账号，记录入口、在线系数、显卡映射和收益展示。
2. PC 完成合法 E6 变更并批准。
3. App 回到前台，最迟 60 秒内读取新值。
4. 对 `/api/config/platform` 注入 503、超时、缺档、TOPS 倒序、重复关键词、镜像不一致和非法 URL。
5. App 必须隐藏入口、标记配置同步失败、停止依赖配置的本地收益循环并提供恢复路径，不能回退 mock。
6. 恢复接口后再次前台刷新，状态恢复且不重复启动循环。

### E6-R08 跨域不变量

1. 分别核对 E1 SKU、E2 任务、E3 生命周期和 E5 设备/DC 状态。
2. 修改 E6 后，这些域的权威状态不得被覆盖。
3. E5 暂停、E2 停派、E3 报废时，E6 开入口不能绕过。
4. H1 阶段不因 E6 变更而改变；E6 也不等待 H1 才生效。
5. 历史已结算收益和历史设备运行快照不得被重算。
