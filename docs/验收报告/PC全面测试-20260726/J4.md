## 二、第一性原理与最小闭环

J4 的最小事实不是“页面有一个执行按钮”，而是：

> 一个已经版本化并演练过的应急剧本，只能由 maker 提案、不同 checker 批准后执行；每一步必须进入目标域自己的权限、幂等、CAS、审计和真实副作用边界；中途失败、并发、超时、取消、刷新或重登都不能把未知结果写成成功，也不能重复副作用。

奥卡姆剃刀下，本轮没有在 J4 复制 C2/K1/I5 业务 SQL，而是增加唯一 `J4DomainActionGateway`，让目标域继续持有业务规则。J2 和 J1 同样调用既有服务入口。贝叶斯更新中，“旧 V3 J1/I3 浏览器走通”只能提高载体健康概率，不能证明尚未接入的四个域或 A2/A4；直接对 action catalog、执行循环和回放门检查后，缺口升级为 P0。墨菲审查默认双击、旧客户端、maker 自批、陈旧版本、同时执行、响应丢失、步骤超时、进程中断、审计失败、取消竞争和重登都会发生。

闭环不变量：

1. 未经 A2 replay context，J4 聚合根在任何幂等缓存、执行记录和目标域副作用之前统一返回 409。
2. 剧本动作只允许显式闭集及精确目标参数，空目标、错域、错 ref、重复 ref、恢复方向均失败关闭。
3. 演练只验证，不改变生产状态；编辑后旧演练失效。
4. 同剧本版本用 CAS，执行用行锁、业务对象锁和幂等键；同 key 异载荷拒绝。
5. 跨域执行前向只进，不伪装跨域事务；已完成止血动作保留，失败后续步骤跳过。
6. 取消是合作式边界，不回滚已完成动作；恢复核对只处理租约过期的未知结果，不等于续跑。
7. 回滚只恢复仍由本 execution 持有的 J1 可逆动作；I3、I5 等不可逆事实不伪装撤回。
8. A2 拒绝审计、J4 逐步追溯和 A4 事件都由服务端权威生成。

## 三、域内与域外调用链

| J4 动作 | 精确引用 | 真实目标域边界 | 下游事实 |
|---|---|---|---|
| J1 提现关停 | `killswitch:withdraw` | `OpsKillSwitchService.changeFromJ4Execution` | 禁止 D2 新提现，保存 execution ownership token |
| J1 Genesis 关停 | `killswitch:genesis` | 同一 J1 原子边界 | 关停 G4/用户端相关入口，可按所有权恢复 |
| J2 地域封锁 | `geo-block:{ISO2}` | `emergencyGeoBlock` | 国家进入可信边缘封锁；J2 审计/outbox |
| C2 账户冻结 | `user-freeze:{positive userId}` | `OpsUserService.updateStatus` | 账户冻结、会话吊销、D2 待处理提现冻结 |
| K1 账户簇冻结 | `cluster-freeze:{clusterId}` | `OpsRiskService.updateMultiAccountClusterStatus` | K1 CAS；受影响用户和 D2 待提现联动冻结 |
| I3 应急通知 | `notify:{campaignNo}` | 既有应急 campaign dispatch | 真实通知计数，明确不可逆 |
| I5 披露发布 | `disclosure-publish:{jurisdiction}:{version}` | `OpsTrustDisclosureService.publishDisclosure` | 校验 draft、七章、revision/content hash 后发布 |
| A2 双人复核 | `j4_playbook_execute`，目标 `J/playbook/{code}` | A2 maker/checker、对象锁、回放上下文 | maker 不可自批；checker 权限重验 |
| A4 事件 | `admin.emergency_playbook_edited/executed` | transaction outbox + schema registry | 编辑版本和 completed/partial 终态可订阅 |

D2 不作为 J4 伪造的独立动作：提现关停由 J1 阻断新单，账户/簇冻结分别由 C2/K1 在其权威边界冻结待处理单。这样 D2 只有一个业务真源，不出现 J4 与资金域双写。

## 六、权限、幂等、CAS 与审计

- PC 同时要求 `emergency_j4_playbook_execute`、A2 提案权和剧本内全部目标域权限。
- 后端批准回放时由 `AuditReplayBusinessPermissionGuard` 重新校验 `emergency_j4_playbook_execute`，目标锁规范化为 `J/playbook/{code}`。
- maker 与 checker 由 A2 状态机分离；maker 自批不可用。
- PC 隐藏按钮不是安全边界；PCFULL-183 修复后，`executePlaybook` 聚合根先检查 replay context，旧客户端和直调都不能绕过。
- Idempotency-Key 同载荷只回放原执行；异载荷返回冲突；已有执行记录优先于进程内瞬时结果。
- 剧本编辑检查 version；K1/I5 等目标域继续检查自己的 version/revision/content hash。
- 同剧本执行用锁；执行恢复用 2 分钟租约；取消标记写入与进度更新不会互相覆盖。
- 所有命令拒绝都记录 `businessDataChanged=false`；审计启动失败时不进入首个目标域。
- completed 和 partial 都发布 `admin.emergency_playbook_executed`，不把 partial 冒充 completed。

## 八、缺陷修复明细

### PCFULL-180：跨域动作缺失

- V4 catalog 增加 J2/C2/K1/I5 参数化动作。
- 前后端双重校验 ISO2、正 userId、clusterId、jurisdiction:version。
- J1/J2 调用既有服务；C2/K1/I5 通过唯一 gateway 调用目标域。
- 目标域继续拥有权限、幂等、CAS、审计、会话和 D2 副作用。

### PCFULL-181：A4 治理事件缺失

- 新增 `20260727_j4_emergency_playbook_event_schema.sql`。
- 注册 revision 281/282 的 server-authoritative schema。
- 编辑事件携剧本、操作、操作者、理由和幂等键。
- 执行事件携 execution、outcome、触发依据和步骤统计。

### PCFULL-182：取消/未知结果不可处置

- 新增 cancel 与 resume HTTP 入口。
- cancel 采用原子请求标记和合作式步骤边界。
- resume 只核对租约超时 execution，未知结果失败关闭。
- PC 对 pending/running 分开展示“取消”和“恢复核对”；终态后才允许所有权回滚。

### PCFULL-183：A2 可绕过

- 在 `executePlaybook` 聚合根首部增加不可绕过 replay context 门。
- 门禁位于命令校验、幂等缓存、execution 创建和全部目标域调用之前。
- 增加“没有任何活动 A2 lock 仍拒绝直调”的单测。
- 跨仓合同锁定服务端 `J4_A2_CONFIRMATION_REQUIRED`，避免以后只依赖 PC 按钮。

### PCFULL-184：恢复路径缺 A4 终态

- 终态重放与 stale recovery 在返回前同时 ensure 最终审计和最终事件。
- 以 `EMERGENCY_PLAYBOOK + executionId + event name` 查询已有 outbox，存在则不重复发布。
- 缺失时从持久 execution 快照重建 completed/partial payload，保持与正常路径同一 schema。
