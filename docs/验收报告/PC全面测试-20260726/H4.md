## 技术 / 墨菲审查

### 已确认缺陷

1. **PCFULL-118（P0）App 活动/抽奖仍是假链。** remote 模式使用静态活动、localStorage、客户端随机数和本地钱包/账单，PC 状态完全不能传播。
2. **PCFULL-119（P1）活动奖励、状态和并发边界不完整。** 写入无 CAS；奖励展示与真实 asset 分叉；状态可回退；USDT 奖励未支持，资产切换和活动激活可绕过 B1。
3. **PCFULL-120（P1）活动 CMS 字段不足。** PC 缺时窗、地域、App href 和真实目标值，App 无法按同一服务端活动配置展示及执行。
4. **PCFULL-121（P1）转盘治理写的不是执行真值。** 档位 amount/voucher/stock 没有管理入口，概率/档位无奖池签名 CAS，护栏写另一数据源，cap 文本可编辑但运行时不消费。

### 对抗性检查结论

- 权限：App 状态及命令要求有效登录用户；PC 活动与转盘写继续使用 H4 专属 RBAC、J1 和审计守卫。
- 单一真源：App remote 只读取 `GET /api/events`；协议或网络失败时清空 canonical 投影，不回退静态活动。
- 账号隔离：切换账号会清空 canonical/pending 状态；旧账号晚到响应不能覆盖新账号。
- 幂等/未知结果：join、claim、spin 在结果未知时保留同一幂等键；先回读权威状态，不能换键重放制造双派奖。
- 活动 CAS：reward/status/featured 携 `expectedValue`；后端在 `H4_EVENT` durable mutex 事务内比较，陈旧页与同值失败关闭。
- 状态机：仅允许 upcoming→ongoing/ended、ongoing→ended；ended 为终态；离开 ongoing 自动清主推，不能复活历史活动。
- 主推唯一性：创建和变更均在 H4 互斥边界内检查；App 又拒绝同时存在两个进行中主推活动。
- B1：奖励金额上调、NEX→USDT、活动激活、真实奖概率上调、budget 上调和 kill 重新开启均由服务端做红线最终裁决。
- 奖池 CAS：签名覆盖 tier/reward/probability/real/kind/amount/voucher/stock；创建、编辑、删除和批量概率均锁 `H4_WHEEL` 后比较。
- 真派奖字段：PC 直接维护 `reward_amount`、`voucher_id`、`daily_stock`；服务端 RNG、库存、budget、kill 和 B1 消费相同字段。
- 护栏单源：budget/kill 写 `nx_growth_wheel_guard` 并做 expected-value CAS；历史 cap 只读，真实每档上限统一由 `dailyStock` 执行。
- 事务：活动领取和 spin 的状态、钱包/券、ledger、强审计及 outbox 在同一事务；中途任一失败不得留下半派奖。

## 修复清单

### PC

- 活动 reward/status/featured 写入补当前值 CAS；主推布尔值显式归一。
- 新建活动补 `targetValue`、geo、受限 `/pages/*` href、开始/结束时间。

- 护栏改用 H4 专属真实表端点；新建只允许 budget/kill，历史 cap 行显示为只读。
- 补 stale/no-change、非法状态推进、budget/cap 和真实奖分类的可理解错误文案。
- 新增 H4 owner 合同与 Playwright 走查脚本。

### 后端

- 新增 `GET /api/events` 登录用户投影，提供活动、用户状态、进度、时窗、地域、跳转和服务端时间。
- 活动 reward 同时更新资产与金额，claim 支持 NEX/USDT/BADGE 的真实原子派奖。
- 活动创建/修改使用 durable H4 mutex、CAS、同值拒绝、单向状态机、主推唯一性和方向化 B1。
- 奖池 Mapper/DTO/服务补齐真实 amount/voucher/stock；pool signature、锁和 CAS 覆盖所有执行字段。
- 新增 H4 wheel guard PATCH；budget 格式和范围严格校验，cap 禁止第二真源写入。
- `schema.sql` 与 `20260727_h4_event_app_canonical_closure.sql` 补 `cta_href`，新表定义补齐转盘真实字段。

### App

- 新增严格 `events-api.ts`：拒绝重复活动 code、多进行中主推、未知枚举、非法 href 和畸形命令响应。
- 活动 store remote 模式读取 canonical state，join/claim 只调真实 API；本地状态写仅保留 explicit mock。
- 活动页增加加载/错误/重试，remote 不再回退静态活动；跳转只接受服务端安全路径。
- 转盘 remote 使用服务端 spin 结果驱动动画、中奖卡和历史，不再客户端抽奖、扣票或修改本地钱包。
- 账号切换与未知结果均采用 generation/pending key 保护，避免跨账号晚到覆盖和双派奖。
