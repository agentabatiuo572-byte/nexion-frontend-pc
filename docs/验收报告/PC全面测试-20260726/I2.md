## 4. 本轮源码修复

PC：

- I 域写请求按 method/path/body 保留不确定结果幂等键，成功或确定性 4xx 才清理。
- 概率提交同时携页面所见 `expectedItems`。
- 模板只有草稿可编辑；发布/归档状态机由后端强校验。

后端：

- social 派发事务内将通知推进到 `DELIVERED`，并核对 insert/deliver/fact 数量。
- 逐用户产出通用 `notification.delivered` 与锁定 `nova.push_sent`。
- Nova CTA 动作成功且幂等落库后产出 `nova.push_clicked`。
- 新建/编辑通道不再接受客户端 CTR，始终由服务端事实决定。
- 通道、模板、概率、真实事件增加条件更新/行锁并发边界。
- 新增统一 `NovaBusinessRuntimeService`，九个非 social 通道共用一套服务端 producer/gate，不复制九份定时器。
- 九通道建立精确真实事件适配表：`welcome←auth.register_completed`、`market←market.curve_advanced`、`upgrade←device.upgrade_recommended`、`dailySummary←earnings.credited`、`tradein←tradein.eligible`、`eventClaim←event.reward_claimable`、`wrapped←nova.wrapped_ready`、`taskLockMonthly←quest.monthly_lock_ready`、`quest←grace/expired/weekly_refreshed`。
- 适配器只消费 allowlist 且 server-authoritative 的 A4 事实；无精确事实明确返回 `NO_REAL_FACT`，不拿 `tradein.completed`、`quest.completed` 等相邻事实制造推送。
- 新增 `(channel_key, source_event_id)` receipt 唯一栅栏；统一执行 H1 分档、tick、cooldown、单通道 kill、已发布模板、slot lease、App 通知入账与 `nova.push_sent`。

App：

- 新增严格 `/api/notifications` 协议层；错误响应、重复 ID、非法优先级/时间/未读数失败关闭。
- remote 模式禁止 localStorage/mock/timer/`Math.random` 生成通知。
- 启动、前台、下拉刷新、通知页和 Nova 浮标回读服务端账本。
- 服务端 Nova 通知按 notification id 去重进入会话；读、全读、清理和 CTA 调真实接口。
- CTA 的不确定结果保留同一幂等键，成功后才导航。
