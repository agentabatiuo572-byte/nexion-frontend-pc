## 4. 修复后调用链

```text
M4 可见 FAQ/SLA 快照(version/status)
  -> PC 固定 value + reason + Idempotency-Key
  -> backend 持久幂等请求哈希
  -> SQL expected status/version CAS
  -> 业务版本递增
  -> A2 recordRequired + A4 FAQ outbox（同事务）
  -> 返回后重读完整 overview
  -> M1 消费矩阵；M2 服务端派生 version/deadline/overdue
```

- 同 key 同载荷重放原结果；同 key 异载荷冲突；不同 key 的旧页面由 CAS 裁决。
- CAS 输家、理由越界、RBAC 拒绝、A2/A4 失败均不得显示成功，也不得留下部分写入。
- FAQ ID 始终按字符串处理；连续同毫秒创建仍以 UUID 后缀避免碰撞。

## 6. 墨菲定律复审

- HTTP 200 缺数组、重复 FAQ ID、缺一类 SLA、未知版本或坏日期：整块失败关闭，写按钮消失。
- 两名运营员从同一版本编辑/发布/删除：仅一人成功，另一人 409 后刷新；审计和 outbox 不产生输家事实。
- 首次提交已落库但响应丢失：保留原输入、基线和 key；重试只回放原结果。
- SLA 在 M4 编辑后，M1/M2 只在权威刷新后展示新矩阵；刷新失败不保留伪成功。
- M2 不使用浏览器时钟自行裁决逾期；详情缺规则/版本/deadline/overdue 任一字段整体失败关闭。
- A2 或 A4 schema/outbox 失败：事务回滚 FAQ 写入，页面不得先提示成功。
- 退出重登或浏览器刷新：FAQ/SLA 与版本全部来自后端，不从 localStorage 复活。
- 低权限角色直调 API：`service_m4_write` 仍由服务端拒绝，页面隐藏不作为唯一门禁。
