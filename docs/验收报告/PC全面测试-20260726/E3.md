## 第一性原理闭环

E3 的最小业务真相不是“后台有一张曲线和几排调整按钮”，而是下面一条可闭合、可回滚、可追踪的单源链：

`nx_compute_e3_config + 已结算产出 + 旧机真实实付价 + E1 在售目标价 → 服务端 quote → 钱包补差 → E4 订单 → 旧机回收 + 新机交付 → D4 账本 + A2 审计 + A4 tradein.completed`

按奥卡姆剃刀，App remote 模式不再复制一套换新公式或本地设备主数据，而是消费后端已有的 fleet/config/quote/submit；显式 mock 模式仍保留演示数据，但不能渗入生产远端分支。按贝叶斯更新，代码证据同时出现 `@/mock/tradein-config`、localStorage 成功写和后端现成真实接口后，“PC 改了但用户下单仍是假结果”从风险假设升级为 P0 已证实缺陷。

资金和状态不变量如下：

1. 折抵只减少本次新机应付，不进入可提现钱包。
2. quote 只作展示；submit 必须锁定事实并重新计算，不能信客户端金额。
3. 旧机回收、钱包扣款、D4 账本、订单、新机交付、置换申请、A4 与 required 审计必须同事务；任一步失败整体回滚。
4. 同一用户和幂等键精确重放返回同一结果；同键不同载荷冲突关闭。
5. 分档按左闭右开 `[0,cut1)`、`[cut1,cut2)`；精确等于界点进入下一档。
6. 读取失败、账号切换、过期响应、协议畸形或缺少 canonical device id 时失败关闭，不能回退旧账号缓存或本地假成功。

## 修复实现审查

### App 设备与换新单源

- `src/api/device-e3-api.ts` 对 fleet、config、quote、submit 做严格协议解析；重复设备 ID、缺字段、非法金额、`discountToWallet=true`、应付不守恒均拒绝。
- `src/store/e3-canonical.ts` 按当前 JWT 用户维护权威快照；账号切换会清空，旧请求通过 revision/userId 双校验不能覆盖新账号。
- remote 设备页只展示 `/api/devices/earnings` 的 canonical device；真实数值 ID 独立保存为 `canonicalDeviceId`，不再拿本地字符串 ID 调后端。
- remote 置换必须先取得服务端 quote；确认后只保存 quote/幂等上下文，不预先改余额和设备。
- checkout 调 `/api/app/trade-in/submit` 完成原子置换；只有服务端返回 `COMPLETED` 后才刷新 canonical fleet。远端失败时保持原状态并允许使用同一提交上下文确认权威结果。
- 后端目前没有 USER 自助停用接口；App remote 停用明确失败关闭，不再用本地操作伪造 E5 成功。

### 服务端定价与原子事实

- 用户设备投影从已支付订单/设备价快照/商品价按优先级得到旧机真实实付价，只累计 `POSTED/SUCCESS/SETTLED/CREDITED/PAID` 的收益回执。
- quote/submit 按服务端旧机归属、ACTIVE、目标在售/库存、资格、严格更高价和钱包余额重新判断。
- submit 锁用户、旧机、目标商品和钱包；扣钱包、写 D4、减库存、写 E4 订单、回收旧机、交付新机、写置换申请/A4/audit 任一步冲突即抛错回滚。
- `discountToWallet=false` 是前后端双重守卫；零应付仍写金额为零的 D4 轨迹，但不执行无意义钱包扣款。

### PC 操作面、A2、B1、A4

- E3 缺少任一现行必需键时整面失败关闭并提供刷新，不能用 fallback 值让运营误调。
- 单值和多字段确认均拒绝 no-op；数字边界、阶梯严格递增/递减、理由和幂等由前后端共同校验。
- 正常运营调整进入 A2 操作确认/提案；服务端仍有活动对象锁、可信 operator、required 审计、outbox 和持久幂等。
- 放大流出方向由服务端 before/after 判断并二次检查 B1，不能只依赖按钮上的闪电图标。
- L4 真实数据面包含 E3 配置变更、置换申请和完成置换；D4 失败入口使用真实筛选链接。

## 墨菲定律对抗结果

已覆盖或在代码层确认关闭：

- 配置缺键/接口 503：整面失败关闭，不显示伪默认值。
- 精确等于 cut：进入下一左闭档，PC/App/报价/B1 一致。
- 旧机非本人、非 ACTIVE、缺实付价：quote/submit 拒绝。
- 目标同机、非在售、非更高价、无库存：拒绝且无业务写。
- 钱包不足：任何订单、回收和交付前失败。
- submit 时配置/价格/库存变化：锁后重算，不信旧 quote。
- 同键重放/异载荷：持久幂等或冲突关闭。
- 任一 DB 写入数量不是 1：抛错回滚，避免半完成。
- 账号切换与迟到响应：旧用户快照不能覆盖新用户。
- quote 返回折抵入钱包或金额不守恒：App 协议层拒绝。
- remote 后端停用能力不存在：明确失败，不落本地假状态。
- 旧 promo 控制仍可见但无真实消费者：已从现行操作面和手册退役。

统一部署后仍需真实故障注入验证 DB 事务回滚、幂等恢复、A4 consumer 和 App 请求结果未知场景，因此没有把源码复审冒充最终运行态复审。
