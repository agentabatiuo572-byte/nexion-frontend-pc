# 评审页后业务循环恢复修复复验

## 裁决

**H5/local-mock PASS；真实后端、原生真机、Janus 生产端到端 HOLD。**

## 根因闭环

1. 业务循环原先可被多个入口停止，却只在 App `onShow` 启动；H5 站内返回不会再次触发 `onShow`。
2. 第一版修复只证明 timer 恢复。墨菲复审发现 local-mock 仍请求 `/api/config/platform`，Vite 返回 200 HTML 后解析失败，使 `syncFailed=true`，结算实际早退。
3. 配置修复后，默认低速账号的设备收益和结算锚点会推进，但聚合值每 tick `toFixed(2)`，0.001 增量被逐次舍弃，30 秒可见金额不动。

最终实现：

- `ensureBusinessLoopsRunning()` / `stopBusinessLoops()` 作为统一启停出口；守卫持续重校验并幂等恢复。
- mock 配置只使用内存种子，600ms 后解除 `syncFailed`，不请求远程平台配置；remote 请求失败仍 fail-closed。
- 账户收益保留 0.001 精度，仅在累计跨过完整分时路由到余额桶；非法/负增量不能减少累计。
- 浏览器门改用默认低速账号，返回业务页后观察 30 秒，同时检查 timer、`configSyncFailed=false`、设备收益、聚合收益、`lastSettledAt` 与 `toFixed(2)` 可见金额。

## 证据

- 先红：配置假绿阶段 4 项失败；低速账号阶段两 fresh context 均 `247.83 → 247.83`。
- 修后首次用户两轮：可见 `$295.50 → $295.53`，raw `247.83 → 247.846`，设备 `0.04 → 0.056`，远程配置请求 0，console/pageerror/failed request 0。
- 墨菲两 fresh context：raw +0.015、device +0.015、anchor +30005ms、可见 `$247.83 → $247.84`。
- 官方业务 runtime 独立连续 3 次退出 0。
- 分币累计纯函数合同 3/3；结构门含 13 组 mutation red checks。
- 最终完整 `npm.cmd run verify` 退出 0。

## 回退/监控

- 回退只允许精确撤销本批配置分流、累计函数和门禁文件，不能覆盖混合工作树其他改动。
- 生产接管前需用真实后端权威收益替换 local-mock 结算，并监控配置同步失败率、收益锚点停滞和客户端/服务端聚合差异。
