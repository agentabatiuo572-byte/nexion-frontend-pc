# L2 实际试用事件漏斗 / hd-sync45

后端 5cb76001 对应 L2-BE-02 已交付“用已有真实事件替换起点”方案，不是新增曝光producer。原算法先每actor取trial.claim_sheet_shown，再按时间找started、redeemed，缺曝光导致已开始者也进不了链，且未按同一试用关联。新实际漏斗仅trial.started → trial.redeemed：TRIAL aggregate_id（H2 claimNo）+ payload.user_id关联，兑换必须严格晚于同actor同trial的开始；每trial取首次开始，各阶段再actor去重，多笔试用不重复计人，不能跨试用串起开始与兑换。主注册四步不变；开始数可能恢复非零，但小样本/关联缺失仍null，不能承诺一定增加。

BiReportMapper.selectL2EventFacts只读未删analytics_event=1、schema_registered=1、server_authoritative=1事件，event_ts >= 旧业务日开始减400天；沿旧时基+08，无新增上界。先由注册事件筛选cohort/phase/locale/ref的actor，再统计这些actor的试用；不是所有试用，也未额外强制试用在注册后。总试用actor/时间可识别覆盖缺失，或选中事件缺TRIAL关联ID，available=false、TRIAL_EVENT_LINKAGE_INCOMPLETE，人数和比例不可用；app.dau未接问题独立仍OPEN。

trialSteps保留三个旧位置：曝光占位n=null/available=false/includedInFunnel=false/EVENT_NOT_PRODUCED；后两行available/includedInFunnel=true，人数及arr按原少于5含0保护。quality.trialBasis给真实两步/同人同trial/逐阶段去重/400天/注册切片/曝光不可用；crossAnalysis.trial复用同一结果并给available/reason。PC在overview和drilldown未知输入边界一次校验，保留原raw合同，另供typed trialFunnel（只含真实两步），不按曝光换算，不把null补0。旧端无trialBasis不启用新事实。交叉原available/reason保留，不另造比例。

现屏幕仍TRIAL_SOURCE_READY=false，因文案/组成由视觉负责：l2-funnel.tsx的KPI问号、试用面板、交叉空态及l2-funnel-views.tsx的aria-label都称三步或曝光缺失导致不可统计。不能直接翻true使旧“三步每步晚于上步”说法对应新两步，也不能把无生产曝光当0。视觉需消费data.trialFunnel.available/steps，区分旧端缺合同、真实关联不完整、样本保护；crossOverride里trial.available亦需判断。typed事实已接入真实读入口；启用显示与新说明已由视觉接上（见文末「界面呈现」）。

升级后复验：真实同actor同claimNo开始/转购计入，两次试用只计一人；跨trial兑换不串联、同时刻不计；注册切片/400日边界与SQL比；缺user/时间/关联ID主试用不可用；0及1–4人保护null，足额人数和转化与cross一致，曝光始终null且排除。旧端无trialBasis保持旧屏幕。此轮未SQL/HTTP/业务写/浏览器验收。

## 界面呈现（hd-vis-be31）

- 「试用后购买比例」卡：新后端可用时值是后端给的 trial.redeemed 的 arr（不前端重算），下行「购买人数 ÷ 开始试用人数」；任一步小样本写「样本过小 · 少于 5 人，不显示」；关联不全（available=false）写「不可用 · 试用记录不全」，问号给 TRIAL_EVENT_LINKAGE_INCOMPLETE 的中文；旧后端没有 trialBasis 时写「来源未接上 · 试用人数还没接上」。
- 首购那一步下的「首购之前的试用」：两步「开始试用 → 试用后购买」，读屏名「试用两步」；问号写「购买要晚于同一笔试用的开始；看到领取弹窗这一步没有记录，不统计」。不可用时是警示提示框并给原因，旧后端是「数据来源还没接上」。不显示成 0。
- 渠道 × 语言选「试用后购买比例」：交叉结果自带 available=false 时写「试用人数暂不可用」和原因；旧后端写「数据来源还没接上」；可用时照原表格。
- 「这页怎么用」：「来源未接上」只剩日活；新增术语「试用两步」；补充页尾一句看到领取弹窗不统计。
