# BUG-504 运营后台逻辑修复

## H4 活动中心

- 创世抽奖在保存冲突后，按编辑表单的值判定自己改了哪些字段。选填语言整组存成英文副本时，在表单中视为空。金额按十进制值比较，报名和开奖时间按同一时刻比较，保留展示和提交的原值。合并时以服务端最新配置为底稿，只放回自己编辑过的字段，奖项按编号匹配。下次确认保存使用最新修订号。
- 冲突时选「按我填的提交」，逐项明细和覆盖摘要都显示将提交的实际内容。选填语言整组留空时，标题和奖名按英文回填。
- 促销草稿或有多语言字段的政策草稿取得成功回执后，如果当前版本已被后续操作修改，完成时提示「原操作已成功，当前版本已变化，请核对最新资料。」提交后读回及查询原结果共用这条判断。
- PC 新建内置活动保存为预告，后端把新记录的经济奖励设为零，确认时无需核验兑付覆盖率。打开活动或提高奖励时，按对应操作的合同执行。

## I5 风险披露

草稿保存回执已确认但详情读取失败时，查询原结果使用保留的原命令号和请求路径。后续编辑形成的新修订不影响原命令结果。只在原命令有明确结论时结束待确认记录，结案后重新读取当前内容。

## I7 课程与奖励

新建、编辑课程草稿及课程版本时须填写 10–50 UVT 的单课奖励。清空或填入超出范围的金额时，草稿保存会被拦下，编辑时的手机预览会提示有效范围。已存课程详情继续显示实际奖励。

## G2 兑换预计

| 概览字段 | 配置键 |
| --- | --- |
| `hours` | `queueEtaHours` |
| `copy` | `queueEtaCopy` |
| `copyZh` | `queueEtaCopyZh` |
| `copyVi` | `queueEtaCopyVi` |

后端接收 `value: ""` 以明确清空某一字段。数据层保存该字段和原命令号，恢复时沿用保存的请求体和命令号。省略值或传 `null` 会被后端拒绝。界面的清空入口和中越说法编辑另行交付。
