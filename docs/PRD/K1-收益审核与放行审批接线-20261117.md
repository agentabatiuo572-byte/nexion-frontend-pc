## 缺失合同及接线前置

必须向后端取得最终候选的 `K1RiskApproval.java`、两服务的 `approvalBefore/previewApproval/applyApproved` 和专项 PRD，或两份已成功建单的脱敏完整 HTTP 请求/响应。具体缺项：

- A09/A11 精确 `command.op`、`params.values` 的键名、类型和嵌套；`expectedVersion` 等旧态是否由客户端传入、如何绑定。
- `before` 是只由服务端读取绑定，还是客户端必须提交完整旧快照；不能将内部根字段 `makerAdminId/proposalReason` 当客户端字段。
- 最终 `action/obj/type/amplifies/sos/roleGate/sourceDomain` 取值，服务端怎样生成/覆盖 `beforeValue/afterValue` 及影响摘要。11 月 16 日批准了服务端摘要增量，不能直接把 11 月 12 日文字草案当最终协议。
- 建单时“旧值/版本已变”“已有待审批锁”的精确拒绝码、HTTP/业务码及回包；结果 JSON 中只有拒绝数值 409。
- A11 当前保护收益列表只投影 `amount`，未返回 `grossAmount/recoveredAmount/netAmount/sourceEnvironment/status`。候选如何提供完整、保精度的放行前事实需确认，不能从 `amount` 编出完整资金快照。
- A2 操作标签的索引需精确 `op`。已存在的业务审计名 `K1_RELEASE_PARAM_UPDATED` / `K1_EARNINGS_MANUALLY_RELEASED` 有中文，不能拿它们当提案命令名。
