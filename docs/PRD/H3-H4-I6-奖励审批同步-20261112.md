# H3、H4、I6 课程奖励审批同步

后端依据 `66ecdb47`，PC 范围为旧 H3/H4 页面及 `i6-i18n.tsx` 内课程区（权限仍名 I7）。本批仅接逻辑，不调整现有页面构成。

- H3 `weekly.champBonus` 仅展示文字，原 `quest-events/config` 直接保存；该例外不适用于实际奖励、倍率、任务增删启停。
- H4 旧活动奖励先 `POST /api/admin/growth/quest-events/events/{id}/reward/preview`，严格采用服务端 `approvalRequired`。只有未配置新规则、启用且仍在有效发奖窗口内的旧活动按资产分开比较：换资产时原同资产数量为 0，正新数量需要审批。同资产数量增加也沿同合同处理；其他合法分支保留直接 PATCH。
- 旧活动 A2：`command={domain:H,op:h4_legacy_event_reward_update,params:{values:{eventCode,value,expectedValue}}}`；`sourceDomain=H4`、`obj=eventCode`、`target={domain:H,type:h4_legacy_event,id:eventCode}`。
- 转盘 A2：`obj=ACTIVE_POOL`、`sourceDomain=H4`、`target={domain:H,type:h4_wheel_pool,id:ACTIVE_POOL}`；`params` 仅含 `values`。新建/修改携 `tierName,rewardName,probabilityPct,realOutflow,rewardKind,rewardAmount,voucherId,dailyStock,expectedSignature`，概率批改携 `probabilities,expectedSignature`，删除携 `tierName,expectedSignature`。概率及发放数量使用十进制字符串（后端不接受浮点 Double），库存及实际资金流出标记为整数。
- 转盘审批复核：后端 `before={wheelSignature,tiers}`，其中 `tiers` 为包含 `tier/reward/prob/real/kind/amount/voucherId/dailyStock` 的 JSON 字符串；`after` 为命令 `values`。A2 修改按 `tierName` 定位旧档并映射到请求字段；概率按全部档位逐项比较，新建无旧档，删除展示目标档从启用到删除。签名与原整池快照保留为核对证据，不参与配置删除差异；其他域解析保持原样。
- 新建奖项提交前必填中奖概率、实际发放数量、每日数量（不限时明确填 0），缺失指出对应字段，不以 0 兜底。规范化支持前导点/加号并保留输入数字；金额不经浮点转换后提交。编辑奖项、批量概率同样先校验再规范化。
- 放大判据：创建 UVT 总需审批，创建 USDT/代金券以四位存储概率大于 0 为准；改另一可兑换奖型且数量大于 0、同型数量增加、概率提高、有限库存变多/不限、UVT 库存收紧导致安慰奖提高，均要审批。删除 0 概率非真实流出 UVT 档若导致后续安慰奖提高也要审批。其余合法直接写，不用「是否发真钱」替代判据。
- 积分退役服务：`POST /api/admin/growth/quest-events/wheel-tiers/{tierName}/retire`，权限 `growth_h4_wheel_pool_write`；完整 body 为 `reason,operator,confirmed:true,expectedSignature`，原 `Idempotency-Key` 持久保存。仅停用 active points 原档、保留历史；不自动补概率、替换奖品或开放发奖。App 可用前须运营配置合法奖池合计 100%。
- I6/I7 A2：首次发布 `i7_course_first_publish`，版本发布 `i7_course_version_publish`，回滚 `i7_course_version_rollback`；目标奖励大于 0 一律审批，包括等额/降额回滚。`sourceDomain=I`、`obj=courseId`、`target={domain:I,type:learning_course_activation,id:courseId}`。`params` 恰好 `courseId,version,expectedRevision,expectedCurrentVersion,expectedCurrentRevision,expectedCurrentStatus`；首次发布优先取唯一 DRAFT 版本，兼容旧草稿时目标修订号为 null。零奖励仍走原直接接口。
- 批准人：另一位有 `platform_a2_operation_approve` 的有效超级管理员；H4 发起人需要对应活动写或奖池写，课程发起人同时需要课程写与奖励调整权。提案收录不等于生效或回滚完成。
- R1：发送前保存完整原 envelope/body、对象、理由、操作者和命令号。未知后原框冻结，关闭重开/刷新后同对象恢复原请求；同奖池不同动作或不同奖项不允许代替原操作。只允许原号原内容重试或精确查询原提案；只有 `isExplicitRejection` 可解除。401/403/408/425/429、`IDEMPOTENCY_*` 保留。24 小时后仍保存、不重发，可继续查原单。

实现出处：`H4GrowthApproval.values/target/makerAuthority/validateChecker`；`OpsGrowthService.updateQuestEventReward/createWheelTier/updateWheelTier/updateWheelProbabilities/deleteWheelTier/increasesUvtFallback/retireWheelTier`；`LearningCourseActivationApproval.prepare/requireExpectedState/validateDecision`；`OpsI18nLearningService.CourseActivation.amplifies/lockCourseActivation`；`OpsGrowthCommandBoundary.execute`（模块/操作/目标作用域与请求 hash）；`AdminIdempotencyService`（认证操作者范围）；`OpsAuditCenterService.createProposal/proposalByIdempotencyKey`。
