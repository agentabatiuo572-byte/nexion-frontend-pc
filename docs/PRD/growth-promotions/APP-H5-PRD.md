# 活动促销 APP / H5 功能规格

> 状态：评审稿，尚未批准进入产品开发。本文定义客户端功能契约，不表示页面、接口或奖励规则已经上线。活动规则唯一源为同包 [PRODUCT-PRD.md](./PRODUCT-PRD.md)，后台操作见 [ADMIN-PRD.md](./ADMIN-PRD.md)。拟新增页面、接口及字段均为待评审方案。

## A1 范围与规则归属

本文覆盖活动发现、查看条件、选择商品、确认奖励、钱包购机、支付结果恢复、自动发奖结果、整单退款后的奖励处理和直接邀请双向奖励进度。首期奖励类型为 `DEVICE / USDT / NEX`，同一活动可按不同购买 SKU 配置不同的固定奖励；同一规则不提供购买者自选奖励、混合奖励、转赠或拼团。多 SKU 订单可产生多条分别归属购买行的奖励，不等于单条规则支持混合奖励。

主购机链固定为 **现有首页广告卡片 → 现有商城 → 商品卡中的活动信息 → 商品详情或直接购买 → 既有下单页逐项赠品 → 既有支付与订单结果**。规则详情仅辅助阅读，不是强制中间页；不为促销另造结账系统。主动离开未支付结账的单次提示见 APP09 及 §P4.3。交互按钮遵循主人指定的 Liquid Glass 方案；视觉参数、素材、按钮表现和设计稿由独立设计说明维护，本文只定义行为、语义和验收门。

普通商品、账户、订单与资金功能在正式 APP 和 H5 保持一致。H5 不获得原生安装证明、手机校准、绑定、手机心跳或手机任务执行权限；购机促销不得成为绕过上述边界的入口。设备奖励是否占容量、如何激活和可用权益由服务端设备契约及主文决定，不能因为是赠品就默认授予原生权限。

## A3 通用客户端契约

| 对象 | 客户端需要的最小内容 | 权威与缓存边界 |
|---|---|---|
| 活动摘要 / 详情 | 服务端活动 ID、名称、说明、状态、起止时间、允许公开的适用说明、商品奖励摘要、参与结果、下一步动作 | 以 `/api/promotions` 及详情结果为准；缓存仅供展示，不据缓存建单 |
| 预计报价 | 报价 ID、有效期、购物项、优惠拆分、预计实付、逐行预计奖励、条款版本、服务器时间 | `POST /api/orders/quote` 只试算，不占资格、预算或赠品；必须标“预计” |
| 已锁定订单 | 订单号、锁定报价与规则版本、金额、逐行奖励承诺、支付状态、`payBy`、可执行动作 | 建单成功才原子占用并锁定；支付前读回，付款接口不得悄改奖励 |
| 奖励项 | 奖励 ID、活动与订单关联、购买行 ID、受益人角色、类型 / 数量、权益说明、单项状态、到账或设备凭证、售后关联 | 服务端单项奖励义务；不以客户端余额差计算是否发放 |
| 页面请求作用域 | 当前账号、会话版本、页面请求版本、活动 / 订单参数、分页游标 | 账号或参数切换使旧响应失效；敏感命令不因自动刷新重放 |

拟议接口统一引用 §P8：`GET /api/promotions`、`GET /api/promotions/{activityId}`、`GET /api/promotions/{activityId}/referral-progress`、`POST /api/orders/quote`、`GET /api/promotion-rewards`、`GET /api/promotion-rewards/{obligationId}`。创建订单沿既有 `POST /api/orders` 或 `POST /api/orders/bundle` 增加 `promotionQuoteId`，其值取服务端试算返回的 `quoteId`；组合项扩展由 §P8 定稿。成交沿既有 `POST /api/orders/{orderNo}/pay` 钱包支付。HDPay 仅用于充值，不作为购机成交、奖励成熟或邀请成交的凭证。

客户端只消费已发布活动版本。活动当前生命周期与新草稿的审批状态分离：新版本处于草稿、审批中或 `APPROVED` 获批待发布，不停止既有已发布活动，也不覆盖当前报价或历史订单。何时发布及发布后作用范围由 §P4、§P9 确定，客户端不把“审核通过”当作“已经开始”。

所有需新增的分页、筛选、邀请进度和详情投影字段都须在 §P8 登记后实现，不能把本文字段表当成现有接口。现有活动 `join / claim / spin` 保持原业务边界；新购机促销自动发奖，不接入现有 `claim` 来重复领取。

#### [FEAT-GROW-APP01] 首页活动广告、辅助入口与活动列表

**① 用户故事**

- 作为浏览商城的客户，我想要找到当前可参加的购机活动，以便比较真实商品与奖励条件后决定是否购买。
- 作为已有订单的客户，我想要查看已参加活动和奖励进度，以便活动停止新参与后仍能回查已有承诺。

**② 验收(GWT)**

- 阳光路径：Given 首页推广位收到服务端可展示的购机促销，When 点击广告卡或其购买按钮，Then 直接进入现有商城并定位活动商品，商品卡按 APP03 展示赠奖；不先跳独立活动详情页。辅助活动列表按服务端状态筛选，规则说明按需打开 APP02。
- 异常1（网络失败）：Given 活动请求超时且无已验证结果，When 页面加载结束，Then 展示加载失败与重试，不把失败解释为“没有活动”，不展示本地模拟活动或模拟赠品；返回商城仍可用。
- 异常2（活动中途停止）：Given 列表展示的活动已被服务端暂停新参与，When 点击购买入口，Then 详情重查状态并说明当前不能新参加；已有订单和奖励入口保留，不把历史承诺隐藏或取消。
- 异常3（账号与分页交错）：Given 正在请求下一页时切换账号或筛选，When 旧请求迟到，Then 旧数据不进入新账号列表；失效游标提示从当前筛选重新读取，不混页、不重复计数。
- 异常4（未登录）：Given 客户从公开入口访问活动，When 活动含个人资格或已参与筛选，Then 只展示公开条件并提供登录入口；登录返回原活动，不把未登录状态标成“不符合资格”。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `activityId` | string | 是 | 无 | 服务端生成的稳定 ID；不从标题推导 |
| `placement / destination` | 投放位置 / 允许的目标 | 广告时 | 无 | 活动服务投影到既有首页推广轮播；购买广告目标为现有商城，不挪用每周任务资格 |
| `title / summary` | 本地化文本 | 是 | 无 | 服务端按 zh/en/vi 返回；缺文案报可恢复错误，不显示翻译 key |
| `state / startsAt / endsAt` | §P9 状态 / 时间 | 是 | 无 | 服务端权威；本地时间只驱动倒计时显示 |
| `rewardSummary` | 公开奖励摘要 | 是 | 无 | 不适合一句话概括时显示“查看适用商品与奖励”，不得伪造统一奖励 |
| `participation / nextAction` | §P8 投影 | 是 | 无 | 由服务端确定；不使用本地购买记录判断首购或已参与 |
| `nextCursor` | string 或 null | 分页时 | null | 服务端生成，绑定账号和筛选；不得拼接页码冒充 |

**④ 状态机 + 禁止动作**

| 当前页状态 | 事件 | 下一状态 / 动作 |
|---|---|---|
| 未加载 | 进入页面 | 加载中 |
| 加载中 | 请求成功 | 有内容或空列表 |
| 加载中 | 请求失败 | 报错并可重试 |
| 有内容 | 刷新 / 筛选 / 换账号 | 请求新作用域；旧数据不能授予操作权限 |
| 任意 | 离开页面 | 取消页面订阅，迟到响应不改当前页 |

活动业务状态只投影 §P9，不在列表自行转为进行中、已参与或已结束。禁止用“浏览过”“点过卡片”增加参与人数；禁止为凑列表数量回填 mock；禁止无理由的不可点击卡片。

**⑤ 交互原型（四态）**

- 默认态：首页沿现有广告卡位置展示真实活动摘要与去商城入口；辅助列表提供筛选、活动时间、奖励概况和规则说明；已有参与活动保留“查看进度”，“我的奖励”稳定可达。
- 空状态：说明当前筛选无活动，提供重置筛选、返回商城；不得暗示参与其他活动即可获得本活动奖励。
- 加载态：保留页面标题、返回和筛选位置，使用与摘要结构对应的占位；已有列表刷新只标明正在更新。
- 报错 / 极限态：网络失败可重试，超长标题可进入详情读全；时间或资格未知时使用未知说明，不显示假倒计时或确定资格。

**⑥ 点击流矩阵**

| 触发元素 | 跳转 / 响应目标 | 反馈与限制 |
|---|---|---|
| 首页活动广告卡 / 广告购买按钮 | `/pages/store/store` | 带活动上下文定位 / 筛选商品，提供查看全部；不增加中间页 |
| 我的 / 任务中的辅助活动入口 | `/pages/events/events` | 未加载先拉公开列表；不自动参加 |
| 状态 / 已参与筛选 | 当前列表 | 重置游标，保留选项；个人筛选需登录 |
| 辅助列表活动卡 / 查看条件 / 查看进度 | APP02 规则说明或本活动进度 | 使用活动 ID 再取详情；购买入口仍直达商城 |
| 我的奖励 | APP06 奖励列表 | 未登录先登录并返回此目标 |
| 重试 / 加载更多 | 当前列表 | 仅重发只读请求；同作用域合并数据 |
| 重置筛选 / 返回商城 / 返回 | 当前列表 / 现有商城 / 上一页 | 恢复实际导航栈；直达页无历史时返回活动中心或商城 |

**⑦ 跨文档一致性**

公开资格与活动状态引用 §P2、§P9；商品与奖励摘要引用 §P3、§P5；接口及分页归 §P8。旧 `/api/events` 和新 `/api/promotions` 必须标识来源并去重映射，不将同一活动生成两条卡片或同时显示“领取”和“自动发放”。同活动 APP/H5 返回同一业务状态，语言只改变文案。

首页现有轮播由 `src/pages/index/index.vue` 的 `home-task-carousel` 装配；`conversion-banner.vue` 经 `home-task-carousel.ts` 的推广分支已跳转商城。现有数据属于每周任务 `promoBanner`，不能用其 `baseReward / multiplier / countdownDays` 冒充购机促销；活动服务应提供独立类型的投影，复用展示容器与跳转方式。新促销不能因当前没有每周任务而错误消失，亦不能覆盖已有新人 / 每周任务事实；投放位选择与优先级按主文和后台配置执行。

#### [FEAT-GROW-APP02] 活动规则辅助详情与适用条件

**① 用户故事**

- 作为准备购机的客户，我想要查看适用设备、固定奖励、参与条件和兑现方式，以便支付前明白能够获得什么以及何时能用。

**② 验收(GWT)**

- 阳光路径：Given 商城商品卡或既有下单页有活动信息，When 主动点“活动说明”，Then 在当前链路打开辅助说明层，展示该 SKU 固定奖励、必要限制和有效时间；关闭回原位置并保留选择，购买动作不强制经过该说明层。
- 异常1（身份条件不符）：Given 服务端判断当前客户不满足新客、首购、无设备或等级条件，When 查看详情，Then 用可理解的资格说明显示原因与可执行下一步，不泄露内部判定算法；不得把“没有设备”显示成“首次购买”。
- 异常2（活动已结束或下架）：Given 活动不再接收新订单，When 打开历史链接，Then 可读取的历史条件及已有奖励仍可回查，新增购买入口禁用并说明；若服务端不再公开详情，则保留个人订单 / 奖励入口，不覆盖已锁定承诺。
- 异常3（商品或赠品不可用）：Given 某购买项停止销售或奖励库存不可用，When 点击对应商品，Then 重查后展示不可用原因；不把指定赠品自动换成其他设备、USDT 或 NEX，不继续沿过期预览建单。
- 异常4（详情刷新失败）：Given 已显示一次详情后再次进入前台，When 刷新失败，Then 保留只读内容并标明无法确认最新状态；必须重试成功才能执行需要当前资格的新建单。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `activityId / version` | string / §P8 版本 | 是 | 无 | 服务端生成；详情版本不是付款承诺 |
| `eligibilityResult` | 资格摘要 | 是 | 未确认 | §P2 服务端结果，区分未登录、未确认和不符合 |

**④ 状态机 + 禁止动作**

禁止点击返回、刷新、自动恢复或充值回跳重放付款；禁止根据客户端超时释放服务端预留；禁止活动暂停后把截止前已锁定订单改为无奖励；迟到支付与对账处理按 §P7 服务端决策展示，客户端不得假定退款成功。

**⑤ 交互原型（四态）**

- 默认态：显示订单号、金额、支付结果、下一步；成功后突出查看订单和奖励进度，不再显示同单支付按钮。
- 空状态：缺少原订单标识时引导订单列表，不默认创建新单；订单不存在与未登录分别说明。
- 加载态：显示正在查询原订单和最近已确认状态，金额与重复付款入口不闪回到可支付。
- 报错 / 极限态：网络错误保留原单恢复入口；余额不足沿钱包既有充值入口恢复，但充值后不自动付款；结果未知不显示确定失败。

**⑥ 点击流矩阵**

| 触发元素 | 跳转 / 响应目标 | 反馈与限制 |
|---|---|---|
| 钱包支付确认 | `/api/orders/{orderNo}/pay` | 同单幂等，记录未决命令关联 |
| 继续查询 / 页面刷新 / 回到前台 | 原订单只读接口 | 查询结果，不重放支付 |
| 去充值 | 既有钱包充值页 | 返回原订单；充值不是成交 |

| 查看奖励 | APP06 | 可按订单筛选，不提供领奖按钮 |

| 返回 / 订单列表 / 帮助 | 既有订单列表 / 帮助入口 | 未知支付状态仍可回查，不能丢掉恢复线索 |

**⑦ 跨文档一致性**

支付仅为既有钱包成交接口，HDPay 归充值链；§P4 的锁定承诺与 §P7 的结算规则不因页面退出改变。状态投影引用 §P9；原单查询及恢复能力需 §P8 明确支持后交付。APP/H5 同账号读回一致不代表 H5 获得手机原生能力。

禁止新增多层促销返利；禁止将既有团队佣金与本活动直邀奖励合并成同一笔收益；禁止分享点击即发购机奖励；禁止改绑既有邀请关系；禁止显示对方未授权的订单或资产。与既有佣金是否叠加只引用 §P6。

**⑤ 交互原型（四态）**

- 默认态：活动详情邀请段显示直接邀请规则、自己的进度与奖励、可用分享入口；被邀请购买者在结账看到自己的固定奖励和必要归属说明。
- 空状态：尚无合格邀请成交时说明真实条件并提供分享；没有推荐码不展示可点击的假二维码。
- 加载态：进度和奖励分别占位，分享配置未确认前入口禁用并说明；不显示缓存账号的邀请码。
- 报错 / 极限态：分享失败可重试或关闭；进度请求失败不回退为零；匿名明细和长文案可读；达标后仍显示奖励处理状态而非“一键领取”。

**⑦ 跨文档一致性**

是否首期开放及奖励对象按 §P1、§P3；推荐关系和人群判定按 §P2；叠加按 §P6；售后按 §P7。分享仍走既有推荐码、配置和渠道能力，活动参数需服务端确认。双方奖励各自独立追踪，统计与页面不能把“我方到账”表述成“双方到账”。

#### [FEAT-GROW-APP09] 未支付结账的单次离开提示

**① 用户故事**

- 作为尚未支付的购机客户，我想要在主动离开时看到本单真实赠礼和期限，并能自由选择继续或退出，以便不会误解奖励何时失效或丢失当前选择。
- 作为已有待支付订单的客户，我想要明确区分退出页面与取消订单，以便退出后仍能在真实付款期限内找到原单继续支付。

**② 验收(GWT)**

- 阳光路径：Given 当前未支付结账含服务端确认的合格选购项和真实预计奖励 / 已锁定奖励，When 客户首次主动离开本次未变化的结账会话，Then 显示一次真实奖励提示；“继续购买”留在原位置，“确认退出”执行原返回目标，主购机链返回商城。
- 异常1（未决支付或票据流程）：Given 正在建单、支付处理中、结果未知或进入已有票据取消 / 恢复流程，When 顶部返回、支付回调、回到前台或页面关闭发生，Then 交易安全与原单恢复优先；不显示营销弹窗遮盖安全提示，不连弹两次，不创建新订单或第二次支付。
- 异常2（不满足展示条件）：Given 没有奖励、资格未知、活动已结束且无有效预留，或不能取得权威时间，When 主动离开，Then 按普通返回或已有必要提醒执行，不伪造“马上失效”或假倒计时，不为触发挽留而把未确认人群写成合格。
- 异常3（重复返回与系统退出）：Given 已在本次未变化报价会话选择继续购买，When 再次点击离开，Then 不重复劝留并执行返回；浏览器关闭、系统退出、支付回调及不可拦截的系统行为不承诺必弹，不循环写 history 阻止退出。
- 异常4（已经建单）：Given 订单已锁定奖励但尚未支付，When 选择“确认退出”，Then 只离开页面，保留待支付订单、原承诺及恢复入口；没有调用取消接口就不得释放预留。后续明确取消订单才走既有服务端取消确认及原单结果查询。
- 异常5（草稿恢复与期限变化）：Given 退出时保留了选购草稿，When 回到商城后再次进入结账，Then 恢复同账号会话内型号、数量和选择并重新试算；旧报价不能自动复活。已有原订单先读回原单，不能将草稿当作新订单重复创建。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `leaveIntent` | 页面级退出意图 | 触发时 | 无 | 顶部返回、显式退出或离开结账的站内导航；不含结账步骤内返回、支付回调、系统关闭 |
| `returnTarget` | 已验证内部导航目标 | 是 | 原目标，无历史时商城 | 不接受任意外部 URL；明确退出执行一次，不二次挽留 |
| `checkoutScope` | 账号 + 草稿 / 原订单作用域 | 是 | 无 | 沿既有账号隔离；不承担活动资格或奖励事实 |
| `leavePromptShown` | 页面会话标记 | 是 | false | 同一未变化报价 / 订单会话最多提示一次；恢复不为再营销而重置 |
| `rewardSummary / endsAt / payBy` | 服务端投影 / 时间 | 提示时 | 无 | 未建单用预计奖励和活动截止；已建单用锁定承诺和 `payBy` |
| `draftSelection` | 商品、数量、既有支付方式选择、活动来源 | 有草稿时 | 无 | 仅同账号现有会话缓存范围；不缓存可信资格、永久优惠或完整支付凭据 |

草稿策略：确认退出保留同账号本次会话内的商品、数量和允许保留的选择；不保证关闭应用后永久保存。若已有订单或支付命令，订单号与必要恢复关联沿现有持久恢复机制保存，不随草稿退出删除。再次打开未建单草稿必须重新报价；原待支付订单必须先读原订单而非从草稿再次建单。登出清理本地展示草稿，但不得把登出当成撤销服务端订单。

**④ 状态机 + 禁止动作**

| 状态 | 事件 | 后继 / 动作 |
|---|---|---|
| 可编辑未付结账，尚未提示 | 主动离开且满足真实展示条件 | 弹窗打开并记本会话已提示 |
| 弹窗打开 | 继续购买 / 关闭 / ESC / 遮罩 | 关闭弹窗，留原页并归还焦点，保留选择 |
| 弹窗打开 | 确认退出 | 关闭弹窗，执行原目标一次，保留草稿或原订单 |
| 本会话已提示 | 再次主动离开 | 直接执行返回，不再次营销提示 |
| 交易写请求未决 / 票据恢复 | 任何离开或回调 | 走既有交易安全与恢复，不进入营销弹窗 |
| 确认步骤 | 返回上一结账步骤 | 仅步骤回退，保留选择，不弹挽留 |

禁止退出页面即取消订单；禁止用活动结束时间替代已锁订单的真实付款截止；禁止称“退出马上失去奖励”；禁止假库存、重置倒计时或“只剩最后一次”话术；禁止把退出控件隐藏成难以发现的入口；禁止以挽留阻止系统退出。主动取消待支付订单沿既有取消确认，促销影响只并入该确认，不再叠一层营销确认。

**⑤ 交互原型（四态）**

- 默认态：在原结账页上打开既有确认弹层，仅展示真实奖励、对应期限和两个可用操作。“继续购买”“确认退出”均可聚焦与操作。未建单文案为“本次选购预计可获赠「{奖励摘要}」。活动将于{结束时间及其时区}结束。是否离开下单页？”；已建单使用“本单奖励已预留至{payBy}。退出后可在订单中继续支付，逾期订单将关闭。”。
- 空状态：无真实奖励或不满足提示条件时不创建空弹窗，正常执行离开；有普通未保存信息时沿既有必要提醒。
- 加载态：不为了展示营销提示阻塞返回并临时拉请求；没有足够已验证事实时跳过营销提示。交易命令本身未决时只显示原有安全恢复状态。
- 报错 / 极限态：奖励或时间无法确认时不显示该营销提示；多 SKU 奖励逐项可读，不能省略成误导性的单一礼包；长文案可完整阅读且两个动作仍可达，关闭后焦点回到退出触发点。

明确取消待支付订单的既有确认使用单独语义：“取消后将释放本单预留的「{奖励摘要}」，此订单将无法继续支付。是否取消订单？”按钮为“保留订单”“取消订单”。这是交易取消，不是营销挽留的“确认退出”；只有服务端取消结果确定后才更新订单及资源状态。
