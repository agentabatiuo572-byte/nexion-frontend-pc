# M3 与 App 会话实时通信契约

更新：2026-09-09。范围：正式 UniApp 的客服/顾问会话与 M3 坐席工作台，Java 单体后端。Nova 模型推理任务沿用独立任务接口。

## 用户行为

- 新建会话、回复和已读确认优先通过 WebSocket 发出；无法连接时使用既有 HTTP 命令，继续复用同一幂等键。
- 正常连接时通过实时事件刷新消息、未读数和已读回执；不执行会话轮询。断线期间每 5 秒补拉一次，重连采用指数退避与随机抖动，上限约 30 秒。
- 恢复连接先读取服务端列表和会话详情，处理恢复期间到达的变更后才进入实时状态。App 对超过最近 100 条窗口的缺口逐页向前补拉至已知消息；保留已经加载的历史。
- 消息按持久化消息 ID 去重，已读回执只能前进。发送成功但确认丢失时保留原命令键，查询原命令结果或使用原键重试。
- 客户端只上报当前会话的输入状态，节流 1.2 秒，状态 5 秒自动过期。在线由已认证连接和心跳确定，未分配坐席显示等待分配；App 后台、退出登录或切换账号关闭旧连接。
- M3 仅有读取权限的账号可以看会话；新建、回复、正在输入和标记用户消息已读需要 `service_m3_write`。
- App 会话中心的顾问、客服分类在空列表和所有历史已结束时均提供明确联系入口。未绑定专属顾问的咨询进入备勤分配；点击入口只打开编辑页，第一条消息提交后才创建会话。已移除但仍在进行的会话通过联系入口继续打开，避免重复创建。
- 顾问、客服会话支持「从列表移除」：仅保存本人 `throughMessageId`，不结束会话、不删除历史、不改变 M3 记录或已读回执。公开新消息 ID 超过该位置时，列表与未读提示重新显示。Nova 是独立固定服务入口，本次不提供移除。

## 协议与边界

1. App `POST /api/app/support/realtime-ticket`，PC `POST /api/admin/content/conversations/realtime-ticket` 领取 30 秒一次性票据。PC 由同源 BFF 使用 HttpOnly 登录凭据代领，响应不可缓存。
2. 连接 `/ws/conversations`，首帧 `{type:"auth",ticket}`。票据不进入 URL，5 秒内未认证关闭。每条入站帧、心跳和业务事件投递前检查登录存活与权限。
3. `command` 含 `requestId`、`operation`（`create/reply/read`）、`conversationNo`、`body`；新建/回复必须带 `idempotencyKey`。`ack.result` 沿用 `ApiResult`。写命令调用现有 Spring controller 代理，保留权限、事务、幂等、状态版本与用户业务写闸门。
4. 持久消息提交后只推授权会话的失效通知，客户端读取自己的权威投影。App 不会收到转交原因等内部 SYSTEM 正文。
5. `watch` 选择当前会话；`typing` 上报输入布尔值；`presence` 返回对端在线及输入状态。所有身份由服务端会话派生。
6. App 读 AGENT 消息；可写坐席读 USER 消息。已读以 `lastSeenMessageId` 为上界，仅确认已显示消息以前的记录，后到消息仍为未读。自然幂等的已读确认不改变业务会话版本。
7. App `GET /api/app/support/conversation-dismissals` 读取本人移除位置；`POST /api/app/support/conversations/{conversationNo}/dismiss` 提交 `{throughMessageId}`，位置必须属于本人的该会话且为未删除公开消息。重复请求位置只前进，相同/较旧请求不更新时间。此个人列表偏好使用 HTTP；消息传输继续使用 WebSocket。
8. 列表响应 `lastPublicMessageId` 只统计 `user/agent` 且未删除的消息。App 遍历全部会话游标后过滤个人移除位置，不能依赖不含正文的列表项 `messages` 判断新消息。历史、后台分页和会话状态不受此偏好影响。

## 部署与回退

- 当前 ticket 与连接注册表为单 Java 实例内存状态；进程重启由客户端重新领票与全量补拉恢复。多个 Java 副本部署前必须增加共享一次性票据存储及跨实例事件总线，不能直接把本契约宣称为多实例闭环。
- Vite 配置 `/ws/conversations` 的 `ws:true` 代理；Next 使用 `beforeFiles` 外部 rewrite 处理真实 Upgrade，先于通用 `/[domain]/[module]` 页面匹配。生产入口须允许 WebSocket Upgrade 与足够的读超时。
- 生产使用 HTTPS/WSS，并通过 `nexion.websocket.allowed-origins` 与现有 CORS 配置声明准确前端 origin。禁止使用通配符来源。
- WebSocket 故障时客户端继续 HTTP 消息命令及 5 秒会话补拉。账号失效/权限被撤回属于终态，停止重试和兜底，等待正常重新登录。
- 启动脚本保持现有登录/MFA/条款规则。真实账号跨端收发验收需要账号本人完成必要的登录与条款确认。
- 升级先执行 `scripts/migrations/20260909_app_conversation_dismissal.sql`（已纳入受控启动链），再更新 Java 与 App；应用请求和 Bean 初始化不执行该表 DDL。回退客户端后标记表可保留，历史及后台不受影响。

## 本次验证记录

- App 和 PC 的真实传输类覆盖：恢复前补拉、恢复期间事件、重复事件、断线兜底、确认丢失保留键、停止后的旧事件隔离。
- App 额外覆盖 300 条历史缺口、消息 ID 去重、已读不回退及账号/页面边界。
- Java 覆盖票据重放、多标签领票、未认证拒绝、撤销登录后拒绝写、会话归属、幂等键要求、只读席位拒绝已读以及 controller 身份清理。
- 隔离嵌入式 Tomcat 与真实网络 WebSocket 客户端验证有效票据、重放拒绝、命令 ACK、授权事件、在线/输入及断线重连。该测试的身份和命令执行使用 mock，不代表真实账号或落库业务验收；另有真实 2048 项出站队列饱和后重新 watch 恢复 presence 的回归。
- 真实 MySQL 使用隔离事务验证 mapper 已读 SQL：两条 USER 消息只确认已显示的第一条，未读数由 2 降为 1、会话版本保持 7，第二次确认影响行数为 0；事务回滚后消息及回执夹具均为 0。
- 两端类型检查、H5 构建和 PC 生产构建通过；真实 8110 / 5173 / 3002 Upgrade 返回 101，无效票据返回 401，错误来源返回 403。
- 真实账号 App ↔ M3 消息收发仍需条款确认后补验，不能用以上自动化结果代替。
