#### [FEAT-KYC-RM01a] 提现地址直管(每网络一个当前地址)

**① 用户故事**

- 作为要提现的用户,我想要直接填写我的收款地址并短信确认,以便不用先给平台转 $1 才能提现。
- 作为更换钱包的用户,我想要自助更换提现地址并清楚知道更换后的限制,以便安全地迁移资产去向。
- 作为老用户(改版前已验证过地址),我想要原地址自动沿用,以便规则切换不打断我的提现习惯。

**② 验收(GWT)+ 异常路径**

- 阳光路径(首次添加):Given 用户从未设置过某网络的提现地址,When 在提现页该网络下点「添加提现地址」→ 粘贴地址 → 短信验证码确认,Then 地址保存为该网络当前地址并标记「新地址保护期 24h」;保护期内提现按既有「新地址持有期」风控信号裁决(小额免审车道对其的豁免规则维持 WD01 现状,不因本规格改变)。
- 阳光路径(更换地址):Given 某网络已有当前地址且无在途提现单,When 用户在地址管理中更换 → 短信确认 → 二次确认(明示旧址停用 + 24h 提现冻结),Then 原子替换为新地址,旧地址进入历史记录不可再收款;提现按钮进入 24h 冻结倒计时;7 天内不可再次更换。
- 异常1(地址格式非法):Given 输入不符合所选网络的地址格式(长度 / 前缀 / 字符集),When 提交,Then 字段级红字指明「地址与所选网络不匹配」,禁止保存;**永不**做静默截断或自动纠正。
- 异常2(在途单拦截):Given 该网络存在未终态的提现单,When 尝试更换地址,Then 拒绝并说明「有提现进行中,完成或取消后可更换」,给出去向入口。
- 异常3(频控拦截):Given 距上次更换不足 7 天,When 再次更换,Then 拒绝并显示可更换的绝对时刻(平台时区口径,给具体时间不说「明天」)。
- 异常4(验证码失败链):Given 短信验证码输错次数用尽或过期,When 提交,Then 走既有 OTP 生命周期规则(失效重取、次数上限),地址不保存、不产生任何变更记录。
- 异常5(跨账号隔离):Given 账号 A 设置了地址,When 同设备切换到账号 B,Then B 看不到也不继承 A 的任何地址与历史(按账号作用域,固定靶:换号不继承)。
- 异常6(存量迁移):Given 改版前已配对地址的用户首次进入新版,When 打开提现页,Then 原地址已是该网络当前地址、可直接提现,无新地址保护期、无需任何重新验证;地址管理内可见其历史来源标记。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `payoutAddress[network].current` | { address: string; addedAt: number; source: `user` \| `migrated` } \| null | 是 | null | 每网络(TRC20/BEP20/ERC20)至多一个当前地址;server-canonical;按账号作用域存储 |
| `payoutAddress[network].history[]` | 同上结构 + replacedAt | 是 | [] | 替换时旧址入历史,仅可查不可用;迁移地址 source=`migrated` |
| `payoutAddress[network].freezeUntil` | number \| null | 是 | null | 更换成功即 `now + 24h`;冻结期内该网络提现提交禁用(倒计时展示);server-canonical |
| `payoutAddress[network].nextChangeAt` | number \| null | 是 | null | `= 更换成功时刻 + 7 天`;频控判定依据 |
| `newAddressHoldUntil` | number | 派生 | — | `= addedAt + 24h`;作为既有「新地址持有期」风控信号的输入,不新造第二套判定 |
| 地址格式校验表 | Record<network, 校验规则> | 是 | 既有规则 | 沿用充值侧已有的网络地址校验口径,禁两套正则 |

删除对象:钱包配对状态及其台账、合规校验编号(`KYC-` 前缀单据)之新增生成、$1 验证金流与返还逻辑。历史台账数据保留只读。

**④ 状态机 + 禁止动作**

地址(每网络):`未设置 →(添加+OTP)当前生效[新地址保护期 24h] →(更换+OTP+确认)当前生效[冻结 24h + 频控 7d]`;旧址 → 历史(终态,不可复用为当前地址除非重新走添加)。

禁止动作与行为边界:**永不**要求向平台转账以验证地址;**询问后**(OTP + 二次确认)才添加/更换;冻结期内**永不**放行该网络提现提交(client 置灰 + server 拒单双重);在途单存在时**永不**允许更换;**始终**把地址判定输入喂给既有风控信号(新地址持有期),不绕过、不复制。

**⑤ 交互原型 · 多状态覆盖**

- 默认态:提现页地址行显示当前网络地址(掩码中段)+ 「管理」入口;地址管理页按网络分组展示当前地址与更换入口。
- 空状态:该网络未设置地址 → 提现页内联「添加提现地址」引导卡(说明一次设置长期使用),不是报错态。
- 加载态:地址数据拉取骨架;OTP 发送与提交沿用既有发码倒计时与 loading 范式。
- 报错/极限态:格式非法红字;在途单 / 频控 / 冻结三种拦截各自给原因 + 绝对时间 + 下一步;冻结中提现页横幅倒计时;超长地址中段省略不换行。

**⑥ 点击流矩阵**

| 触发元素 | 跳转 / 响应目标 | 转场 / 反馈 |
|---|---|---|
| 提现页地址行「添加提现地址」 | 地址管理页(带网络参数) | 右进左出;完成后返回提现页并回填 |
| 提现页地址行「管理」 | 地址管理页 | 右进左出 |
| 地址管理「更换地址」 | 当前页表单态 | 输入新地址 → OTP → 二次确认弹窗(明示冻结与频控) |
| 二次确认「确认更换」 | 当前页 | 原子替换 + 成功提示 + 冻结横幅出现;失败 → 错误态可重试 |
| 拦截态说明内的去向入口(在途单) | 提现追踪页 | 右进左出 |
| 「查看历史地址」 | 当前页展开区 | 只读列表,含来源与停用时间 |

**⑦ 跨文档一致性**

- 与 FEAT-WD01 的衔接:小额免审免的「新地址 hold」指的就是本规格的新地址保护期,口径一处定义;风控路由与六闸零改动。
- 与 FEAT-WD02 的衔接:提现页费用区不受本规格影响;两包实现同队列相邻,实现线一次性处理提现页结构变更并同步走查断言。

#### [FEAT-KYC-RM01b] 全站 KYC 叙事与机制移除

**① 用户故事**

- 作为普通用户,我想要在任何页面都不再被要求「完成验证才能继续」,以便充值、兑换、换新一路顺畅。
- 作为曾经完成过 $1 验证的用户,我想要我的历史账单与回执仍然可查且看得懂,以便对账不困惑。
- 作为运营,我想要产品对外不再承诺身份认证能力,以便宣传口径与实际能力一致。

**② 验收(GWT)+ 异常路径**

- 阳光路径(全站扫除):Given 改版完成,When 在全站任意页面浏览与操作,Then 不再出现 KYC / 实名 / 身份认证入口、提示、徽章与说明页;个人资料与安全页不再有认证状态行;充值页不再有验证流分支;大额兑换直接放行(不再弹 $100 门);设备 / 以旧换新资格判定不再包含认证条件。
- 阳光路径(提现门替换):Given 用户未设置提现地址,When 进入提现页,Then 看到的是「添加提现地址」引导(RM01a 空态),而非「先完成钱包验证」拦截横幅。
- 异常1(历史账单/回执):Given 用户存在历史 $1 验证账单或验证回执,When 查看账单列表与详情,Then 记录保留、金额与时间不变,类型标签以中性措辞展示(如「验证返还(历史)」),点开不引导到任何已删除页面(死链兜底至账单详情本身)。
- 异常2(旧入口深链):Given 用户从历史消息 / 收藏进入已删除的验证页路由或带验证参数的充值链接,When 页面加载,Then 平滑落到对应现行页面(充值页正常态 / 安全页),给一句「该流程已下线」提示,**禁** 404 / 白屏。
- 异常3(进行中的验证流):Given 改版上线时存在停在「转账待确认」中途态的验证流程用户,When 其打开原流程,Then 显示流程已下线说明;**其已转出的 $1 若已被侦测到,照常返还入余额**(在途资金不因下线而吞没);未侦测到的给客服入口。
- 异常4(资格规则回归):Given 以旧换新 / 高价值商品购买原本包含认证条件,When 移除后用户操作,Then 其余资格条件(持有时长 / 账号状态等)照常判定,不因删除一项条件而放宽其它条件或误放行。
