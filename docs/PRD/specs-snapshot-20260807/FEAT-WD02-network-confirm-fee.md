#### [FEAT-WD02a] 用户端 · 提现费用 = 网络确认费 + NEX 自选抵扣

**① 用户故事**

- 作为发起 USDT 提现的用户,我想要只看到一笔含义清晰的「网络确认费」,以便确切知道到手金额、不被多项费用困惑。
- 作为持有 NEX 的用户,我想要自主选择是否用 NEX 抵扣本次网络确认费,以便自己权衡「省手续费」和「留着 NEX」。
- 作为提现过的老用户,我想要历史提现单仍按当时的费用快照展示,以便对账时数字对得上。

**② 验收(GWT)+ 异常路径**

- 阳光1(默认不抵扣):Given 费用配置已拉取、用户选择 TRC20 网络、输入 ≥ 最小提现额 $20,When 进入确认区,Then 费用明细仅一行「网络确认费 −$1.00」(金额 = 该网络配置值),NEX 抵扣开关**默认关闭**,到手 = 提现额 − 网络确认费;不出现任何「惩罚/penalty」字样与行。
- 阳光2(勾选抵扣):Given 用户 NEX 余额按 $0.40/NEX 折算 ≥ 网络确认费,When 打开「用 NEX 抵扣」开关,Then 当前页即时重算:显示将消耗的 NEX 数量与抵扣后费用($0.00),到手 = 提现额;提交时烧 NEX 与建单同一原子提交(对齐 v1.0 §5.1 并发契约),成功后账单含 NEX 消耗记录。
- 异常1(NEX 不足,部分抵扣):Given 用户 NEX 折算价值 < 网络确认费,When 打开抵扣开关,Then 显示「可抵 $X.XX,仍需支付 $Y.YY」,`实际费 = max(0, 网络确认费 − NEX 折算额)`,不允许负数;NEX = 0 时开关置灰不可开,旁留「去赚 NEX」入口。
- 异常2(费用配置拉取失败/非法):Given 配置同步失败或值非法(< 0、> 上限 $25、非数值),When 用户进入提现页,Then 费用明细区显示失败态 + 「重试」,提交按钮置灰且给出置灰原因;**永不回退到写死费率下单**(沿用 WD01 费率门语义)。
- 异常3(烧 NEX 失败回滚):Given 已勾选抵扣且提交,When NEX 扣减与建单的原子提交失败,Then 整单失败、NEX 余额不变、Toast 提示可重试;禁止出现「NEX 已烧、单未建」或反之的半态。
- 异常4(历史单展示):Given 存在改版前含惩罚费的历史提现单,When 用户查看该单/账单详情,Then 按落单时的费用快照原样展示(可含历史「惩罚费」行),不按新规则重算;新单一律新结构。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `PlatformConfig.withdrawFee.networkConfirmFeeUsd` | Record<`trc20`\|`bep20`\|`erc20`, number> | 是 | 见 WD02b 种子 | **单源 = 后台 D5**,server-canonical,client 仅拉取缓存展示;合法域 [0, 25];拉取失败 → 异常2 |
| `PlatformConfig.withdrawFee.nexFeeOffsetRate` | number | 是 | 0.40 | 不变,权威 PRD §13.4;client 只读 |
| `WithdrawalRecord.fee.networkConfirmUsd` | number | 是 | — | 落单时快照,禁事后重算 |
| `WithdrawalRecord.fee.nexBurned` | number | 是 | 0 | 用户勾选才 > 0;= min(用户NEX, ceil(费/0.40)) 的实际折算消耗 |
| `WithdrawalRecord.fee.actualFeeUsd` | number | 是 | — | `max(0, networkConfirmUsd − nexBurned × 0.40)`,server 权威校验等式 |
| `WithdrawalRecord.fee.penaltyUsd`(历史) | number | 否 | — | 仅历史单存在;新单不生成该字段 |
| `offsetWithNex`(提交入参) | boolean | 是 | false | 用户显式勾选;server 侧无此意图则永不烧 NEX |

删除字段:`networkFeeRate` / `networkFeeMin` / `networkFeeMax`(比例夹逼三件套)、`withdrawPenaltyFeeRate`(含 phase 阶梯)。

**④ 状态机 + 禁止动作**

提现单状态机沿用 FEAT-WD01(本规格零改动,不双写)。费用相关禁止动作:
- 配置不可用时禁止下单(client 置灰 + server 拒单)。
- client 禁止自算费用入库:`actualFeeUsd` 以 server(mock 同构)重算为准,client 展示值仅 UI cache。
- 未勾选 `offsetWithNex` 时**永不**扣减 NEX;勾选后烧 NEX 与建单同事务,禁半态。
- 行为边界:**始终**展示费用明细与到手金额;**询问后**(用户勾选)才消耗 NEX;**永不**默认抵扣、**永不**收取惩罚费、**永不**用写死费率兜底下单。

**⑤ 交互原型 · 多状态覆盖**

- 默认态:金额输入 → 费用明细单行「网络确认费 −$1.00」+ NEX 抵扣开关(关)+ 到手金额;切换网络即时刷新费用值。
- 空状态:NEX = 0 → 抵扣开关置灰 + 「去赚 NEX」入口(沿用现有签到/挖矿入口);无历史提现单不影响本区。
- 加载态:费用配置拉取中 → 明细区骨架占位(< 300ms 不展示防闪烁);拉取期间提交按钮置灰。
- 报错/极限态:配置失败 → 明细区失败态 + 重试按钮 + 提交置灰原因;NEX 部分抵扣 → 「可抵 $X,仍需 $Y」;费用 = $0(后台配 0)→ 明细显示「网络确认费 $0.00」不隐藏行;烧 NEX 失败 → Toast + 全量回滚。

**⑥ 点击流矩阵**

| 触发元素 | 跳转 / 响应目标 | 转场 / 反馈 |
|---|---|---|
| 费用行「?」图标 | 当前页 | 打开「费用说明」半屏:仅解释网络确认费(链上确认成本)与 NEX 抵扣规则;删除惩罚费段落 |
| 「用 NEX 抵扣」开关 | 当前页 | 即时重算实际费/到手/消耗 NEX;NEX=0 时不可点(置灰态) |
| 「去赚 NEX」入口 | 现有签到/NEX 页路由 | 右进左出,返回后开关状态保留 |
| 费用配置失败态「重试」 | 当前页 | 重新拉取;成功恢复明细,失败保持失败态 |
| 「提交提现」按钮 | 现有确认弹窗 | 沿用 WD01 提交链;弹窗内费用行同步为单行网络确认费 |

**⑦ 跨文档一致性**

- 费用单源:后台 D5(WD02b)→ 前端 PlatformConfig 拉取,**跨仓种子逐键等值**(uniapp mock 种子 ↔ admin D5 种子,焊 parity 哨兵,对齐 fx-parity 先例)。
- 抵扣率 $0.40/NEX 权威仍在前端 PRD §13.4,本规格只引用不双写。
- 提现单状态机、风控路由、小额免审归 FEAT-WD01/SPEC-7,本规格零触碰。
- i18n:费用行、说明半屏、开关行、部分抵扣文案 en/zh/vi 三语镜像;「网络确认费」为用户可读词,禁出现 penalty/惩罚残留(实现线 grep 收口)。
- 实现线三端同步清单:uniapp `platform-config` 种子与费用纯函数 / admin D5 字段 + EXPECTED_KEYS 哨兵 / 自检脚本(withdrawfee/feegate)断言随公式更新;提现页结构改动前同步 walkthrough 断言。

#### [FEAT-WD02b] 后台 · 提现网络确认费配置(D5)

**① 用户故事**

- 作为运营,我想要按网络分别调整 USDT 提现的网络确认费,以便匹配不同链的真实成本(TRC20 便宜、ERC20 贵)。
- 作为风控/审计,我想要每次费用调整都留确认、理由与审计记录,以便追溯谁在何时为何改价。

**② 验收(GWT)+ 异常路径**

- 阳光路径:Given 运营在 D5 提现参数页,When 将 TRC20 网络确认费从 $1.00 改为 $1.50 并保存,Then 弹确认(含改动前后值)+ 必填理由 → 审计落账 → 保存成功;前端下一次配置拉取生效,在途单不受影响(快照)。
- 异常1(越界拒绝):Given 输入 −1 或 30(> 上限 25)或非数值,When 保存,Then server 422 拒绝 + 字段级红字与合法域提示,不落库、不产生审计记录。
- 异常2(保存失败可重试):Given 保存请求失败(网络/冲突),When 返回失败,Then 显示失败态 + 原值回填 + 「重试」;不出现「界面已改、库未改」的假成功。
- 异常3(惩罚费下线迁移):Given 改版落地,When 运营查看 H1 逐月旋钮与 D5,Then 「提现惩罚费率」行已移除且无死引用;历史审计记录保留可查,不删账。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认(种子) | 生成规则 / 约束 |
|---|---|---|---|---|
| `D.withdrawFee.networkConfirmFeeUsd.trc20` | number | 是 | 1.00 | 合法域 [0, 25],步进 0.5;server 权威 |
| `D.withdrawFee.networkConfirmFeeUsd.bep20` | number | 是 | 1.00 | 同上 |
| `D.withdrawFee.networkConfirmFeeUsd.erc20` | number | 是 | **5.00(建议)** | 同上;⚠️ 待签字项:主人口径「默认每笔 $1」,但 ERC20 与充值侧通道费($5)及真实 gas 相称才可信 → 建议 1/1/5,坚持全 $1 改种子即可 |
| 审计记录 | AuditEntry | 是 | — | 沿用 A2 审计结构:操作者/前值/后值/理由/时间;确认⟺审计耦合 |

删除字段:D5 只读区「提现惩罚费率」、H1 dial `withdrawPenaltyFeeRate`。法币/银行卡提现费率**不在本规格**(归包 B,D5 预留分区即可)。

**④ 状态机 + 禁止动作**

N/A(参数配置,无状态机)。禁止动作与行为边界:高敏改价**询问后**(确认 + 必填理由)才落库;**永不**静默生效、**永不**绕过审计;**始终**对越界值 422。

**⑤ 交互原型 · 多状态覆盖**

- 默认态:三网络费用输入行(当前值 + 合法域提示)+ 保存按钮。
- 空状态:N/A(配置项恒有种子值,无空列表场景)。
