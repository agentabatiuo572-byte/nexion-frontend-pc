#### [FEAT-AUTH03] 注册发码强制人机验证

**① 用户故事**

- 作为平台运营方,我想要每一次注册取码都先通过人机验证,以便阻断脚本批量注册小号。
- 作为首次注册的真实用户,我想要一次简单的拖动就能取到验证码,以便不被复杂验证劝退。
- 作为已注册的老用户,我想要登录取码维持原有体验,以便日常登录不因反作弊被拖慢。

**② 验收(GWT)+ 异常路径**

- 阳光路径:Given 用户在注册页填妥国家码与手机号,When 首次点「发送验证码」,Then **先弹滑块验证层**(不发码);拖动至缺口容差内 → 成功态 → 弹层关闭 → 自动携凭证完成发送 → 进入验证码输入步骤并启动 60 秒重发倒计时。
- 阳光路径(登录不变):Given 用户在登录页,When 24h 内第 1、2 次发码,Then 直接发码不弹滑块;第 3 次起弹滑块(FEAT-AUTH01 原规则)。
- 异常1(滑块位置不符):Given 滑块层已打开,When 释放位置超出容差,Then 轨道错误提示 + 拼图抖动复位 + 目标位置重新随机,可立即重试;连续失败 5 次 → 弹层关闭 + Toast「尝试次数过多,请稍后再试」,本次发送中止且不计入发送次数。
- 异常2(用户中途关闭滑块层):Given 滑块层打开,When 用户点遮罩或关闭按钮,Then 弹层关闭、**不发码**、按钮回到可点态、无倒计时、无任何计数变化;再次点击重新弹出。
- 异常3(凭证过期/复用):Given 滑块通过后签发的凭证超过 120 秒未消费或已被消费一次,When 用它请求发码,Then 返回 `captcha_required`,重新弹滑块;凭证单次有效,不允许隐式复用。
- 异常4(重发按钮同样受管):Given 注册页已进入验证码输入步骤且倒计时结束,When 点「重新发送」,Then 同样先过滑块再发码(注册场景不区分首发与重发)。
- 异常5(60 秒冷却内被绕过):Given 距上次成功发码不足 60 秒,When 通过脚本/时序竞态直接调发码接口,Then 返回 `rate_limited`(含剩余秒数),不生成新码、不失效现有码;即便携带有效滑块凭证也照样拒绝(冷却优先于凭证)。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `config.otpGate.captchaAlwaysScenes` | string[] | 是 | `["register"]` | **新增**;列出「每次发码必过滑块」的场景;平台可配(后台参数组),空数组 = 全部回落到次数阈值规则 |
| `config.otpGate.captchaAfterSends` | number | 是 | 2 | 不变;仅对**不在** `captchaAlwaysScenes` 内的场景生效 |
| `config.otpGate.captchaTicketTtlSeconds` | number | 是 | 120 | 不变 |
| `scene`(发码入参) | `login`\|`register`\|`reset` | 是 | — | 不变;判定是否强制滑块的唯一依据,禁用页面路径推断 |

判定规则(纯函数,server 与 mock 同构):`需要滑块 = captchaAlwaysScenes.includes(scene) || 该手机号24h成功发码数 >= captchaAfterSends`。

**④ 状态机 + 禁止动作**

发码流程状态:`idle → captcha_pending →(通过)sending → cooldown(60s)→ idle`;`captcha_pending →(关闭/失败上限)idle`(不进 sending)。

禁止动作与行为边界:滑块未通过时**永不**发码;凭证**永不**复用;冷却期内**永不**因持有凭证而放行;**始终**在注册场景先验证后发码;失败与关闭**永不**计入发码次数(避免用失败刷高计数反向触发登录侧阈值)。

**⑤ 交互原型 · 多状态覆盖**

- 默认态:注册页「发送验证码」按钮可点;点击后滑块层由底部升起,含拼图轨道与提示文案。
- 空状态:N/A(无列表类空态);手机号未填或格式不合法时按钮本就置灰,不进入本流程。
- 加载态:滑块图形资源加载中显示轨道骨架(< 300ms 不展示防闪烁);验证通过到发码返回之间,滑块层显示成功态并禁止重复拖动。
- 报错/极限态:位置不符 → 轨道红色提示 + 抖动复位;连续 5 次失败 → 关闭 + Toast;凭证过期 → 重新弹层;冷却中被拒 → Toast「操作过于频繁,{s} 秒后可重发」;断网 → 滑块层内失败态 + 重试按钮,不静默关闭。

**⑥ 点击流矩阵**

| 触发元素 | 跳转 / 响应目标 | 转场 / 反馈 |
|---|---|---|
| 注册页「发送验证码」 | 当前页 | 打开滑块层(不发码);手机号非法时按钮置灰不可点 |
| 滑块拼图块(拖动释放) | 当前页 | 通过 → 成功态 → 自动关闭并发码;失败 → 抖动复位 + 重随机 |
| 滑块层遮罩 / 关闭按钮 | 当前页 | 关闭且不发码,按钮回可点态 |
| 验证码步骤「重新发送」(倒计时结束后) | 当前页 | 同「发送验证码」:先弹滑块 |
| 登录页「发送验证码」 | 当前页 | 前两次直接发码,第三次起弹滑块(原规则,不变) |
