#### [FEAT-GEN10] 前端 · 创世节点市场关闭态

**① 用户故事**

- 作为运营,我想要让创世节点在前端保持可见但不可购买,以便在时机未到时先建立认知与期待,而不是把入口藏起来。
- 作为浏览创世节点的用户,我想要清楚知道现在买不了以及原因,以便不反复尝试点击、不误以为是故障。
- 作为已持有创世节点的用户,我想要在市场关闭期间仍能查看我的持仓与权益,以便确认自己的资产不受影响。

**② 验收(GWT)+ 异常路径**

- 阳光路径:Given 后台把创世市场状态设为「暂未开放」,When 用户进入创世节点页,Then 页面内容(介绍 / 档位 / 权益 / 规则)照常展示,底部主按钮置为不可点并显示「当前市场暂未开放」,不显示倒计时、不显示剩余名额紧迫感文案。
- 阳光路径(持仓不受影响):Given 用户已持有创世节点,When 市场处于关闭态,Then 持仓、分红、权益页面照常可看可用;仅「购买 / 二级市场挂单」入口锁闭。
- 异常1(深链绕过):Given 用户从站外链接 / 历史记录直达购买页或结算页,When 市场为关闭态,Then 页面渲染锁定态并给出返回出口,**服务端(mock 同构)拒绝下单**,不出现「前端能提交、后端才拒」的落差。
- 异常2(状态优先级冲突):Given 市场关闭态与预售倒计时 / 售罄 / 熔断同时成立,When 用户查看主按钮,Then 按 **市场关闭 > 熔断 > 售罄 > 预售倒计时** 取最高优先级单一文案,不叠加、不闪烁互换。
- 异常3(配置拉取失败):Given 前端拉不到创世运营配置,When 用户进入创世页,Then 按**保守态**处理(视同不可购买)+ 失败提示与重试入口,**禁止**在配置未知时放行购买。
- 异常4(下单途中状态翻转):Given 用户已打开购买半屏,When 运营此刻切到关闭态,Then 提交时被拒并就地转为锁定态 + 说明,已支付资金不产生扣款(下单失败即回滚)。
- 异常5(关闭期到期恢复):Given 运营把状态改回开放,When 用户刷新或重新进入,Then 恢复正常购买链路,不需要清缓存、不残留锁定文案。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `genesisConfig.marketStatus` | `open` \| `closed` | 是 | `open` | **新增**;单源 = 后台 G4,server-canonical,client 仅缓存展示;`closed` = 可见但锁购 |
| `genesisConfig.closedNoticeKey` | string | 否 | 默认文案键 | 可选的文案变体键(仅在既有 i18n 键集合内取值,禁后台自由输入正文,防绕过文案纪律) |
| `genesisConfig.saleStartAt` | number \| null | 是 | null | 不变(预售锚);与 `marketStatus` 相互独立,优先级低于它 |
| `genesisConfig.showcaseEnabled` | boolean | 是 | true | 不变(商城展示开关);关闭市场**不等于**下架,两者独立 |

**④ 状态机 + 禁止动作**

购买可用性判定(单一派生,禁多处各判一套):
`closed → 锁购` ;否则 `熔断 → 锁购` ;否则 `售罄 → 转二级市场` ;否则 `预售未到 → 倒计时锁` ;否则 `开放购买`。

禁止动作与行为边界:关闭态下**永不**可提交订单(前端置灰 + 服务端拒单双重);**永不**在关闭态展示倒计时或名额紧迫文案(避免对不可购买的东西制造紧迫感);**始终**保留内容浏览与持仓查看;状态变更**永不**影响已成交订单与已持有资产。

**⑤ 交互原型 · 多状态覆盖**

- 默认态(关闭中):页面内容完整,底部主按钮灰态 + 「当前市场暂未开放」;档位区展示价格但不可选。
- 空状态:N/A(内容页恒有内容);若用户无持仓,持仓区沿用既有空态引导,不受本状态影响。
- 加载态:配置拉取中主按钮显示骨架/禁用态(< 300ms 不展示),期间不可点,避免「先可点后变灰」的误触。
- 报错/极限态:配置拉取失败 → 保守锁购 + 「暂时无法获取状态,请重试」+ 重试按钮;深链直达购买页 → 整页锁定态 + 返回出口;下单途中翻转 → 就地锁定 + 说明,不留半成品订单。

**⑥ 点击流矩阵**

| 触发元素 | 跳转 / 响应目标 | 转场 / 反馈 |
|---|---|---|
| 底部主按钮(关闭态) | 当前页 | 置灰不可点,附「当前市场暂未开放」说明;禁静默无反馈 |
| 档位卡片(关闭态) | 当前页 | 可查看详情,不进入结算;点击给出同一锁定说明 |
| 「了解创世节点」/ 规则入口 | 既有说明页 | 正常跳转(内容浏览不受限) |
| 「我的持仓 / 权益」 | 既有持仓页 | 正常跳转 |
| 二级市场入口(关闭态) | 当前页 | 一并锁闭并说明(与购买同一状态源) |
| 配置失败态「重试」 | 当前页 | 重新拉取;成功恢复真实状态,失败保持保守锁购 |

**⑦ 跨文档一致性**

- 状态源唯一:`marketStatus` 归后台 G4([FEAT-GEN10b]),前端只读派生,禁在页面各处硬编码判断。
- 与既有预售锁 / 售罄 / 熔断的关系写在 ④ 优先级链,四者共用同一派生出口,不新造第二套判定。
- 锁定态视觉复用既有锁定卡与 dock 范式(视觉细节归实现线与设计 skill,本规格不落像素)。
- i18n:「当前市场暂未开放」及配套说明 en/zh/vi 三语镜像;文案禁工程词与枚举值。
- 实现前必做:创世模块在 `admin-ops` 与 `Nexion-admin-prototype` 两仓的 parity 核对,以最新仓为改造面(批次决议 §五)。

#### [FEAT-GEN10b] 后台 · 创世市场状态开关(G4)

**① 用户故事**

- 作为运营,我想要一个开关直接关闭创世节点市场,以便无需改价格 / 改档位就能立即停售。
- 作为风控与审计,我想要每次开关都留确认、理由与记录,以便追溯停售与恢复的决策链。

**② 验收(GWT)+ 异常路径**

- 阳光路径:Given 运营在 G4 创世运营页,When 把「市场状态」从开放切到暂未开放并填写理由确认,Then 保存成功、审计落账,前端下次配置拉取即生效;页面显示当前状态与最近一次变更信息。
- 异常1(未填理由):Given 确认弹窗打开,When 理由为空即点确认,Then 阻止提交 + 字段级提示,不落库、不产生审计记录。
- 异常2(保存失败):Given 保存请求失败,When 返回错误,Then 显示失败态 + 原状态回填 + 重试入口,禁「界面已切、库未切」的假成功。
- 异常3(与熔断并存):Given 熔断闸已开启,When 运营再切市场状态,Then 两者可独立存在且互不覆盖;页面明示「当前生效的是熔断」以免运营误判已恢复销售。
- 异常4(关闭期误操作恢复):Given 市场处于关闭态,When 运营切回开放,Then 同样走确认 + 理由 + 审计(恢复销售是放大流出方向的动作,不豁免)。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `G.genesis.marketStatus` | `open` \| `closed` | 是 | `open` | 单源;写入走 G 域既有参数写入范式(版本号 + 幂等键 + 理由) |
| `G.genesis.marketClosedNoticeKey` | string | 否 | 默认键 | 下拉选择既有文案键,禁自由文本输入 |
| 审计记录 | AuditEntry | 是 | — | 操作人 / 时间 / 前值 → 后值 / 理由;确认⟺审计耦合 |

**④ 状态机 + 禁止动作**

状态:`open ⇄ closed`(双向,均需确认与理由)。禁止动作与行为边界:**永不**静默生效;**永不**无理由变更;**永不**用市场状态代替熔断闸(两者用途不同,不合并);**始终**在页面展示当前生效的最高优先级限制来源。

**⑤ 交互原型 · 多状态覆盖**

- 默认态:状态选择控件(开放 / 暂未开放)+ 当前状态徽标 + 最近变更摘要 + 保存按钮。
- 空状态:N/A(配置项恒有值)。
- 加载态:页面数据拉取骨架;保存中按钮 loading 并防连点。
- 报错/极限态:理由为空 → 字段级红字;保存失败 → 失败态 + 重试;熔断同时开启 → 顶部提示当前实际生效来源。

**⑥ 点击流矩阵**

| 触发元素 | 跳转 / 响应目标 | 转场 / 反馈 |
|---|---|---|
| 「市场状态」选择控件 | 当前页 | 切换为待保存态,未确认前不生效 |
| 「保存」 | 确认弹窗 | 展示前后值 + 必填理由;确认 → 审计落账 → 成功提示;失败 → 失败态 |
| 确认弹窗「取消」 | 当前页 | 关闭弹窗,回到未保存态 |
| 文案变体下拉 | 当前页 | 仅在既有文案键内选择,预览对应用户端提示 |

**⑦ 跨文档一致性**

- 与 [FEAT-GEN10] 前端两端字段名、取值域、默认值三处一致。
- 熔断闸沿用 J 域既有键,本规格不新增 kill 闸、不改闸数(哨兵计数不动)。
- 后台 PRD G 域需补该开关条目(实现批次收口时走后台 PRD 同步)。
