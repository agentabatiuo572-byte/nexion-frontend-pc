#### [FEAT-VND01] 用户端 · 银行卡法币提现

**① 用户故事**

- 作为越南本地用户,我想要把收益直接提到我的银行卡,以便不必先懂加密钱包就能拿到钱。
- 作为第一次法币提现的用户,我想要清楚看到按什么汇率折算、扣多少费、到手多少盾,以便下单前心里有数。
- 作为提交后等待的用户,我想要看到订单当前走到哪一步,以便知道还要等多久、卡在哪里。
- 作为运营,我想要法币提现走与 USDT 同一套风控与审批,以便不出现绕过风控的第二条出金路径。

**② 验收(GWT)+ 异常路径**

- 阳光路径:Given 用户可提余额 ≥ 最小提现额且已过风控,When 在提现页选「银行卡(越南盾)」通道 → 输入提现金额 → 选择已保存的收款账户 → 查看折算明细(卖出牌价 / 法币提现费 / 到手盾数)→ 确认提交,Then 生成提现单进入受理态,余额即时冻结对应金额,页面转入订单追踪;服务商回执返回成功后订单转已到账并落账单。
- 阳光路径(报价时机):Given 用户填写金额,When 进入确认页,Then 按当前卖出牌价生成**短时报价**(默认 10 分钟)并倒计时展示;倒计时结束未提交则报价失效,需刷新重新报价——**禁**用过期报价下单。
- 阳光路径(风控通过后重新报价):Given 订单命中人工审核,When 审核通过,Then **重新生成报价**再执行付款(审核期间不锁汇);若新报价与用户下单时偏差超过阈值(默认 2%),需用户在应用内二次确认后才继续,超时未确认则订单取消并解冻余额。
- 异常1(资金来源不合规):Given 用户余额中包含未消费的充值本金,When 计算可提法币额度,Then 仅「收益与可提桶」部分可提,充值本金部分不计入并给出说明与去向(可用于购机消费或原路退款),**永不**把充值本金折算成法币出金。
- 异常2(收款账户缺失或校验失败):Given 用户未添加收款账户,或账号 / 户名格式不符所选银行规则,When 提交,Then 字段级提示并阻止提交;账户信息校验失败**不产生**提现单、不冻结余额。
- 异常3(牌价不可用):Given 卖出牌价拉取失败或数值非法,When 用户进入法币通道,Then 该通道置灰并说明「汇率更新中,请稍后或改用 USDT 通道」,**永不**回退到写死汇率或复用买入价折算。
- 异常4(服务商拒付 / 退回):Given 订单已提交服务商,When 返回失败或银行退回(账户不存在 / 户名不符 / 账户冻结),Then 订单转「已退回」终态,**冻结金额原额解冻回余额**(不扣手续费),页面给出退回原因与修改账户后重试的入口。
- 异常5(服务商超时无回执):Given 订单提交后超过承诺时效仍无回执,Then 订单保持「处理中」并升级为人工跟进态(不自动成功、不自动失败),用户侧显示「银行处理中,已为你跟进」+ 客服入口;资金保持冻结不回滚。
- 异常6(重复提交 / 并发):Given 用户连点或多端同时提交,When 请求到达,Then 以落盘为准仅生成一单(幂等键),第二次为 no-op;**禁**出现双份冻结或双份出款。
- 异常7(通道停用):Given 运营停用法币提现通道或触发熔断,When 用户进入提现页,Then 该通道置灰并说明,已提交在途单不受影响照常推进。

**③ 数据字典 + 生成规则**

**④ 状态机 + 禁止动作**

`草稿 →(提交)受理中 →(风控 pass)待付款 →(重新报价+执行)处理中 →(服务商成功回执)已到账`(终态);
`受理中 →(风控 manual)人工审核 →(通过)待付款 | (拒绝)已拒绝(解冻)`;
`处理中 →(失败/退回)已退回(解冻)`;`处理中 →(超时)人工跟进 →(最终回执)已到账 | 已退回`;
`受理中 | 人工审核 →(用户取消,仅未进入付款前)已取消(解冻)`。

禁止动作与行为边界:客户端**永不**推进任何状态(全部服务端权威);**永不**用过期报价执行付款;**永不**在人工审核期间锁汇;**永不**从充值本金桶出金;**询问后**(报价偏差超阈值时用户二次确认)才继续执行;失败与退回**始终**原额解冻且不收费;通道停用**永不**影响在途单。

**⑤ 交互原型 · 多状态覆盖**

- 默认态:提现页顶部通道分段(USDT / 银行卡),法币态显示金额输入、可提额度说明(区分收益桶)、收款账户行、折算明细卡(卖出牌价 + 费用 + 到手盾数)、报价倒计时、提交按钮。
- 空状态:未添加收款账户 → 明细区替换为「添加收款账户」引导卡;可提余额为 0 → 说明当前无可提金额及如何产生收益。
- 加载态:牌价与费率拉取骨架(< 300ms 不展示);报价生成中按钮 loading;提交中防连点。
- 报错/极限态:牌价不可用 → 通道置灰 + 改用 USDT 提示;账户校验失败字段级红字;报价过期 → 明细区转「报价已过期,点击刷新」;偏差超阈值 → 二次确认弹层(新旧报价对照 + 倒计时);退回态 → 原因 + 改账户重试入口;超时跟进态 → 说明 + 客服入口;超长盾数字千分位不溢出。

| 折算明细「?」 | 说明半屏 | 解释卖出牌价、费用构成、到账时效 |

**⑦ 跨文档一致性**

- 风控:法币轨与 USDT 轨**共用**同一套风控路由与闸门(FEAT-WD01 / SPEC-7),不新造第二套判定、不新增绕过路径;新增的通道维度只作为风控输入信号。
- 费用:USDT 侧网络确认费(FEAT-WD02)与法币侧提现费率是**两套独立参数**,不互相派生、不共用字段;提现页费用区按通道切换展示。
- 牌价:买入与卖出共用同一基准价,两个点差各自可配;全站 VND 取数口从「唯一 quoteRate」改为「按方向取 buyRate / sellRate」,实现线须逐个消费点核对方向不取反(充值取买入、提现取卖出)。
- 账户管理:收款银行账户与提现地址并列在同一管理页,共用「短信确认 + 保护期 + 频控」机制口径(FEAT-KYC-RM01a),不写两套。
- **同名收款校验:不做**(主人 2026-07-31 裁决,反洗钱不在本轮考量)。收款账户安全由账户保护期、7 天频控、风控分与人工审核四项承担;实现线不得因此另加身份类字段或验证步骤。此处仅作决策留痕,非待办。
- i18n:通道名、牌价与费用说明、报价过期与偏差确认、退回原因、跟进态 en/zh/vi 三语镜像;金额与货币格式按越南本地习惯,盾数不显示小数。

#### [FEAT-VND01b] 后台 · 法币提现费率与双向牌价配置

**① 用户故事**

- 作为运营,我想要分别设定入金与出金的汇率点差,以便两个方向的价差按业务需要各自调整。
- 作为运营,我想要配置法币提现的费率与限额,以便覆盖代付成本并控制出金节奏。
- 作为审计,我想要每次调整都留确认、理由与记录,以便追溯每一次价差与费率变化。

**② 验收(GWT)+ 异常路径**

- 阳光路径:Given 运营在汇率牌价模块,When 分别设置买入点差与卖出点差并保存,Then 页面实时预览两个方向的派生牌价与价差幅度;确认(含前后值 diff)+ 必填理由 → 审计落账;前端下次拉取即按方向取数。
- 阳光路径(费率):Given 运营在提现参数模块,When 设置法币提现费率(百分比 + 最低收费 + 封顶)与单笔上下限、日限,Then 保存后前端法币通道按新参数计费与校验。
- 异常1(点差越界):Given 任一方向点差超出合法域(0–3%)或为非数值,When 保存,Then 拒绝并给字段级提示,不落库、不产生审计记录。
- 异常2(价差方向倒挂):Given 配置导致卖出价 ≥ 买入价(即平台在两个方向都亏),When 保存,Then 阻断并明确提示倒挂风险,需超管确认才可强制保存(默认拒绝)。
- 异常3(费率与最小提现额冲突):Given 最低收费 ≥ 最小提现额,When 保存,Then 拒绝并提示会导致用户到手为负或为零。
- 异常4(保存失败):Given 请求失败,When 返回错误,Then 失败态 + 原值回填 + 重试,禁假成功。
- 异常5(通道启停):Given 运营停用法币提现通道,When 保存,Then 属放大/收紧资金流出方向的动作,走超管确认 + 审计;在途单不受影响。

**④ 状态机 + 禁止动作**

N/A(参数配置)。行为边界:**询问后**(确认 + 理由)才生效;倒挂配置**默认拒绝**,仅超管可强制;**永不**静默改变对外汇率口径;**始终**在保存前预览两个方向的派生牌价;通道开关**永不**影响在途单。

**⑤ 交互原型 · 多状态覆盖**

- 默认态:基准价 + 买入点差 + 卖出点差三输入,右侧实时预览两个方向派生牌价与价差;下方费率与限额分组;通道开关独立成行。
- 空状态:N/A(配置项恒有种子值)。
- 加载态:数据拉取骨架;保存中按钮 loading 防连点。
- 报错/极限态:越界字段级红字;倒挂阻断提示 + 超管确认路径;费率与最小额冲突提示;保存失败态 + 重试。

| 触发元素 | 跳转 / 响应目标 | 转场 / 反馈 |

| 买入 / 卖出点差输入 | 当前页 | 实时校验 + 双向牌价预览联动 |

| 「保存」 | 确认弹窗 | 前后值 diff + 必填理由 → 审计落账 |
| 倒挂强制保存 | 超管确认弹窗 | 二次身份确认 + 风险声明,拒绝为默认动作 |

| 「恢复默认」 | 当前页 | 回填种子值,仍走保存确认链 |

**⑦ 跨文档一致性**

- 与 [FEAT-VND01] 前端字段名、合法域、默认值三处一致,焊跨仓逐键等值哨兵;既有汇率跨仓数学一致性哨兵需扩展到卖出方向(否则新方向是无人看守的敞口)。

- 后台 PRD D 域补法币提现参数与双向牌价条目(实现批次收口时同步);新增模块走后台模块位置清单。
- 实现前必做:汇率与提现参数模块在两仓的 parity 核对,以最新仓为改造面(批次决议 §五)。
