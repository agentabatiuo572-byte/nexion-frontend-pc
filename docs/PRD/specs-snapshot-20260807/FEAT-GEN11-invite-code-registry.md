#### ① 用户故事

- 作为运营,我想要**在后台批量生成**创世邀请码并看到每个码的去向,以便把限量名额精确发给目标用户、事后可追溯。
- 作为运营,我想要**作废还没被用掉的码**(填理由、留痕),以便发错人或渠道作废时止损。
- 作为用户,我想要输入手里的邀请码后**明确知道成功与否、失败是哪种失败**,以便知道该找谁而不是反复重试。

#### ② 验收(GWT)+ 异常路径

- **阳光1(发码)**:Given 运营在后台创世域邀请码区,When 选择生成数量 N 并确认,Then 系统生成 N 个互不重复的码、状态「未使用」、记录发放人与时间;列表立即可见;生成动作留审计。
- **阳光2(核销)**:Given 用户持一个「未使用」的码,When 在创世页提交,Then 校验通过 → 该码状态置「已使用」、记录核销账号与时间;用户获得资格门的「持码」条件;**同一个码再次提交一律拒绝**。
- **异常1(码不存在)**:Given 提交的码不在码表(含格式正确但从未发放),When 提交,Then 拒绝并提示「邀请码无效」,不改变任何状态。
- **异常2(码已被使用)**:Given 码状态为「已使用」或「已作废」,When 提交,Then 拒绝并提示对应原因(已被使用 / 已作废),**不泄露核销者身份**。
- **异常3(本账号已持码)**:Given 当前账号已核销过任一码,When 再提交另一个码,Then 拒绝并提示「本账号已使用过邀请码」;**已持有的码不受影响**(不覆盖、不释放)。
- **异常4(作废)**:Given 运营作废一个**未使用**的码,When 确认(必填理由),Then 状态置「已作废」、留审计;**已核销的码不提供作废入口**(见 ④ 禁止动作)。
- **异常5(并发核销)**:Given 两个账号同时提交同一个未使用码,When 并发,Then **只有一个成功**,另一个按异常2 拒绝(先占后改,不允许两边都成功)。

#### ③ 数据字典 + 生成规则

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `code` | string | 是 | — | 形如 `NEXGRID-OG-XXXX`,后 4 位由**系统生成**(不接受手输,避免撞码与人为规律);全表唯一 |
| `status` | `"unused" \| "used" \| "void"` | 是 | `unused` | 状态机见 ④ |
| `issuedBy` | string | 是 | — | 发放操作者标识 |
| `issuedAt` | number(ms) | 是 | — | 发放时刻,server 时钟 |
| `note` | string | 否 | — | 发放备注(发给谁 / 哪个渠道),运营可填 |
| `redeemedBy` | string \| null | 是 | null | 核销账号;仅 `used` 态非空 |
| `redeemedAt` | number \| null | 是 | null | 核销时刻;仅 `used` 态非空 |
| `voidedBy` / `voidedAt` / `voidReason` | string \| number \| null | 是 | null | 仅 `void` 态非空;`voidReason` 必填 8-200 字 |

**不设字段**:有效期 / 过期时间 —— 主人 2026-08-04 拍板**不设**(创世为限量销售,码本身即稀缺凭证;再加时限徒增运营解释成本)。

用户侧既有字段 `user.genesisInviteCode` 语义收窄为「**本账号已核销的那个码**」(一人至多一个)。

#### ④ 状态机 + 禁止动作

```
unused ──(用户核销)──> used     [终态]
   │
   └───(运营作废)────> void      [终态]
```

**禁止动作**:
- **永不**允许 `used → void`(已核销 = 资格已发生;要收回资格走「取消资格」而非「作废码」)—— 主人 2026-08-04 拍板;
- **永不**允许 `used`/`void` 回到 `unused`(两者皆终态,不可复用);
- **永不**允许手输码值创建(只许系统生成);
- **永不**在拒绝文案里泄露核销者身份;
- 作废属高敏动作:**询问后**(确认弹窗 + 必填理由)才执行,**始终**留审计。

#### ⑤ 交互原型 · 多状态覆盖(后台侧)

- **默认态**:码列表(码值 / 状态 / 备注 / 发放人时间 / 核销账号时间),按状态筛选;顶部「生成邀请码」入口。
- **空状态**:尚未发过码 → 引导态 + 生成入口,不是空白表格。
- **加载态**:列表骨架;生成中按钮 loading 防连点。
- **报错/极限态**:生成失败 → 失败态 + 重试,不出现「界面已加、库未加」的假成功;作废失败同款;已核销的码**不渲染作废入口**(不是渲染后禁用 —— 禁用态仍暗示"某些条件下可作废")。

#### ⑥ 点击流矩阵(后台侧)

| 触发元素 | 响应目标 | 转场 / 反馈 |
|---|---|---|
| 「生成邀请码」 | 确认弹窗 | 选数量 + 可填备注 → 确认 → 审计落账 → 列表刷新 + 成功提示 |
| 状态筛选 | 当前页 | 即时过滤;计数随之更新 |
| 未使用码的「作废」 | 确认弹窗 | 展示码值 + **必填理由 8-200** → 确认 → 审计 → 状态转 `void` |
| 已使用码 | — | **无作废入口**(见 ④) |
| 核销账号 | 用户详情 | 可跳转查该账号(复用既有用户查询入口) |

#### ⑦ 跨文档一致性
