#### [FEAT-PSP01] 用户端 · 托管页充值流程

**① 用户故事**

- 作为想充值的越南用户,我想要选好金额后直接跳到支付页扫码付款,以便不用手工抄银行账号和附言码。
- 作为付完款的用户,我想要立刻看到「已收到,正在核实」并在到账后收到明确通知,以便不必反复刷新猜测状态。
- 作为付款中断的用户,我想要清楚知道这笔订单还有效多久、能不能继续付,以便不重复付款。

**② 验收(GWT)+ 异常路径**

- 阳光路径:Given 用户在充值页选择法币通道并输入金额,When 确认下单,Then 平台按当前**买入牌价**锁价生成充值订单(含唯一订单号与有效期)→ 跳转服务商托管页 → 用户扫码付款 → 付款完成后回跳应用,应用显示「已收到付款,正在核实」;服务商回调经平台校验通过后订单转已到账,余额与账单同步更新并推送通知。
- 阳光路径(入账权威):Given 用户已从托管页回跳,When 应用渲染状态,Then 状态一律来自平台订单查询结果;**客户端回跳参数只影响展示,永不作为入账依据**——未收到服务商回调前,订单停留在「核实中」,余额不增加。
- 异常1(付款中断 / 用户放弃):Given 订单已创建但用户未完成付款,When 用户返回应用,Then 订单为「待付款」并显示剩余有效期与「继续付款」入口;超时后订单转「已过期」,不占用额度、不产生资金记录。
- 异常2(迟到付款):Given 订单已过期,When 服务商后续仍回调该笔付款成功,Then **不自动入账**,转人工核实队列并在用户侧显示「已收到一笔逾期付款,正在处理」+ 客服入口;运营核实后可手工入账或原路退回。
- 异常3(金额不符):Given 实付金额与订单金额不一致(多付 / 少付),When 回调到达,Then 订单转差额核实态,不按订单金额入账;少付按实收处理或退回、多付退差,均由运营裁决并留审计。
- 异常4(重复回调 / 重复付款):Given 同一笔付款的回调重复到达,或用户对同一订单付款两次,When 平台处理,Then 以服务商流水号做幂等,重复回调为 no-op;重复付款第二笔进人工核实,**禁**双倍入账。
- 异常5(回调验签失败或来源不可信):Given 回调签名校验不通过、时间戳超窗或来源不匹配,When 平台收到,Then **拒绝处理并告警**,不改变任何订单状态、不入账;不向调用方泄露失败细节。
- 异常6(服务商不可用):Given 托管页拉起失败或服务商健康检查异常,When 用户下单,Then 通道置灰并说明,引导改用备用通道(人工转账轨 / USDT 链上轨),已创建订单不受影响。
- 异常7(牌价失效):Given 下单时锁定的买入牌价已超过锁价窗,When 用户在托管页迟迟未付,Then 订单按既有锁价规则处理(到期即过期,不按新价追补),口径与既有银行轨一致,不新造第二套锁价逻辑。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填 | 默认 | 生成规则 / 约束 |
|---|---|---|---|---|
| `depositOrder.orderNo` | string | 是 | — | server mint,全局唯一,禁客户端生成;作为对账主键 |
| `depositOrder.channel` | `psp-hosted` \| `bank-manual` \| `usdt-chain` | 是 | — | 通道枚举单源;`psp-hosted` 为本规格新增 |
| `depositOrder.amountUsd` / `amountVnd` | number | 是 | — | 下单即定;`amountVnd` 按**买入牌价**换算并锁定,精确到盾 |
| `depositOrder.fxSnapshot` | { buyRate; lockedAt; expiresAt } | 是 | — | 锁价快照;调价不影响在途单 |
| `depositOrder.status` | 见状态机 | 是 | `pending_payment` | server-canonical,客户端只读 |
| `depositOrder.providerRef` | string | 否 | — | 服务商侧流水号;回调幂等键 |
| `depositOrder.creditedAt` | number | 否 | — | 入账时刻,仅由回调驱动写入 |
| 回调请求 | 原始字节 + 签名 + 时间戳 + 事件号 | 是 | — | 验签基于**原始报文**;事件号做永久唯一键;超窗拒绝 |
| 适配层接口 | `createHostedOrder` / `queryOrder` / `handleCallback` / `refund` | 是 | — | **服务商无关契约**;换厂商只换实现,不改上层编排 |

**④ 状态机 + 禁止动作**

`pending_payment →(用户付款 + 回调校验通过)credited`(终态);
`pending_payment →(超时未付)expired`;
`expired →(迟到回调)manual_review →(运营裁决)credited | refunded`;
`pending_payment →(金额不符回调)amount_mismatch → manual_review`;
`任意态 →(回调验签失败)状态不变`(仅告警,不流转)。

禁止动作与行为边界:**永不**以客户端回跳参数入账;**永不**在回调验签通过前改变余额;**永不**对同一流水号重复入账;**永不**自动入账逾期或差额付款(一律人工裁决);**始终**对每次回调做幂等与留痕;失败**永不**向外暴露内部细节。

**⑤ 交互原型 · 多状态覆盖**

- 默认态:充值页法币通道 → 金额输入 + 牌价行 + 应付盾数预览 + 「去支付」;下单后订单卡显示有效期倒计时与「继续付款」。
- 空状态:无历史充值记录时,最近入金区显示引导而非空白;通道未开通时显示说明与备用通道入口。
- 加载态:牌价与通道健康检查拉取骨架;拉起托管页时全屏 loading 并可取消返回;回跳后「核实中」态带进度说明(非通用转圈)。
- 报错/极限态:托管页拉起失败 → 错误态 + 重试 + 改用其它通道;订单过期 → 过期态 + 重新下单入口;迟到 / 差额 → 人工核实说明 + 客服入口;牌价不可用 → 通道置灰;网络断开回跳丢失 → 从订单列表可恢复查看该单状态。

**⑥ 点击流矩阵**

| 触发元素 | 跳转 / 响应目标 | 转场 / 反馈 |
|---|---|---|
| 法币通道分段 | 当前页 | 切换表单;通道不可用时置灰 + 说明 |
| 「去支付」 | 服务商托管页(外部) | 全屏跳出;跳出前落单并展示订单号 |
| 托管页回跳 | 订单核实中页 | 展示「已收到付款,正在核实」;状态以平台查询为准 |

| 「重新下单」 | 充值页 | 带回原金额,重新锁价 |
| 「联系客服」(人工核实态) | 客服入口 | 右进左出,携订单号 |
| 「查看账单」 | 账单页 | 到账后可核对入账记录 |
