# B38 后端九项交付契约

日期：2026-11-08。来源：[九项目标及验收状态](https://github.com/agentabatiuo572-byte/uvel-docs/blob/main/handoffs/2026-10-28/backend/B38-GOALS-20261108.md)。本文件记录后端目标与候选接口，**不是已发布或正式 TEST 通过证明**。

用户本轮最新决定：先只改后端；不修改前端 UI，不继续页面预览调整。页面是否已接入单独记账，后端实现／接口验收与页面完成分别报告。原 BE-01～47 与本轮 B38 重号目标不得互相核销。

## 1. D6 汇率与资金审批（B38-BE-02）

- 整组比较基准价、买入点差、报价有效期。提高基准价或降低最终充值报价走 A2；直接 PATCH 不能绕过。降低基准价通常也降低充值报价，不能仅按单字段“下降”认定无资金风险。
- 基准价上调在提案和批准时均检查可靠覆盖率及红线；批准重核当前版本、双方现有权限、不同执行人。旧版提案不覆盖新配置，待审不改变当前值或旧单锁价。
- 新增 `POST /api/admin/finance/fx-quote/preflight`，沿 `FxQuoteUpdateRequest` 接收整组值、expectedVersion、reason。响应包括 `current/proposed/before/after/approvalRequired/baseRateIncrease/rechargeQuoteDecrease/fundingCheckRequired/fundingCheckPassed`。不足或不可靠返回 `D6_TREASURY_COVERAGE_BLOCKED`，直接敏感保存返回 `D6_FX_QUOTE_APPROVAL_REQUIRED`。
- 提案沿 `POST /api/admin/platform/audit/operations`，命令 `D/d6_fx_quote`、目标 `D/fx_quote/current`。原键找回和批准沿 A2 现有契约。
- 汇率读取的可空 `approval` 提供原工单、状态、提交／决定时间、预期版本及 applied；新订单取生效后新牌价，已有订单保持自身锁定值。
- PC D6 的配套提交、预检和原单入口暂未接入；后端交付不冒充页面可办理。

## 2. 未知操作结果核查（B38-BE-03）

- 超过 24 小时、查询 NOT_FOUND 或关闭标签页均不能自动解锁、换号重发。核查绑定原对象、动作、命令和请求摘要，记录核查人、时间、依据／工单及结论。
- 核实成功只根据权威原业务凭据收尾，不重放资金或配置；确证未执行才允许后续新操作，原命令不得再次执行。证据不足保持未知和锁定。
- 核查只接受服务端已保存的来源与证据，不能以操作者填“成功”替代资金事实。未保存可信来源的旧记录继续待核查，不能凭空补原请求。
- 集合入口按明确业务对象绑定，不能将同一 URL 的所有无关 A2 提案或导出全部锁住。
- 用户已确认独立核查权限 `platform_a2_unknown_investigate` 仅授有效超管，且服务端校验当前真实超管身份与原业务范围；财务／风控即使误获该码也不能结案。不因原批准权自动获得结案权，亦不增加付款／退款或重执行能力。前端不改。
- 成功审计关联必须匹配服务端原记录 ID、scope、命令号及请求哈希，不能用另一用户同键审计串证。已知成功或确定失败不允许降为 UNKNOWN。批量与单项按同一权威对象成员互斥，订单号大小写别名不能绕过，执行上下文不跨请求。

## 3. 权限对齐（B38-BE-RBAC）

- 财务主管可查看 D5/D7 待批进度及本人原单，A2 范围限定 D 域；保留精确本人 E4 原单读取／撤回，不开放无关业务审批。没有因此新增批准权。
- E4 财务主管／有权超管可发起退款，增长不可发起；由另一有权超管批准。直接退款路由及共享服务均要求实际 A2 回放上下文和原工单，不能以直退接口绕过双人。
- 客服仅在既有授权用户范围读取账单和运行余额；两个业务入口统一执行对象范围校验。不得以 `finance_d4_read`、平台导出或写权替代单用户权。
- D6 读取角色为财务、财务主管、风控、审计、超管；增长拒绝。风控 I5 只读，不保留旧内容写入／发布授权。
- 启动 seed、前向迁移及软删除授权关系恢复须同口径；正式 TEST 验新旧库重跑、重登及重启后授权，不以按钮隐藏代替接口拒绝。

## 4. 普通订单退款后的任务收益（B38-BE-06）

- 未完成任务随退款停止，不再派发或获得该任务收益；已完成未结算任务按原规则结算一次；已到账设备收益不扣回。试用转购和促销奖励追回保持各自规则，退款金额沿 B37 独立决定。
- 当前计算 V2 已验证完成任务的结算不依赖退款后的设备仍持有。退款后模拟任务只允许处理退款前已存在的当前任务：截止前已完成者结算，跨过退款截止者取消，结算后关闭；不补派或生成回填任务。
- 订单详情的 `refundImpact` 区分 `completedPending`（taskCount/usdtAmount/uvtAmount）、unfinishedTaskCount、stoppedTaskCount、`creditedRetained`（同金额结构），含 scope=ORDINARY_PURCHASE、asOf、runtimeComplete、runtimeUnavailableReason。待结算合并已有持久事实与 Redis VERIFIED 并减掉已提交 allocation，不重复别名；运行态失败或可见模拟任务的运行关联缺失／不匹配时，完成待结算及未完成总数为 null，不以 0 冒充空任务。重试失败不能丢失来自权威退款订单的停止归因。试用转购不套用本项投影。
- PC E4 现有 UI 保留，配套影响展示暂未接入。

## 5. D4 区间核对（B38-BE-09）

- 每币种读取严格早于 from 的最后一笔已结算账单余额，按账单时间及 id 确定末笔，作为 openingBalances 和区间计算起点。区间无流水的币种仍带入期初。
- 未结算账单不参与；closingBalances 从期初叠加区间已结算交易，不以缺流水推成零。历史 to 不与当前钱包比较，真实逐笔断点保留，统计不混入假钱包差额。
- 客服仍需授权用户范围。PC 本轮不改，页面显示适配单独记录。

## 6. 历史充值累计异常（B38-BE-26）

- 先按异常类型、来源订单、资金及账本证据盘点，并列累计影响。财务负责人签认逐类方案后才可实际处理。
- 只有证据齐全记录可受控修复／结案，保留签认、执行人、依据与结果；不足项保持 OPEN 和累计不完整。重复处理不重复资金或账本，不批量清 OPEN。
- 正式 TEST 只读盘点：当前异常表 0 条、OPEN 0、待核金额 0；没有执行清理，也不能凭空集证明清理链通过。财务责任与正／反样本仍待明确。
- 不恢复退役的充值冲正入口；PC 历史累计指引本轮不改。

## 7. D1 银行卡待人工核对（B38-BE-27）

- 银行订单接口新增 `settlementStatus=UNSETTLED|MANUAL_REVIEW|CREDITED`；非法值拒绝。按原意图与唯一支付方原单计数，一订单一次，不因回单联接或重复回调重复统计。
- `total` 应用全部筛选；`manualReviewCount` 按渠道／订单状态／关键词范围统计完整待人工总数，不受结算状态选择及分页影响。概览 `bankManualReviewCount` 同一权威查询全量统计。
- 待人工列表只以 MANUAL_REVIEW 结算状态筛选，不额外限定 PROCESSING 而漏掉已过期仍须核对的订单。保留原支付渠道、订单展示状态及实际结算事实。
- PC 页签、待办和筛选本轮未接入，不将后台新增字段当页面已显示。

## 8. 提现网络实际可用状态（B38-BE-29）

- App 与后台共用网络配置、提现总开关、支付方模式及每网能力判定。运营配置开不代表实际可用。
- 后台保留 `networkEnabled` 配置，`networkStatus` 含 configured、enabled、disabledReason、state（AVAILABLE/UNAVAILABLE/UNKNOWN）；读取失败、缺失或非法总开关为 UNKNOWN／enabled=null，App 继续拒绝使用不可靠能力。
- `networkStatusReliable` 标记完整性；任一状态未知时 effectiveNetworks=null，不能当空数组宣称已确认没有可用网。明确关闭、供应方未启用等确定事实显示不可用原因。
- TRC20/BEP20/ERC20 按后发 B42“三网同一套审查规则”决定；本项投影不新增 TRC20 专属审查规则，也不替代 B42 独立修复。
- 配置写入、版本和原审批门槛不变。PC D5 本轮不改，未知状态的页面消费待独立接入。

## 9. K1 权威用户编码（B38-BE-36）

- 收益查询 LEFT JOIN 实际未删除用户，按与 C1 一致的服务端权威编码规则返回 userNo，同时保留 userId。用户缺失或删除时 userNo=null，不从孤立收益 userId 在前端拼造。
- 金额、上限、排序及收益读取权限不变，不增加用户详情授权。是否能跳转仍由现有 `user_c1hub_read` 和目标页范围控制。
- 本轮只交付后端字段；K1 编码展示和链接暂未改动。
