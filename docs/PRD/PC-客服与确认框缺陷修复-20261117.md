# PC 客服与确认框逻辑修复（2026-11-17）

## 共用数字确认（BUG-413、BUG-163-17/19）

单值和多字段的未修改判定按十进制字符串规范化比较，保留合法金额末位差异。多字段先检查普通十进制格式，再检查步长；不接受科学计数。方向比较同样不经浮点。当前值未配置且新值为 0 时不触发放大提示；未配置仍是未知，不补成已配置的 0。F2 缺层仍需后端初始化（UnilevelCommissionService.requireCompleteLayerRates:307–317），沿用 F2-P01。

## M3 接待实例（BUG-416）

结束接待的原命令按 actorId/customerId/sessionRef 保存；当前实例和历史实例分别恢复。不同 sessionRef 的历史记录不阻断当前接待结束；历史完整原记录仍保留，查询入口沿用。过期历史只查不重发。依据 SupportSessionService.end:108–116：结束携带实例引用，不匹配时 SUPPORT_SESSION_CHANGED；成功原键优先回放。旧无实例记录沿用保守核对，不推断原请求失败。

## M1 与 M3 读取（BUG-164、BUG-163-06）

M3 conversationNo 定位等资格及可见范围就绪后才消耗选中意图。M1 暂停维护明细使用每页实时 snapshot 的数量，不再和旧卡片数字强制相等；仍校验本页列表和同次 overview 的数量。analytics 各明细续页必须回传自身 queryVersion，缺版本不能绕过后端 SUPPORT_ANALYTICS_VERSION_REQUIRED；维护绩效明细使用 expectedQueryVersion。授权名册的可接待切片由 availableSupportRoster 返回，筛选 enabled !== false 且 status !== disabled，卡片同用该切片。名册 permission/error/loading/ready 分开，不增加权限；下钻呈现与无权限说明交视觉。

## 客服恢复及支付理由（BUG-163）

模板／话术重试只重读 session-templates/overview，不刷新名册、会话或资格；FAQ 已独立读 knowledge/overview。URL 有 intent 时覆盖本标签页旧选项，没 URL 意图才恢复 sessionStorage。普通 403 不证明原发送失败；重放被拒、会话忙或权限变更保留原命令（私聊内容仍按权限失效合同清除）。结束接待重放被拒同样不提供基于该拒绝的解除。精确 SUPPORT_COMMAND_NOT_FOUND 才可进入未过期原样重试。

C5 支付规则理由按 Java String.trim 去掉首尾所有 U+0000–U+0020 后计算 UTF-16 长度并提交，范围仍 8–200；不改控件和文字。C2 动作台账登记当前会话撤销审批、代看和黑白名单，既有用户读写授权不变。G2 规格移除退役 KYC 累计阈值，现行只有个人与平台日额度。
