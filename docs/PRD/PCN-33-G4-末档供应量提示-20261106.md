# PCN-33 · G4 末档供应量确认提示

2026-11-06。适用端：PC 管理端「金融产品 → 创世节点销售与收益」（`/finance-products/genesis`）。用户已确认本次具体页面变更。

## 业务行为

- 修改现有最后一档时，在原确认表单中随截止输入展示「末档截止数量：修改前 → 修改后」和「系列总供应量：修改前 → 修改后」。前值取本次打开表单时的档位和页面总量，后值取本次输入。
- 在现有末档后新增档位时，展示原末档截止到新末档截止的变化，以及已有系列总供应量的对应变化。新增说明明确：保存时会同步调整已有系列总供应量，不会自动开放销售；尚未发布系列时仍需单独发布，发布时以末档截止确定总量。
- 明确末档截止数量和系列总供应量均不得低于已售数量。空值、非整数、未超过本档起点或低于已售数量的输入不展示数值后值，显示「待填写有效截止数量」。提示本身不改变原表单校验和服务端裁决。
- 没有已发布系列时不虚构系列总供应量变化，明确显示「尚未发布 → 尚未发布」。

## 保持范围

首档创建、非末档编辑、删除及服务端允许直接保存的操作沿用现有行为；末档增加已有系列总量和追加档位按下述已确认审批交互执行。末档动态提示复用现有 `multi-field.feedback`，不修改共享确认组件或通用 A2 语义。提示中的后值表示拟改目标，须审批的修改在批准后生效。

## 验收方式

对应本轮计划 G4-01 至 G4-04、CROSS-01：真实页面分别打开末档编辑和新增档位，输入有效整数、空值和小数，核对前后值与已售下限提示；非末档只读打开后取消。保存验收由统一 TEST 操作完成，保存后回读末档截止和系列总量，核对原价格、市场与收益参数保持原值。供应增加或提价仍服从现有审批与覆盖率门禁，不因提示绕过。

公共 TEST 写验前须记录完整档位、系列总量、已售数及最新版本，并确认本轮拥有修改窗口。新增档位删除后会将上一档截止延长到被删除档位的截止，不会自动恢复总量；恢复必须在重新回读最新版本后，再把原末档截止改回原值。保留正常版本递增、软删除记录及审计，不直接回滚数据库或版本序列。

本文件描述预期行为；真实页面验收和公共 TEST 保存／恢复结果由本轮统一验收回执记录，不将未执行项记为通过。

## 本轮追加确认：总量增加的审批交互

用户在真实 TEST 发现末档从 1000 调至 1001 被服务端以 `G4_CATALOG_APPROVAL_REQUIRED` 拒绝后，明确同意补齐审批交互。

- 已有系列的末档截止增加至高于系列总供应量，以及在现有末档后追加档位，确认按钮改为「提交审批」。待审期间沿用原档位与原总量，另一位有权超管批准后生效。无系列时不虚构总量审批，首档与原直接保存路径保持既有行为；非末档编辑及删除入口不改。
- 发起及本人查询需实际持有 `finprod_g4_price_write`；涉及系列供应量还需 `finprod_g4_write`，不以超管角色名替代实际业务权限。批准仍由服务端要求另一位超管持有 `platform_a2_operation_approve` 和上述业务权限。本次不新增权限或决策编号，理由沿用既有规则。
- 提案调用既有 A2 `POST /api/admin/platform/audit/operations`，`sourceDomain=G4`，`obj=tiers`，锁对象为 `G/genesis_catalog/tiers`；命令为 `G/g4_genesis_tier_change`。修改参数精确为 `tierId/to/priceUSDT/expectedTiersVersion`，新增精确省略 `tierId`。前后摘要、发起人、源版本及审批执行仍由服务端绑定和校验。
- G4 价格档位区增加「查询原提交结果」入口，有 A2 查看权限者可进入现有操作记录查看审批。前端为本人的整个档位目录保留独立待定提案槽，与首次每日收益比例的提案分开存储。
- 发起请求前持久化完整原始档位基线、截止与单价输入、版本、理由、完整提案及命令键。存储失败则不发送；结果未知时保留原记录。刷新或重开后展示原输入并先查询精确原键，允许找回已经批准、驳回、撤回或过期的原单；查无原单才允许在有效期内按完整原请求与原键重试，过期只查询，不生成替代键。
- 查询成功后重新读取当前 G4 配置，并分别展示原审批单状态；旧票据的状态不作为当前配置值的依据，不自动把旧方案重提交。待审票保留查询入口；已决票在回读成功后结束本地待定记录。源版本变化等冲突由既有服务端裁决，不能以当前输入覆盖原待定提案。
- 创建或查询返回的票据均须匹配本人（`mine=true`）、原目录对象（`obj=tiers`）及服务端规范动作「调整创世节点价格档位」，才可作为本次回执回读当前配置、显示成功或结束本地记录。不匹配时保留原输入和原键，继续核对。当前服务端未给 G4 档位票据提供专用 `operationCode`，不猜测其值。
- 恢复开始时已存在原记录的，即使原键查询因权限返回 404，随后原键重试也被明确拒绝，仍保留该原记录和原键；本次权限结果不能证明以前的未知请求没有落票。只有无在途历史的首次请求收到确定性拒绝，才可结束该本地记录。
- 本轮只接通末档增加系列总量和追加档位的审批。供应总量不增加的纯涨价，以及非末档编辑、删除若被服务端要求审批，继续保留原拒绝；本轮不新增这些审批入口，不宣称所有目录审批均已接通。

## 2026-11-07 已确认增量：未售价格提高的审批交互

本节替代前一批「纯涨价、非末档编辑、删除仍保留原拒绝」的范围限制。适用端与页面仍为 PC「金融产品 → 创世节点销售与收益」的价格档位确认弹窗，复用既有布局、输入、理由、审批提示和恢复入口。

- 末档纯涨价、非末档价格或截止调整，以及删除档位导致未售价格提高，先沿用原直接保存请求。只有服务端以确定性 `409 / G4_CATALOG_APPROVAL_REQUIRED` 拒绝时，在同一弹窗保留本次截止、单价及操作理由，显示另一位有权超管批准后生效，主按钮改为「提交审批」。操作者再次点击才向 A2 发起提案，不把直写拒绝自动转为已提交审批。其他校验、版本冲突、网络异常及服务端未知结果不触发该转换。
- 服务端允许直接保存的操作继续原成功回执及当前配置回读。已有系列增加总供应量仍在提交前显示「提交审批」，不增加一次直写尝试。非末档修改只调整本档截止及下一档起点，系列总量不变；删除沿用原相邻区间补齐规则，至少保留一档，不修改总量。
- 纯价格、非末档与删除提案的发起及本人原键恢复只要求实际 `finprod_g4_price_write`；末档输入实际改变已有系列总量时，另外要求 `finprod_g4_write`。另一位审批人仍由服务端要求超管身份、`platform_a2_operation_approve` 和本次对应业务权限；发起人不得自批，不新增或放宽服务端授权。
- 更新、新增仍使用既有 `G/g4_genesis_tier_change` 命令；删除精确传 `action=delete`、`tierId`、`expectedTiersVersion`，不携带截止或单价。三类操作统一沿用本人的 `G/genesis_catalog/tiers` 待定槽，待审时原档表、价格、系列总量保持原值，批准后按服务端绑定快照及覆盖率规则执行。
- 提交前保存完整原始动作、相邻档位标识、输入、理由、版本、提案和唯一命令键；沿用原键查询、原键重试、过期只查询、已决票回读当前配置及未知结果不丢记录的既有规则。删除恢复仅展示原删除对象与理由，不出现更新字段，不将删除恢复成更新请求。
