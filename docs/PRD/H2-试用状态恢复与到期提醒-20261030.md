# H2 试用状态恢复与到期提醒

日期：2026-10-30。适用正式 App 与共享 H5 的 TEST 修复；不代表生产合并或发布批准。本规格覆盖试用状态恢复和到期提醒，其他试用资格、购买、取消、结算规则保持既有契约。

## 到期提醒

“试用抵扣金与 UVT 已失效。”只用于服务端明确确认的自动到期结果。前端须曾在当前账号绑定中成功读取同一领取单的有效试用/宽限状态，再收到该领取单更高版本、明确自动到期的结束结果，才产生一次提醒。同一绑定中同一领取单重复轮询不得重复提醒。

历史结束记录首次加载、断网恢复、HTTP 503 后恢复、主动取消/解绑取消、已转购以及结束原因未知，都不作为新到期事件。客户端时间流逝或本地状态从未知/无试用恢复成已结束，不能单独触发提醒。

断线期间确实到期的同一领取单，恢复后读取到明确自动到期的新版本时，仍应提醒一次。隐藏或退出业务页面期间不弹；返回并确认当前账号/当前结果后可消费尚未展示的真实事件。账号切换、同账号重新绑定与旧请求返回均不得继承其他绑定的提醒资格。

## 服务端只读事实

`GET /api/trial/state`、`/api/trial/eligibility` 及同源领取单投影增加 `endReason`：

| 记录状态与持久原因 | endReason |
| --- | --- |
| CANCELLED/FAILED 且原因严格为 auto_end 或 auto_settlement_window_expired | expired |
| 其他 CANCELLED | cancelled |
| 其他状态或历史失败原因不明 | null |

`finishedAtEpochMs`读取同领取单的既有`closed_at`，单位毫秒，未知为 null，仅作结束时间展示和证据。提醒依据服务端明确结束原因；客户端不利用时间戳、当前配置或旧期限快照重新判定业务到期。

兼容旧服务端缺少`endReason`的响应：状态和权限继续按原权威读取处理，到期提醒保持静默，不把未知原因猜成到期。此修复只增加读取既有列及投影字段，不改变定时任务、快照、取消/结算SQL、数据库结构或账务。

## 失败、权限与验收

读取失败时，当前交易授权、可用抵扣金额、报价与领取资格继续清空或进入未知，不能用保留的提醒证据发起交易。允许保留当前绑定内最近确认的领取单编号、版本及生命周期状态，专用于识别恢复后真正发生的到期事件。

必要验收：历史结束记录冷启动/断网/503恢复无误报；有效试用恢复仍有效时静默；明确自动到期（含离线跨期）提醒一次；手动取消和已转购静默；重复/旧版本/跨领取单/换账号/同账号重绑不误报；旧响应兼容；TEST真实页面操作与部署版本分别记录。模拟接口边界只证明客户端判定，不替代真实后端自然跨期验收。
