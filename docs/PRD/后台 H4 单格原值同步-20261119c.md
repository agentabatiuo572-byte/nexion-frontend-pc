# 后台活动文案与原命令同步

## I6 完整性修复 · `9081d087`

修复请求可携带扩展语 `translations`。省略时沿用已存译文，空对象表示清除扩展语，传入对象则按实际内容保存。现有三语编辑入口省略此项。重扫也检查已填写的扩展语中的占位文本和退役品牌。修复保存新草稿及对应版本，报告仍按实际公开文案或未发布词条的最新版本计算。

修复回执沿用问题类别，并可带实际保存的 `messageKey` 和 `version`。后台核对原问题类别、原词条及版本。看到两个新增字段时，新版本须晚于能够从原操作记录读到的版本。修复分配版本时已有草稿可能更晚，回执可比画面上的旧版本多一版以上。旧回执缺省这两个字段时沿用原问题类别校验。按原请求重试使用原正文和命令号。通用只读回执仍只提供业务状态，无法给出实际修复数或保存的草稿版本。

## H4 直接命令的原结果 · `015237a4`

新建、删除、修改既有活动，保存玩法、创世抽奖草稿、转盘护栏或奖池等已登记的直接命令，按本机保存的原路径、原目标、原命令号查询只读回执。查询要求当前账号是原提交人，并持有 H4 读取权限。成功回执进入已保存待重读状态。明确拒绝或确认未执行结案。查无、处理中、未知、查询失败、无来源旧记录均保留。24 小时后的直写记录可查原结果。审批单、媒体上传、促销分别沿用既有的命令合同。

## H4 活动单格并发校验与缺项 · `e4efdabf`

活动单格保存携带读回原值作为 `expectedValue`。字符串保留大小写、首尾空白、空串和短横线。缺格发送 `__MISSING__`。原值不符时以 `409 CONTENT_LOCALE_STALE` 处理，按现成冲突流程重新读取。网络结果未知后按原请求重试，原命令号、JSON 正文和其中的 `expectedValue` 保持一致。按原号查询只传命令定位所需的值。

活动概览和综合读取对每条活动提供 `copyReadiness.missing` 和 `copyReadiness.incomplete`。路径如 `localized.en.name`。后台活动开放检查、现有卡片和待处理缺项使用这两类服务数据，显式空数组表示没有该类缺项。旧版响应省略该字段时，沿用既有本地计算。

## H4 玩法就绪和现金奖名 · `1bf7308a`

已启用玩法的就绪检查也采用英文和运营区域语言。缺英文时读模型报告缺项，启用状态仍以 `enabled` 为准。后台继续读取玩法就绪和启用状态。无规则旧活动发放正额 UVT 或 USDT 时，管理端 `appRewardNames` 使用两位小数的完整奖名，例如 `1.00 USDT`。后台按原样读取三个语言的奖名。App 和 Lite 继续用金额和资产拼显示文字，已参与用户的奖励快照独立于管理端当前活动配置。

促销批准和发布请求仍提交候选的版本、预期修订号、证据和理由。初版批准门按运营区域语言检查冻结合同，服务拒绝使用现有 `PROMOTION_FIELD_INVALID` 路径。
