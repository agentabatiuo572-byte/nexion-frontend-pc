# BE-08 J1 业务开关恢复审批

J1 单项和批量关停在确认后即时执行。已关停且符合原恢复前置条件的业务显示「提交恢复审批」，确认框显示蓝色「批准后生效」标签，摘要写批准前业务仍关停、另一位有权超管批准后恢复，发起人不能自审。提交成功显示申请编号，业务仍显示「已关停」。有权发起恢复审批的管理员可在结果未知时核对原申请，刷新后仍使用原命令号及原请求。

A2 将 J1 恢复申请标为应急，排在其他待办前。发起人不能执行自己申请。另一位有 A2 审批及 J1 恢复权限的超级管理员可以批准或驳回。资金业务批准时重新检查覆盖率，检查失败仍保留待批工单。试用开关继续免查覆盖率。A2 原有其他工单的排序和权限沿用现有规则。

J1 的覆盖率卡使用服务端估值可靠性及恢复判定，健康线显示服务端实际健康线。百分比展示及其与红线的比较不自行放行资金恢复。估值不可靠或缺少上述判定时，当前覆盖率显示「暂时无法判断」，资金业务的新恢复入口禁用，原恢复申请仍可核对；若按原键未查到申请，保留该键并提示当前只能核对，不继续提交资金恢复，待服务端允许恢复后才可沿原键续原请求。资金检查结论仅在服务端允许恢复时显示绿色勾号，受阻或无法判断使用警示标识，禁用的恢复按钮使用中性样式。关停和无需备付金检查的业务继续各自权限与流程（2026-11-06，BUG-313）。

验收从 J1 确认关停与提案，在 A2 核对置顶、发起人限制和另一位管理员执行，再回到 J1 确认最终状态。覆盖率变化与提交结果未知分别核对未恢复和原单可查询。

原恢复申请结果未知后，先查询原命令；查不到且未过期、当前仍获服务端恢复许可时，才沿原号、原字段及原理由重试。重试被明确拒绝仍保留原记录，不把后来一次拒绝当作首次申请未成功；超过 24 小时仅查询。

恢复被拒时说明「系统尚未允许恢复」，引导到资金页核对覆盖率和估值，不能一概解释为低于红线或承诺补足储备即可申请。业务卡与折叠总表保留；批量关停只选一项时直接写业务名，不放折叠；多项时清单默认收起，逐项列业务、控制能力及状态变化。结论解释标题为「恢复业务怎么操作」。

2026-11-07（HD-FIX7）：首次收到或按原命令查到 pending 回执后，原业务卡常显「恢复待审批」、审批号及「到操作记录与审批核对」，暂停新恢复申请，业务继续显示已关停。重新进入页面使用现有 A2 overview 的 J 域 pending 投影恢复标记；查询中或查询失败时暂停新恢复入口，不把未读到当作没有审批。无 A2 读取权限时不能声称已核查待审批投影。

业务卡受阻时按钮仍写「提交恢复审批」，中性禁用并在悬停说明原因和核对去向；「恢复受阻」写在状态标签上。关停、批量关停和补录框不重复小标题，触发依据占整行，展开摘要不重复影响和事实。
