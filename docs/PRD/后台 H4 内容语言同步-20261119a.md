# 后台 H4 内容语言同步

后端核对版本为 `7ad56246`，包括 PR #61、`4dfa316e`、`e3ff8d2e` 和 PR #59 的春季转盘迁移。本文登记改版线的数据合同。

## 既有活动、玩法与转盘

- `events-overview.events[*]` 和 `event-rules.rules[*]` 返回 `appUsesAuthoredRewardName` 与 `appRewardNames`。后者是按 `en`、`zh`、`vi` 给出的完整奖励文字。旧版本缺这两项时保留原有校验路径。
- 转盘和没有规则且未配置正额 UVT 或 USDT 奖励的既有活动使用运营奖名，这两类活动在发布前校验奖名。有规则的非转盘活动显示规则奖励摘要。无规则的正额现金活动向 App 和 Lite 返回资产名及单独的 `rewardAmount`，由客户端拼接一次。参与用户读取自己的奖励快照，管理端预览数据以当前配置计算。
- 玩法就绪的 `missing` 包含配置缺项和必填语言缺格。`incomplete` 列出已填写一部分的选填语言缺格。字段随 `ready` 一起读取。开启直接拒绝及 A2 提案预检也可返回两类明细，活动开放以对象数组给出语言及格名，玩法开启以 `localized.{语言}.{格名}` 路径给出。
- 后端单格更新英文时会同步已有英文副本。选填中越整组留空可在开放、开启或建单时补齐。直接开放和建单的补齐、审计与业务写入使用同一事务。批准依据已保存并绑定的内容。PC 以单格回执的键、语言和格名核对原操作，再重新读取完整文案。
- 现阶段活动单格 PATCH 的 `expectedValue` 来自所读单格及原有 CAS 处理，纯空白和单个短横线按 `__MISSING__` 提交，其他值经 `trim()`。`events[*].copyReadiness` 及按读回原始字符串比较的 CAS 随后续合同接入。
- `EVENT_ALREADY_EXISTS` 同时涵盖现有活动及已删除活动保留的编号。春季转盘迁移把满足旧种子条件的进行中状态收回为预告，保留已推荐、有运营文案、已修改玩法或有首次启用待审的记录。

## 商城促销

- 普通草稿的标题和条款可分别省略语言键。PC 用浏览器 `trim()` 判断空白并从提交字典中省略该键，保留其余原字符串及扩展语言。提交某个空字典可清空这组已保存的语言。整个标题或条款未提供时沿用原 PATCH 语义。试算提交同样的草稿形状，内存补齐后计算，回执的 `configHash` 对应实际请求稿。
- 送审核对候选版本及原修订。成功回执的 `resource` 是目标 `VERSION`，标识为活动编号、冒号和候选版本号，修订为原修订加一。服务在同一事务内补齐适用语言并写入待审状态、完整合同及 `contentHash`。内容已完整时，重新计算可得到相同哈希。PC 通过重新读取取得权威版本及哈希，送审前的试算结果随本次重读退出。
- OpenAPI 的 `PolicyDraft` 与 `PolicyVersionInput` 使用 `AuthoredPolicyContent`，已存 `Policy` 使用 `StoredPolicyContent`，两者均按政策类别判别。可本地化的政策元件是设备权益说明、资产可用性说明和退款条款。请求在可选语言整组为空时由服务补齐，已存政策仍以三种基础语言输出。

## 创世抽奖与信任版块

- 创世抽奖以一期标题及所有奖项名组成同一语言组。新建草稿、保存草稿或创建开启提案时按英文及运营区域语言补齐，批准按已冻结提案执行。直接保存以轮次、修订和已保存抽奖结构核对回执后重读。保留可选的标题及奖项扩展译文结构，已存在的扩展标题由服务在省略该属性的旧编辑请求中保留。
- 信任版块保存草稿、发布及回滚的每项内容最多 500 个 Unicode 码点，含链接。已发布版本的公开读取继续执行链接的原安全规则。

运营区域语言选择、提交前补英语、各页面提示与预览的文字交给对应的编辑器及界面工作。共享后端核对限读取。写入、失败回放和 App 用户端读回需要隔离环境验收。
