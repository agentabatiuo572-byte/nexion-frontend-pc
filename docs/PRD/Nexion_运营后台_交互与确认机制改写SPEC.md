## 2. ④a 段模板与范本

### 2.1 放置规则

- 新子段「**④a 交互与弹窗规格**」插入每个子模块 ④ 操作动作之后,作为 ④ 的**子段**——8 段模板编号、lint 的 ①-⑧ marker 校验、所有"68 个 8 段子模块"叙述零改动。**任何文档不得把 8 段改写为 9 段**。
- ④ 表「Maker-Checker」列**改名「确认弹窗」列**(不删列):取值 `{ID}(理由必填)` / `{ID}(理由必填+B1 红线预检)` / `否(只读/直接生效留痕)`。
- 弹窗 ID = `{模块ID}-MD{n}`(如 `D2-MD1`),全 PRD 唯一;④ 表的 ID 与 ④a 的定义双向一一对应。
- 只读/导航动作只进 ④a(1) 触发总表(点击行为=跳转),不写 (2) 弹窗条目;非高敏动作可「直接生效+toast+留痕」不开弹窗;批量动作信息区必含 server 分拣预览。
- 布局描述只到**结构/分区/控件类型**粒度(PRD 不写视觉:无颜色/字号/间距)。

### 2.2 模板原文

```markdown
**④a 交互与弹窗规格**

> ④ 表「确认弹窗」列的弹窗 ID 在此逐一定义。弹窗容器统一复用基础 Modal/Drawer,
> 弹窗内容逐弹窗单独设计;本段约定结构/分区/控件类型/行为与状态,不约定视觉。

**(1) 动作触发总表**

| 动作(同④) | 触发控件 + 位置(引用②分区) | 形态 | 可用态规则 | 点击行为 |
|---|---|---|---|---|
| <动作名> | <②(x)区 + 控件位置> | 行内按钮/主按钮/菜单项/链接/开关 | <何态可用/无权限是否渲染> | 打开弹窗 <ID> / 跳转 <路由> / 直接生效(toast) |

**(2) 弹窗规格(逐弹窗)**

##### [<模块>-MD<n>] <弹窗标题>
- **功能**:一句话——该弹窗确认什么动作、产生什么后果。
- **布局结构**(自上而下分区):
  1. **信息区**:本次操作对象的只读关键字段清单(字段名逐一列出)。
  2. **影响预览区**(放大流出/资金类动作必有):server 预检结果展示
     (如拟生效后兑付覆盖率、影响用户数);红线警示条的渲染条件与文案要点。
  3. **输入区**:见下控件表。
  4. **按钮区**:取消 + 确认。
- **输入与选择控件**:

| 字段 | 控件类型 | 必填 | 校验(client + server) | 默认值 |
|---|---|---|---|---|
| reason | 多行文本 | 是 | 8–200 字;server 空值返 400 `REASON_REQUIRED` | 空 |
| <业务字段> | 单选/下拉/数字输入/日期/复选 | | | |

- **按钮区**:`[取消]`(关闭,无副作用)· `[<确认文案,含动作语义>]`(主按钮;
  必填项未过校验置灰;提交中 loading 锁定防双击;携 `Idempotency-Key`)。
- **错误态**:逐错误码声明弹窗内行为——422(红线/业务规则,弹窗不关,内联错误条
  + server 返回的当前值)/ 409(状态机非法转移,提示已被处理 + 刷新)/ 403 / 400。
- **成功反馈**:弹窗关闭 + 列表/详情就地更新 + toast 文案要点 + 审计落 A2(引用④审计点)。
```

### 2.2a 业务弹窗契约

弹窗内容必须匹配触发按钮的业务语义。改角色必须有角色选择;改授权必须有权限 diff;编辑文案必须有 en/zh 或对应业务字段;创建课程必须有 title/body/category/duration;提现处置必须有 approve/reject/delay/freeze 业务选项。只有 reason textarea 的 edit/create/repair/role/permission/action 弹窗视为 business-incomplete-modal。纯展示弹窗必须显式 readonly,不得出现可执行主按钮。

```markdown
**④a 交互与弹窗规格**

| delay | ②(d)决策区菜单项 | 菜单项 | 仅 `review-pending` | 打开弹窗 D2-MD3(持有天数选择) |
| freeze / unfreeze | ②(d)决策区菜单项 | 菜单项 | review-pending 及在途态 / 仅 frozen | 打开弹窗 D2-MD4 / D2-MD5 |
| 查看单笔详情 | ②(a)行内 withdrawalId 链接 | 链接 | 恒可用 | 跳转单笔详情面板 |

**(2) 弹窗规格**

##### [D2-MD1] 提现放行确认
- **功能**:对单笔提现执行 approve(`review-pending → review-passed`),确认金额、
  风险与水位影响后即时生效;放行实时核减 D3 储备并影响 B1 覆盖率。
- **布局结构**:
  1. **信息区**:withdrawalId / userId(链至 C1 画像)/ 金额(USDT)/ 目标地址+链 /
     风险评分(K4,含分档)/ KYC 态(C4)/ 命中规则(K3)/ 24h 第几笔 / 当前状态。
  2. **影响预览区**:server 预检(simulate=withdraw_approve)返回「放行后兑付覆盖率」;
     低于黄线展示警示条(当前值+黄/红线);低于红线时警示条升级为阻断提示
     (确认按钮置灰,文案含「覆盖率低于红线,server 将拒绝(422)」);
     大额(≥A1 大额阈值)单加「大额放行」提示行 + K5 复审状态。
  3. **输入区**:见下表。
  4. **按钮区**:取消 / 确认放行。
- **输入与选择控件**:

| 字段 | 控件类型 | 必填 | 校验 | 默认值 |
|---|---|---|---|---|
| reason(放行理由) | 多行文本 | 是 | 8–200 字;server 空值 400 `REASON_REQUIRED` | 空 |
| 确认勾选(仅大额) | 复选框「我已核对地址与风险信息」 | 大额必勾 | 未勾确认钮置灰 | 未勾 |

- **按钮区**:`[取消]` · `[确认放行]`(主按钮;reason 未达标/大额未勾选/预检覆盖率
  低于红线时置灰;提交 loading 锁定,携 `Idempotency-Key`)。
- **错误态**:422 `COVERAGE_BELOW_REDLINE`(含 server 回传当前覆盖率,弹窗不关)/
  409 状态机非法(已被他人处理,提示+关闭后刷新行)/ 422 K5 复审未过(提示转 K5)/ 403。
- **成功反馈**:弹窗关闭;行内状态更新 `review-passed`;toast「已放行 · 已记审计」;
  事件 `withdraw.approved` + admin 审计(operator/amount/reason)。
```
