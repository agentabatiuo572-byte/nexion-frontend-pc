# K1 账户组处置和放宽规则提示

- 「解除误判」「判定为正常」提交 A2 审批，批准执行时才检查当前兑付覆盖率。低于红线或估值无法读取时不能执行，工单继续待批，账户组状态和提现限制不变。
- A2 按工单 `coverageCheckOnApproval` 标记显示批准检查提示；详情与执行确认使用同一口径。
- 调大同 IP、设备、支付工具三个上限，在保存时检查覆盖率；IP 允许名单新增、重新启用或延长有效期也检查。收紧上限、移除名单不受该放宽门槛阻断。
- 规则和允许名单只影响后续检测；既有待判定组、成员及其限制保留，等待人工判定或解除，不因新投影变少或消失自动清除。已冻结账户也不因此解冻。
- 确认框常显资金影响、覆盖率与检查时机；账户及异常状态逐条列示，遗漏账户说明数量，不能把提交提案写成已经通过检查。

依据：后端 `origin/test@0f0eb538` 的 `OpsRiskService`（处置、上限、名单保存）、`RiskReleaseParamsService`（覆盖率可靠性与红线）和 `MultiAccountClusterBatchService`（保留既有组及成员）。上述规则是当前行为，替代早期“尚无检查、会自动清除”的说明。
