# D1 / D5：USDT 分网络资金控制

按用户 2026-11-07 确认的图中方案实施。构建、TEST 发布、页面操作与真实链上资金验收分别记录。

## D1：充值与地址设置

「收款与出款开关」为 BEP20、ERC20 各显示一行充值开关、实际状态、未生效原因及独立提交审批按钮。开关开启且库存不足显示「地址准备中」，不把库存不足显示成网络关闭。读取不到新契约时明确提示无法编辑，不伪造默认值。

每行提交只改变该网充值，必须由另一名仍有权限的管理员复核。共享闸版本和网络版本变化后旧提案不可通过。草稿随本行版本更新，另一行刷新不覆盖尚未提交的本行选择。

实际开放 = 网络运营开关 + 服务启动/RPC 配置 + 全局分配地址及入账总闸。普通单网关闭不关闭另一网。恢复共享充值闸须明确提交恢复审批，另一网充值保持关闭，不恢复出款。

全局出款总闸仍作为两个网络的共同上限单独显示和审批；分网络出款跳转 D5，D1 不增加第二套分网出款开关。紧急关闭关闭全部共享资金闸及两个网络充值权限，后续分别审批恢复。只读人员可查看状态，不能提交或审批。

## D5：提现参数配置

保留 TRC20 / BEP20 / ERC20 三个既有配置按钮与审批流程。配置值和「实际可用」分开显示：每网呈现配置开关、实际状态、不生效原因，并提供 D1 USDT 资金设置入口。顶部网络摘要只列后端 `effectiveNetworks`；无实际可用网络明确显示暂无可用网络，旧接口未提供权威状态时显示尚未核实。

页面实际网络与 App `/api/withdrawals/policy` 同源：D5 开关、全局出款总闸、服务商币种、RPC、风控与对账均满足才可用。PROVIDER 下 TRC20 不可用。页面不再把「D5 配置开启」宣称为 App 已可提现。

## App / H5 Lite 与业务影响

充值先读只读 `GET /api/deposits/policy`，不通过请求各网地址探测开关；只显示开放网，并从 policy 读取准确费用。选中后才申请地址，全部关闭或读取失败不默认申请 BEP20。库存不足仍允许显示该网的准备中状态。

提现及地址换绑只使用实际开放的提现网络；全部关闭时不能换绑或发送验证码。服务端申请、保存换绑、首次出款分别复核权限，成功幂等回放和已发出原单查询继续可用。外部 USDT 下单及付款履约受选定网充值开关控制，余额购买沿用原流程。

## 验收

实际操作 D1 两网独立提案和双人审批、D5 开关与实际状态、App / H5 Lite 初次充值加载及地址换绑。验证关闭网络不能通过旧页面或直接写接口继续操作；检查只读 policy 不消耗地址。页面按生成设计稿与现行 D 域规则完成独立复核。未执行的真实链上资金动作不得宣称通过。
