# D1 / D5：USDT 分网络资金控制

按用户 2026-11-07 确认的图中方案及 2026-11-08 确认的 TRC20 增量范围实施。构建、TEST 发布、页面操作与真实链上资金验收分别记录。

## D1：充值与地址设置

位置：「充值与收款对账 › USDT 充值 › 充值与地址设置 › 收款与出款开关」，同一子页签下方另有「全局紧急停用」。字号沿用 rd 组件，不另设。

「收款与出款开关」里的「分网络充值开关」表固定三行：BEP20（BNB Smart Chain）、ERC20（Ethereum）、TRC20（TRON）；列为网络、充值开关（开启 / 关闭）、实际开放情况、操作。实际开放时写「已开放」，已开放但地址库存不足写「已开放 · 地址准备中」，不把库存不足显示成网络关闭；未开放时写后端原因。兼容旧两网响应：没有 TRC20 开关行时，充值开关写「尚未配置 / 待后端配置」，实际状态写「待核实 / 请核对部署后刷新」，「调整」、补充收款地址和立即完整对账不可用。整个分网络开关未返回时，表的位置写「读不到分网络充值开关，当前不能修改。请刷新后再试。」，不伪造默认值。

每行「调整」打开修改框，只改这一条网，写现在的值和改后的值（相同值不能提交），提交审批后由另一名仍有权限的管理员复核，其他网络不受影响。这一条网已有待复核提案时「调整」禁用。共享闸版本或网络版本变化后，待复核行写「配置版本已变，请拒绝后重新申请」，旧提案不可通过。

「待复核申请」（有提案时展开）每行写提案号、发起人、「现在 → 提案值」和发起理由；复核和拒绝的确认框写现在的值和提案值。本人发起的申请禁用「复核通过」「拒绝」，原因写「这是你发起的，需要另一位管理员处理」。

提案、复核、紧急停用发生结果未知时，在 USDT 充值页签顶部常显结果未确认条（开关提案、开关提案复核、紧急停用三网），只给当前管理员；条上「读回核对」按返回的各网开关写充值状态、链上出款和待复核提案数，「按原操作重试」按原路径、参数、理由和请求号恢复，不另建同类提案或同一申请的复核请求。上一个开关提案结果未确认时，新提案入口禁用；未知提案不阻断紧急停用。只有重试被后端带原因码的 4xx 明确拒绝，人工核实原操作结果后才能「解除待确认」；401、403、408、425、429、`IDEMPOTENCY_*`、结果未知、处理中、响应读不懂和没有状态码的本地错误均不算，原命令保留，可在权限、有效期等条件允许时再重试。超过 24 小时不能再重试，记录保留。恢复取得明确结果后重读实际状态；读取失败明确提示，不能当作状态已核实。开关的结果未确认和待复核提案也进页面的跨区提醒。补充地址、地址池保存、完整对账、入金复核发起／复核、签名原文在PC仍归为不可原号重发：只读回事实，不给重试或“核对后解除”，原记录留至关标签页，不以读回相同值证明原操作结果。后端现有origin/test已为相应端点增加幂等适配，PC尚未接入，不能继续概括为“后端不收幂等键”；页面边界见PRD v1 D1④。可重发命令的解除仍只清本地，不撤销操作或办理后端结案。

实际开放由后端核验网络运营开关、服务启动/RPC 配置、全局分配地址及入账总闸、收款服务能力、风险与对账条件。普通单网关闭不关闭其他网络。全局暂停时每行多一个「申请恢复」，只申请恢复所选网络充值，其他网络充值保持关闭，不恢复出款；恢复共享充值闸须明确提交恢复审批。

全局链上出款总闸作为 BEP20、ERC20、TRC20 三网共同上限单独一行显示和审批；值写开关状态，名称旁问号说明出款条件，修改框写现在的值和改后的值。分网络出款由「前往 USDT 提现参数」进入 D5，D1 不增加第二套分网出款开关。全局紧急停用的按钮、待确认条和确认框标题写「紧急停用三网」，页面说明为停止三网地址分配、自动入账和新出款，继续接收回调并查询原单；旧提案失效，恢复须分别重新核对条件并提交审批。只读人员可查看状态，不能提交或审批。

**历史后端缺陷 BUG-403**：旧后端`fa6286a5`把网络更新行数写死为2，TRC20迁移后三行时整笔回滚；本次既有`origin/test@8e48596d`已改按 `CregisNetwork.values().length` 校验，不能继续把三网必败当当前代码现状。本轮未操作真实紧急停用，实际部署、权限、版本与结果须独立验收。

「收款状态」折叠里三网各有一行出款能力，专属收款地址池表三网各一行库存与最近完整对账；「最近对账与告警」抽屉也分别写三网完整对账。后端返回了 `addressPools` 但缺某网时，该网库存写「尚未配置，请核对部署后刷新」，折叠摘要写「该网未配置」；整个 `addressPools` 未返回或已有该网池但不可用时，库存写「暂不可用，请刷新核对」，不误报尚未配置；未接入收款服务时折叠摘要仍写「未接入」。补充地址按接入、共享闸、该网地址池可用、TRC20 开关已配置及库存条件依次检查；立即完整对账按读取状态及 TRC20 开关是否已配置判断，不只凭缺地址池禁用。

共同充值规则共享最低额、固定费和确认数（15–10000），已发现交易保留原规则；说明写「BEP20、ERC20 和 TRC20 共用这三项」「TRC20 还须通过固化区块核验」，确认框动作写「提交 USDT BEP20 / ERC20 / TRC20 共同充值规则」。地址池三网分别计算库存、共用补充目标，TRON 地址及交易标识不与 EVM 混用。银行卡支付设置的「USDT 链上充值」行，值写「在「USDT 充值」看」，旁边弱化写「BEP20、ERC20、TRC20」。

新增原因按中文显示：`ADDRESS_ASSET_UNAVAILABLE` 为「收款服务未开通该网络收款地址」，`CHAIN_PROOF_UNAVAILABLE` 在充值状态写「TRON 节点或收款服务暂时读不到」，在出款能力行写「暂停 · TRON 节点读不到，链上确认核不了」。TRC20 首次空库存对账的 `CREGIS_TRC20_BOOTSTRAP_NOT_EMPTY_OR_READY`、`CREGIS_TRC20_BOOTSTRAP_PROVIDER_NOT_EMPTY` 分别解释未满足空库存条件、服务商已有记录；都说明本次没有建地址或入账，不把失败当作对账完成。

订单付款与手续费加入 `CREGIS_USDT_TRC20`，网络为 `TRC20`。付款方式筛选含 TRC20，付款手续费为银行卡、BEP20、ERC20、TRC20 一张表，不增加按网络分开的页签。旧响应缺渠道时表里仍补该行，写「未配置」「后端没返回这个渠道，不能修改 / 用户付款时看不到；核对部署后刷新」，计入付款方式总数和未配置数，不补默认费用；已返回但未配置的渠道沿用既有填写流程。TRC20 付款详情「金额明细」写「外部链上费用 · 用户在钱包里另付的 TRX、能量和带宽不算在内」，折叠摘要写「外部链上费用由用户另付」。付款记录、详情和原请求恢复沿用既有规则，不把付款成功直接视为业务履约完成。

付款手续费表的共用数字框接受合法十进制和千分位，非法输入整次拒收、保留前值并在框下提示，不删字后拼数；确认框显示保留值。手续费表可暂时输入开头负号，原非负金额范围仍禁止保存负数，本金整数与费用精度限制不变。

订单付款的锁定汇率、应付越南盾、银行卡充值表头「应付（₫）」「实际收款（₫）」、判断要点和人工确认入账的金额均用 ₫（如「1 USDT = 26,390 ₫」）；VietQR 金额范围错误同样用 ₫。汇率对名称「VND/USDT 基准价 / 基准汇率」及引用 App 原文「每 USDT 兑换 VND」保留。

「归集与付款」下两个面板标题为「BEP20 自动归集与甲方付款」「BEP20 归集与甲方付款准备」，说明均明确只适用于 BEP20。本轮不扩展 TRON 自动归集、甲方钱包配置或付款执行。

## D5：USDT 提现参数

位置：「资金与财务 › USDT 提现参数」（`/finance/params`），打开和点「刷新」时读取，不自动刷新。没有修改权的账号页头写「你只能查看」，不出「调整」。

**页面结构。** 页头下一句结论，下一行都带「兑付覆盖率 X，红线 Y」。结论按先后取一条：有修改结果未确认（「N 项修改结果没确认，确认前这页暂停修改」或「1 项放宽结果没确认，确认前暂停放宽，收紧照常」）；覆盖率低于红线或读不到可靠结果（红色「放宽已暂停」，收紧不受影响）；用户一个网络都用不了（「用户现在不能发起 USDT 提现」，第二行写原因和下一步）；有放宽等批准；都没有时写现状，只有审批列表读到、网络实际状态读到、提现开关开着且没有网络被挡时才说「没有要处理的事」。结论没说到的「用户不能提现」「放宽等批准」「审批状态读不到」另起一条提示。下面两组配置行，每行名称、问号说明（这是什么、什么时候生效、显示位置、改了会怎样）、当前值和「调整」：

- 「额度和时效」：每日提现次数、余额可提上限、小额免审线、到账时效。
- 「网络和费用」：TRC20 / BEP20 / ERC20 提现各一行，网络确认费（三个网络一个值，用「、」隔开），UVT 抵扣率。
- 「随运营阶段变化的设置」折叠，六行只读：当前运营阶段、到账审查窗口、加强合规审查、大额门槛、BEP20、ERC20 现在怎么审、TRC20 现在怎么审，带按权限显示的「去运营阶段设置」。前三行来自 H1，门槛来自后端合规规则，后两行由当前读值推导，规则见下节。
- 页底相关页面：资金储备与应付款、资金与应付款总览、提现审核、操作记录与审批、用户行为事件，进不去的不显示。

**提现网络每行写实际状态。** 这页关着写「关闭」；开着时，读到能用写「开启 · 用户能用」，被挡写「开启 · 用户现在用不了」并写原因，读不到实际状态写灰色「开启」。用户能不能用和 App 提现同一个判断：「紧急停用开关」的提现开关开着、这页开着、出款服务接通；接打款服务时还要全局出款总闸开着、打款服务开通了这个网络、最近完成过完整对账、没有没处理的资金风险。网络本身状态来自后端 `networkStatus` / `effectiveNetworks`；提现开关 D5 接口不返回，页面另读紧急停用开关告警快照（`/api/admin/emergency/kill-switches/alerts`）。提现开关关着时开着的网络都写「用户现在用不了」，原因是提现开关；提现开关读不到时写「用户能不能用：—」，不猜。三个网络都在这页关着时结论句下一行写「要恢复，在网络和费用里点那个网络的「调整」开启，开启要审批」。打款方模式下打款服务没开通的网络（如 TRC20），这里开着 App 也不显示。

关掉网络：用户不能再用这个网络发起提现；接打款服务时，这个网络上已提交、还没交给打款服务的提现也暂停打款，已交给打款服务的继续查询核对。关掉最后开着的网络时，确认框写「提交后三个网络都关着，用户不能发起 USDT 提现」。

**整组「调整」抽屉。** 点任一行「调整」打开这一组的右侧抽屉：额度和时效四项一起提交，三个提现网络一起提交，三个网络确认费一起保存（可「恢复默认」，只回填，默认值比现在低算放宽），UVT 抵扣率单独一项。每项下面写现在的值、范围和改成后会怎样，空着或超范围时错误写全范围。共用数字框的科学记数法、空格、单位、字母、多余小数点、错误逗号分组及不允许的负号整次拒收、保留前值并提示；合法千分位不改数值，范围、精度、步长及百分数换算照旧。保留值合法时可以继续，最终确认框写保留的值。底部写「已改 n 项」，含放宽时标「含放宽」「批准后生效」，全部收紧时标「立即生效」。抽屉有改动时关闭或点「刷新」都先问，刷新的选项是「放弃改动并刷新」。最终确认框写改了哪几项的前后值，理由必填。

**放宽提交审批，收紧立即生效。** 放宽指：调高每日次数、小额免审线、余额可提上限或 UVT 抵扣率，缩短到账时效，开启任一网络，调低任一网络确认费。一组里有一项放宽，整组提交审批，另一位超级管理员批准后生效，发起人不能批自己的单，批准前当前值不变；提交和批准时各查一次兑付覆盖率，低于红线或读不到可靠结果都被拒。全部收紧时提交后立即生效，不查覆盖率。放宽被挡（没有发起审批的权限、上一次放宽结果没确认、已有放宽等批准、覆盖率不够）时，抽屉里写原因；这一组已经是最紧的值时「调整」直接禁用。有放宽等批准时提交收紧，确认框提示「有放宽在等批准，收紧后那张审批单要重新发起」。修改权按字段分：每日次数、小额免审线、到账时效要 `finance_d5_daily_limit_write`，余额可提上限要 `finance_d5_balance_max_write`，提现网络、网络确认费、UVT 抵扣率要 `finance_d5_fee_write`；放宽另要发起审批权。

**结果未知。** 提交前把命令号、改动值和理由存在浏览器里，存不下就不发。收紧和放宽的结果没确认时都常显在页面上方，写发出时间和内容，读取失败时也在。
- 收紧结果未知（含 2xx 但读不出数据）：确认前这页所有「调整」暂停；只能「按原操作重试」，同一命令号、同内容、同理由，要有原命令里每个字段的修改权。
- 放宽结果未知：只暂停放宽，收紧照常。有操作记录读权或发起审批权的账号先「查询原操作」查原审批单，查到就回读；明确查不到才能按原操作重试；两种权限都没有的直接重试原内容，已提交的不会重复提交。只有 `A2_PROPOSAL_NOT_FOUND` 算查不到，其他读取失败按结果仍未确认。
- 放宽的原审批命令按原操作重试时，若本轮查询精确返回 `A2_PROPOSAL_NOT_FOUND`、随后提交被后端带原因码的 4xx 明确拒绝，沿用原资格自动清除本地审批记录，页面说明原命令已清除。仅查询查无原单不清记录。收紧重试、或放宽重试后记录仍保留时，只有明确拒绝才给人工核实后「解除待确认」。原因码包括业务接口的 `reasonCode`、审批接口的 `backendMessage`；401、403、408、425、429、`IDEMPOTENCY_*`、结果未知、处理中、响应读不懂和没有状态码的本地错误均不算，原操作保留，可在权限、有效期等条件允许时再重试。这不改变首次提交被拒后是否保号的判断。解除只放开本页的锁，不发请求，不写操作记录。
- 收紧、放宽超过 24 小时都不能再按原操作重试，也不能解除待确认；记录和锁都留着，到操作记录与审批核对。

**确认框覆盖率行。** 放宽的确认框写「兑付覆盖率 X，红线 Y」：覆盖率一位小数，红线按配置原值写（如「兑付覆盖率 753.8%，红线 100%」），后果和检查说明放进提示图标；低于红线时换成红色全文「… 兑付覆盖率 X，低于红线 Y，提交会被拒绝」。结论句和放宽被挡原因中的两项使用同一精度，比较仍用接口原值。

到账审查窗口、加强合规审查、小额免审线和到账时效的实际生效规则，写在 PRD v1 D5「现行参数口径」。

**待后端。** D5 读接口直接带提现总开关（现在两次读取之间可能短暂不一致，点「刷新」对齐）；财务主管读待批审批（BE-RBAC）未交付，财务主管看不到有没有放宽在等批准，按命令号能查自己发起的原审批单。

页面实际网络与 App `/api/withdrawals/policy` 同源：D5 开关、全局出款总闸、服务商币种、RPC、风控与对账均满足才可用。TRC20 也必须满足项目实际收付权限及独立 TRON 节点要求，配置缺失或未启用仍按真实原因显示不可用。页面不把「D5 配置开启」宣称为 App 已可提现。
