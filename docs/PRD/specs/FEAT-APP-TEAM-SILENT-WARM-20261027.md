# 团队静默暖刷新

- 团队收入与邀请奖励已有当前作用域确认结果时，后台暖刷新不显示“正在刷新”“暂显示上次结果”等可见状态。收入卡保留原累计拆分控制行的外观和高度，读取中仍由原禁用语义、焦点与处理函数守卫禁止操作。辅助技术可读取既有 `aria-busy`，不插入新的状态行。
- 邀请奖励已启用或已关闭的有效读取都属于已确认读取；后续同作用域暖刷新保留原预留说明高度，不显示加载说明，也不把已失效的奖励承诺、邀请码或分享资格继续展示为可用。该读取标志只是本实例展示状态，不是奖励或分享资格。
- 首读未知、真实错误和原重试反馈保留。账号、绑定、环境或目录上下文失效清空展示状态；继承编译期环境重建合同，不支持旧页面跨后台继续复用。原奖励快照、请求围栏、分享及佣金授权不变，邀请规则/记录弹层没有有效规则时仍显示原反馈。
- 同步清理不再被消费的中英越 `network.projectionRefreshing` 文案由本轮全局整合统一执行，避免并行编辑共用语言文件。本候选只移除团队可见消费，不改三语共享文件。
- 本条款仅覆盖上述两个团队主卡。既有邀请进度空列表与成员箭头几何修复保持，返回滚动的未定位问题不凭此条款宣称解决。所有页面的静默暖刷新由同轮全局审计与分工另行覆盖；冷读、失败、提交进度和业务倒计时不混同暖刷新。

## 2026-10-28：收入卡失败反馈连续性

同一账号、绑定、语言、环境和有效只读目录上下文中，收入卡已出现真实失败和重试反馈后，普通重新进入或手动重试的未决读取继续保留该反馈。仅当当前成员网络与佣金读取均真实成功时恢复原累计收入拆分文案；其中一项先成功、另一项仍未决或再次失败时，不短暂显示正常文案。数值展示与实时状态、操作资格保持原合同，不增加等待时长或加载说明。

账号、绑定、语言、环境、目录上下文或业务写入使原展示作用域失效时同步撤销该反馈，旧请求不能在新作用域恢复旧错误；新作用域当前读取的真实错误仍正常反馈。冷读未知仍静默且不制造零。此次仅修主 Team 收入卡已经观测到的反馈闪变，不改变 Rank、邀请卡、其它页面或滚动行为。原生逐帧验收由主测试任务另行执行。

## 2026-10-28：离线目录重试的只读展示连续性

已有同账号、绑定、语言、环境和业务上下文的确认目录展示凭据时，网络断开、超时或服务暂时不可用之后再次读取，`error → loading → error` 全程保留收入与邀请奖励的历史数字及节点，并保留原错误和重试反馈。冷读没有确认凭据时不制造数字。只有展示使用此凭据，目录购买授权、成员/佣金实时资格、邀请码与分享操作不因此恢复；读取失败时原操作禁用保持。

严格拒绝、协议或配置不匹配，以及账号、绑定、语言、环境、目录准备或业务写入导致凭据失效时，仍同步清历史并拒绝旧响应。旧固定读取窗口的离线画面可能没有触发重试，不作为重复实际请求的验收替代。
