# Home / Store 被动读取与已读展示补充（2026-10-27）

## 适用范围

Home 每日签到小卡、Home 活动入口、Store 促销入口/券票；以及 Store、PromotionEntry、ReferralProgress 的目录被动读取。本条追加于全站静默暖刷新约定，不改变活动、商品阶段、库存、报价、购买、签到或领奖规则。

## 行为

- 同账号绑定、语言、环境与同一首页活动查询，Home 与 Store 共用一份仅在内存中的读取；合并进行中请求，成功结果供普通页面返回复用 15 秒。活动分页或活动列表查询仍分别读取。
- Store、活动入口及团队活动入口的普通页面目录读取合并请求，成功结果可复用 15 秒。显式目录重试/交易流程仍走既有强制新读取与请求 epoch 合同，每次实际结果仍触发原运行态版本通知。
- Home 签到与 Store 券目录的普通返回同样合并读取并复用 15 秒；429 按 Retry-After 冷却，0 表示可立即重读；未提供期限时为 30 秒。冷却不把失败改成成功，也不清除已确认展示。所有同范围目录读取（包括手动重试、强制刷新及写后重读）共同遵守这一冷却：期限内返回失败，不发请求、不把缓存提升为成功或 ready；依赖真读的操作保持关闭。
- 首次未读采用固定占位，促销入口不在内容流插入“正在读取最新信息”。已有卡片、签到天数/勾选及券票在暖读期间保留；已成功读取为空的活动入口在暖读期间保持为空。
- 普通读取失败保留已确认展示并保留错误/恢复入口。签到状态未确认时转到每日签到页恢复；促销读取失败保留原卡片及重试入口。
- 账号/绑定范围变化清除旧展示；精确 HTTP 401/403 清除受影响展示。旧账号、旧绑定、旧语言、旧运行态响应不能回写新范围。页面隐藏不会丢弃同范围正在完成的只读预热。
- 券票展示与可选券/领券资格分开：运行态失效立即清可选券，旧券票只供展示；点击券票须以当前成功读取的券资格打开领取入口，否则进入奖励列表。签到提交仍先执行强制读取；展示快照不能授予签到、购买或领奖权。

## 验证边界

本候选通过 actual SFC、真实 store 与 API 边界模拟验证；未执行 UI、ADB、真实 API、build、发布或真机验收。Store 六商品列表在同范围暖读/普通失败时保留以及新成功空列表删除已有回归，但这不能单独证明手机录像中的 6→0→6 根因已消除。目录冷却到期后，force=true 仍启动最新请求 epoch；旧成功、旧失败及旧范围的 429 不能覆盖新范围结果或设置新范围冷却。账号/环境切换沿用 prepareProductCatalog 的范围重置，清除旧期限。未遇到 429 时的强制读取与每次实际结果通知合同保持不变。


## 券目录与签到读取冷却补充

- 券目录与签到状态的所有同范围读取入口共同遵守已知 HTTP 429 的 Retry-After，包含普通返回、手动/强制刷新及动作前后的读取；0 可立即重读，未提供期限时为30秒。期限内返回读取失败，不用旧展示冒充新鲜成功。
- 普通商品目录运行态版本通知仍立即失效券的live可选资格，但不代表账号或HTTP入口变化，不能清除券目录已有冷却。展示快照继续保留，读取状态维持明确失败；真正账号/绑定范围重置清除旧期限，旧范围响应不能设置新范围期限。
- 已知冷却期间，尚未发出的领券/签到里程碑命令保持关闭；签到和复活卡沿原有前置强读返回失败而关闭，不额外给平时领取增加GET。实际POST的幂等键、签名和成功回执处理不变。
- 已发出POST的成功canonical结果仍可更新已确认展示并按原合同返回，不因后续GET处于冷却而回滚或重放POST。POST快照不得清除未到期GET冷却，实际GET成功处才清读取期限；冷却到期或新账号正常强读可恢复。

## 签到首次读取遇运行态变化的自动接续

- 同账号/绑定仍拥有该读取时，旧runtime的成功或失败都不能写入当前数据；若已有最新runtime读取，则合并等待，否则接续一次当前runtime真实读取。首读旧99不得进入展示，当前真实2到达后自然恢复ready，无需用户重新切回首页。
- 每次外部runtime失效至多接续一条当前读取；再次外部变化继续使用现有请求范围合并。没有timer、固定等待或自行重复重试。账号变化/新generation取代后不得替旧账号发恢复读或抢当前状态。
- 同HTTP范围的已知429期限仍约束恢复：当前owned旧runtime读收到429时保留期限并进入可恢复error，不发补读；已有新generation时旧429不得污染新结果。当前恢复GET正常失败时正常error/retry，不能无请求永久loading，也不能继续自驱重读。
- API环境与points客户端在runtime模块初始化时固定；实际新环境启动新的运行时/store，不沿用旧环境Promise。本增量不引入热切环境机制，不改变POST命令或回执。

## 签到读取的严格失权优先级

同当前账号且仍持有当前generation的GET返回精确HTTP401/403时，即使仅runtime已变化，也立即清除私有展示快照/规则/里程碑资格并结束error；不得按普通过期读取自动补读，也不得由全局认证恢复替代store拒绝处理。已被新账号或新generation取代的401/403继续忽略，不清新owner。成功过期读取的自动恢复与429期限处理保持原合同。
