# 付款截止、页面目录、充值线路与H4兼容

日期：2026-11-01。后发实施合同；不等于公共TEST部署、商户实款或全端验收。

## 购买付款

普通订单以创建时刻加30分钟为统一截止，活动已有更早pay_by从严；其他购买命令以冻结报价业务时刻加30分钟。报价有效期不超过15分钟且不超过同一截止；收款意图固定沿用订单截止，不因重新报价、失败重试或通用TTL设置延长。

截止后停止新付款，仅按原意图查询已付款确认。BEP20确认宽限3分钟，ERC20与银行卡5分钟，不延长用户可付款时间。已核实的付款时刻须早于有效截止，确认观察须早于宽限末端；无法证明按时的到款进入人工处理。HDPAY实际paidAt/expirationTime格式及时区仍须供应商权威资料，不从未知字段猜测付款事实。

曾有直付意图的订单由直付观察器处理固定到期，通用关单不得提前或推迟窗口；用户取消与付款中状态互斥。未到账及结果未知到期先查原单，再同事务结束商务订单、释放真实已占资源及权益；资金未知对账继续，迟到款不自动退款或入钱包。失败重试的新意图与旧键终态分别保留。

HDPAY状态5为EXPIRED/PAYMENT_FAILED，截止前可新报价/新键重试；状态4为MANUAL_REVIEW/PAYMENT_REFUNDED_REVIEW，即便原先已交付也不得掩盖。App仅DELIVERED进入完成页，人工状态不因旧交付回执显示购买成功。交付、超时、人工结果通过唯一事实接入既有消息及推送队列；队列记录不等于原生送达。

仅钱包支付（含零元权益确认）需要PIN。外部USDT/银行卡不读取PIN状态；费用未知或通道缺配置继续关闭。此轮不写费用参数、不开放通道、不改变整数充值本金与直付小数规则。

## L6与充值

有效目录补活动详情、创世抽奖、手机绑定，保留已登记支付密码；四个退役页拒绝新行为上报。旧事件不删，历史统计、筛选与CSV继续读取退役元数据原名称和层级。有效目录和历史目录有各自查询范围。

2026-11-04 修复 BUG-234、BUG-252。窗口、终端和语言相同时，矩阵与聚合 CSV 在逐页、一级和二级统计中保留只有点击的页面，三级继续限于叶子页。点击事件只贡献点击，PV 和 UV 为 0 的行在现有数值字段以 0 表示不可计算的停留和跳出，不为上卷增加停留样本或跳出分母。当前筛选导出沿用矩阵的排序指标及方向，`sortDir` 接受 `asc`、`desc`，缺省保持降序。导出继续使用 `bi_l6_export` 并留下审计。

旧card不再接受新充值且不能由旧开关重新开放；银行卡仅HDPAY，复用vietqr总开关。供应商配置缺失明确不可用，禁止回落人工转账或分配账户池。历史原键、原费用快照、回调、拒付和对账保留；退役不丢旧账。

## H4候选

资金首次安装仍使用原固定来源。H4在独立受控批次更新资金只读函数，仅额外允许指定的AFTER UPDATE ROW触发器，保留definer、原函数/赋值和EXECUTE授权；其他未知触发器继续拒绝。原锁定SQL与摘要不改。安装中断进入既有发布hold并按受控步骤恢复，不借其他功能部署自动安装H4。

专用MySQL8.4安装、重放、拒绝未知和故障恢复已验；业务TEST H4、Linux发布broker、真实资金API只读与原生推送送达另验。UVT旧数据和F1首次配置见[数据专题](FEAT-DATA-UVT-VRANK-BOOTSTRAP-20261101.md)。
