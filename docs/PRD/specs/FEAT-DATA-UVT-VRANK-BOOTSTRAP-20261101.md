# UVT 历史资产迁移与 V0–V8 首次配置

日期：2026-11-01。范围：BUG-010、BUG-007；本规格记录本轮后发合同，具体部署、实景及旧库副本验收另以回执为准。

## UVT 数据代码

2026-10-29 后端已统一消费 UVT，本次将历史结构化资产/币种代码 NEX 改为 UVT，行情 NEX_USDT 改为 UVT_USDT；NEX 行情代码同样改为 UVT。此条取代此前“仅展示改名、协议资产码保持 NEX”的冲突内容。*_nex 数据列、API 字段名、配置键、业务引用与幂等标识继续保持既有契约，不做金额换算或重算，不引入新旧双读。

迁移盘点数据库内所有 nx_ 业务表的 asset、currency、from_asset、to_asset、payment_asset、reward_type、rank_currency 字符列；奖励枚举 nex 改为 uvt。金额、余额、时间戳、用户等级、原始审计、事件或已签快照 JSON、原始哈希不改写。旧 NEX CHECK 以追加迁移扩为可承载 UVT 的约束，应用的新写入和读取仍为 UVT。

财务唯一键出现新旧代码冲突时，整个数据迁移事务回滚并返回 UVT_LEGACY_MIGRATION_CONFLICT；保留两条原账，不合账、不删账、不覆盖目标值。部署保持失败状态，需按真实业务单号、金额和重复事实受权核对后重试。

行情的唯一键碰撞采用明确的市场数据策略：已有 UVT 目标行情完整保留，碰撞的旧 NEX 行情整行（含原始 ID、代码、价格、时钟、曲线等）、目标 ID 及冲突索引存入 nx_uvt_legacy_price_archive 后去重。相同值与不同值遵循同一规则，常规行情读取采用目标报价，旧报价仍可在迁移档案审计。非碰撞历史行情原值改码，标签同步 UVT；归档不涉及用户账或资金流水。迁移失败会一并回滚归档及去重。执行需停止写入并保留正常发布备份。

启动序列不再重放会将 promotion CHECK 重建为 NEX-only 的旧 20261025_promotion_order_discount.sql，改由新增兼容迁移承接其状态/资产检查；旧锁定 SQL 字节不改。重复执行不重置已迁移行情或运营已写的 UVT 标签。

直属奖励的旧启动步骤同样改用20261101兼容版本，保留其全部表、时钟及互斥步骤和fresh前置，只将审批after_value维持TEXT，避免九级完整审批后重启被旧1024字列定义阻断。原SQL字节、审批原文/hash/状态保持。

## F1 新库首次配置

没有已确认的完整数值种子，不恢复历史 V0–V12/USD 数据，不把 TEST 当前财务配置当新环境默认值。新库通过 PC F1“首次配置 V0–V8”显式录入九级定义，再走既有确认及 A2 双人审批。提案和审批均要求 network_f1_write；A2 的创建/审批、同人禁止、对象锁、审计及回放规则继续生效。

命令为 `{domain:'F', op:'f_vrank_bootstrap', params:{ranks:[...]}}`；sourceDomain 为 F1、obj 为 current；固定目标锁 `{domain:'F',type:'vrank_bootstrap',id:'current'}`。服务端重建完整九级审阅内容，不能以客户端摘要掩盖实际参数；A2 after_value 扩为 TEXT 保存完整审阅。初始化仅允许配置表与奖励表彻底为空；任何完整、部分或已软删配置均返回 `409 VRANK_BOOTSTRAP_REQUIRES_EMPTY_CONFIGURATION`，不覆盖、不补写未批准默认值。初始化原子写入 V0–V8，必达审计失败全部回滚；不修改用户等级、历史收益或历史奖励，也不执行补发。

每级必须顺序为 V0 至 V8，字段如下：

| 字段 | 合法域 |
|---|---|
| titleCn、titleEn | 去首尾空白后非空，最长64字符；请求不得含首尾空白 |
| selfComputePoints、teamComputePoints | 0–9007199254740991整数，沿2026-10-28算力点合同 |
| directRefs、requiredDownlineCount、leadershipVotes | 0–2147483647整数 |
| requiredDownlineRank | count=0时为null；count>0时为严格低于当前阶的V0–V8 |
| unilevelDepth | 显式0表示不开通，或L1、L1-L1至L1-L7 |
| peerBonusRate | 0–1，最多4位小数 |
| rewards | 首次配置必须显式[]；奖励随后使用原F1编辑器配置，沿用原权限、资产可用性、确认、审计和B1覆盖率检查 |

V1及以上至少有一项正门槛，防止全零定义令全部账号自动晋级。所有数值均由本次受权配置明确提交。成功后 `/api/config/v-ranks` 和 F1 列表从实际业务表读取完整九级；原晋升引擎及逐阶奖励规则不变。配置失败或缺失继续明确失败，不能用客户端 mock 阶梯代替。

PC 每次只编辑一级，九级全部校验通过后才进入理由确认；提交后可进入 A2 查询原申请，刷新后仍须从原申请恢复，不能换号重复提交。A2 列表使用九级摘要，详情及执行确认展示完整中文字段、全部九级和明确的零值；前端展示不改变服务端审批快照。

初始化后的五项晋升门槛由真实配置行决定，不按旧原型的等级字段组合隐藏；算力点保持精确安全整数，不能截成32位。后续单值维护继续使用现有 network_f1_write、幂等和审计机制；2026-11-05 起，有效条件放宽另走 [F1 条件与奖励审批](../F1-条件与奖励审批-20261105.md)，收紧或无实际放宽的维护即时生效。首次整套配置仍走本节九级初始化审批。分支最低等级的“不要求”写入为NULL；选项仅有低于本级的有效等级。分支数和等级分开维护时，未设置完整的过渡状态按原晋升引擎保守处理，不制造晋升。

## 2026-11-01 独审补充：不可变证明与当前资产代码

历史的签名/回执、榜单发布payload、source_fact_json、来源快照、证明JSON及ordered_events_json保留原始NEX字节和原hash/version/业务ID。迁移后的结构化asset/currency为UVT，读取者必须在原始证明完整性、范围、时钟、金额和身份核验通过后，使用受限的“原NEX等义于当前UVT”投影对照当前业务表；不能因为保留原始证明而将NEX/UVT视作矛盾，亦不能将此兼容扩大到USDT、其他币种、反向UVT→NEX、缺失证明或任意字段差异。

资金回执先使用原始JSON核对原SHA256、参与人和账本链，再把其中Account.currency=NEX投影为UVT供当前分配/来源验证器使用；新写入仍只接受当前UVT/USDT。资产/币种投影不改amount、源业务引用、事件ID、source_ref、配置键或任意文案，不持久化回写原证明。来源对象包含的原账、收益条目、佣金、设备、质押、兑换、Genesis、直属奖励及其恢复链保持原完整字段与金额约束。

客服榜单先核原payload hash、Snapshot viewVersion和原stream哈希，再将结构化已迁UVT列与原NEX证明按上述语义对照。旧stream哈希和原版本不重算；当前索引及公开币种为UVT。Redis缓存同样先校验原Snapshot版本后建立当前币种索引；旧/新流同时存在时保留最新已验证发布，不能覆盖新版本或隐藏任一损坏证据。当前SQL只查询UVT结构化行，不增加NEX资产双读。与币种改名无关的真正篡改、金额、权限、时间或身份矛盾仍明确拒绝。
