# UVEL 暖 Tab 返回首帧滚动位置（2026-10-28）

## 交互约定

Home、Earn、Store、Team、Me 的已访问 Tab 返回时，首个可见内容帧使用该 Tab 当前查询及账号范围内已保存的滚动位置。切换时不得先显示页面顶部，再跳回已保存位置。首进没有快照的 Tab、被替换的查询从顶部开始；账号、绑定 epoch、语言或环境变更重建共享底座后不得沿用旧快照。

共享底座须以当前实际可见 Tab 的布局为准恢复，保留已有转场。Tab 内容与导航标记分批到达时，不使用仍可见的旧 Tab 高度判断新 Tab 已就绪。真实内容尚不足以到达保存位置时，保留恢复请求，随真实布局变化继续尝试；用户开始滚动后取消该请求，之后迟到的旧导航通知、内容增长不得夺回滚动位置。

返回子页、后台恢复、主动刷新、分页和再次点击当前 Tab 回到顶部仍沿用现有业务；主动回顶先取消尚未完成的滚动恢复，并同步保存当前可见 Tab 的顶部位置，即使紧接着切换其他 Tab 再返回也应保持顶部。隐藏或过期访问的回顶通知不改变当前恢复请求，普通手动滚动取消恢复时仍保存真实滚动位置。App 的保留 Tab 快照归当前共享底座实例所有，H5/普通子页不读取原生 Tab 的快照。

## 验证边界

本地回归使用真实 renderjs chassisView、mountChassis 和 Chromium DOM/layout/帧边界，覆盖暖返首帧、快速 A/B/A、旧回执、分批 DOM patch、未知高度、用户滚动优先、查询替换、后台返回和实例重建。该回归证明前端时序边界；独立审查及新原生真机首帧影片验收另由本轮主负责人执行。
