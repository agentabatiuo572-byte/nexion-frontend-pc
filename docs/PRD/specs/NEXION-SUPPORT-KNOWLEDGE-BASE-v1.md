# NEXION 客服知识库与标准话术 v1

> **现行客服输出原则（2026-08-28）**：对用户只说明当前生效的产品规则、入口、条件和结果；不得描述、确认、比较或枚举任何历史产品设计、曾用规则、已替代方案或曾经存在的功能。当前购买和提现不要求 KYC，提现地址按 App 当前页面直接管理。

> 订单、验证码、报价或活动本身当前处于过期、取消或结束状态时，可以按用户可见记录说明；不得借此扩展产品过往设计。

> 文档状态：客服执行基线（不代表金融/代币功能已获上线批准）  
> 目标：客服只陈述可验证事实，不猜测状态、不承诺收益或无依据时限、不索取密码/OTP/私钥，并把每次处理闭环到工单、权威数据、升级和用户确认。

## 1. 客服红线

### 永远不能做

- 向用户追溯、确认、比较或枚举历史产品设计；即使用户主动追问或在问题中列出，也只回答当前有效规则。
- 索取或接收密码、短信/邮箱验证码、MFA 恢复码、私钥、助记词、银行卡密码或远程控制权限。
- 通过聊天截图判断充值、提现、订单、KYC 或奖励“已经成功”；必须查服务端权威状态与业务号。
- 对结果未知的资金操作说“失败了，请重试”，或让用户重复付款/提现。
- 承诺固定收益、APY、NEX 价格、上所、一定到账、一定解冻、一定通过 KYC 或具体补偿。
- 用“监管要求”“MSB/MiCA/Chainalysis/PwC”等未在 CLM 台账获批的说法安抚用户。
- 代替用户更改身份、钱包地址、提现状态、风险决定、账本或审计记录。
- 为赶 SLA 绕过数据作用域、maker/checker、二次确认、工单版本/CAS 或操作理由。

### 每单必须记录

`ticketNo`、用户验证方式、用户 ID（不记录秘密）、问题类别、业务号、当前权威状态、最近状态时间、已执行只读检查、用户看到的错误、风险信号、升级对象、下一次更新触发点、最终结果和用户确认。

## 2. 身份验证与数据最小化

| 风险 | 可使用的验证 | 禁止 |
|---|---|---|
| 普通咨询 | 登录态工单、非敏感订单尾号、App 内消息 | 索取完整证件、完整地址、OTP |
| 账号/安全 | 登录态 + 已绑定渠道挑战；高风险走专门恢复流 | 仅凭昵称/截图/来电号码改绑 |
| KYC/钱包/提现 | 强认证 + 业务号 + 服务端主体一致；按风险规则升级 | 客服手工放行或复制完整证件到工单 |
| 数据权利/删除 | 账号内申请或受控外部验证流程 | 要求用户发送密码、私钥或无关材料 |

用户主动发送秘密时：停止处理该秘密，告知用户不要再分享；按安全事件流程标记/限制附件访问；不得在回复中复述。

## 3. 标准处理算法

1. **确认诉求**：用一句话复述用户想解决什么，不先给结论。
2. **安全验证**：选择与风险相称的验证方式，只收最少字段。
3. **读取事实**：从工单授权范围读取用户、订单/资金、风控、审计和供应商 reference；记录时间。
4. **分类状态**：已完成、处理中、需要用户动作、被拒绝、结果未知、服务受阻。
5. **执行允许动作**：提供说明、补充材料入口、刷新权威查询、创建升级；写操作必须按权限/审批执行。
6. **明确下一步**：说明谁在做什么、下一次更新在何种事件触发；没有已批准 SLA 时不编造时长。
7. **关闭验证**：权威状态已终结、跨域影响一致、用户收到结果、工单记录完整后关闭。

## 4. 知识库目录

### KB-01 无法登录 / 验证码收不到

- 检查：账号是否存在、账号状态、发送限流、模板/通道状态、验证码过期、设备时间、登录失败计数。
- 动作：让用户从官方入口重新请求一次；若通道异常，创建平台升级，不关闭为“用户问题”。
- 话术：“我已确认你的登录请求。请不要把验证码发给任何人（包括客服）。我正在检查账号状态和发送通道；如果系统无法确认上一次请求结果，我们不会让你连续重复操作。”
- 升级：疑似账号接管、SIM 换卡、同一账号多地快速登录、通道大面积失败。

### KB-02 MFA 丢失 / 换手机

- 检查：是否仍有可信会话、恢复流程资格、近期改密/改绑、风险命中。
- 动作：进入受控恢复；完成后吊销旧会话/恢复凭证并通知用户。
- 禁止：客服直接关闭 MFA、接收恢复码。
- 关闭：新 MFA 已绑定、旧凭证无效、A2 审计存在、用户重新登录成功。

### KB-03 账号被冻结/停用

- 检查：权威账号状态、来源、内部原因码、期限/退出条件、关联风险/安全工单，以及是否存在经风控/法务批准的 `publicDisclosureCode`。
- 话术：“当前账号处于受限状态。客服不会绕过安全控制；我会提供已获批准的用户说明、需要的材料和申诉入口。最终结果以复核状态为准。”
- 披露边界：只允许回复 `publicDisclosureCode` 对应的公开文案；不得披露 AML/反作弊命中、供应商标签、调查范围或可被用于规避控制的内部原因。没有公开代码时，只说明账号受限和申诉入口。
- 升级：理由缺失、状态与审计不一致、无申诉入口、禁用后旧会话仍有效。

### KB-04 KYC 待处理

- 检查：`nx_kyc_profile.status`、提交时间、供应商 reference、需要用户动作、重复档案、SLA 是否已批准。
- 话术：“核验仍在处理中。请不要重复提交证件，除非页面明确要求补充。我们会在状态发生变化或需要你操作时通过官方渠道更新。”
- 禁止：承诺一定通过/固定完成时间；把 `nx_user.kyc_status` 投影当唯一事实。

### KB-05 KYC 被拒绝/需要补件

- 检查：仅使用经风控与法务批准的 `publicDisclosureCode` 及对应公开文案；内部供应商、AML、反作弊或调查原因不得因“有原因码”而披露。
- 动作：有获批公开代码时给出最少且具体的补件要求和安全上传入口；没有公开代码时只说明核验受限，并提供安全补件入口与申诉入口。
- 禁止：要求通过聊天发送证件；披露可被用于规避风控的内部规则。

### KB-06 钱包地址配对/换绑

- 检查：网络、地址格式、KYC 配对事实、冷却/强认证、是否有进行中的提现。
- 话术：“为避免资产发往错误地址，客服不能直接替你修改。请使用账号内的安全换绑流程，并逐字确认网络和地址；进行中的提现不会自动改到新地址。”
- 升级：地址疑似被替换、用户否认操作、跨网络、旧地址仍可提交。

### KB-07 充值未到账

- 收集：`depositNo` 或链交易哈希、网络、资产；不收私钥。
- 检查：链上可见性、确认数、地址归属、状态、`ledger_id`、结果未知/失败原因。
- 话术：“我已按交易号检查。链上确认和账户入账是两个步骤；在权威状态确认前，请不要重复转账。我们会以充值单和账本结果更新你。”
- 升级：已满足确认数但无账本、重复入账、错误网络、链重组、金额精度异常。

### KB-08 重复扣款 / 支付结果未知

- 检查：订单号、paymentNo、供应商支付 ID、回调验签、权威查询、账本/订单副作用。
- 动作：冻结重复尝试建议，进入对账；不要把超时当失败。
- 话术：“当前支付结果尚未确认。请先不要再次支付；我们正在对照支付机构和订单记录，确认后只保留一次有效结果。”
- 升级：两个成功扣款、回调验签失败却变更状态、退款/拒付冲突。

### KB-09 提现审核中

- 检查：withdrawalNo、状态、费用快照、风控决定、是否已广播、目标网络/地址（遮罩）。
- 话术：“提现正在按当前状态处理。客服不会绕过审核或承诺具体到账时间；你可以在状态页查看进展。若需要补充信息，我们只会通过官方入口通知。”
- 禁止：让用户再提一笔测试；承诺 30/45 天，除非 SLA/条款已正式批准且适用该用户。

### KB-10 提现结果未知/广播异常

- 检查：`chain_tx_hash`、广播次数、供应商查询、链上状态、账本冻结/扣减；区分未广播、已广播未确认、未知。
- 动作：保留原提现单、幂等键、每次广播尝试、供应商 reference 和链查询证据；未知期间不得释放被占用余额、创建替代提现或重新广播。资金团队进入对账，补偿/冲正由独立双人审批。
- 话术：“系统还不能确认这笔提现的最终结果。为避免重复转出，我们已停止重复操作并进入核对；结论会以同一个提现单更新。”
- P0：出现两个链交易、余额为负、账本与链上方向不一致。
- 终结条件：链/供应商查询、提现单、账本、可用余额和用户可见状态一致；若存在两笔链交易，两个事实均不可变保留并分别进入追回、补偿、冲正或持续观察的批准流程。

### KB-11 提现失败/退回

- 检查：是否最终失败、扣款是否解冻/冲正、费用如何处理、失败原因能否安全披露。
- 关闭：账本恢复、状态终结、A2/A4 一致、用户能看到原因与可行下一步。
- 禁止：只改页面为失败而不核对余额。

### KB-12 余额或账单不一致

- 检查：以 `nx_wallet_ledger` 顺序和 `balance_after` 为主，核对重复/缺失业务号、资产、精度和投影缓存。
- 话术：“我会以账本记录核对，而不是仅依据页面缓存。核对完成前请不要通过重复交易尝试修正余额。”
- P0：负余额、跨用户流水、单笔重复、资产币种混淆。

### KB-13 订单未生成/状态不更新

- 检查：订单号、库存预留、支付状态、回调、过期、幂等键和 outbox。
- 动作：结果未知先查询，不重新创建；库存和订单必须一起核对。
- 升级：付款成功无订单、重复订单、关闭后库存未释放。

### KB-14 退款、退货与拒付

- 检查：销售地区、法定权利、订单/支付/物流、设备激活、奖励/等级影响、财务状态。
- 话术：“我们会按你的订单、支付方式和适用退换规则核对。设备激活或奖励状态不会自动取消你依法享有的权利；最终处理及影响会在确认前列明。”
- 禁止：引用未经地区审查的“一经激活最终成交”。

### KB-15 设备离线 / 无任务 / 显示算力异常

- 检查：所有权、设备状态、`last_seen_at`、网络、服务事件、任务状态、指标定义。
- 话术：“设备在线状态、设备能力指标和已结算收入是三类不同事实。我会分别核对；页面显示值不代表已入账收益。”
- 禁止：承诺持续有任务、解释为设备月龄必然导致收益下降，除非有获批证据。

### KB-16 设备解绑、下架或置换

- 检查：进行中的任务、待结算金额、所有权、订单、折抵快照、二次确认和可恢复性。
- 动作：向用户列出具体受影响对象；不可逆操作必须用户明确确认。
- 关闭：旧设备状态、任务、账本、新订单、审计均一致。

### KB-17 奖励未到账/被审核

- 检查：活动版本、资格时间、地区、反作弊、事件/账本、是否为当前允许的奖励类型。
- 话术：“奖励资格和实际入账是两个步骤。我会按活动版本和账本核对；在确认前不会承诺奖励数量或补发。”
- 禁止：用 App 客户端常量补发；对被商店/市场阻断的 NEX 活动做承诺。

### KB-18 推荐关系、佣金或等级争议

- 检查：推荐发生时间、代码快照、关系权威 ID、合格行为、退款/拒付、规则版本、账本。
- 动作：只解释获批单层规则；网络奖金当前 BLOCKED。
- 升级：关系被改写、多账号、用户付费与上级收益直接挂钩、会计来源不明。

### KB-19 锁仓、兑换、NEX 价格/上所咨询

- 当前门禁：真实用户功能及推广保持 BLOCKED，客服不提供投资建议。
- 话术：“目前客服无法向你提供 NEX 价格、上所时间、收益预测或投资建议。相关功能是否开放以你所在地区的正式产品页面和已生效条款为准；请勿依据非官方消息作出资金决定。”
- 安全：发现冒充官方募资、转币、私聊地址，立即进入安全事件流程。

### KB-20 账号删除与数据权利

- 检查：申请来源、身份、账户内未决资金/订单、法定保留例外、供应商传播。
- 话术：“你可以申请删除整个账号及相关数据。若某些记录依法或因未结交易必须暂时保留，我们会说明类别和原因；停用账号不等于完成删除。”
- 关闭：App 内/外状态一致、主库/对象/SDK/供应商完成或记录合法例外、访问凭证吊销、用户收到确认。

### KB-21 隐私、安全或冒充举报

- 动作：停止要求用户继续交互可疑链接；收集最小证据；创建安全事件；必要时冻结风险动作而非擅自删除证据。
- 话术：“感谢你报告。请不要继续回复对方或提供验证码、密码、私钥/助记词。我们不会通过私聊要求转币或共享这些信息。该报告已进入安全核查。”
- P0：私钥/会话泄露、管理员账号接管、大量用户受影响、公开数据泄露。

### KB-22 大面积服务不可用

- 检查：状态页、告警、错误范围、资金写入是否安全停止、已知恢复/回滚状态。
- 话术：“我们确认部分服务受影响。为避免重复操作，请暂时不要重复支付、充值或提现。我们会在确认范围或状态变化时更新；尚未确认的结果会逐笔核对。”
- 禁止：无证据报恢复时间；把产品故障归因用户网络。

### KB-23 试用设备已有收益，但钱包余额未增加

- 现行规则：试用期间，收益只显示在试用设备卡片中，不写入钱包余额，也不可提现或折现。它是试用累计收益，属于购机抵扣权益；对用户不使用 `shadow` 等内部技术名称。
- 购买结算：完成设备购买时，USDT 试用收益优先抵扣购机款；仅超出抵扣上限的 USDT 部分（如果存在），在购买、支付和履约成功后进入 USDT 余额。试用产生的 NEX 在购买完成后，按试用转化规则进入 NEX 余额。
- 不入账边界：取消购买、支付失败，或试用结束后在有效期内未购买，试用收益不会进入余额。
- 用户自查入口：App “我的 → 免费试用 → 查看抵扣规则”。
- 异常判定：刚开始试用后余额不增加属于正常规则，不直接转人工。只有在设备购买、支付、履约均已成功后，应入账的超额 USDT 或 NEX 仍未到账，才属于结算异常，需按订单记录核对。
- 标准话术：“这不是余额漏账。你当前看到的是试用累计收益，属于购机抵扣权益，不是试用期间可提现的真实余额。”

### KB-24 NexGrid 怎么拉新、怎么形成邀请传播

- 对外定位：NexGrid 当前主要通过“产品体验 + 用户分享”拉新。新用户可先了解平台、完成新手引导，并通过免费试用体验设备运行和产出展示；已有用户可在 App 分享专属邀请链接、邀请码、二维码或邀请海报。
- 传播闭环：好友通过公开邀请入口注册后，也会获得自己的分享入口，可以继续向朋友介绍平台，形成自然传播。客服只说明用户可见、可操作的公开流程。
- 权益边界：邀请用于帮助朋友进入并了解产品，不代表必然获得奖励。当前没有已批准并生效的推荐奖励活动，因此当前没有启用的推荐奖励；以后如有活动，具体权益只以 App 当期正式公示并已生效的规则为准。当前未启用多级或网络奖金，不按拉人头或发展下线计酬，也不承诺收益。
