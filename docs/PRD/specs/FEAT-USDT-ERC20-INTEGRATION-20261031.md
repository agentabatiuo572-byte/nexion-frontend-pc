# USDT ERC20 接入（2026-10-31）

状态：test 候选实现与本地定向验证。TEST 部署、实际页面操作及真实链上资金验收分别记录，不因本文或测试通过视为已完成。未经本批明确批准不得合并 main；不自动开启充值、自动入账、归集或出款。

## 范围与网络事实

保留 BEP20，新增 Ethereum 主网 ERC20 USDT。网络标识为 BEP20 / ERC20，地址格式均可能为 0x 开头的 EVM 地址，地址相同或格式相同不代表网络互通。只按用户所选网络及服务端返回能力操作，不回退到其他链。币种、链 ID、USDT 合约、精度、确认数与真实 RPC 证据由后端网络配置及服务商项目能力共同核实；商户收银台存在 ERC20 币种不是 WaaS 能力证明。

## App / H5 充值

入口：我的 → 钱包 → 充值 → USDT 链上。保留现有网络 chip、专属地址、二维码、复制、费用、最低额、确认数、风险警示和最近入金样式；正式模式显示 BEP20、ERC20 两项。

选择网络调用 `GET /api/deposits/address?network=BEP20|ERC20`。成功、关闭和准备中均须返回请求的 network。只有 enabled=true、响应网络匹配且地址及策略字段有效才展示可复制地址和二维码；不使用 Mock 地址。关闭、缺失能力、未知响应或读取失败不得保留另一网络地址。切网络立即清空地址、二维码和复制成功状态，旧响应凭 generation、账号绑定 epoch 隔离；返回页面按当前网络重新读取。服务端仍可按既有试点规则单独关闭自动入账，此时沿用人工复核提示。

费用、最低额与确认数取服务端共同充值政策，不用 ERC20 固定默认费。最近入金按行 network 显示；旧数据未带 network 时按历史 BEP20 兼容。已入账记录进入交易详情时传原行网络，ERC20 展示 Ethereum / Etherscan，BEP20 展示 BNB Smart Chain / BscScan。错误网络或资产风险提示与现有中、英、越三语同步。

## 两条购买路径

1. 钱包充值：ERC20 充值经供应商和独立链证据确认后进入 USDT 余额，用户随后走钱包购买与原支付密码流程。
2. 订单直付：购买、试用转购买、升级置换及扩容的外部付款增加 `paymentMethod=CREGIS_USDT_ERC20`，报价和付款单 `network=ERC20`；原 `CREGIS_USDT_BSC` / `network=BSC` 保留。收款核实后履约，`walletDebitUsdt=0`，不再给钱包余额充值后扣款，避免双计。

两条路径分别归属，不能把同一笔链上入金同时充值和支付订单。订单直付只认服务端费用快照、原付款单与原命令号；网络切换须新报价，不能替换既有付款单网络或费用。ERC20 费用未配置时不能创建新报价。恢复及查询沿用原单，未知结果不能新建或重复付款。

App 直付选择增加 Ethereum / ERC20，地址二维码、复制与错网提示使用付款单网络，说明外部钱包 ETH Gas 另付；BSC 仍说明 BNB Gas。相关文案均有中文、英文、越南文。订单交付回执、试用、升级置换和容量回执解析均识别新增 paymentMethod，仍验证原业务身份、金额及零钱包扣款。

## 提现与 PC 资金管理

提现 App 已有 USDT-ERC20 网络及地址绑定、分网络费用界面，是否可选继续取 `/api/withdrawals/policy` 的 enabledNetworks；服务端须综合支付商币种能力、Ethereum RPC、D5 网络开关、总闸和风控。新增顶层 `networkCapabilities=[{network,configured,enabled,disabledReason}]` 仅作权威能力说明，不绕过 enabledNetworks。ERC20 TX_ORPHANED 映射冻结，继续占用原提现槽位，不显示为失败退款。

PC D1 `/finance/recon`：订单直付费用及记录增加独立 ERC20 渠道。新渠道初始 configured=false、费用 null，不以 0 代替未配置；仅明确填写并保存的渠道进入更新，原付款单保留旧费用快照。Cregis BEP20/ERC20 共用最低充值额，在直付区域只读，仍由原 A2 双人审批修改，不增加旁路。付款详情按链展示 ETH / BNB Gas。

Cregis 资金状态展示各网 networkCapabilities、入金记录网络与异常队列原网络；地址池切换网络读取 `exceptions.addressPools.BEP20|ERC20`，保留旧 addressPool 作为 BEP20 兼容，缺 ERC20 池时不可创建。补充一个地址调用 `POST /cregis/addresses/provision?network=...`，确认框冻结原网络。库存、核验中和未知创建分别按网络计算，自动补充目标配置仍共用。写权限、CAS、双人审批、原请求恢复规则不变。

## 配置与未验边界

代码接线不等于开通：须独立核实 Cregis 项目 ERC20 建址、回调/查询和 payout 能力，Ethereum 主网 RPC 与确认策略，ERC20 直付费用及 D5 开关。ERC20 充值与出款分别新增独立批准开关，默认关闭，不继承既有 BEP20 总开关或历史 ERC20 业务配置的启用值；关闭时不分配库存地址、不给新单自动入账、不创建新出款，已发原单仍可只读查询恢复。地址池“可补充”状态也必须包含该网充值批准状态。

本轮 ERC20 异常退款、孤立款人工认领明确返回网络不支持，不沿用 BEP20 资金处分路径；自动归集和甲方付款仍只处理 BEP20。ERC20 充值复核入账与重组证明/冻结恢复按原事件网络核验。现有 BSC 专用归集/付款准备不能直接用于 ERC20；未实现或未获授权路径须关闭，不把 ETH Gas 当作 BNB。

本地验证覆盖：选链请求和响应严格匹配、切网络立即清地址、迟到响应隔离、关闭网络不借用地址、ERC20 二维码/复制/记录详情、三语警示、ERC20 外部购买精度与恢复、ERC20 未决提现冻结、PC 分网地址池和能力、独立费用配置及旧部署兼容。无真实转账、提现、归集或外部付款测试。TEST 页面及真实设备证据由整合发布阶段补充。

复核补充：PC“最近完整对账”摘要须按当前所选网络筛选并显示网络名；旧无网络记录仅兼容BEP20，不得让ERC20借用BSC完成时间。缺network但有供应商chainId/chain_id时，60识别ERC20、2510识别BEP20；未知链显示待核实。新购买原命令持久化原报价paymentMethod/network并在create/query/重载恢复时严格匹配；历史记录首次按原key/quoteId恢复后绑定，后续不准改网。

PC资金面板的 App 收款入口、自动入账能力、地址分配、自动入账及出款总闸均明确标注“全局”。这些值来自共同配置或总闸，不随网络选择变化；某网池不可用、出款未就绪或尚无完整对账时，全局开启不表示该网已经开通。分网络能力、地址池与最近完整对账继续按所选网络分别展示。嵌入式和独立式面板复用同一文案与状态逻辑。
