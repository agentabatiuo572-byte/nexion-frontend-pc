日期：2026-10-29。适用：首页我的设备、赚取算力队列、设备仓库；依据用户本轮明确的激活列表与六槽要求。

## 列表与数量

- 2026-10-30 用户纠正：购买成功自动激活；激活即 Online；取消激活后直接退出算力队列并回到仓库，不存在 Offline 产品状态。算力队列展示账号当前已确认激活的设备实例，不要求购买后再次手动激活。心跳与执行器健康不另拆成设备业务状态，也不改变实际任务执行资格或收益。
- 设备行按实例 ID 区分，同型号的两次购买不得按型号合并或覆盖。两台均有效并已激活时显示两行；旧实例真正到期或结束后退出有效队列，新实例独立保留。历史订单和累计收益记录不随退出队列删除。
- 2026-10-30用户明确取消Cloud Share免槽：手机、PC算力、Cloud Share、Box、Rack所有有效激活实例合计最多6台，每实例占1槽；试用及已保留订单继续遵守原有容量预留规则。详见[统一六槽与N路执行](UVEL_全设备统一六槽与按激活数并行_TEST_20261030.md)。
- 分母取后端权威容量，产品值为 6；后端激活、置换、套餐与管理端限制必须一致，不能只把前端分母写成 6。
- 容量C还计入原有合法订单/试用占位，执行N只统计合法有效激活设备；等待当前任务后停用在实际停用前仍占槽并显示Online，原任务合法收口、不再接下一任务，真正停用后才释放。执行器负责多账号时按总有效激活数提供独立runner，不把某一账号六槽误用为全服六任务上限。

## 账号设备与当前手机

账号已激活的手机可能绑定于另一安装。该实例按权威激活事实显示业务 Online，不因当前安装未校准或技术心跳缺失而改写成“激活当前手机”或业务 Offline；设备能力、实际任务与收益仍读取对应实例的真实记录。未确认激活事实时显示读取/确认反馈，不能猜为 Online。

## 首页添加与当前任务（2026-10-30 纠正）

抵扣升级以指定旧设备的位置继承：旧机已激活时，取消旧机激活后用其抵扣，新机直接进入原算力槽并激活；旧机未激活、在仓库时，新机直接入仓库。该置换不按满槽与否分支，不新增一个槽位；旧机归属、版本、幂等及交易失败回滚仍校验。旧任务只通过合法取消处理，不生成完成回执或奖励。普通不抵扣的新购成功自动激活；保留旧机的全价购买不是抵扣置换。

首页“添加设备”和赚取页空槽统一读取当前账号可选择的仓库设备；有可选择设备时打开选择弹窗，用户选定后执行正常激活并读回；没有时才跳商城。库存读取失败或尚未就绪不能当空仓跳购买；取消选择不改变设备状态。手动停用后的已购设备保留在仓库，重新启用仍须正常归属、版本及六槽校验。购买时的容量与资格限制保持，购买失败不能显示激活成功。

首页与赚取页算力队列的当前任务与进度条直接可见，不依赖点击箭头或展开，详情展开另展示统计及管理。按实例显示真实任务；无任务不虚构进度，暂停不继续增长。100%估时不是完成，仍以真实回执及结算判定完成与收益。隐藏数据时同时遮住任务敏感信息与百分比，三语、亮暗主题保持一致。

当前手机的校准、绑定、执行与遥测资格继续独立校验；只读展示不能激活当前安装或获得执行权限。当前手机激活入口仍在“更多方式”和设备管理中，未确认激活的手机不进入队列。
