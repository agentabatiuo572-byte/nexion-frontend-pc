# 目录临时读取失败与团队历史数字（2026-10-28）

已确认的同账号、同绑定代次、同环境、同语言、同业务对象数字，在目录普通网络中断、连接超时、HTTP 5xx、429 时允许继续作为只读历史内容展示。目录读取失败仍返回失败并清除实时目录、可售状态和服务器权威标记；历史内容不授予购买、报价、资格、邀请复制或业务写入权限。

目录只读上下文凭据独立于目录商品快照，不携带商品、库存、资格或服务器实时权威字段，仅记录已验证的生产来源、空 run、目录 revision、账号绑定代次和目录事件 runtime 代次。严格认证（包括业务 envelope 的 401/403）、业务拒绝、协议错误、配置错误、未知错误、账号重绑、环境变化均撤销该凭据。仅本次目录读取自身发布的 runtime 事件允许沿用已确认上下文；外部 runtime/业务写入或嵌套的新 runtime 立即撤销，旧未决目录响应不能恢复。真实非生产或非空 run 不建立该凭据。

团队和邀请消费者仍独立验证每项业务快照和账号、绑定代次、语言、环境所有者；历史数字一旦撤销，不得仅凭新目录凭据重新建立。语言和所有者 A-B-A 必须拒绝旧请求。

429 冷却适用于主动强刷、普通读取和被动 revalidate；显式 0 有效，未给有效 Retry-After 使用 30 秒。目录自己的 runtime 通知、写入后的重读与旧响应失效规则继续保留。

验证范围：本地组合源码可复现目录失败导致 Team 数字清空的路径；真实手机本次目录请求的网络错误 code 未采集，不把组合测试视作手机验收。实际 Team/Invite 消费及真机验收由整合和独立验收负责。


同步观察者重入边界：目录响应写入展示快照、只读凭据或任何实时字段后，必须再次核对该请求原始账号绑定/请求/runtime 代次。同步观察者触发业务写入或 prepare A-B-A 后，旧响应立即停止，不得继续发布成功或把旧响应绑定至新账号代次。目录 runtime 发布先由 runtime 增加真实代次，再在通知前原子更新凭据；仅实际通知 scope 对象身份且仍 current 才是自身目录事件，不能用预测代次数值冒认。回调中触发的新写入及外层随后发出的旧通知均不得恢复凭据或实时资格。

429 数字优先级：只有真实 HTTP429、错误类别为 http 且没有认证 401/403 冲突才设置冷却。auth/business/protocol/configuration 类别即使附带 status429，也不因数字而阻断新的恢复读取；HTTP404+业务code429、HTTP503+业务code429均不设置429冷却，后者仍仅按5xx只读历史处理。
