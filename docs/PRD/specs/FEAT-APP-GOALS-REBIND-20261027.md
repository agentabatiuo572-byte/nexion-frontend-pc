# Goals 绑定后自动恢复补充（2026-10-27）

在原非团队静默/静态候选基础上修复正常页面返回的 Goals 恢复路径。已有旧读取未结束时，页面先收到账号绑定 epoch 或 onShow，随后同一 tick store 对同一账号重绑；当前新读取成功后，页面应自动显示该绑定的成功空结果或目标列表，不要求用户额外点刷新。

Goals store 提供仅用于只读订阅的 readBindingEpoch，在原 scopeEpoch 递增并清理旧状态后、原 ensure 前通知页面。页面同步清旧展示归属/推荐文字并订阅该实际绑定的 ensure；仍按原 app owner、store scope、成功 revision 与请求 epoch 校验。原旧请求 success/error 均不能回填或清当前成功；实际 401/403/503 保留错误与重试。保存、删除、幂等、推荐跳转和权限门禁不放宽。

冷态未知目标/期限时，固定预设名称与按钮继续显示，input 为 —，没有默认 1000/90 的视觉选中；实际当前读取成功后才显示匹配的选中状态。已保存目标未修改时 Save 仍按原规则禁用；成功空结果可正常编辑。

验证包含真实 SFC + 实际 Pinia store 的 return-before-bind、立即/延迟成功、空/非空、旧成功/错误迟到、真实错误重试和环境失效后零 create。UI、滚动和原生页面实景仍由主任务验收。
