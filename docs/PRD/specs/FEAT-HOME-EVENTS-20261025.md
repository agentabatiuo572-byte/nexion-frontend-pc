# UVEL 首页、信任中心与活动规则（2026-10-25）

本规格覆盖推荐课程、网络脉搏、信任中心、原型全部十项活动及新增创世抽奖。适用于正式 App `test`、共享 H5 和 PC/后端 TEST；取代旧原型同功能的模拟数据、装饰性活动和本地领奖逻辑。实现与验收状态分别记录，本文件不是发布成功证明。

## 1. 推荐课程

推荐依据当前账号接口的完成状态：先选择未完成的精选课程，再按发布顺序推荐其他未完成课程。完成学习/测验后返回首页重新读取，推荐下一项；奖励由原课程服务发放，不因推荐切换再次领取。

卡片展示课程名称、真实时长、奖励、进度以及“开始/继续学习”。全部已完成显示回顾入口；尚无课程与读取失败分别显示对应状态，不能作为“全部完成”。首页进入课程携带来源，返回首页；课程中心仍按自身导航返回。切账号、语言、运行环境及离开页面后，旧请求不可覆盖新页面。支持中文、英文、越南文及窄屏。

## 2. 网络脉搏与 H9

网络脉搏展示“注册用户 / 在线设备 / 设备预估排名”三格，移除更新时间。注册用户读取 H9 的公布基数、月增长率和时间锚，由服务端按每月 30 天计算；在线设备使用 H9“首页数字增长”的同一持久化随机批次当前值。公开投影字段为 `publicStats.networkPulse`。

两个展示数字在配置重新读取时更新，不增加每秒请求，也不在网络脉搏另造随机序列。介绍页仍按既有批次逐秒显示。设备预估排名按以下独立规则计算；不改写真实人口、真实榜单或设备算力。缺失/失败显示未取得状态，不能默认零；H9 数字不写入财务、设备或真实经营统计。

H9 配置保存回读和刷新必须保留服务端实际数值精度；输入步长不作为舍入规则，不能出现已保存 2.91% 而表单显示 2.9% 或无操作即提示未保存改动。

H9 页面说明须明确：在线设备展示量用于设备预估排名；注册用户数字、旧虚拟人口和历史算力分位表不参与该排名。展示配置不改变真实设备算力和资金账单，不能笼统声称整页配置“不影响个人名次”。历史配置继续保留。

### 2.1 设备预估排名

H9 增加独立“设备预估排名”卡片，开关、档位表和保存入口位于同一板块。默认关闭、配置版本为 0、档位为空；不能因修改其他首页展示字段自动开启或覆盖。具备 `growth_h9_write` 权限的操作员可增删档位、编辑名称、占比、最低及最高算力，并填写 8–200 字理由保存；无权限只读。保存读回服务端配置和版本，冲突后重新读取再修改。相同提交意图重试复用幂等编号，结果未知时不得宣称未生效。

管理接口 `GET/PATCH /api/admin/growth/device-rank-config`。读取及保存返回 `{version, enabled, tiers:[{name, sharePct, minTops, maxTops}]}`；保存提交 `expectedVersion, enabled, tiers, reason` 及 `Idempotency-Key`，服务端鉴权、校验版本并记录审计。名称去除首尾空格后 1–60 字；开启时须配置 1–20 档，关闭时允许空档，非空时仍完整校验。占比允许 0、最多两位小数，合计严格 100%；算力为 0–1000000000 TOPS、最多六位小数，最低不得大于最高。允许区间重叠或相等，不把档位名称当作真实设备型号认证。

总规模取 H9 当前在线设备展示量 N，不另提供人数输入。支持规模 1–1000 万台，在线量为 0 或超出上限时 App 显示排名暂不可用；配置保存不阻止，首页展示增长也不会被排名上限截断。后端按配置档位占比及算力范围生成 N−1 个参考设备样本，当前绑定手机作为剩余一台参与，使用该手机有效算力，不合计其他手机或云设备。名次为严格高于当前设备算力的参考样本数 + 1，同算力并列，范围为 1..N。客户端明确标注模拟参考，不宣称真实设备榜单，不影响奖励、余额或设备收益。

服务端共享版本化快照；同配置、同规模重复请求不重新随机，规模增长只追加样本，规模减少使用稳定样本前缀。只有档位分布实际变化才更新随机种子并建立新模型；开关切换会更新配置版本但保留模型，相同配置重复保存不更新版本。查询使用有界缓存及排序后二分计算，不向 App 传输样本，不新增每秒轮询。未激活或无有效算力显示未上榜；关闭、配置缺失、缓存异常或请求故障分别显示对应不可用状态，不回退既有真实名次或硬编码名次。中文、英文、越南文一致。

## 3. 信任中心

使用整条圆角标题栏；平台介绍读取 I4 发布的 UVEL 文案，无简介时给出中性引导。页面提供“规则与资料”四入口：UVT 使用说明、服务条款、隐私政策、风险披露，对应现有正式页面，支持三语。I4 请求失败不阻断这些入口。

平台运行数据仅采用真实验证统计。公开资料仅展示已配置、可打开的有效链接；不能用厂商技术规格冒充平台审计、储备证明或合规资质。原型中的投资方、认证、审计机构、媒体、团队、交易所上线和虚构金额不是可直接发布的资料。保留真实资料缺失状态，不制造文件或无效链接。

### 4.1 页面和配置边界

转盘扇区按真实奖励金额与类型显示双行短标签，单位随语言切换，完整保留金额且不跨扇区或遮挡中心；奖池和中奖结果继续显示完整奖名。历史优先复用奖档、类型、金额均匹配的显示名，否则按该笔回执的类型与金额显示，不展示奖档内部代码，也不以当前配置金额改写旧奖励。

转盘历史时间由服务端返回显式时区偏移，客户端统一换算并标明 UTC；旧无时区值留空，不按终端时区猜测。

本人在同一活动 ID 与代码下存在真实转盘记录时，活动显示已参与、完成进度 1；仅打开转盘不算参与。关闭转盘后，当前可见活动列表（含任务中心内嵌页）重新读取一次参与状态；读取失败显示正常错误态，不轮询或自动补发抽奖。

“我的 → 账户”常驻“任务中心”入口，进入今日、本周、活动和成就页签；不因任务全部完成、任务读取状态或 H9 新手任务开关而隐藏。用户可经“任务中心 → 活动”进入活动列表、幸运转盘和创世抽奖。

非转盘活动进入专属详情，展示期限、玩法、当前进度、条件及复合奖励；“总奖池”不能显示为个人奖励。关闭、未开始、结束或不符合资格时不可参与。活动列表保留全部、进行中、预告、已参与、已结束筛选。区域竞赛使用本活动榜单，不能跳成全站排行榜。

H4 新增玩法与开放设置，管理接口 `/api/admin/growth/event-rules`，写入单项带活动代码、配置版本及幂等键。开启前检查三语内容、合法期限、玩法字段、关联促销/商品、预算及库存。首次开启后冻结玩法和有效期；关闭后同一期不得重开。关闭阻止新增参与，不取消已形成的结算义务。两类奖池的既有参与者继续观察到原截止时间；关闭前已达标或已完成交易的个人奖励仍可见并可领取，关闭后不新增资格。旧内容创建入口也必须生成关闭草稿；未知玩法不能绕过发布校验。

升级优惠的“减 $500”通过正式促销购买规则配置为“订单立减（USDT）”：仅购买者可选，协议 `buyerReward.type=DISCOUNT_USDT`、`calculation=FIXED`、`amount` 为最多六位小数的正金额，不配置资产政策；预算使用独立的 `DISCOUNT_USDT` 额度。立减按购买规则组数减少对应商品应付，不产生余额奖励或待发奖励义务，不能超过该商品扣除已有优惠后的应付金额，超出时阻止报价。现行退款链仅支持正实付订单，含立减的整单净实付必须大于 0，否则拒绝报价并提示调整购买数量或活动配置；多商品订单允许某一行实付为 0，但整单仍须大于 0。立减付款后计入已用立减额度，不产生待发余额奖励；整单真实退款后恢复对应额度。PC 编辑、组合预览与审核展示“订单立减”，试算分别列出优惠合计、其中订单立减和应付金额；旧响应缺少立减明细时显示未提供。结算、叠加、售后、报价、审核发布的批准政策及双人审核要求继续生效。

黑五全场八折通过 `voucherId` 关联现有 H7 百分比券（如 `BF20`），不新增折扣引擎。PC 从真实券目录选择，保留未出现在当前目录的存量关联并提示核对；券读取失败或缺少 H7 查看权限时不得伪造可选项。开启前要求券已启用、减免 20%、面向全部用户及全硬件、无最低消费及优惠封顶、领取入口不限或含商城，且有效期覆盖活动全期；缺项分别显示可用券、折扣、适用范围、领取入口和期限的具体处理提示。每账号领取一次、仅用于单笔订单，重复领取不增发；订单沿用现有券抵扣、核销及退款规则。`promotionActivityId` 为可选叠加；填写后仍须已发布且覆盖活动全期，关联券须允许与其他优惠叠加，并遵守既有促销叠加政策。配置额外创世票时仍须关联正式促销及票预算，仅关联券不承诺额外票奖励。

活动开始提醒沿用站内通知契约：用户在预告期订阅，活动开始且仍开放时由现有调度送达一次；相同活动与账户仅一条通知。站内已送达使用 `DELIVERED` 并记录送达时间，不将 `SKIPPED` 当作送达，不进入外部推送队列。通知写入与订阅的已通知标记在同一事务，任一步失败不得伪标完成，后续调度可重试。通知中心及未读数继续尊重用户的系统通知偏好，不提升为强制通知。历史修复仅处理与真实 H4 订阅精确关联、已标记通知、未删除的 `EVENT/SKIPPED` 记录，保留原内容、创建及已读时间，不更改其他跳过记录或外部推送。

H7/E08 使用新幂等键重复领取已发放券时，返回同一 `grantId`、`replay:true` 及实际状态（`AVAILABLE`、`USED`、`REVOKED` 或 `EXPIRED`）；已用券保持 `USED`，不重发、不重置。同一幂等键重放的原回执仍是当时快照，`GET /api/vouchers` 才是当前状态。App/H5 领取后必须读取最新券列表，仅当前确实可用才提示领取成功或进入报价；已用、撤销、过期或读回失败均不因旧回执变为可用。

复投加抽奖券活动受 G1 的 App 质押展示总开关 `G.staking.app_visible` 约束。总开关关闭时，H4 开启检查显示“请先在G1展示App质押功能”，活动不接受新参与或复投；已生成的创世票权益保留，不因展示关闭而撤销。

活动赠机及设备交付的硬件功耗必须是唯一、明确的瓦数。在既有明确数值（可带 `W` 或 `W TDP`）之外，仅允许 `W` 后附 `（单卡额定）` 或 `（显卡额定合计）`，也接受成对英文括号。例如 `200W（单卡额定）`、`1800W（显卡额定合计）` 分别写入设备 `base_power_w=200`、`1800`，不按说明推测或乘算卡数。功耗范围、多功耗、`kW`、说明中附加数字及其他自由说明继续拒绝；商品上架、真实库存、显存及数据中心等原校验保持不变。

幸运转盘需要降级时，仅选择当日库存仍可用的 UVT（协议资产码 NEX）安慰档，`dailyStock=0` 保持不限库存的既有含义。所有安慰档当日库存耗尽时，返回 `409 WHEEL_COMFORT_TIER_MISSING`；在生成抽奖记录和扣除次数之前失败，保留免费次数或加抽票。库存恢复后可重试，不得以耗尽档位继续发奖。

活动规则与创世抽奖的日期控件均按标注的 UTC 录入和存取，接受浏览器的分钟或秒精度输入，保留秒值；不得拼接重复秒段或按操作员电脑本地时区偏移。

App/H5 活动期限、开奖及回执时间明确按 UTC 展示。中文格式 `yyyy-MM-dd HH:mm · UTC`，英文和越南文格式 `dd/MM/yyyy HH:mm · UTC`；手机本地时区及原生语言格式化能力不能改变显示时刻。

App 与 H5 均须完整显示轮盘扇区及各奖项标签；转盘围绕圆心旋转，顶部指针、外圈及中心盖保持固定，停止位置对应服务端中奖结果。原生端不得出现空白扇区或奖项标签挤成一串，奖项名称中的特殊字符按普通文本显示。

抽奖失败按实际原因提示：活动未开放、次数不足或暂不可用时分别说明，并重新读取次数与记录；不得统一声称区块链繁忙或次数未扣。未决意图按账号、API 环境和活动持久保存，弹层、页面重挂载、App 重启及切号往返均复用原幂等键；无法读取或保存意图时不提交抽奖。首次请求确定拒绝才可结束该意图；一旦结果未知，重试的 400、401 或 409 只代表本次重试的结果，不能证明原请求未执行。只有同键返回的本次抽奖回执才能解除未决状态；刷新显示零次数或活动结束也保留原意图核对入口。切换账号或活动后不展示旧请求的迟到失败。

转盘幂等请求摘要包含 UTC 日期；服务端保留已完成命令回执，不因普通幂等期限到期而将旧命令作为新抽奖执行。未决请求重试前先读取当前活动状态；只有权威日期与原意图 UTC 日期相同时才允许同键重放。跨日或无法确认当前日期时仅允许只读核查，不再发送抽奖 POST，不自动生成新键，也不按金额、奖档或时间相近猜测历史记录归属；无法取得唯一关联的原回执时提示联系客服，避免过期键被当作新抽奖再次消费加抽券。

已接入结构化规则的正式 H4 玩法，其“奖励”字段仅用于展示，可填写设备、优惠券或复合奖励说明。新建仍生成关闭草稿；真实奖励种类、数量、预算及库存由玩法配置决定，不能从展示文案推算或改变。编辑奖励说明不修改经济字段，也不能绕过启用时的规则完整性、公开文案、库存及兑付覆盖率校验。未接入结构化规则的旧活动仍沿用原资产与金额校验；幸运转盘奖励仍由奖池配置管理。

### 4.2 活动删除

活动中心的促销与邀请推广、既有活动列表提供“删除”活动操作。此处删除对象包含由模板创建的活动草稿；单设备赠礼、首购礼、直邀首购双向礼、多型号组合、复购召回五种内置模板继续保留。

只有草稿及已结束活动允许删除，进行中、待开始、暂停或待审核活动不能删除；进行中活动即使另有改版草稿，也不能把整个活动当作草稿删除。后端在锁定活动后核对当前状态与版本，不依赖按钮隐藏；草稿还须核对草稿版本，防止旧页面删除已被编辑、送审或发布的活动。既有活动以真实启用记录、显式结束状态及 UTC 期限判断，关闭开关不等于已结束；列表状态与删除判断采用同一口径。

删除前明确展示活动名称及影响并要求确认与原因；取消不产生修改，失败显示具体错误。成功后刷新并返回列表，删除结果未知时核查原命令，不生成另一笔删除。正常删除采用逻辑标记，阻止新参与、编辑、发布、复制及再次开启；保留历史订单、奖励、领取回执、账本与审计，不回收已发奖励、不修改余额或库存，也不扩大原有领取期限。历史义务继续遵循原业务规则。促销历史详情可只读访问并标明“已删除”，保留奖励与统计入口，便于处理删除后发生的退款与奖励追回；不能因列表移除而切断售后处理。

促销删除沿用活动归档管理权限和现有命令审计/幂等契约；既有活动删除沿用 H4 写权限与增长命令边界。无权限请求、陈旧版本和不允许状态在服务端拒绝。该产品能力与此前专门授权的 TEST 物理数据清理不同。

删除成功反馈只关联原活动；之后成功新建或复制活动时清空旧反馈及历史入口，避免误认为新草稿已被删除。既有活动依赖 H4 活动互斥锁记录；升级时补齐缺失记录，缺锁时仍拒绝写操作。

### 4.3 持币及区域结算

持币连续期依据真实余额变化，余额跌破门槛会中断；开启前没有观察记录的时间不能补算。区域来源取已验证账号国家，加入时固定；当前注册国家支持 CN/VN，未知国家不得猜测归属。

持币开始时间不早于活动开始、实际开启及首次达标观察时间三者中的最晚时间。钱包变为沙箱或删除状态时中断观察；活动领奖和创世抽奖均拒绝非正常、沙箱或已删除账号。活动时间按同一 UTC 口径存取，客户端、JVM 与数据库连接时区不同不得改变有效参与窗口。

区域订单必须实际支付，排除退款、撤单及退款处理中记录。截止结算读取并锁定相关成员和订单；奖池分配、预算、奖励入账及结果在同一事务完成，任一步失败全部回滚后重试。持币平分同样原子结算。精度为六位小数，余数确定分配，合计等于奖池。已成功结算的快照保持不变，后续退款不重新计算已完成活动奖励；不得把结算失败显示成已到账。

区域与持币详情新增本人到账金额 `myRewardAmount`（USDT），只读取本活动、当前鉴权用户的 `PAID` 奖池结果；未到账、无记录或其他玩法为 `null`，真实已到账零额保留为 0，不从地区总额或进度估算。原 `results` 与账务保持不变，地区奖励明确标注总额，本人实际到账单独展示并保留最多六位小数；区域活动不展示固定 0/1 的虚假个人进度。

## 5. 独立创世抽奖

创世抽奖使用升级、复投及既有 G7 发放的创世票，与每日幸运转盘次数分开。App 新增独立入口，展示可用票数、报名与开奖时间、奖品、名额、本人报名及中奖结果；用户主动提交正整数票数，不自动报名。

PC 可创建轮次草稿，配置三语名称、开始/开奖时间、1–20 个奖项及名额，总名额上限 100。奖项支持 UVT、USDT、设备；设备每名一台，配置数量代表中奖名额。开启前检查设备真实资格及同商品汇总库存，库存不是占用承诺，兑现时仍检查库存和用户容量。

| 状态 | 行为 |
|---|---|
| DRAFT | PC 编辑，App 不公开 |
| OPEN | 时间窗内报名，经济字段冻结；零报名可退回草稿，已有报名不能取消 |
| PROCESSING | 已固定中奖人，奖励发放中；逐项显示待发放/已发放，不允许报名和改奖 |
| DRAWN | 开奖完成，只读结果；无人有效报名也可结束，无虚构中奖者 |

按票数加权、无放回抽取，一张票同轮最多中一个奖，未中奖票仍已使用。来源持仓退出/票被作废、订单退款等导致开奖前资格失效时，不得中奖。结果固定后，发奖失败保留同一中奖人与回执重试，不重新抽签；全部奖励发放成功后才进入完成态。中奖后源权益变化不回溯改写已固定结果。

并发报名不能超用票；同幂等键只代表同一次报名意图，超时后复用原票数和原键。轮次关闭/开奖后仍允许回查此前成功命令。定时扫描到期轮次与失败发奖分开处理，失败轮次轮转重试，不阻塞新开奖。

接口：App `GET /api/events/genesis-raffle`、`POST /api/events/genesis-raffle/{id}/enter`；PC `GET/POST /api/admin/growth/genesis-raffle`、`PATCH /api/admin/growth/genesis-raffle/{id}`。管理端沿用 H4 读写权限及命令审批边界；用户只能提交自己的票和读取自己的结果。
