# NEXION 数据与隐私清单 v1

> **现行裁决(2026-08-07)**:全项目已取消 KYC、钱包配对、C4 与 K5；本文相关旧字段、门禁、用例、权限或流程仅保留为历史基线，不得作为现行实现、运营或验收依据。

> 状态：设计与上线门禁基线，不是法律意见，也不是可直接提交商店的最终声明。
> 范围：用户 App（`D:\workspace\NX1.0`）、PC 管理端、后端及其 MySQL / Redis / MinIO / 消息与日志链路。
> 依据：当前 PRD、前后端代码、App `src/manifest.json` 与 2026-08-04 可核验的平台规则。任何声明均须以最终发布包、运行时 SDK/网络抓包和部署清单复核。

## 1. 不可妥协的处理原则

1. **目的限定**：没有明确业务目的、责任域和退出机制的数据，不采集。
2. **最少够用**：默认不采通讯录、精确位置、广告标识符、短信、通话记录；功能可由低敏数据完成时不得升级权限。
3. **服务端权威**：账户、资产、KYC、风控、同意版本和删除请求由服务端留痕；本地缓存不能作为合规权威。
4. **默认遮罩**：PC 列表、导出、日志、告警、截图默认掩码；查看明文须独立权限、理由和审计。
5. **秘密不落日志**：密码、验证码、完整令牌、私钥、助记词、CVV、完整银行卡号不得写入日志、埋点、审计详情或客服会话。
6. **保存期可执行**：每类数据必须绑定保存类、删除/匿名化作业、例外理由和失败告警；不能只写政策不落作业。
7. **第三方同责**：SDK、云服务、支付/KYC 服务商的实际采集和共享必须进入同一清单；未登记不得进发布包。

## 2. 分级与保存类

### 2.1 数据分级

| 等级 | 定义 | 典型数据 | 默认控制 |
|---|---|---|---|
| P0 公开 | 主动公开且泄露无实质伤害 | 已发布活动文案、公开商品信息 | 完整性与版本控制 |
| P1 内部 | 运营内部数据，不直接识别个人 | 聚合 KPI、配置版本、无用户维度指标 | 登录、最小角色授权 |
| P2 机密 | 可关联账户或业务行为 | 用户号、订单、设备记录、工单 | 行列权限、遮罩、导出审计 |
| P3 受限 | 身份、金融、安全或高风险画像 | KYC、钱包地址、银行信息、IP、会话、风险评分 | 加密、双层权限、明文访问审计 |
| P4 特殊 | 密钥或不可逆高危数据 | 密码散列、MFA secret、令牌、私钥 | 不出安全边界；不可展示/导出/埋点 |

### 2.2 保存类

保存类先定义生命周期，不臆造法律期限。`TBD` 必须由法务、财务、风控和数据 Owner 在上线前给出日历值。

| 保存类 | 适用 | 删除策略 |
|---|---|---|
| R0 瞬时 | 验证码明文、请求上下文、一次性上传中间件 | 请求结束或短 TTL 自动销毁 |
| R1 短期 | 会话、失败登录、临时导出、网络诊断 | 30/90 天候选，最终值 TBD；TTL + 定期清理 |
| R2 账户期 | 个人资料、设备、偏好、通知已读态 | 账户有效期；注销后删除或去标识，宽限期 TBD |
| R3 交易/法定 | 账本、订单、充值、提现、KYC 法定记录 | 依法定/争议期限保留，具体年限与地域 TBD；与可删资料分离 |
| R4 不可变证据 | A2 审计、关键 outbox、监管处置证据 | 依法定审计边界保存；到期封存/销毁，禁止业务侧物理篡改 |

## 4. App 权限与 SDK 现状门禁

当前 `NX1.0/src/manifest.json` 的 `modules`、`sdkConfigs` 均为空，`uniStatistics.enable=false`；但 Android 清单声明了 CAMERA、READ_PHONE_STATE、GET_ACCOUNTS、READ_LOGS、WRITE_SETTINGS、网络/Wi-Fi 变更、挂载文件系统等一组高风险或宽泛权限。当前源码检索只明确发现系统信息读取与剪贴板写入，未发现这些宽泛权限全部有对应用户功能。

因此发布前必须执行：

1. 逐条建立“权限 → 可见功能入口 → 首次触发时机 → 拒绝后降级 → 商店声明”映射；没有真实必要性的权限从最终原生 manifest 移除。
2. CAMERA 只在用户主动发起扫码/证件拍摄时申请；READ_PHONE_STATE、GET_ACCOUNTS、READ_LOGS、WRITE_SETTINGS 等默认判为阻断项，除非 Owner 给出不可替代的第一性用途和平台允许依据。
3. 对 `getSystemInfoSync`、WebGL renderer、deviceMemory、hardwareConcurrency、屏幕密度做运行时数据流核验：仅本地处理与上传服务端是两种不同声明；上传任一派生值也要纳入清单。
4. 对 H5/WebView 与原生壳分别抓包；商店声明取所有在售版本、地区和第三方代码的并集，不以“某分支没触发”为免责依据。
5. 每次依赖升级生成 SDK BOM：名称、版本、供应商、数据类型、目的、域名、是否关联身份、删除接口、隐私清单/政策链接、签名与漏洞状态。

## 5. 用户权利闭环

| 请求 | 用户入口 | 身份校验 | 执行动作 | 不删除例外 | 完成证明 |
|---|---|---|---|---|---|
| 查阅/副本 | App 隐私中心或网页 | 登录 + 高敏二次验证 | 生成结构化副本，默认遮罩第三方信息 | 风控规则细节、他人数据、法定限制 | 请求号、范围、生成/下载时间 |
| 更正 | 资料页；KYC 走专门复核 | 登录；KYC 强验证 | 更新权威字段并传播消费者 | 历史交易不得改写，仅补更正记录 | before/after 审计 |
| 注销/删除 | App 设置内易发现入口 + 公开网页 | 重新认证与明确确认 | 冻结新交易→结清/争议检查→删除或匿名化 R2→撤销会话/token→通知处理方 | R3/R4 法定账本与审计；必须向用户说明类别和期限 | 状态通知、完成时间、保留例外摘要 |
| 撤回同意/退订 | 隐私选择与通知设置 | 登录 | 停止可选处理/营销；不影响撤回前合法处理 | 必要服务通知、安全处理 | 同意版本与撤回审计 |
| 限制/申诉 | 风险决定页、客服/申诉入口 | 登录 + 证据 | 暂停自动不利动作，进入人工复核 | 安全止损可临时维持 | 决定、理由码、复核人和时限 |
| 投诉/联系 | App/网站隐私联系入口 | 按请求风险 | 分派隐私工单，追踪 SLA | 无 | 工单号与升级链 |

注销必须是业务编排，不是简单 `DELETE user`：先阻断新资金动作，确认未完成订单/提现/申诉，再撤销会话和推送 token，匿名化推荐树与可删资料，向 KYC/推送/分析等处理方发删除任务，并让失败进入补偿队列与告警。

## 6. 第三方与跨境登记模板

每个处理方一行，未完成不得进入生产包或真实数据链：

| 字段 | 必填内容 |
|---|---|
| 身份 | 法定名称、产品/SDK、版本、合同主体、子处理方 |
| 数据流 | 字段级输入、输出、域名/IP、触发入口、是否后台持续运行 |
| 目的与角色 | 业务目的；控制者/处理者角色；禁止二次营销条款 |
| 地域 | 用户地域、处理与备份地域、跨境机制与影响评估编号 |
| 生命周期 | 保存期限、删除 API/SLA、合同终止清理、备份淘汰 |
| 安全 | 加密、访问控制、审计、事件通知时限、渗透/认证证据 |
| 商店映射 | Apple 数据类型/用途/是否关联/跟踪；Google 收集/共享/目的/可选性 |
| Owner | 业务、技术、法务、安全负责人和复核日期 |

当前可预见但尚未完成登记的处理方类别：云主机与对象存储、KYC/活体、支付/银行、链节点、推送、邮件/短信、客服、崩溃与分析。具体供应商不可臆造。

## 7. 商店隐私声明草案映射

这只是“可能需要声明”的上界，不代表已确认采集。Apple 要求申报 App 与第三方代码的实际数据处理；Google Data safety 同样要求开发者对自身及第三方 SDK 的收集、共享和安全实践负责。最终答案以**发布二进制静态扫描 + 权限触发走查 + 全链路抓包 + 服务端落库核对**为准。

| NEXION 数据 | Apple 候选类型 | Google 候选类型 | 核验问题 |
|---|---|---|---|
| 手机/邮箱/显示名 | Contact Info | Personal info | 是否都上传、是否可选、是否关联账户 |
| 用户号、安装 deviceId | User ID / Device ID | Device or other IDs | ID 是否稳定、是否跨 App/用于跟踪 |
| 型号、OS、IP、诊断 | Diagnostics / Device ID / Coarse Location（视用途） | App info and performance / Device IDs / Location（视用途） | 是否持久化、IP 是否推导地域 |
| KYC 证件/自拍 | Sensitive Info / Photos or Videos | Personal info / Photos and videos | 是否做生物识别、供应商是否保留 |
| 钱包、银行、交易 | Financial Info / Purchases | Financial info / App activity | 自有系统是否接触完整支付数据 |
| 工单与会话附件 | Customer Support / User Content | Messages / Photos and videos / Files | 自由文本与附件是否进第三方客服 |
| 点击、浏览、A/B | Product Interaction | App activity | 是否用于分析、营销或跨服务跟踪 |
| 崩溃与性能 | Crash/Performance Data | App info and performance | SDK 是否自动带用户/设备标识 |
