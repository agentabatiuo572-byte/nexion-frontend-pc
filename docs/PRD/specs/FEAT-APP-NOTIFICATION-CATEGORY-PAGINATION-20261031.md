# 消息分类分页与固定清理入口

2026-10-31，依据用户对资金分类假「加载更多」和长列表清空已读不可达的反馈。补充 App 正式 PRD §11.2.2、§11.2.2a。已有 PRD 要求区分真实分页/空态、保留补拉游标、清理确认及 critical 保留；此次明确分类分页与按钮位置。

- 服务端先按全部、资金、设备、团队、活动或系统分类筛选，再按原游标分页。只要当前分类到尾就不显示加载更多；其他分类剩余记录不代表当前分类还有数据，空分类不自动扫描全账户分页。
- `GET /api/notifications` 新增可选 `category=all|finance|device|team|rewards|system`，省略/all兼容原全部语义，非法值拒绝；分类映射与 App 原始类型映射一致，未知类型归系统。保留原本人可见、偏好、强制通知、保留及 priority 筛选规则。账户总未读及可选分类未读摘要不受本次列表筛选影响。
- 分类结果、游标及在途请求按账号和分类隔离。周期头页补拉保留当前分类历史和已到尾的状态；不得把已结束的分页复活。切分类、换账号或离页的迟到结果不得覆盖当前内容，分页连点不重复发请求，失败可重试。
- 后台头页刷新不将分页按钮变成「正在加载更多」。加载更多仅代表用户当前分类的实际下一页，尾页隐藏。
- 清空已读沿原玻璃按钮，在通知分区固定页底操作区显示，位于列表滚动容器之外；长列表顶部/滚动后可达，安全区留位且不遮末条内容。服务分区不显示通知清理。
- 清空范围仍是当前账号全部服务端允许清理的已读通知，不限当前分类。须确认，可取消/系统返回，换账号或离页使旧确认失效；保留 critical、未读、业务原单、资金/会话历史与永久通知去重事实。不修改原交易、资金及消息读确认协议。

验收包含分类尾页及空分类、混合类型多页、15秒头刷新后尾页不复活、切分类/账号/旧响应隔离、清空入口在长短列表均可见、确认取消与原单导航。实际删除规则采用隔离测试，不为验收批量删除现有用户通知。TEST/真机结果另记，不以本文代替发布或验收。
