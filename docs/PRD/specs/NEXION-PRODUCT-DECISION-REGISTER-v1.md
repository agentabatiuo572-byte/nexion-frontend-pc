> 文档状态：执行基线（未获授权的事项不视为已决策）  
> 适用范围：PC 管理端、App、后端、运营、客服、合规与应用商店送审  
> 原则：服务端事实优先、最小必要复杂度、风险与证据成比例、每项决策必须形成“决策—落地—验证—监控—复盘”闭环。

## 1. 状态与优先级

| 状态 | 含义 |
|---|---|
| `FIXED_BASELINE` | 已由现有产品/验收约束确定，后续实现不得绕过 |
| `PROPOSED_DEFAULT` | 可继续用于设计与文档，但上线前必须由 Owner 签字 |
| `NEEDS_OWNER_APPROVAL` | 存在真实产品取舍，未批准前不得形成对外承诺或不可逆实现 |
| `BLOCKED_EXTERNAL` | 依赖法律意见、供应商证明、商店政策或外部资质 |
| `DEFERRED` | 当前版本明确不做，必须写清重新进入条件 |

优先级：P0 阻断发布或可能造成资产/合规损失；P1 阻断完整业务闭环；P2 影响体验、运营或口径一致性；P3 可延期优化。

## 4. 决策治理流程

1. **提出**：Owner 使用上表 ID，补充事实、方案、最坏后果和受影响对象；不得只写“待讨论”。
2. **证据**：区分代码事实、生产事实、政策事实和假设。概率判断需写出先验依据、可推翻证据及观测窗口。
3. **决策**：P0 至少由业务 Owner、技术 Owner 与对应风险 Owner 共同签字；法律分类不得由研发代签。
4. **落地**：同步状态机、API 合同、字段字典、权限矩阵、文案、客服话术、监控和回滚方案。
5. **验证**：从可见入口执行正常、异常、并发、刷新重登、权限及跨域用例；保存候选版本和证据哈希。
6. **运行**：为关键假设设置指标和告警；结果偏离时回滚或重新打开决策。
7. **复盘**：关闭项不得删除，只能追加替代决策、批准人、日期、证据和被替代版本。

建议时限：P0 在进入实现或发布前关闭；P1 在依赖模块联调前关闭；P2 在文案/UI 冻结前关闭；P3 可进入版本待办。该时限为治理建议，不代替管理层批准的 SLA。

### 4.1 机械发布门禁

- 任一 P0 尚未转为具有完整关闭记录和可复核证据的 `FIXED_BASELINE`，候选自动判定为 `NOT_READY_FOR_PRODUCTION`；`PROPOSED_DEFAULT`、`NEEDS_OWNER_APPROVAL`、`BLOCKED_EXTERNAL` 和 `DEFERRED` 均不能放行 P0，不依赖人工维护一份容易漏项的 ID 名单。
- 任一与目标市场/功能相关的 P1 阻断未关闭，目标市场或功能不得启用；缩小发布范围时必须保存功能、地区和用户群白名单证据。
- “已讨论”“已有口头结论”“代码可运行”均不是关闭状态。只有关闭模板字段完整且证据哈希可复核，状态才可更新。

## 6. 当前结论

- 50 项中，11 项为固定基线，7 项为建议默认，20 项需要内部 Owner 批准，12 项依赖外部法律、供应商或市场证据。
- 当前存在未形成完整关闭记录的 P0（包括 `PROPOSED_DEFAULT`、`NEEDS_OWNER_APPROVAL` 和 `BLOCKED_EXTERNAL`），因此机械门禁结论为 `NOT_READY_FOR_PRODUCTION`；后续以状态与关闭记录查询结果为准，不再依赖手写的部分 ID 示例。
- 本台账不修改 API、数据库或页面；它是后续声明、合规、供应商、数据、客服、参数、威胁、演练与送审材料的决策入口。
