# 试用结束后的购买容量核对与初始设置恢复

2026-11-01，补充 App 购买结算、试用结束入口及六槽容量规则。来源为用户报告的 TEST 3778 账号：首页「试用已结束」卡片「选购设备」→免费试用结束页「去购买」→UVELBox S1 结算页。

- 试用结束后的入口进入普通购买，不复用已失效的试用抵扣或试用预留槽位。是否允许购买仍以当前服务端资格、容量及付款检查为准。
- 容量预检严格返回 HTTP 428、业务码 428、`USER_ONBOARDING_REQUIRED` 时，结算页显示「请先完成初始设置，再返回购买。」及「完成初始设置」入口，不误报「暂时无法核对激活名额，请重试」。已知设置前置缺失时，重新同步或立即支付不得反复发起相同的无效容量请求，也不得放行新订单。
- 恢复入口复用现有初始设置：App 原生进入手机设置流程；H5 进入支持的设置说明页。返回购买页后重新读取服务端状态；打开设置入口本身不表示已完成。账号、会话或页面变化后，旧请求不得覆盖当前容量或显示旧账号的设置提示。
- 网络、协议或其他未知错误仍显示原容量重试提示并阻止新购买；不因本次修复放宽后端初始设置、认证或支付门禁。
- 服务端容量决策含有效订单与试用预留。`REPLACE_REQUIRED`、`NO_ACTIVE_DEVICE` 即使已激活设备数低于上限也可能合法，客户端不得用单一已激活数否定这些阻止决策。仍校验金额、资金充足标记、替换来源及返回上下文；仅 `CAPACITY_AVAILABLE` 可按普通购买继续，且已激活数必须低于上限。
- 六槽满额仍在扣款前拦截，换购及原订单恢复沿用既有服务端规则。初始设置恢复不释放设备、不清空订单、不增加槽位。

验收分别记录：原路径可操作结果、严格错误分类、设置入口与返回后的重新核对、预留槽位决策以及账号/页面失效隔离。未真实完成的设置、扣款、购买与激活不得记为通过。
