# G3 价格与首次排程审批确认（BUG-286）

本批仅调整「UVT 价格管理」的每日目标价、每日上涨概率、手动当前价和自动按日推进四处现有确认；已按用户 2026-11-05 明确确认的四框设计参考实施。颜色、字体、输入、按钮及键盘行为沿用现有设计 token 和操作确认组件，局部使用平面绿色主按钮与琥珀色审批提示。设计参考是示例，不作为运行数据。

| 确认入口 | 提交方式与实际生效时点 |
| --- | --- |
| 一周价格计划 · D1～D7 目标价 | 提高显示精确当前值、拟改值及「提交审批」。另一位有批准权限的超管批准后只更新计划，当前价保持不变，后续推进到该日才发布目标价。降低仍直接保存计划。 |
| 一周价格计划 · D1～D7 上涨概率 | 提高提交审批，降低直接保存。均只改计划，当前价保持不变。提交与批准按拟改后整周最高目标价复核现有应付款的覆盖率，不把概率换算成未来兑换人数或虚构应付款。 |
| 手动设置 · 当前价格 | 提高提交审批，待审期间全站沿用当前价；批准后立即发布新价，下次自动切换仍按计划执行。降低仍直接发布。提交与批准按拟发布价复核覆盖率。 |
| 自动按日推进 | 当前真实配置为空表示首次，不等于 0。首次显示「未配置 → 拟改」、首次审批提示与「提交审批」；批准前不启用所提排程，批准后按所填时区安排后续推进，本次不当场改价。已有排程普通调整仍直接保存。未填时区沿用原有 UTC 规则。 |

理由沿用后端实时规则，至少 8 字、最多 200 字。价格保持十进制文本，最多八位小数；概率保持六位精度，输入步长仍为原有 0.01。页面不凭当前覆盖率的四舍五入显示值作拟值红线判断，服务端按提案和批准当时的原始金额核验。缺少配置修订号时禁止创建审批。

## 命令与权限

审批复用现有 A2 创建及本人按原幂等键查询接口：`domain=G`、`op=g3_market_policy_change`，`params.values` 使用后端窄合同。

| action | 原请求字段 | 对象锁 |
| --- | --- | --- |
| curve-cell | action、dayIndex（0～6 整数）、field（targetPrice / pumpProbability）、value（字符串）、expectedRevision（curveRevision） | G / nex_market_curve / weekly |
| current-price | action、value（字符串）、expectedRevision（priceRevision） | G / nex_market_override / currentPrice |
| initial-schedule | action、value（排程文本）、expectedRevision（scheduleRevision） | G / nex_market_control / schedule |

价格及概率审批为 fund / amplifies=true，首次排程为 param / amplifies=false。来源固定 G3。四项分别沿用原目标价、概率、现价和 G3 写权限；只有另一位有批准权限的超管可批准，发起人不能自批。本人回执查询不要求额外 A2 全域读取或新菜单权限；错误来源、对象、旧修订及无权请求仍由后端拒绝。本批不改变 G4、其他 G3 动作、恢复权限或已退役业务。

直接保存沿用全周 PUT、当前价 PATCH、排程 PATCH。全周请求保存完整原 expectedFrames；现价及排程保存原 expectedValue，不以之后读取的新值替换旧基准。

A2 沿用既有详情与批准框的「完整变更内容」，读取服务端持久化的中文 beforeValue / afterValue，不新增区域、字段或权限。仅上述四类 G3 规范动作与对象对应的批准确认，将通用「确认后立即执行」替换为该票持久化的「生效时间」，避免将更新周计划或启用后续排程误说成当场发布现价；其他域保持原文案。服务端原始 B1 快照的数值编码由后端合同维护，本次不修改共享 JSON 解析或新增原始快照展示。

## 未知结果恢复

- 会话存储按账号、对象及字段（计划含日期）保存命令号、原完整输入、理由、expected 基准及原请求体。持久保存失败时不发请求。
- 丢响应、网络未知、不可读回执或上游未知时，重开同一确认回填原拟值和理由并锁定。原请求仍未确认时不能改参数、换对象复用或另铸编号；切换账号/权限代次会销毁旧确认，提交前再次核对身份及权限。
- 审批可「查询原操作」：只读本人原单，找到后回读当前配置；暂未查到可继续查询，或在有效期内按原请求重试，重试前仍先查询原键。查询失败不得以新提案替代。
- 直接保存没有按原键查询接口，未知时仅允许在有效期内按原完整请求重试。不能用当前业务值“看起来相同”认定原命令成功。
- 幂等有效期从首次尝试起算，最多 24 小时，重试不续期；过期或本机时间倒退不发送重试。过期审批仍可只查，过期直接保存仅保留原内容供核对。
- 新提交的明确拒绝释放该次恢复记录，保留框内输入便于核对；已有未知原命令遇到拒绝仍保留证据，不能丢弃原键重新发起。业务成功后附加刷新失败不将已知成功伪装成提交失败。

## 验收边界
