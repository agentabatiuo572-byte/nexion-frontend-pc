# H9 首页与网络展示配置（2026-10-28）

## 模块与入口

H9 按「首页数字增长、网络脉搏注册人数、全球作业基座、全球网络、设备预估排名、历史估算」集中配置。每个模块只展示相关输入、说明与保存按钮；切换模块保留未保存草稿。刷新及保存不清空其他模块的草稿。选中卡片写入 `module=home|network|jobs|globe|rank|history` 网址参数；刷新、分享链接和页面历史恢复同一块，未知参数回首页块，其它参数保留。

介绍页在线设备/累计已发放继续读取首页数字增长；首页网络实况的注册人数读取注册基数与增长规则，在线设备与介绍页共用当前批次；设备预估排名仍按独立排名配置计算。真实设备、余额和任务不受这些展示设置影响。

设备预估排名的表格、开关、输入、帮助和底部操作统一使用 H 域样式。

## 赚取页任务中心（2026-11-03）

「首页与网络展示设置」→「赚取页任务中心」提供一项「全球作业基座」：

| 配置 | 合法范围 | 说明 |
|---|---|---|
| 全球作业基座 | 留空，或 0–100000000 整数（个） | 留空 = 不发布 |

- 发布后，App / H5 Lite 赚取页任务中心「N 个全球作业进行中」显示真实进行中作业数 + 基座；留空保存表示不发布（清除），只显示真实作业数。只用于展示，不参与任务派发、结算或资金。
- 输入非数字、小数或超出范围时就地提示，不能保存。保存沿用 H9 原有确认：改动前后值对比、填写理由、版本校验与审计。
- H9 管理接口的 `values.activeJobsBase` 与 App、H5 Lite 读取的 `publicStats.activeJobsBase` 表示同一个发布值。新旧记录默认均为 null。保存 0 是发布零，显式保存 null 是清除，旧客户端省略该字段时保留原值。真实作业数仍取首页概览的 `onGrid.activeJobs`，赚取页与地球页只加一次基座。

## 全球网络

全球网络继续明确标识「模拟数据」。固定的8个城市、坐标与翻译属于静态内容。App/H5 不内置数值回退：无有效配置时数值显示占位，地图和城市入口仍保留；读取新配置后更新指标。动画计时器不重复请求接口，隐藏页面暂停采样，恢复按当前时间与最新配置显示。

全球网络与首页共用同一个配置入口。在线节点总数取「首页数字增长」的在线设备，与介绍页、网络脉搏一致。进行中任务总数取赚取页任务中心的显示值。H9「全球网络」配置这两个总数在 8 个中心的分布，以及吞吐、延迟和数据变化间隔。

| 配置 | 合法范围 |
|---|---|
| 数据变化间隔 | 1–86400秒，最多3位小数；存储为整数毫秒 |
| 每任务小时处理量上下限 | 0–10000，下限≤上限，最多6位小数 |
| 延迟浮动上限 | 0–60000整数毫秒 |
| 每中心分布比例 | 0–100%，最多2位小数；8 个中心合计必须等于 100% |
| 每中心基础延迟 | 0–60000整数毫秒 |

8个中心必须完整且无重复：新加坡、东京、胡志明市、伦敦、巴黎、法兰克福、纽约、圣何塞。页面在分布比例下方显示实时合计，合计不是 100% 时就地提示且不能保存。确认弹窗列出各中心比例与基础延迟的前后值。

节点数、节点浮动上限和并发任务占比上下限已不影响展示，页面不再提供输入；后端仍返回时保存按当前已保存值原样回传。

H9 管理接口与 App 公开配置均返回 `globeDisplay.centers[].sharePct`。启动迁移按旧节点数占比分配至 0.01%，余数优先分给小数余数较大的中心；八个旧节点数全为零时各分 12.50%。再次执行迁移会保留已经发布的比例。旧客户端只提交节点数或调整延迟时，沿用当前已发布比例。

原全球网络基线（5400ms、处理量2.2–3.8、延迟浮动6ms；各中心基础延迟 18、22、26、16、20、14、24、17 毫秒）保持；原各中心节点基数 236000、253000、163000、249000、208000、217000、316000、284000 由后端 B22 换算为默认分布比例。不隐式开启其他模块。

## 保存、权限与兼容

每次保存只合并当前模块草稿和最新已保存值；仍通过 H9 原有权限、版本校验、理由确认、幂等与审计。设备排名沿用其独立接口与版本。其他模块若有未保存修改且服务端同字段发生变化，保留草稿并提示刷新，不覆盖他人设置。保存结果未知不宣称未执行；刷新失败保留已有内容和草稿，但相关配置不可再新写，直到成功重新读取。主配置失败不阻断独立排名，排名失败不阻断其它五块。

全球网络配置使用现有 H9 聚合内的 `globeDisplay` 字段，不新增资金配置或通用缓存。旧记录由后端补足原展示基线；旧客户端省略此字段时保留已保存配置。旧客户端重试使用原 H9 指纹，避免升级后误判同一幂等请求。

## 原请求恢复与校验（2026-11-15）

8个写入口（保存首页、开启、暂停、保存注册人数、保存基座、保存历史估算、保存全球网络、保存排名）仍是2个原PATCH端点、growth_h9_write和HIGH审计，不走审批，不增加资金覆盖率闸或环境审批锁。主配置五块共享版本，排名独立版本；主配置version=0和关闭排名v0空档都是合法读模型。

发前将完整原请求字节、路径、方法、对象、理由、操作者、版本、原号和确认上下文保存到本次会话；无法耐久保存就不发送。主配置7入口共用已有存储键/唯一实例，排名沿用原独立键。结果未知时冻结同一后端对象，原确认理由冻结；刷新仍有原记录和恢复入口，读失败也可恢复。24小时内只按原body/原号重试，超过24小时保留只读核对。旧记录缺完整请求只读核对；不拿现在的设置补造旧请求。

首次提交明确拒绝按共享isDeterministicRejection丢首次号；按原请求恢复只有isExplicitRejection认定的明确拒绝才能结案，401/403/408/425/429和幂等层未收敛不是原结果。成功或明确拒绝后结束恢复框；原号成功回放是历史回执，重新GET当前配置成功前不允许新修改，不能把回放直接当当前值。H9没有按原号查询结果或受控调查接口，“查询原结果”只读取当前配置供人工核对，不自动解除未知记录。

必填数值不把null/空串转0；主配置/分位/跳动组/金额精度/范围仍严格校验。作业基座保持省略、null、0三态；后端支持的旧无跳动及旧全无share配置继续兼容。金额超过两位在保存前拦下，科学计数法及合法尾0按实际精度判断。

## 展示口径与已知例外（2026-11-15）

累计已发放照App/Lite写成$，后端只有paidCents且未带币种，H9-BE-02仍待后端明确；该值是展示值，不换算、不代表实际结算币种。历史估算用publishedDailyUsdPerDevice的USD口径，原值不舍入。管理端没有App此刻批次数的采样读模型（H9-BE-01），首页卡显示设定值，“App上的样子”是配置示意；不能把它当实时监控。

注册人数参考线与App/后端使用相同锚和步长中值：base+floor(ticks×(min+max)/2)，App/后端实际值还加同源32位hash的0..spread偏移；PC已有说明。月增长只有没设跳动时被后端人数公式使用，只改月增长不会重置旧锚。App普通网络脉搏卡片仍可读服务端月复利，快照等本地estimate消费面缺跳动时不可用，保留参数入口并登记App一致性边界。首页平均增加图不计达到9万亿后的封顶，属于参考区间，不是实际播放值。

设备排名由服务端按已存手机档案算力和独立分布返回，未启用/无手机/人口不可用有各自状态；Lite不显示手机个人排名。关闭时可清空档位，不能一律承诺下次开启仍有原档位。无独立实时采样、不完整恢复旧记录、超过24小时无原号结果查询，是当前能力边界；不通过删除未知记录或制造后台API绕开。

跨仓parity脚本支持NEXION_APP_REF指定目标提交；共享App当前工作树若是旧单步版本，默认检查仍如实报差异。指定b52d3152或已发布origin/test时，min/max、全球网络和作业基座与PC真实字段匹配；脚本不切换或修改App仓库。
