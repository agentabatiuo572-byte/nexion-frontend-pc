## 后端改动、前端原状与跟进

`OpsNotificationCampaignService.overview/stats` 在同一个只读 REPEATABLE_READ 快照和 asOf 内读取。本月 cohort 为本月创建、未删除的活动：`monthCampaigns` 是其总数，`monthSent` 是其中当前 sent 的数，`monthScheduled` 是其中当前 scheduled 或 sending 的数，`monthDraft` 是其中当前 draft 的数。`criticalInflight` 单独统计全量 critical 且 scheduled/sending 的活动，不能称为月内待发的子集。前端一直直接取这些后端字段，没有自行按列表重算本月；本轮继续直接取值。

`stats.basis` 保留 asOf、timeZone（BusinessCalendar.legacy 当前有效业务时区）、storageTimeZone（Asia/Shanghai）、monthFrom、weekFrom、rangeEndExclusive、monthBasis、notificationBasis。月份从业务月首、周从周一开始，上下界转换成持久时钟的无偏移文本，左闭右开，上界为同一 asOf，不是月末/周末。不能用浏览器本地时区解释这些持久文本。

basis 另含 deliveryFactsComplete、knownSentCount、knownReadCount、weeklyReadCount（可空）、weeklyReadKnownCount、undatedReadCount、weeklyReadAvailable、weeklyReadBasis、weeklySwipeAvailable、weeklySwipeReason。已读率沿全部当前 SENT 活动，用真实已读/真实发送；覆盖不全或分母为零不返回 avgReadRate。本周已读沿同一活动集合，按 read_flag 与 read_at 计数，覆盖不全或有旧已读缺 read_at 时主值不可用，已知量另保留。weeklySwipe 不再返回，原因 LEGACY_ESTIMATED_CONVERSION_REMOVED；阅读不能推算实际滑动或转化。PC 接收缺省/null，原数字槽用现有“—”，不补 0，不自行算平均/本周数。

每行 `deliveryFacts` 为 source、timeZone、asOf、complete、reason、sentCount/readCount（可空）、firstSentAt/lastSentAt（可空）、timeBasis。source=NOTIFICATION_DELIVERED_OUTBOX_TO_NOTIFICATION_ID；timeZone=Asia/Shanghai；timeBasis=RETAINED_LINKED_NOTIFICATION_PUSHED_AT_WINDOW。实际时间为带 offset 的持久 pushed_at 最早/最晚窗口；只证明进入用户通知流，不证明外部供应商/终端送达。通过注册权威 notification.delivered 事件的 campaign_id、notification_id/NOTIFICATION aggregate ID 去重关联，包含收件箱淘汰但仍保留的软删通知，不按文案/受众猜关联。

complete 仅在有正发送数、关联通知数等于具备发送时点的数、且与原活动精确 sent 字符串完全一致时为 true。完整时 sent/read 投影真实数；不完整时 read 不返回，原 sent 仅旧记录值，reason=DELIVERY_FACT_COVERAGE_UNCONFIRMED。PC 数据层保留原 sent 和完整性，不把旧值当成真实总数。列表和详情已有数槽只展示完整事实，不完整显示“—”；在 visual worker 加上旧记录值的明确标识后，可消费 raw sent。旧后端无事实字段继续原读法。新写回执的 deliveryFacts={} 归一化为缺省，不把它当概览事实；旧快照与回执仍可恢复。

已发送的完整事实在已有“发送”槽用 business-time 解析 offset 后转当前业务时区，多用户显示 first–last（秒），单通知可为单时点。没有完整窗口显示“—”，不拿排期、创建或更新时间补。部分窗口保留在数据层，未在无部分标识的现有槽冒充整条活动历史。原排期槽继续显示排期，不改写调度行为。
