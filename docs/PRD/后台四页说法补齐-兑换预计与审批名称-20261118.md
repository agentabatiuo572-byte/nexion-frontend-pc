# 运营后台四页说法补齐 · 2026-11-18

后端 `3ea9ca18` 新给的数据在 G2、A2、H1、B4 页面上有了位置和说法。只改界面和文字，请求、权限和能不能提交都不变。

## G2 兑换风险规则

- 原「额度和手续费」面板改名「兑换参数」，最下面多两行：「预计处理时长」（1–999 的整数小时）和「预计说法」（运营写的一句话，用 `{hours}` 代表小时数）。两项都是确认后立即生效，不走审批，权限是 `finprod_g2_write`；兑换暂停时也能改。
- 两项没设好（空或不合规）时，排队单上不显示预计时间。第一项没设好的那一行在值下面标「排队单上不显示」；设好后标「立即生效」。说法一行放不下时省略，悬停看全文；时长设好时说法这一行显示换好小时数的整句。
- 调整框：时长填 1–999 的整数，说法要写上 `{hours}`、最多 240 个字、不能换行，填写提示是「写预计多久，不写具体几点；用 {hours} 代表小时数」。框里随输入预览「排队单上显示：「……」」；另一项还没设好时写哪一项没设好。提交的请求和原来的参数修改一样：`PATCH /exchange/params/queueEtaHours` 或 `queueEtaCopy`，正文 `{value, reason, operator}`。
- 结果未知时，和其他参数一样进「兑换的原操作」提醒，行内标「结果未知」，可以查询原结果或在 24 小时内按原请求重试（同一个命令号，正文不变）。
- 排队单详情的「预计处理」：后端给了运营设的预计说法时原样显示那句话，说明写「按「兑换参数」里设的预计显示，不是排好的处理时间」；没设好或旧版本后端时仍写「等运营处理」。旧后端写死的「明天 00:00」继续不显示。
- 个人、平台额度拦截清单的问号按当前超额度处置策略多一句：排队时「用户选了「超额时排队」的进入排队，其余直接拒绝」，拒绝时「超过额度的兑换直接拒绝，不排队」。地区拦截的说明写「所在地区被封锁」，不露页面代号。
- 「处理排队」确认框的动作名从「处理今天的排队兑换」改成「处理排队中的兑换」：批次从最早排队的选，不限创建日期。
- 预计说法现在只在后台这页的排队单详情里显示；App 和 H5 排队后的提示还没接这两项。
- 「这页怎么用」新增「设排队单的预计时间」三步。

## A2 操作记录与审批

- 新格式的创世参数审批单动作已经带参数名（如「调整创世参数 · 节点总量」），列表第一格不再重复写对象名，也不再露参数键；详情「对象」写参数名，参数键收进「技术信息」问号。
- 变更后摘要里后端写的「确定新增应付 Δ N USDT」显示成「新增应付 N USDT」；新格式单原值为空时同样写「= 空」。
- 旧格式单按创世节点页的名字显示：`price` 写「系列当前价」，`royalty` 写「转让手续费」。
- 批准时检查兑付覆盖率的说明分开：K1 解除误判、判定为正常仍写「账户组状态和提现限制保持原样」；别的单用通用一句「低于红线时不执行，审批单继续待处理，原状态不变」。
- 「谁能批准」：后端已把代审门槛统一成「另一位有审批批准权限和对应业务权限的管理员」，页面照写；存的门槛是「超管」时写「另一位超级管理员」。

## H1 运营阶段设置 · 阶段归因

- 后端不再给固定参考值，六个阶段都是「未提供效果数据」。折叠摘要写「6 个阶段 · 还没有效果数据」，卡片列主要驱动、阶段参数、负责模块，不再列「参考值」这一格；旧版本后端给数值时仍列「参考值」。
- 问号和「这页怎么用」的术语改成：每个阶段主要靠哪项参数、由哪个模块负责；系统还没有效果数据，不代表已测出的效果。
- P5、P6 不再固定显示停用提示；只有某一行确实提到已停用的提现惩罚费率时才显示「这份资料含已停用的提现惩罚费率，不能当作现在的依据」。

## B4 运营阶段状态

- 提现惩罚费率仍标「已停用，现在不收」。下个月配置里它的值不同时，写「0% → 20%（不收）」，不让人以为下个月会收。

## 共用错误说明

- `VALUE_REQUIRED` 的中文改为「新值为空或不符合填写要求，本次没有保存。」（G2 两项预计、G7、成长和活动等保存都用这个码）。
