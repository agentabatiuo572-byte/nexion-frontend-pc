# A2／F4 审批读数与原操作恢复（2026-11-27）

PC test PR #182、#183、#185、#186、#188 和 BUG-786 分支合入后的现行规则。规范依据 admin-console/spec 02 OP-69、OP-90、OP-93、OP-126、OP-128、OP-129、OP-153，03 ST-34；后端 B134、B136、F4-BE-08。

## F4 派奖与团队激励池审批

- **判断顺序**（A2 批准总榜派奖、团队池结算；F4 总榜发起）：本次读数等待或读失败 → 排行榜暂停 → 团队池设置不完整（只挡未结算的周）→ 已派／已结算（不查覆盖率）→ 未结算才查兑付覆盖率。
- **读数等待**：这次打开读到之前确认禁用，原因只在按钮说明里（「正在加载最新状态，读到后才能批准／发起。」），读数区写「正在加载…」。
- **读失败**：确认禁用并常显原因（「本周奖池读到后才能批准。」「总榜预览读到后才能批准／发起。」），读数卡给「重试」，重读成功后照常判断（OP-128）。
- **本周池「实发／估算」**：只凭团队激励池概览同一份回包的 `currentWeekSettled`、`weeklyInjectedAmount`（B136）；为 true 标实发、金额用精确已发合计；为 false 且有金额标估算；旧后端缺字段时只写「本周池」，已结算判断沿用投票投影。
- **总榜发起框奖池**：预览读到后用预览里的奖池，和名单、测算合计同一次读数；读到前用页面配置占位。
- **审批结果**：按 B134 写「入账 N 笔，合计…」或「没有发钱：原因」；被暂停或覆盖率挡下时写原因和时间，待审批行常显最近一次被挡的原因（悬停看时间）；单张结果字段坏只影响这张单；非 F4 单不按 F4 解析。
- **批准被挡下后**：同框确认禁用，原因「这次没有执行：<原因>。审批单仍待审批，关掉后重新打开，按最新读数再批准，或驳回。」，理由带回重开的框。
- **覆盖率快照 503**：这两种批准上按写前明确拒绝处理（F4-BE-08），不进原号恢复。

## 原操作恢复

- **A2 审批决定**（批准、驳回、撤回）结果未知：刷新后先按原号查询，明确查不到且没过 24 小时才能按原操作重试；过期写「已超过 24 小时，不能再重试，请在「操作记录」里按单号核对。」。重放成功按回执写实际结果。
- **重试被明确拒绝的原因**：按保存的拒绝码出一句事实（一张表），恢复行、再查询后、刷新后、解除框都写同一句，不沿用普通提交的「重新加载」指引。
- **审批提案过期解除**（R1-提案过期）：I5、B5 的审批提案超过 24 小时、按原号明确查无（`A2_PROPOSAL_NOT_FOUND`）后可勾选核实后解除本标签页记录；查询中、查询失败不给。
- **D1 资金记录重试被拒**：能走核查结案的给「核查结案」，走不了的给「核实后解除」；再查询后按查到的写，原操作还在执行时不给解除。
- **B5 提高红线审批单**：查询原操作失败时框里常显失败原因。
