# A2 批准、驳回、撤回结果未知后的结案（2026-11-19）

A2「操作记录与审批」里批准、驳回、撤回一张单时回包丢失，页面留下「结果未知」，这张单在本页锁住，只能查询或按原请求重试。以前两种已经有明确结论的情况仍然留着记录：重试被后端明确拒绝时要人手动「解除原操作记录」；查询读到单已是这次要的结果时，只说「和这次批准对得上」、仍让人重试。现在这两种都直接结案。

## 规则

- **按原请求重试被后端明确拒绝**（带原因码的 4xx，例如 409「用户的团队分组尚未完成」）：原操作没有生效，直接解除这条记录，提示「<操作>没有生效：<原因>。原记录已解除，这张单可以重新处理。」，不再要人手动解除。
  - 依据：后端 `OpsAuditCenterService.idempotentTicket` 在按原命令号回放之前只检查权限；原操作已成功的，同号重试原样回放成功；还说不准的，返回 `IDEMPOTENCY_RESULT_UNKNOWN`。所以同号重试被业务规则拒绝，就说明原操作没有生效。
  - 权限不足（401、403）、超时、限流、`IDEMPOTENCY_*` 不算明确拒绝，记录照旧保留。
- **查询原结果读到单已是这次要的终态，且处理人就是当前账号**（批准→已批准、驳回→已驳回、撤回→已撤回）：这次操作要的结果已经发生，单也不会再被处理，直接结案，提示「已确认：<操作>已生效」。
  - 处理人对不上或读不到处理人、单还是待审批、单已过期：照旧保留记录，说明现在的状态。
- 机制参数、手动清理、导出不变：它们的后端在按原号回放之前还有别的检查，重试被拒说明不了原操作的结果，仍由人核实后解除。

## 不变的

批准、驳回、撤回的请求、资格和按钮不变；按原请求重试仍发同一命令号和同一内容；结果未知不自动重发、不换号；超过 24 小时只能查询。
