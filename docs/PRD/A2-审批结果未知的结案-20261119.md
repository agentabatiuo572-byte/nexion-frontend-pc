# A2 批准、驳回、撤回结果未知后，重试被明确拒绝就结案（2026-11-19）

A2「操作记录与审批」里批准、驳回、撤回一张单时回包丢失，页面留下「结果未知」，这张单在本页锁住，只能查询或按原操作重试。以前按原操作重试被后端明确拒绝（例如 409「用户的团队分组尚未完成」）后，记录仍留着，要人手动「解除原操作记录」。现在这种情况直接结案。

## 规则

- **按原操作重试被后端明确拒绝**（带原因码的业务 4xx）：原操作没有生效，直接解除这条记录，提示「<操作>没有生效：<原因>。原记录已解除。」，不再要人手动解除。
  - 依据：后端 `OpsAuditCenterService.idempotentTicket` 在按原命令号回放之前只检查权限；原操作已成功的，同号重试原样回放成功；还说不准的，返回 `IDEMPOTENCY_RESULT_UNKNOWN`。所以同号重试被业务规则拒绝，就说明原操作没有生效。
  - **例外，仍保留由人核实**：理由不合规的拒绝（`REASON_TOO_SHORT_MIN_*`、`REASON_TOO_LONG_*`、`A2_REASON_*`）。理由长度在回放之前按**当前**下限校验，下限调高后原理由会被拒，这证明不了原操作没生效。
  - 权限不足（401、403）、超时、限流、`IDEMPOTENCY_*` 不算明确拒绝，记录照旧保留。
- **「查询原结果」不结案**：它只能读到单现在的状态和处理人。同一账号在另一个标签页用另一个命令号处理了同一张单时，读到的完全一样，证明不了是原命令的结果；页面照旧说明现在的状态，记录保留，用「按原操作重试」确认。要让查询也能结案，需要后端按原命令号给出批准、驳回、撤回的结论（后端待办 A2-BE-10）。
- 机制参数、手动清理、导出不变：它们的后端在按原号回放之前还有别的检查，重试被拒说明不了原操作的结果，仍由人核实后解除。

## 不变的

批准、驳回、撤回的请求、资格和按钮不变；按原操作重试仍发同一命令号和同一内容；结果未知不自动重发、不换号；超过 24 小时只能查询。
