# D1 USDT-BEP20 充值规则

运营人员在 D1 的 Cregis 收款区查看和申请调整最低充值额、固定充值手续费及链上确认数。三个字段作为一组按当前版本提交 A2 审批；在另一位有权限的管理员批准并执行成功前，原配置继续生效。审批、拒绝或版本冲突均应可查询；提交结果不明时核对原提案；未取得提案时可在首次提交后的 10 分钟内使用原命令号和原请求重试，超过重试时间后仅能继续核查，不创建新提案。变更不修改收款、自动入账或出款开关。

最低额和手续费以 USDT 计，最多六位小数；最低额大于零，手续费不小于零且低于最低额。确认数为 15–10000 的整数，且不得低于服务端环境可能更高的安全下限。实际值来自后端权威配置，页面不得以默认值替代读取失败。TEST 目标为最低额 1 USDT、手续费 0 USDT、确认数 15；若环境安全下限更高须保留该下限，环境实际生效值须经审批及读回确认。

最低额、手续费和确认数按系统首次发现交易时生效的配置确定，已经发现的交易保留规则快照；环境安全确认数下限提高时，未入账交易仍须满足更高的下限。已入账交易的金额不因后续调整重算。旧的已发现未入账交易迁移时保留原有规则，确认数不得低于原来生效值。链上转账低于最低额、链上确认不足、异常和供应商核验均继续遵循现有处理与安全门，不因配置界面开放而直接入账。充值记录与入金复核页面展示服务端记录的毛额、手续费和净额；缺失时显示未提供，不推算或固定填值。App 和 H5 对最低额、手续费、充值记录金额保留最多六位有效小数，优先使用服务端精确金额；旧接口无法可靠还原时显示占位。读取历史失败时保留已加载的历史并提供重试；地址读取失败时不可使用未经确认的地址。

验收应覆盖：无权限只读；三项边界、精度和版本冲突；提案前后值、另一管理员审批与拒绝；未批准不生效；提交结果未知时查询原提案、在首次提交后的 10 分钟内用原请求和命令号重试以及超时后禁止重试；批准后配置读回；首次发现前后交易的手续费快照与已入账记录不变；确认数不足不提前入账。供应商和链上实况仍须以真实证据单独验收。
