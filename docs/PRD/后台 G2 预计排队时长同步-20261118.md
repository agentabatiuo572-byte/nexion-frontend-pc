## 兑换风险规则

管理总览 `GET /api/admin/market/exchange` 提供 `queueEstimate.hours` 和 `queueEstimate.copy` 两个配置原值。它们分别由 `queueEtaHours` 和 `queueEtaCopy` 参数维护。配置独立于五项额度、费率和排队策略。旧版本可省略 `queueEstimate`，新版尚未配置时可返回空字符串，后台保留读回原值。

`PATCH /api/admin/market/exchange/params/{paramKey}` 复用 `Idempotency-Key` 与 `value`、`reason`、`operator` 请求体。维护预计时间的两项都要求 `finprod_g2_write`，沿用参数直接保存和原请求恢复。客户端原样发送 `value`，包括首尾空白及 `{hours}`，服务按既有更新流程校验和保存。有效时长为 1–999 的十进制整数，文案校验使用去掉首尾空白后的值，最多 240 个码点，须含 `{hours}`，其余字符遵照输入校验。服务把所有 `{hours}` 替换为有效时长，并通过排队单的 `etaLabel` 提供完整说明。缺任一有效值时使用现有的无预计时间状态。

当平台日额度用尽，允许排队的策略和请求进入人工队列，其余请求拒绝。实际到账随人工批次处理。预计时长与预计文案的两个编辑位置及排队详情的说明交界面决定。App 和 Lite 的兑换数据目前没有管理端的 ETA 投影，已定位排队成功提示、排队计数和兑换说明里的固定时间文案。
