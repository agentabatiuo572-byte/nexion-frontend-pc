# BE-27 区域大使材料核验

2026-11-07。本规格为原47项BE-27的当前实施合同，取代F4c旧版中“一次开四桶”“确认即放款”“仅KOL发票核验”及旧`/agent`接口示意。本轮只改变F4大使申请、对应A2工单和A1/A6独立核验权限表现；申请资格与现行预算政策沿用已有规则。

## 申请与材料

原申请保留编号、申请人、城市、日期与申请额。申请类别为线下活动、KOL推广、物料或开发支持；新申请批准仅登记所选一类额度，金额等于合法申请额，不发起钱包实际转账。历史已批准的状态和额度不重分，也不伪造材料核验通过。

四类必要材料分别为：线下活动的签到／活动／费用，KOL推广的推广／流量／费用，物料的清单／配额／费用，开发支持的需求／工时／验收／费用。文件由本人原申请上传，私有鉴权读取，支持PNG／JPEG／PDF，单份不超过10MiB，最多12份有效附件；PC仅查看，不代申请人上传。

本人提交或补交产生新材料版本；两项旧核验结论不沿用。历史待审缺类别由本人明确补齐，不猜默认。财务认可额不足时不自动修改申请额；本人可在退回补交时下调原申请金额，新版本重新核验。终态不能修改材料。

## PC流程

- F4原列表显示单类别、申请额、申请状态、材料版本与进度，通过“查看材料”进入原申请详情。
- 详情按类别展示必要材料、缺项、附件与来源说明，显示本版业务和财务核验的结论、人员显示名、时间、理由、人数或认可金额，并可查看历史核验。页面不接收或展示核验管理员ID。
- 业务与费用核验分别授权。结论需明确选择“通过”或“需补材料”，填写理由；需补材料可选择缺项，直接记录到原申请供本人补交，不额外发送外部消息。线下业务通过须核实至少100人的有效去重人数，不能用预计人数或每日签到代替；费用通过须填写认可金额。
- 同版必要材料齐全、两核验通过、认可金额不低于申请额、日期已到且当前账号获准时，才可发起批准。F4按服务端`canProposeApproval`决定提案可用性，允许核验人发起A2提案；A2按`canApprove`决定最终执行，核验人不能成为最终批准人，超管同样遵守。最终权限沿用现有规则；不要求额外第三位管理员。未核齐、需补、过期或权限不足时显示具体原因并禁用发起批准。
- 批准确认显示单类别、申请额、认可额和材料版本；经现有A2提案，由另一位有权且未参与本版核验的管理员最终执行。批准时重新核验当前材料、金额、版本、申请状态、权限和原兑付覆盖率门。
- A2对应详情与确认显示原申请、上述金额和两项结论，并比较提案材料版本与当前版本；缺失或过期版本的旧批准票不能执行，须核对后重新发起。批准／驳回意图只读原命令生成的`applicationDecision`，不使用可被说明文案替换的“变更后”文本判断；正常批准票始终展示提案版本。驳回仍走既有A2流程，不要求材料先通过。
- 2026-11-08文案澄清：仅大使`applicationDecision=APPROVE`票，A2详情底部和执行确认的影响提示均为“批准执行时，系统会重新核验材料版本、核验结论、认可金额及兑付覆盖率。任一条件不满足时，审批单继续待处理，申请状态和所选类别预算额度保持原样。”；两处“谁能执行”均显示“另一位具有审批和大使批准权限、且未参与本版材料核验的管理员”。只修正这四处展示，其他票沿原文案，实际权限、存储gate和审批流程不变。
- F4提案原因读取独立`proposalBlockers`，包含缺少A2提案权限的具体原因；核验人可以提案，最终执行仍按`approvalBlockers`限制，二者不混用。
- 核验命令保存原载荷、理由、版本与幂等键，按当前账号和原申请隔离；结果未知可在刷新或重开详情后继续原命令，不改内容重发。保留的成功回执超过24小时仍可使用原键恢复并收敛；未知状态继续由服务端隔离，不换号重做。终态详情也保留原核验结果核对入口。原键恢复先读保留的成功回执；若服务端明确返回“材料版本已变化”或“申请已处理”的未执行冲突，则收敛该原核验、保留未执行说明并刷新当前材料，解除旧版本对新材料的阻塞；权限收回或其它不明错误不据此清除原命令。

## 权限与接口

### 核验时间契约（2026-11-08，BUG-387）

材料包中的 `businessReview.reviewedAt`、`financeReview.reviewedAt` 和 `reviewHistory[].reviewedAt` 表示同一绝对时刻，读取时按既有 `Asia/Shanghai` 存储时区还原为 ISO 8601 UTC 字符串（带 `Z`），未核验或时间为空时返回 `null`。数据库仍保存原业务时间，不迁移历史核验事实，不改变核验结论、管理员显示名、金额和权限。

该输出规则共用于 App 材料读取、申请最新/历史摘要和 PC 材料读取/核验/审批摘要。现有 App 按设备时区、PC 按选定业务时区显示这一时刻，设备处于 UTC+7 或 UTC+9 时不得把存储时钟当作设备本地时钟。页面布局、控件和格式化规则本批不改。

历史成功幂等回执保存原始响应。材料提交和核验接口在返回出口将旧回执中上述核验时间按同一存储时区转换，保留旧回执原有的秒精度；既有UTC时间与空值保持。回放继续使用原键、原载荷和原材料版本，不重复写核验、材料版本或审计，也不重写原存储回执。升级前回执的兼容处理与当前读取分别验收；实际覆盖与剩余项以本轮验收回执为准。

`network_f4_ambassador_material_review`为业务核验，`network_f4_ambassador_finance_review`为费用核验；读取沿`network_f4_read`。超管可核两类，财务主管仅费用核验并有必要读取／菜单，审计只读。现有普通增长不因`network_%`通配自动得到新核验写权；指定业务主管通过现有A1/A6显式授权，不新建主管角色。核验与最终批准分别授权。

A1账号详情按当前角色实际授权分别显示两项核验能力，角色变化预览使用独立名称。A6详情显示两项授权，编辑仍以权限目录与原审批流程为准，不在前端预选或自动授予。

PC材料：

- `GET /api/admin/teams/ambassador-applications/{id}/materials`
- `GET /api/admin/teams/ambassador-applications/{id}/materials/files/{fileId}`；fileId为不透明字符串，私有二进制透传。
- `POST /api/admin/teams/ambassador-applications/{id}/materials/review`，携`Idempotency-Key`与`expectedMaterialRevision,stage,decision,reason`，按职责携`verifiedAttendees`或`recognizedBudgetUsdt`，需补时可携`missingKinds`。

材料包含单类别、日期、申请额、版本、状态、要求、附件、来源说明、缺项、两项核验、历史、当前动作可用性及批准阻断原因。批准命令沿`F/f_ui_config`与`F.ambassador.{id}.status`，独立保存`expectedMaterialRevision`；`sourceDomain=F4`，`obj=原申请号`，锁对象为`F/ambassador_application/原申请号`。A2返回`ambassadorMaterialProposal`权威摘要；客户端不为旧提案自动绑定当前材料。
