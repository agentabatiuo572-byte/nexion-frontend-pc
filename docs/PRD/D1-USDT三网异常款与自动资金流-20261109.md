# D1 USDT 三网异常款与自动资金流（2026-11-09）

本次补齐 ERC20 异常款认领、原路退款，以及 ERC20/TRC20 自动归集到cregis与自动cregis转平台收款钱包。沿用 BEP20 的资金业务规则。代码接入、部署验收与真实资金验收分别记录，不能互相替代。

## 异常款认领、原路退款

- BEP20、ERC20、TRC20 均按原事件网络查询供应商、核验 USDT 合约、精度、交易日志、金额、收款子地址、实际 Transfer 转出地址和确认数；TRC20 还需固化区块证明。
- 认领与原路退款均须由实际转出钱包签署一次性原文，绑定部署、项目、网络、Token、交易、日志、金额、处置动作、目标用户及有效期。ERC20 使用 Ethereum 钱包消息签名。交易所或合约无法提供有效签名时保留待核查，公开交易哈希不能替代归属证明。
- 认领仅处理尚未归属的观察款；按该网的政策快照扣费并一次性入账。原路退款只能退到经过证明的原转出地址，保留原毛额、费用、净额和原业务号，不接受另填任意收款人。
- 继续使用原权限、双人复核、来源占用、A2 对象锁和保留型幂等。已入账、已退款或被其他处置占用的同一来源不能再次处分。关闭发送后，已发原单仍可查询与核验；未知结果不得新建付款。

## 自动归集到cregis与自动cregis转平台收款钱包

1. 仅处理首次启用水位之后、已核实入账的钱包充值事件；每网首次水位独立，暂停恢复不重置。订单直付款不作为钱包充值重复处理。
2. 对每笔事件自动归集充值毛额至本网络 Cregis 管理的归集钱包；供应商原单与链上真实转账均核实后，才进入转平台收款钱包阶段。
3. 从该 Cregis 归集钱包向该网平台收款钱包转出用户入账净额。充值手续费留在 Cregis 归集钱包，BNB/ETH/TRX 链上手续费由平台另付，不重复入账或扣用户余额。
4. 发出前重新核对事件、金额、来源归属、该网余额、燃料、运行批准、业务开关及出款能力。缺地址、缺燃料、风险阻断或读证据失败时不发送。
5. 各网策略、任务、地址占用、事件水位、币种、链证据和查询游标独立。相同 EVM 地址在 BEP20 与 ERC20 上也不能串网查询、审批或恢复。
6. 先持久化发送意图，再提交一次。超时、断电或供应商响应不明进入 UNKNOWN，不自动重发；只能绑定经核实的原 CID 查询。仅无 CID 的明确创建拒绝允许按原任务申请重试。回调验签并核对网络、Token、地址和金额，只作为查询线索，不能直接标记完成或批准发送。

## PC 后台页面

用户于本任务明确确认设计稿与影响范围。D1「USDT 充值 → 归集到cregis与cregis转平台收款钱包」沿用现有资金域样式，自动流程卡内提供 BEP20/ERC20/TRC20 分网切换。显示当前网络地址、运行批准、归集及转出开关、提案、任务与原 CID；确认框冻结网络。缺地址显示“待配置”并禁止启用，Gas 名称随网络变化；警示带图标与警示色，开关与操作按钮左右分组，任务区用分隔和居中空态表达。切换网络、账号或权限后，旧响应和旧确认框不能继续操作。

D1 嵌入式及独立式面板共用实现。人工准备单仍保留原 BEP20 准备性质，不将准备单当作自动执行授权。App/H5 无页面变更。

### 自动流程名称调整（2026-11-09）

用户最初指定「自动归集到cregis」「cregis转平台收款钱包」，随后明确要求右侧自动开关加上“自动”，并统一下方人工准备区的旧称。当前两个自动功能显示为「自动归集到cregis」「自动cregis转平台收款钱包」；人工准备类型为「归集到cregis准备」「cregis转平台收款钱包准备」。自动卡的标题、状态、提案/暂停确认、任务文案，以及人工卡的标题、地址角色、说明、下拉选项、记录类型、确认详情与对应错误提示同步使用新称；资金分区导航也同步。三网与 D1 嵌入式/独立式共用实现。人工准备单仍只有 BEP20、仍只保存记录，不执行转账。

「自动归集到cregis」仍指将充值子地址的充值毛额归集到 Cregis 管理的归集钱包；「自动cregis转平台收款钱包」仍从该钱包转出用户入账净额到既有收款地址。显示名不修改 `platformAddress`/`counterpartyAddress`、`collectionEnabled`/`paymentEnabled` 或链上路径。充值手续费留在 Cregis 归集钱包，链上手续费由平台另付。

两个选项禁用的直接条件为加载/提交中、运行总开关未批准或地址未配齐；提交提案还要求当前无待复核提案。已显示写控件的管理员并不能越过服务端运行批准。当前 TEST 运行总开关及自动策略仍关闭，此次改名不授权实付。启用前须核实 Cregis 出款能力、对应网络地址及 BNB/ETH/TRX 手续费，再完成运行批准和另一管理员复核。

## 接口与部署

- `/api/admin/finance/cregis/auto-forward/status`、`tasks`、`policy`、`tasks/{id}/recover` 增加 `network=BEP20|ERC20|TRC20`，省略仍为 BEP20。任务返回原始 `chainId`，状态返回 `network`、`configured` 和 `gasSymbol`。缺完整地址配置时两个地址均返回 null。
- 保留 BEP20 旧付款业务号、旧幂等请求结构、任务意图、CID、状态、版本与水位。新网业务号额外带网络。
- `20261109_cregis_multinetwork_auto_forward.sql` 为前向迁移；旧自动流程建表步骤登记为启动前置。新网策略初始关闭、水位为空，迁移不授权、不重置旧网开关，也不回填历史任务。
- 现有 `NEXION_CREGIS_AUTO_FORWARD_ENABLED` 仍为运行总批准。新网还分别需要 `NEXION_CREGIS_ERC20_AUTO_FORWARD_ENABLED` / `NEXION_CREGIS_TRC20_AUTO_FORWARD_ENABLED`，默认 false。
- 新网各自从安全运行配置读取 `NEXION_CREGIS_{ERC20|TRC20}_PLATFORM_ADDRESS`、`NEXION_CREGIS_{ERC20|TRC20}_COUNTERPARTY_ADDRESS`；默认空，不继承 BEP20 地址。服务端核对地址格式与任务快照，供应商钱包绑定须在启用前另行核实。
- 每网启用仍须已批准的供应商出款能力、RPC、全局资金闸、风控对账及另一管理员复核。充值开关不代表自动资金流程已批准。
