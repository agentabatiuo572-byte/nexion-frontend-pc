# PCN-29：B0 今日概览资金快照导出留痕

日期：2026-11-06。用户已确认本次页面变更范围。适用 PC 今日概览 `/` 页头的「导出资金数据」。

## 页面与权限

- 仅当前真实登录会话角色为 `superadmin` 且包含 `overview_b0_export` 时在页头显示次按钮「导出资金数据」。新快照须资金读取成功；已有待确认快照时仍保留恢复入口。
- 点击打开标准操作确认框，常显蓝色生效标签、JSON 格式与快照范围，其后填写导出理由。确认框读取 A2 服务端理由规则，检查可见字符数及最长 200 字；服务端再次按当前规则裁决。空理由、过短理由不能确认。
- 确认前取消不发出导出登记请求，也不触发下载。
- 后端必须同时验证导出权限及数据库中的超管身份；页面隐藏按钮不能替代后端鉴权。

## 原快照与登记顺序

首次点击时冻结当前页面原有 JSON 快照，字段与原含义不变：

| 字段 | 既有口径 |
|---|---|
| `generatedAt` | 本次点击生成快照的 ISO 时间 |
| `coverageRatio` | 页面账本覆盖率，沿用两位小数处理 |
| `redlinePct` / `healthyPct` | 当前红线与健康线 |
| `reserveUsd` / `liabilitiesUsd` | 当前储备金与负债 |
| `netExposureUsd` | 当前储备金减负债 |
| `accounts` | 原账户列表，每项保留 `key`、`label`、`amount` |

确认后先可靠保存本次原快照 JSON、理由、请求号及真实管理员 ID，再发 `POST /api/admin/ops-dashboard/exports`；请求体仅 `{ reason }`，请求头携带原 `Idempotency-Key`。该精确 BFF 路由使用 HttpOnly 会话 cookie、强制改密门、固定后端路径，仅转发规定的认证、JSON 类型和幂等头，不代理任意子路径、查询参数或调用方认证头。

服务端成功回执包含 `exportNo`、`recordedAt`、`format`、`fileName`；只在得到有效 JSON 导出回执、当前身份和权限仍属同一会话后，浏览器才下载已冻结的 JSON，使用服务端 `fileName`。下载发起后清除本次待定记录。界面成功提示显示服务端导出号，供 A2 精确核对。

**后端只登记导出意图、理由、真实操作者、导出号及文件名等审计事实，不接收或保存此 JSON 内容，也不提供快照文件下载链接。** JSON 仍由浏览器生成；不能把登记成功表述为后端已保存 JSON 或已验证文件内容。

## 结果未知与恢复

- 沿用共享待定命令存储，按真实 `adminId` 隔离，记录只包含本次原快照、理由、请求号及恢复元数据，不保存 token、cookie 或凭据。
- 网络中断、HTTP 5xx、业务信封 `code >= 500`（包括 HTTP 200 携带 `{ code: 500, message: "INTERNAL_SERVER_ERROR", data: null }`）、上游结果未知、响应不可读或成功回执不完整时，不下载、不删除原记录。后端全局异常处理存在仅返回失败信封、不设置 HTTP 错误状态的实际路径，不能仅依据 HTTP 200 判定为明确拒绝。弹窗保留且锁定原理由；同标签页刷新、导航离开后重新打开首页导出，也恢复原 JSON 字节、原理由及原请求号。期间账本刷新不会替换本次待定快照。
- 重试仅重发原理由及原请求号。服务端在 `B0_SNAPSHOT_EXPORT:<adminId>` 作用域内按原理由幂等回放，保持同一导出号和文件名，不重复登记成功审计。
- 首次明确业务拒绝允许修改理由后再提交；已有未知结果后的再次鉴权或规则拒绝不清除原记录，避免丢弃可能已经成功的登记。
- 浏览器无法可靠持久化时，在请求前停止。共享存储期限为首次尝试起 24 小时，不因重试延期；过期后保留证据并停止重放，需联系值班人员核对 A2。当前后端没有独立导出回执查询接口，页面不能自动裁决过期未知记录。
- 存储沿用 `sessionStorage`：支持同一标签页内刷新和重新打开页面；关闭标签页、主动清理浏览器存储、切换真实账号不承诺继续恢复。切换账号按共享身份认领规则清理旧账号命令，异步回执不会给新账号触发旧快照下载。
