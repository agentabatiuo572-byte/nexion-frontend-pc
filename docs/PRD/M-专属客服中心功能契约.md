# M 专属客服中心功能契约

最后更新：2026-10-09

本契约承载客服中心的产品职责；[开发落地规格](Nexion_运营控制后台_开发落地规格.md#域-m--客服中心)承载端点索引，[M3 实时通信契约](M3-会话实时通信契约.md)承载传输协议。运营账号与角色仍由 [V1 A1/A6/A8](Nexion_运营控制后台PRD_v1.md)管理。

## 1. 目的、入口与边界

专属客服以本人待回复、首次联系和维护任务为先；主管以本人负责组的数据总览、组对比与客服数据为先，调度操作辅助；总管理员查看全部获准客服域的服务覆盖、经营结果、分组和主管数量。统计必须可进入同口径对象或事实列表。

| 入口 | 职责 |
|---|---|
| M1 `/service/overview` | 本人工作台、组概览/组详情、客户入口及多维统计 |
| M2 `/service/tickets` | 原工单及内部协作，不由新客户列表替换 |
| M3 `/service/sessions` | 专属会话、原资料及工具、新客户统计 |
| M6 `/service/leaderboard` | 四个独立业绩榜与公开客服成绩摘要 |
| M4 `/service/kb-sla` | 原知识库、FAQ、分类和 SLA |
| M5 `/service/scripts` | 原服务规则、话术及继承配置 |
| A1 运营账号 | 客服创建、性别、头像；管理资格仍与个人接待资格分开 |

人工服务统一为一个“专属客服”身份。App 的首页、个人中心、消息中心、订单求助等原入口到达同一专属客服服务；通知和工单属于内容类别。App 实现职责属于 App 工程，本后台合同不代替其验收。旧入口可兼容跳转，合法历史会话继续可达；不因改名重绑客户、重开首充、修改历史作者或重抽旧头像。

## 2. 数据模型与不变量

| 对象 | 最小合同 |
|---|---|
| 资格 | 既有运营账号的个人服务/主管资格及启停、生效历史；允许多名主管，兼任分别判权 |
| 客服组 | 稳定 ID、名称、唯一当前主管、启用/停用/归档状态、版本；一层平级 |
| 负责人/成员历史 | 账号、组、起止时间、版本、操作号、操作者、原因；同客服同时至多一组，允许待分组 |
| 客户绑定 | 客户唯一当前合法专属客服与历史；当前组由当前客服当前组派生，分组不建第二份绑定 |
| 未绑定路由 | 客户、可信目标组或全局未路由、版本和历史；路由不是个人绑定 |
| 付款事实 | 稳定源事件 ID、客户、来源、成功状态/时间、实际金额/币种、购机原单/退款关系、源及覆盖版本 |
| 首充事实 | 客户唯一首事件、来源、时间、金额/币种、事件时客服/组及归属状态 |
| 查询/榜单版本 | 权限与范围版本、定义/数据版本、期间/时区、币种、截至时间、覆盖及不可用原因 |

历史生效区间为 `[开始,结束)`，以服务端成功提交为生效点。绑定、调组和负责人移交不得反推或搬动历史付款归属；同刻事件依可证明的事务顺序/归属版本，证据不足保持未知。状态、历史、审计原子写入，过期版本拒绝。

## 3. 权限与管理动作

| 能力 | 专属客服 | 主管 | 总管理员 |
|---|---|---|---|
| 当前客户/会话/资料 | 本人当前合法绑定 | 当前负责组的获准对象 | 全部获准客服域对象 |
| 组经营与成员统计 | 个人工作台及本人组名称 | 当前负责的零个或多个组 | 全组、待分组、未路由和异常 |
| 对客发送 | 本人当前绑定且个人服务资格、原写权有效 | 管理资格不授代发；兼任仍只按个人资格 | 同主管 |
| 组内分配/正式转绑 | 无 | 来源/目标均在负责范围，目标客服合格 | 可跨组，沿既有正式流程 |
| 创建/改名组、负责范围内调成员 | 无 | 新组负责人固定本人；来源/目标均为本人组 | 全部合法组 |
| 跨主管调组、待分组处理、全局路由、整组移交 | 无 | 无 | 可以 |
| 主管目录、数量、资格管理 | 无 | 不开放其他主管目录 | 按账号模块原权限查看/管理 |
| 公开业绩榜 | 获准公开汇总 | 获准公开汇总 | 获准公开汇总 |
| 账号/资金/风控/导出等 | 原动作权限与对象范围交集 | 同左 | 同左，统计管理权不增加专项写权 |

主管“全部”仅合并当前负责组；无负责组是合法空态，不能退回全平台。主管兼任的个人服务范围不扩大组经营范围。主管数和客服数分别按账号去重，全部人员取两集合并集，不直接相加。

全局未路由池仅总管理员可看；可信组路由但未绑定者进入该组队列，个人绑定后退出队列。主管不能经数量、搜索、旧地址、附件、工单、导出或实时订阅旁路。待分组客服保留本人服务权，不自动进入主管范围；停用客服保留存量绑定和历史，单列待交接，不随机换人。

管理写入须明确目标、前后影响、理由、版本、原命令号和确认，并记录审计。整组移交原子切换当前与历史组访问权；旧主管不能凭任职历史继续读组数据。停用/归档组前处理成员、队列及未结束路由/分配依赖；主管资格退出前移交其负责组（含归档组），个人服务资格退出另处理合法绑定。失败回滚，未知结果按原命令查询，不换号盲重试。

## 4. 指标、事实与归属

### 首充与金额

首充是客户全历史、全部合法币种中最早一次合格成功外部充值或设备实付，每客终身一次。实际成功充值排除礼赠、人工加款、测试、重复、未成功；购机排除赠机、免费试用、零实付、待付/失败/仅预授权。真实余额购机、正额折后购买、付费试用转正式、组合购、保留旧机另购与正额差价置换按其真实付款源适配；单独续费、续存算力或服务支付不混为购机。

先按 `(成功时间,充值优先的固定来源序,稳定源事件ID)` 确定全球唯一首事件，再按日期/币种筛选。组合订单按付款事实去重，不按设备/SKU重复计款。成功充值不允许退款；购机成功后退款保留真实首次付费事件，重复/测试/错误事实只能经原权限及审计更正后重算。

充值与购机金额始终分列，不加为新增资金或收入；不同币种不换汇相加。充值业绩额为本期成功充值额，不存在充值退款扣减。购机榜原单有效额 = 本期合格成功购买金额 − 与原单唯一关联且截至榜单时已成功的退款金额；跨月退款归原购买月份及原客服，不归退款时现客服。提现、内部转账、手续费、购机消费及银行卡 chargeback 追回不用于扣减充值业绩。购机退款事件经营统计保持自身成功时间/归属，与原单有效额分开。

缺真实成功充值全历史、事件时归属或充值来源失败时，相应数值/覆盖保持未知或部分覆盖；当时未分配不摊派给个人，真实0须有完整覆盖证据。充值榜不以缺充值退款源禁榜，但充值不退款不代表购机退款源或参榜资格历史完整。缺购机完整成功付款、原单关联或退款结果源时，购机榜不得用毛额、假定退款0或已知子集冒充完整有效额及完整名次。购机超额退款、币种不符、关联不明须待核实，不截零掩盖错误。

### 指标字典

| 类别 | 口径与下钻 |
|---|---|
| 当前资产 | 当前绑定、组队列、成员、客户余额、持有设备及连接状态；用当前归属快照，不随期间伪装历史资产 |
| 期间经营 | 首充、成功充值/购机/提现/购机退款按各自成功事件及事件时归属；来源/本金/手续费/实到分列，源 ID 去重 |
| 当前客户累计画像 | 本人/本组当前客户全历史首充、成功充值、资金和邀请画像；与期间业绩明确分开 |
| 邀请 | 直属和全部可达后代去重、不含本人；邀请团队充值不混入个人或组直接经营，重叠树行不能相加 |
| 服务 | 待回复按客户去重，读不清待回复；首次联系、待维护、维护执行与真实维护成功分开；暂停主动维护仍可处理求助 |
| 活跃 | 使用真实客户活动与既有可配置窗口，客服发消息/已读/设备运行不当客户活动 |
| 设备 | IDC 持续托管，设备按 ID 去重；有证据的运行/故障/维护、离线、未知和不适用分开，无闲置指标或唤醒营销 |
| 平台覆盖 | 已绑定有组、已绑定待分组、组待分配、全局未路由、异常互斥；仅总管理员看全平台分母 |

事件时未分配、明确待分组及历史未知分开；不能定位组的历史仅交总管理员核实。原客服保留获准历史汇总，转出客户的身份、逐笔资金、会话与链接不因历史业绩重新开放。获准跨客服邀请汇总不授予范围外个人明细、外组经营切片或全局队列数量。

累计与排序用服务端授权全集，不从当前页或近几笔记录求和。金额精确十进制；真实0、未知、无权限、失败独立。比例标分子/分母，分母0不适用，覆盖不全不给精确率；不以期间首充除当前绑定伪造转化率。

## 5. 工作台、查询与下钻

主管组范围为“全部负责组/单组”，数据视角为总览、客服、客户、资金、设备、活跃；单页一张主列表。单组可进入组内客服切片和当前客户；总管理员另有主管目录、待分组与全局未路由入口。

服务端先授权、筛选、全量精确排序，再稳定分页；未知数置末，稳定对象 ID 只固定同行次序。客户默认排序：待回复/首次联系/待维护/沉默/未首充/待分配分别优先最早待处理、分配、到期、活动、注册、入池；全部/活跃/已首充/不再维护分别按最近活动、首事件、状态变更最新。允许字段以服务端当前视角能力为准，金额排序先选币种。

各可见统计数字、分布、趋势、0与比例都进入相同范围、期间、币种、来源和口径的真实列表；比例进入分子/分母，未知进入有权待核实对象及原因。受限历史明确仅汇总可见，不伪造等量明细。返回保留有效条件和位置；切组清无效客服筛选、关闭或重验旧详情，全部区块同步改组。后页、详情、本人摘要使用同一查询版本，版本变化回首刷新；晚到旧响应不能覆盖新范围。

页面默认、空、加载、失败/未知状态明确，失败保留条件和重试入口；无权限停止读取并清理旧正文/附件/缓存及订阅。日期和金额单位由共同查询明确；姓名截断、K/M 紧凑显示仅是展示，不改原值、排序、明细或权限。

| 参数/能力 | 合同 |
|---|---|
| 自动继承 | 新配置默认 `UNLIMITED`；可显式 `LIMITED`，根0、直接邀请1，N+1按无客服规则处理；统计后代层数与绑定继承独立 |
| 存量继承 | 已有明确有限/无限配置保留；确认存在的 `UNCONFIGURED` 仅通过有版本可审计迁移改无限，只影响以后新注册；缺字段或读失败不是未配置 |
| 无客服处理 | 复用显式主管分配/随机规则，可信路由限定合法组/候选；不追溯改旧绑定或自动捞旧池，正式人工分配另行预览确认 |
| 客服性别/头像 | 原账号模块明确男/女/未指定；新建从许可且已审核男/女池随机一次，未指定用混合池，持久化资源ID及版本；不猜性别，不随刷新、改名/性别、调组重抽，不批量替换旧像 |
| 头像更换 | 本人或具有原账号管理权且在原范围内的人员明确更换，受控图片校验/审计，成功保存后替换；失败留旧像，未知先回查，池不可用不造假照片 |
| 客户与历史作者头像 | 复用已存授权照片，失败回退缺失态；历史真实作者不替成当前客服，头像不作身份核验事实 |
| 静默提醒/结束 | 新策略1/5分钟；提醒整数1–30，结束整数2–120且大于提醒；仅总管理员与原配置权交集可改，理由至少6字，新段取得版本快照，存量值和活跃段保留 |

M3 继续保留收件箱搜索/筛选/数量/分页、单客/人群主动联系、状态/结束/转工单、独立归档与还原、历史会话及工单、风险/资金/设备/标签备注/维护资料、完整档案与原模块合法操作。新统计追加，不替换原业务；原字段范围、敏感操作确认、取消、失败重试和返回出口保留。

快捷回复模板、客服话术和商品用互斥选择层，支持搜索/空态/失败重试/关闭/Esc；已发布有效内容追加草稿，不覆盖、不自动发送。商品先预览，图片经受控上传后人工发送；提交重验有效性。草稿按登录身份/客户/会话隔离，撤权后不再可见。

文字/商品/图片共用真实发送与权限通道：提交中→已接受/结果未知/确认失败；已接受不等于送达。阅读未知/未读/已读独立，真实回执单调前进，发送未知不伪装未读；未知查原命令，失败同键重试，取消选择或上传不破坏原稿。读不清待回复、客服操作不算客户活跃或维护成功。

静默只从成功客户消息或合法客服人工发送的原成功时间计时，草稿/输入/系统消息/已读/刷新不续期。当前段进行中且无待回复才提醒一次后结束；新消息/回复与到期按版本重验，事实未知不关闭。只结束当前段，不解绑、不换客服、不转备勤池；后续求助仍在同一合法归属的新段。主管审阅不授代发，临时跨坐席转接及冒名发送不恢复。

## 7. 四个独立排行榜

| 榜 | 排名值及时间 |
|---|---|
| 首充人数 | 当自然月发生的全球唯一首事件、事件时归本客服的客户数；充值/购机来源分列 |
| 充值贡献 | 该自然月成功充值额，分币种；成功充值不退款，不作退款扣减 |
| 购机贡献 | 该自然月合格设备实付原单截至榜单时有效额，分币种 |
| 绑定客户规模 | 当前合法绑定客户去重人数，固定截至现在，不带月份/币种，不冒充新增业绩 |

前三榜按后台业务时区自然月 `[月初,次月初)`，只开放真实覆盖月份。月榜候选是当月有真实有效服务资格者，包括后来停用/离岗；纯管理者不参榜，兼任按账号一次。规模榜还包括有合法绑定待交接的停用/撤资格账号。未知资格历史不据今天名单补齐。

按精确值降序、真并列为 `1、2、2、4`；完整可信0正常入榜，缺数/错误/覆盖不足不作为0。任一候选不足影响全榜时标暂定，已知子集不称完整名次；不可排名或暂定不授确定前三荣誉。搜索仅定位已算全榜，保留名次；单页一张长榜，切榜/期间/币种/范围回首，“定位我”进入本人所在页。

全员、本人组或负责组范围由服务端授权；组筛选按当前参榜成员重算本范围排名，不冒称历史组贡献。公开投影仅展示名/授权头像、当前组名、资格启停标记、名次、获准聚合、口径覆盖与时间；不含客户ID、交易号、联系方式、附件或隐藏明细。客户/资金/会话/导出仍单独判断当前对象权。

日变化比较上一业务日末最后一份完整发布快照，显示真实基线时间；必须同榜、币种、月份、定义、范围和可比候选集合。月初/缺基线/覆盖不足/集合变更显示不可比，不补0；仅确证新增资格称新入榜，补历史/调组不称新入榜。历史月不显示日升降；迟到事实、购机原单退款或审计更正可发布可追溯新版本，不能改写旧日末基线。

计算成功原子发布，全表/本人/摘要同版；失败不发布半榜，保留真实截至时间和重试条件。既有配置仅控制已覆盖默认榜/月份/币种与刷新（推荐5分钟、允许1–60整数分钟），不改算法；不新增奖金、薪酬、处罚、综合分或人工改名次入口。

## 8. 验收

| 场景 | 必须结果 |
|---|---|
| 三资格、无组主管、兼任、两主管组和全管理员 | 本人/负责组/全部范围及人数正确；伪造组/客服、旧URL/附件/导出/订阅不扩大范围 |
