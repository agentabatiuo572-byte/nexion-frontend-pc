# M 专属客服中心功能契约

最后更新：2026-11-02

本契约承载客服中心的产品职责；[开发落地规格](Nexion_运营控制后台_开发落地规格.md#域-m--客服中心)承载端点索引，[M3 实时通信契约](M3-会话实时通信契约.md)承载传输协议。运营账号与角色仍由 [V1 A1/A6/A8](Nexion_运营控制后台PRD_v1.md)管理。

## 1. 目的、入口与边界

专属客服以本人待回复、首次联系和维护任务为先；主管以本人负责组的数据总览、组对比与客服数据为先，调度操作辅助；总管理员查看全部获准客服域的服务覆盖、经营结果、分组和主管数量。统计必须可进入同口径对象或事实列表。

M1 首次进入按默认 USDT 查询服务端权威范围；登录态中的可读模式只用于选择首个请求视角（全部→总览、负责组→客服、本人→客户），不授予数据权限。实际范围以本次服务端响应为准；旧模式提示请求的视角被拒绝时，再用总览重新核对，仍被拒绝则关闭私有内容。当首屏查询条件完全相同时，范围核对响应直接用于首屏统计，避免串行重复计算；响应范围变化后，重新查询对应视角，不显示旧视角行。月份日历只在本人月绩或期间筛选需要时读取；保留加载、失败、重试，获取服务端月份边界前不发期间统计。月份返回不重算当前客户/设备统计。手动刷新、筛选变化和范围撤销仍重新读取，身份变化清除旧响应；失败和未知语义保持原合同。M1 不读取当前页面不消费的旧负载策略；切换子页按页面重新读取。实时会话、坐席核验、持续接待及共享知识库/话术工具继续沿原合同并发加载，保留已发布内容、合法空态及失败重试。

M1 首屏统计及本人工作台保留直接加载；其他运营域、M3–M5页面以及M1的待分配、客服与分组和客户资料面板按进入时加载代码。M6 进入榜单路由时直接准备本页功能，与登录核验并行，核验完成后才读取获准榜单；不先显示功能加载占位再启动本页功能，不将榜单代码加入其他页面的首屏。代码加载中显示明确状态，失败保留重新加载页面入口；按需加载不删功能、不复用旧授权数据，也不改共享内容工具和持续接待的数据依赖。性能验收以实际点击到关键统计与可用操作为终点，加载占位不算达到首屏目标。

M1 性能目标：关键数据接口从浏览器发起到完整响应不超过 300ms，点击入口到关键统计与可用操作呈现不超过 1 秒；以真实数据、当前授权和实际页面验证，不能用空壳或永久加载替代。用户于 2026-10-29 批准后台按 60 秒周期汇总统计并保存完成版本，替代此前最多延迟 5 秒的约定；正常统计时效约 1 分钟加计算耗时。请求和手动刷新只读取最新完成版本，不在请求内启动重算；计算期间或后台更新失败保留上一完整版本，不能发布半版。无可用版本或读取失败明确显示不可用及重试，不补 0、不伪造更新时间。

页面展示统计真实数据截至时间（`asOf`，不是请求返回时间）；本人客户统计与期间业绩分别显示各自时间。当前显示的统计超过 2 分钟时提示「统计更新延迟」，提供读取最新统计入口；读取到新版本后按真实时间恢复正常提示。停留页面也能到期提示，仅更新提示自身，不以每秒重绘整个工作台计时。提示不得承诺实时统计；后台故障继续显示上版时仍保留其原时间。登录身份、读权限、组管理范围和客户当前归属仍在每次读取中即时校验；缓存不授予权限，也不保留跨身份的私有 HTTP 回包。冷启动优先复用已有完成版本，缺版本时明确不可用，不把首次重算成本留给首位访问者。

后端实现合同：每 60 秒在请求外完整汇总，将完成版本及客户级统计投影保存到 Redis，版本完整后原子发布。请求以当前授权和客户归属筛出获准客户，再读取完成版本的投影形成对应视角、筛选和分页；不能直接复用旧权限范围的整包响应，也不能在请求内重放支付、流水或设备历史证据计算。计算失败不覆盖上一完整版本；无可读取的完整版本时返回明确不可用。存储实现仅属于服务端合同，不进入工作台用户文案。

| 入口 | 职责 |
|---|---|
| M1 `/service/overview` | 本人工作台、组概览/组详情、客户入口及多维统计 |
| M2 `/service/tickets` | 原工单及内部协作，不由新客户列表替换 |
| M3 `/service/sessions` | 专属会话、原资料及工具、新客户统计 |
| 客户全景 `/service/customers/{customerId}` | M1/M3 当前获准客户的完整只读档案；从会话进入可返回原会话，从工作台进入可返回工作台 |
| M6 `/service/leaderboard` | 净贡献额、首充人数、客户规模三个榜与公开客服成绩摘要 |
| M4 `/service/kb-sla` | 原知识库、FAQ、分类和 SLA |
| M5 `/service/scripts` | 原服务规则、话术及继承配置；新用户欢迎语（中/英/越三语） |
| A1 运营账号 | 客服创建、性别、头像；管理资格仍与个人接待资格分开 |

人工服务统一为一个“专属客服”身份。App 的首页、个人中心、消息中心、订单求助等原入口到达同一专属客服服务；通知和工单属于内容类别。App 实现职责属于 App 工程，本后台合同不代替其验收。旧入口可兼容跳转，合法历史会话继续可达；不因改名重绑客户、重开首充、修改历史作者或重抽旧头像。

## 2. 数据模型与不变量

| 对象 | 最小合同 |
|---|---|
| 资格 | 既有运营账号的个人服务/主管资格及启停、生效历史；允许多名主管，兼任分别判权 |
| 客服组 | 稳定 ID、名称、唯一当前主管、启用/停用/归档状态、版本；一层平级 |
| 负责人/成员历史 | 账号、组、起止时间、版本、操作号、操作者、原因；同客服同时至多一组，允许待分组 |
| 客户绑定 | 客户唯一当前合法专属客服与历史；当前组由当前客服当前组派生，分组不建第二份绑定 |
| 客服邀请码 | 客服、码、有效/已作废状态，以及生成、重置、作废的操作者、时间和理由。码以 `CS` 开头，大小写不敏感，与用户邀请码（`NX` 开头）不重叠；每位客服同一时间只有一个有效码，可反复使用，重置即作废旧码；作废不改变已注册客户的绑定 |
| 未绑定路由 | 客户、可信目标组或全局未路由、版本和历史；路由不是个人绑定 |
| 待绑定客户池身份展示 | 客户信息中显示昵称/编号、ID及脱敏手机号；手机号沿用管理端前三位、后四位格式，未提供时显示“—”。只读取当前获准客户范围，不返回原始手机号，不新增逐行详情请求或修改分配行为。搜索支持精确客户 ID、昵称及手机号包含匹配；输入完整号码或任意连续数字片段均可，按实际号码搜索而非脱敏文本；手机号中的 `%`、`_` 不作为通配符。列表与总数使用同一过滤条件，搜索重置到第一页，清除后恢复列表；返回手机号仍保持脱敏 |
| 付款事实 | 稳定源事件 ID、客户、来源、成功状态/时间、实际金额/币种、购机原单/退款关系、源及覆盖版本 |
| 首充事实 | 客户唯一首事件、来源、时间、金额/币种、事件时客服/组及归属状态 |
| 查询/榜单版本 | 权限与范围版本、定义/数据版本、期间/时区、币种、截至时间、覆盖及不可用原因 |

历史生效区间为 `[开始,结束)`，以服务端成功提交为生效点。绑定、调组和负责人移交不得反推或搬动历史付款归属；同刻事件依可证明的事务顺序/归属版本，证据不足保持未知。状态、历史、审计原子写入，过期版本拒绝。

## 3. 权限与管理动作

| 能力 | 专属客服 | 主管 | 总管理员 |
|---|---|---|---|
| 当前客户/会话/资料 | 本人当前合法绑定 | 当前负责组的获准对象 | 全部获准客服域对象 |
| 组经营与成员统计 | 个人工作台及本人组名称 | 当前负责的零个或多个组 | 全组、待分组、未路由和异常 |
| 对客发送 | 本人当前绑定且个人服务资格、原写权有效；他人接待中不能发送 | 当前负责组已绑定客户，以本人身份发送并须取得接待（第 6 节「主管发起会话与会话互斥」）；不冒充专属客服 | 全部获准客服域的已绑定客户，规则同主管 |
| 组内分配/正式转绑 | 无 | 来源/目标均在负责范围，目标客服合格 | 可跨组，沿既有正式流程 |
| 创建/改名组、负责范围内调成员 | 无 | 新组负责人固定本人；来源/目标均为本人组 | 全部合法组 |
| 跨主管调组、待分组处理、全局路由、整组移交 | 无 | 无 | 可以 |
| 主管数量、资格管理 | 无 | 无 | 数量在工作台总览查看；资格在「运营账号与权限」逐个账号管理，按账号模块原权限；组和负责人在「客服与分组」查看 |
| 公开业绩榜 | 获准公开汇总 | 获准公开汇总 | 获准公开汇总 |
| 客服邀请码 | 查看、生成、重置本人的码 | 查看并作废当前负责组成员的码 | 查看并作废全部客服的码 |
| 账号/资金/风控/导出等 | 原动作权限与对象范围交集 | 同左 | 同左，统计管理权不增加专项写权 |

主管“全部”仅合并当前负责组；无负责组是合法空态，不能退回全平台。主管兼任的个人服务范围不扩大组经营范围；本人工作台、客户名单、维护待办和主动联系仍按本人合法绑定读取，不因负责组变化遗漏。主管数和客服数分别按账号去重，全部人员取两集合并集，不直接相加。

登录和会话刷新返回当前有效的个人服务、主管及全局查看资格；身份标识分别显示专属客服、客服主管或兼任，不按职位名称推断资格。兼任主管默认进入负责组概览，专属客服默认进入个人工作台；无有效资格不能进入客户、会话及榜单页面。角色授权、服务资格和对象归属共同生效，其他岗位和自定义角色不能仅凭岗位名称获得客服范围。

全后台确认摘要统一由调用方显式声明类别；客服中心的操作确认框由发起方说明这是哪类操作，执行摘要按这个类别写影响和提交前提示，不按说明或正文里的文字猜测：更换本人头像、会话结束与归档、删除内部备注、删除常见问答、会话类别启停各有自己的说明；配置、内容发布和其余操作沿用原有写法。

内置客服角色默认仅开放 M1–M5 及由 M1/M3 阅读权派生的业绩榜；M1/M2/M3 保留原业务读写，M4/M5 默认只读，主管动作仍受负责组限制。客户资料、设备、资金及商品推荐使用客服域内的受限查询，不默认开放平台总览、全局客户/设备、财务或账号授权管理。重置密码、账户处置及资金调整保留原入口和独立授权；额外职责由 A6 显式配置，不因客服或主管身份自动增加权限。

M1/M3 的完整档案入口复用现有客户全景页，只调用 `GET /api/admin/content/support-workbench/customers/{customerId}/full-profile`，不授予全局 C1 阅读权，不回退到 C1 接口。服务端按当前资格、本人/负责组/全部获准范围及字段权限裁剪；不可读分区保持隐藏，安全、团队及审计资料不自动开放。页面只读，保留原服务资料中的标签、备注、工单及资金快捷入口；唯一例外是支付安全的解除操作，沿用独立解除权限和服务端 `releaseAllowed`，不因客服或主管身份自动获得。缺失金额、计数显示“-”；加载失败可重试，归属撤销或权限变化清除旧资料。

新建账号默认选择专属客服；创建客服账号时，同一事务建立个人服务资格和有效客服档案，初始待分组，不自动授予主管资格。账号继承客服角色的当前有效授权，不复制旧权限。显式选择其他角色或暂不分配时保持该选择；恢复管理入口仍仅允许创建总管理员。主管资格及负责组通过既有独立授权流程设置。

菜单以当前获准页面为准，权限信息缺失不得按静态岗位补全；默认入口必须可访问，零页面时提供重新核验与退出。资格或授权变化后清理旧视图及在途读取，保留同一操作者的未决命令号。每次后台鉴权读取当前有效授权，角色授权成功提交后的新请求不得用旧权限缓存放行；刷新后只展示新的获准范围。

兼任主管的会话收件箱合并其当前获准管理会话与本人合法绑定会话，并按会话号去重；组移交不使仍合法绑定的本人会话消失，也不增加代发权限。范围变化立即清除旧组页、资料和在途结果，重新读取分组与会话；失败保留重试入口，不以旧名单或推测权限替代。

全局未路由池仅总管理员可看；可信组路由但未绑定者进入该组队列，个人绑定后退出队列。主管不能经数量、搜索、旧地址、附件、工单、导出或实时订阅旁路。待分组客服保留本人服务权，不自动进入主管范围；停用客服保留存量绑定和历史，单列待交接，不随机换人。

管理写入须明确目标、前后影响、理由、版本、原命令号和确认，并记录审计。组管理查询原操作返回未找到记录时，提示「系统没有这条原操作的记录，请求可能没有送达」，继续保留原操作及既有重试条件，不把未找到记录写成执行失败。（BUG-163，仅文案项）整组移交原子切换当前与历史组访问权；旧主管不能凭任职历史继续读组数据。停用/归档组前处理成员、队列及未结束路由/分配依赖；主管资格退出前移交其负责组（含归档组），个人服务资格退出另处理合法绑定。失败回滚，未知结果按原命令查询，不换号盲重试。

「正式转绑客户」（M3 会话的「•••」菜单）和「维护状态与正式转绑」（客户资料弹层）进入 M1 后直接打开该客户的转绑表单，不用切页签，超级管理员、纯主管和兼任主管同一入口。表单写明客户、当前专属客服、转给谁、绑定版本和理由。总管理员可转给任一可接待的专属客服；主管只能在客户当前专属客服所在的负责组内转绑，表单只列该组成员。客户不在主管负责组内时不显示入口（待分组兼任主管的本人客户即属此类），直接打开链接也只显示拒绝说明，本人客户可转到「我的客户」查看。普通专属客服沿这些链接仍进入本人客户详情，不能转绑。

转绑、M3 首次分配、M5 待分配设置和「结束会话」的结果分三种。系统明确拒绝（版本、目标不可接待等）时显示具体原因，不写成结果未知。结果未知时保留原操作编号，转绑、首次分配和待分配设置同时锁定目标、理由和内容，不能改动后沿用旧编号提交；刷新、关闭重开或切换客户后原操作还在，先用原编号查询：成功或失败即收敛，系统明确回复没有这次操作的回执才可按原操作重试，编号和内容都不变。转绑查到失败时，表单重新加载最新归属，由操作者重新确认后用新编号提交；查询被范围拒绝、读回失败或重试被拒绝都不能说明原写入失败，原操作继续保留，不开放重试。首次分配未确认时，会话页头显示「核对上次分配」；待分配设置未确认时，卡片只显示原内容和「查询原操作」。「结束会话」按操作员和客户分别保留，切到另一位客户结束会话不影响原记录。M5 服务规则、首次分配和待分配设置的原操作从首次提交起超过 24 小时后，页面不再重试，只能继续查询；这是页面的限制，系统保留的回执和查询不受此限。

## 4. 指标、事实与归属

### 首充与金额

首充是客户全历史、全部合法币种中最早一次合格成功外部充值或设备实付，每客终身一次。实际成功充值排除礼赠、人工加款、测试、重复、未成功；购机排除赠机、免费试用、零实付、待付/失败/仅预授权。真实余额购机、正额折后购买、付费试用转正式、组合购、保留旧机另购与正额差价置换按其真实付款源适配；单独续费、续存算力或服务支付不混为购机。

先按 `(成功时间,充值优先的固定来源序,稳定源事件ID)` 确定全球唯一首事件，再按日期/币种筛选。组合订单按付款事实去重，不按设备/SKU重复计款。成功充值不允许退款；购机成功后客户不能发起退款，仅有相应退款权限的后台人员按现有确认、理由及审计流程主动处理。后台购机退款保留真实首次付费事件，重复/测试/错误事实只能经原权限及审计更正后重算。

业绩额采用净贡献：真实成功充值计一次；全部实际付费消费不限硬件，仅尚未计入贡献的资金用于消费时新增贡献，充值后的余额消费不重复计入。成功提现和后台退款只冲减已计入贡献的原来源；收益提现不冲减原业绩。申请、处理中、失败、拒绝、取消不冲减，失败返还和退款保留原资金来源与顺序。兑换、持有转换、内部转移或二级出售延续原币成本、贡献和归属，不将同一笔钱再次计为充值或消费贡献。充值、消费和退款流水仍按各自业务类型展示，不相加冒充新增资金。

成功提现按实际余额扣款冲减，包含实际扣款中的手续费；手续费不增加业绩。App申请额已含手续费，到账额为申请额减实际手续费，不再次相加；NEX抵扣单独追踪实际NEX扣款，不按折算值新增贡献。来源分配采用消费优先已计贡献资金、提现优先未计贡献且已释放的可提收益，同类按原来源和贡献形成顺序；提交提现时固定来源，后续收益不替换。资格、额度、退款权限和资金安全规则仍按现有业务，统计缺口不能阻止合法提现或后台退款。

贡献依形成时的客服、组、主管归属；冲减发生在真实成功的期间，仍归原贡献，调组或转绑不搬历史。跨月冲减可使该月净贡献为负，不截零；不同币种不换汇相加，原始精度参与排名。缺真实资金来源、成功历史、原归属、退款关联或提现终态时保持未知；已知部分可展示，不授完整名次。净贡献覆盖不足不抹去独立证实的首充人数或绑定客户数，真实0须完整证据。充值成功不允许退款，但不免除其它资金来源完整性检查。

## 5. 工作台、查询与下钻

主管组范围为“全部负责组/单组”，数据视角为总览、客服、客户、资金、设备、活跃；单页一张主列表。单组可进入组内客服切片和当前客户；总管理员另有待分组与全局未路由入口。

服务端先授权、筛选、全量精确排序，再稳定分页；未知数置末，稳定对象 ID 只固定同行次序。客户默认排序：待回复/首次联系/待维护/沉默/未首充/待分配分别优先最早待处理、分配、到期、活动、注册、入池；全部/活跃/已首充/不再维护分别按最近活动、首事件、状态变更最新。允许字段以服务端当前视角能力为准，金额排序先选币种。

各可见统计数字、分布、趋势、0与比例都进入相同范围、期间、币种、来源和口径的真实列表；比例进入分子/分母，未知进入有权待核实对象及原因。受限历史明确仅汇总可见，不伪造等量明细。返回保留有效条件和位置；切组清无效客服筛选、关闭或重验旧详情，全部区块同步改组。后页、详情、本人摘要使用同一查询版本，版本变化回首刷新；晚到旧响应不能覆盖新范围。
